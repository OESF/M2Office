# 契約書チェック

契約書（NDA・売買・業務委託など）を AI が読み、概要・注意したい点・修正の案・相手に確かめること・交渉の進め方の案を平易にまとめる公式の拡張機能です（仕様書 第28章、ADR-0043）。
**スキル（SKILL.md）の書き方のまま**書いています（仕様書 第12.12節）。表も画面も持たず、拡張の仕組みだけで作れることの見本でもあります。

**法務の境界**: 論点の整理と条文の要約にとどめ、法律上の判断と、契約を結ぶかどうかの判断はしません（第28.2節）。
結果の冒頭に「論点の整理であり、法律上の判断ではありません」の旨を必ず置きます。表示と規約の文面は、公開の前に弁護士の確認を受けます（Q-97）。

## 構成

| ファイル | 内容 |
|---|---|
| `SKILL.md` | 業務の指示（推論が読む）。境界・進め方・自社の立場の見分け方・照らす基準・3 段階の分け方・結果の形 |
| `reference/common.md` | どの種類でも見る観点（期間と更新・解約・損害賠償・補償・知的財産・個人情報・支払い・裁判所など）と、一般に入る条項 |
| `reference/nda.md` | 秘密保持契約の 10 の観点（第28.6.2節） |
| `reference/sales.md` | 売買・取引基本契約の観点 |
| `reference/outsourcing.md` | 業務委託（請負・準委任）の観点。フリーランスの取引に関する法律に当たりうる点 |
| `HELP.md` | 利用者向けの説明 |
| `evals/contract-review.json` | 評価のケース（第28.10節）。見本の契約書は `docs/evals/contract-review/` |

観点の資料には確認日を書いています。**法改正に合わせて直してください**（第28.6節）。

| ツール | すること | 危険度 |
|---|---|---|
| `file.read_text` | 契約書を文字にする（画像や文字の無い PDF のページは読み取り） | 読むだけ |
| `pdf.extract` | PDF をページごとに読む | 読むだけ |
| `knowledge.search` | 会社の知識から「契約の基準」を探す | 読むだけ |
| `docx.render` | 結果を Word の文書にする | 下書き |
| `skill.read` | 観点の資料を開く（補助のファイルがあるので自動で加わる） | 読むだけ |

## 決まり

- `metadata.m2office-private: "true"`（学ばない業務。第12.12.3節）。秘書は結果から学ばず、秘書の答えに結果の要点を添えない
- `effort: xhigh`（高性能のモデル。上限はトークン 30 万・時間 10 分。第12.12.5節）。契約書の全文をツールを呼ぶたびに読み直すため
- 自社の立場は聞かない。基盤が指示に添える会社の正式名称・略称（第12.12.5節）で、当事者のどちらが自社かを見分ける
- 導入は管理者が「配布元から追加」で行う。既定では入れない（第28.3節）

## 確かめ方

```bash
npm run ext:validate extensions/contract-review
```

本物の Gemini で、`docs/evals/contract-review/` の見本の契約書を 1 つずつ渡し、`evals/contract-review.json` の `expect` のとおりかを確かめます。
