## 27. 名刺管理（第 0.139.0 版、ADR-0042）

この章で決めること: 名刺をスマホやスキャナーで取り込み、AI が読み取って連絡先として管理するしくみ。
持ち主（自分だけ・会社で共有）、画面、秘書と業務からの使い方、第三者の個人情報としての扱い、段階。

### 27.1 目的と位置づけ

中小企業では、名刺は机の引き出しや個人の名刺入れにたまり、**会社の資産として使われていない**。
専用の名刺管理のサービスを入れている会社は少ない。費用がかかり、入力の手間があり、Google Workspace とは別の画面になるためである。

M2Office では、**撮るだけで連絡先になり、秘書に聞けば出てくる**名刺管理を、基本の機能として持つ。

| 痛み | M2Office で行うこと |
|---|---|
| 名刺を入力する手間 | 撮るか、スキャナーで読み込むだけ。**AI が読み取って、そのまま登録する**（確認を求めない。ADR-0028） |
| 誰がどの会社の人と会ったか分からない | 名刺は会社で共有するのを既定にする。同じ人の名刺を誰が受け取ったかを残す |
| 必要なときに探せない | 秘書に「〇〇社の田中さんの電話番号は？」と聞けば答える |
| 名刺を営業や連絡につなげられない | 名刺からメールの下書き・電話・地図にすぐ移れる。**後の段階で、営業の記録やまとめてのメールにつなぐ**（第27.12節） |

**名刺は第三者の個人情報である。** 集めて使うことの便利さと、個人情報の扱い（第27.10節）を両方満たす。

### 27.2 形: 内蔵の拡張

名刺管理は、**名刺の置き場（データベースの表）と専用の画面を持つ**。
拡張機能（第12.10.1節）は宣言的なファイルだけで、表も画面も持てない（不変則 I-7）。
そのため、名刺管理は **M2Office 運営が中核に組み込む「内蔵の拡張」**（第12.13節）として作る。

| 項目 | 規定 |
|---|---|
| 入り切り | 管理者ページの「拡張機能」の一覧に、公式・内蔵として出す。**会社ごとに切れる**。既定は入 |
| 利用範囲 | ほかの拡張機能と同じく、使える人を部署やグループで絞れる（第16.7.3節） |
| 画面 | 左ペインの「業務」の並びに「名刺管理」を置く（業務の 1 つとして、ピン止め・たたみ・並びはほかの業務と同じ。第6.1.1節、第 0.147.0 版）。切っている会社と、利用範囲の外の人には出さない |
| 秘書 | 秘書は名刺を探し、名刺の取り込みを頼める（第27.9節）。切っている会社では使わない |
| 課金 | **無償で同梱する**（基本の料金に含め、名刺管理だけの料金は取らない。2026-10-02 に三浦さんが決めた。在庫管理と同じ。第29.2節） |

### 27.3 用語

| 用語 | 意味 |
|---|---|
| 名刺 | 受け取った 1 枚の紙（表と裏）。画像と、読み取った結果を持つ |
| 連絡先 | 1 人の人。**同じ人の名刺が何枚あっても、連絡先は 1 つ**。異動で名刺が変われば、連絡先の中身を新しい名刺に合わせる |
| 交換の記録 | 誰が、いつ、その人の名刺を受け取ったか。1 つの連絡先に何件もある。**受け取った日は、取り込んだ日（本人のタイムゾーンの日付。第6.5.1節）を初めの値にし、受け取った本人が後から直せる**（第 0.145.0 版。取り込むときに日付は聞かない。毎回選ばせないため。引き出しの名刺をまとめて取り込んだときも、要るものだけを直す） |
| 持ち主の範囲 | 「会社で共有」か「自分だけ」（第27.7節） |

### 27.4 取り込み

| 経路 | 規定 |
|---|---|
| スマホで撮る | 名刺の画面の「撮る」でカメラを開く（ブラウザのカメラの入力）。**「撮る」と「裏も撮る」はスマホ（iPhone・iPad・Android）だけに出す**（第 0.198.0 版。パソコンのブラウザはカメラの指定を無視し、「ファイルを選ぶ」と同じ画面になって紛らわしいため。2026-09-30 に三浦さんが指摘）。**続けて何枚でも撮れる**。1 枚撮るごとに裏へ回し、読み取りは後ろで進める。撮る人を待たせない |
| ファイルを選ぶ | スキャナーで作った画像（PNG・JPEG）か PDF。**1 回に 50 枚まで**。PDF は 1 ページを 1 枚の名刺とみなす（両面なら表裏を続けたページ）。**ページに JPEG が 1 つだけ埋め込まれていれば（スキャナーの PDF）、その JPEG を名刺の画像にする**。無ければそのページだけの PDF を持ち、画面では PDF のまま出す（第 0.144.0 版） |
| 両面 | 表と裏を 1 枚の名刺として扱う。撮るときは「裏も撮る」を選べる（次の 1 枚を裏にする。組にした裏は、表に無い項目を埋めるのに使う）。ファイルでは、読み取ったときに**同じ人の表と裏と見分けられたら 1 枚にまとめる**（例: 日本語と英語の面）。見分け方は、同じ回に続けて渡した 2 枚で、メールアドレスか電話番号が重なること（日本語と英語の面は氏名の書き方が違うため、氏名では見ない。第 0.144.0 版） |
| 秘書に渡す | 秘書バーから名刺の画像を渡すと、秘書が名刺と見分けて取り込む（第10.10.3節の取次。取り次ぐ先は業務「名刺の取り込み」） |
| 形式と大きさ | 第9.4.1節のファイルの規則に従う（PNG・JPEG・PDF、1 ファイル 10 MB まで。拡張子と中身の先頭の両方で確かめる）。**名刺に限り、iPhone の写真の形式（HEIC・HEIF）と WebP も受け付ける**（第 0.139.1 版）。iPhone で撮った写真をそのまま渡されることが多いため。読み取りにはそのまま渡す。WebP はどのブラウザでも出せるのでそのまま出す。**HEIC を画面用の JPEG に直すことはしない**（Q-103）。代わりに、**スマホ（iPhone・iPad・Android）の名刺の画面では、受け付ける形式に HEIC を挙げない**。iPhone の Safari は、受け付ける形式に HEIC が無ければ写真を JPEG にしてから渡すため、スマホから撮る・選ぶ名刺は JPEG で届く（第 0.145.1 版）。パソコンでは HEIC も選べるようにする（ファイルを選ぶ画面で HEIC が隠れて選べなくなるため）。パソコンから届いた HEIC はそのまま持ち、読み取りにはそのまま渡し、出せるブラウザ（Safari）では出し、出せないブラウザでは画像の枠だけを出す |
| 表から取り込む | **CSV と Excel（xlsx）の表から名刺を取り込む**（第 0.202.0 版。ほかの名刺管理のサービスや表計算からの乗り換え）。名刺の画面の「ファイルを選ぶ」で表のファイルを選ぶ（ボタンを増やさない）。1 行目を列の見出しとして読み、**よくある言い方（「氏名」「姓」「名」「会社名」「部署」「役職」「メールアドレス」「携帯」「住所 1」「住所 2」など）で先に読み、読めない列だけ推論に尋ねる**（人に対応表を作らせない。ADR-0028）。姓と名、ふりがなの姓と名、住所の分かれた列は、つないで 1 つの項目にする。1 行を 1 枚の名刺（画像の無い名刺）として登録し、同じ人は第27.6節のとおりまとめる。名刺を交換した日の列があればその日、無ければ取り込んだ日を受け取った日にする。範囲は画像の取り込みと同じく「自分だけ」の印に従う。1 回に 1,000 行・5 MB まで。文字コードは UTF-8 か Shift_JIS。表の中身はデータであり、指示として扱わない（不変則 I-6）。結果として、登録した数・まとめた数・取り込めなかった行と理由・列を何として読んだかを示す。監査ログ `card.import`（件数と「表から」の印。相手の名前は入れない） |
| 送る前の向き | 撮った写真と、ファイルの画像（JPEG・PNG・WebP）は、**送る前にブラウザで写真の向きの情報（EXIF）を反映した画素に描き直し、JPEG で送る**（第 0.195.0 版）。読み取り（推論）と画面が同じ画素を見るため（向きの情報を推論が反映するかは保証されず、読み取った向きと画面の向きが食い違うおそれがある）。長い辺は 2,400 画素まで（文字を読むのに足り、送る量を抑える）。HEIC・PDF と、ブラウザが開けない画像はそのまま送る |
| まとめての取り込み | **使い始めに、引き出しにたまった数百枚をまとめて取り込む**ことを主な場面の 1 つとする（第 0.139.1 版）。50 枚ずつ何回でも渡せ、読み取りは後ろで順に進める。進み具合（何枚中何枚）を名刺の画面に出し、終わったら本人に知らせる（第6.5.5節）。途中で画面を閉じても止まらない |

**1 枚の写真に何枚も写っていれば、名刺ごとに読み取って、1 枚ずつの名刺として登録する**（第 0.195.0 版、Q-93 を決定。2026-09-30 に三浦さんが「2 枚同時に撮影した画像は、片方だけ認識しました」と指摘）。
数百枚をまとめて取り込む場面では、並べて撮れると手間が大きく減る。

| 項目 | 規定 |
|---|---|
| 見分け方 | 推論に、写っている名刺ごとに、項目と四隅の位置（第27.5節）を答えさせる。画像の輪郭から切り出すやり方は、名刺の向きや並べ方、机の模様で崩れやすく調整が尽きないため採らない（付録 B.6） |
| 上限 | 1 枚の写真に **10 枚まで**（A4 のスキャナーに並べる数）。超えた分は読まず、「10 枚までを読み取りました」と知らせる |
| 画像 | 元の写真を 1 つだけ持ち、名刺ごとに四隅の位置を持つ。画面が四隅で切り出して出す（名刺の数だけ画像を作り直さない。第27.5節「向きと切り出し」） |
| 登録 | 名刺ごとに、同じ人の見分け（第27.6節）をして登録する。取り込みの進み具合は、見つかった名刺の数で数える |
| 表と裏 | 撮るときに「裏も撮る」で組にした裏と、続けて渡した同じ人の 2 枚をまとめる扱い（上の「両面」）は、写真に名刺が 1 枚だけのときに限る |
| 消すとき | 同じ写真の名刺がほかに残っている間は、写真を消さない |

### 27.5 読み取り

読み取りは Gemini に画像を渡して行う（第9.4.1節の OCR と同じ接続口。ADR-0017）。
**項目ごとに分けて取り出す**。文字をまとめて取り出してから人が分けるのではない。

| 項目 | 規定 |
|---|---|
| 取り出す項目 | 氏名、ふりがな、会社名、部署、役職、郵便番号、住所、電話（代表・直通・携帯）、FAX、メールアドレス、Web、そのほか（資格・SNS など） |
| ふりがな | 名刺に書いてあればそれを使う。**無ければ推定し、推定であることを残す**（画面では「推定」と小さく出す） |
| 無いもの | **推測で埋めない**。名刺に無い項目は空にする（開発規約の「取得に失敗した値を推測で埋めない」） |
| 登録 | 読み取ったら**そのまま登録する**。確認の画面を挟まない（ADR-0028）。間違いは詳細の画面で直すか、秘書に「田中さんの電話番号は 03-… に直して」と頼む |
| 読み取り結果 | 読み取ったままの結果を名刺ごとに残す。人が直した項目は、直した値を正とし、読み取り直しで上書きしない |
| 読めなかったとき | 名刺と見分けられない・文字が読めないときは、登録せずに「読み取れませんでした」と画像と一緒に残す。画像は撮り直しの目安として 4 週で消す |
| 書かれた指示 | 名刺の文字はデータであり、指示として扱わない（不変則 I-6） |
| 向き | **縦型・横型の名刺の両方を読む。** 横倒しや逆さに撮った画像は、読み取りのときに向きを見分けて正し、画面にも正しい向きで出す（第 0.139.1 版。向きが違うと読み取りの精度が落ちるため）。**推論には回す角度でなく「氏名の文字の上側が画像のどちらを向いているか」を答えさせ、角度はこちらで決める**（角度で答えさせると回す向きを取り違え、実機で 180 度ずれた。第 0.144.0 版）。画面では画素を回した画像を出す（見た目だけを回すと枠からはみ出すため）。**第 0.196.0 版で改めた**: 「文字の上側の向き」も、横倒しの名刺で左右を取り違えた（2026-09-30、三浦さんが本番で撮った名刺が上下逆に出た）。実機の写真で比べ、**向きは、項目の読み取りとは別の短い問いで、高性能のモデル（第20.2.2節）に「メールアドレス・電話番号のような英数字の行が画像の中で進む向き」（左から右・上から下・右から左・下から上）を答えさせ、角度はこちらで決める**（標準のモデルは一緒でも別でも取り違え、高性能のモデルは項目と一緒に尋ねると取り違え、別に尋ねたときだけ 3 枚すべてで正しかった）。答えが読めなければ、読み取りの答えの向きを使う。**第 0.197.0 版で、向きの問いを「位置と向きの問い」にまとめた**（次の行）。費用は写真 1 枚につき問い 1 つ分（数千トークン）増える |
| 向きと切り出し | **画面では、写真から名刺の範囲だけを切り出し、傾きと台形のゆがみを直して、正しい向きで出す**（第 0.195.0 版。2026-09-30 に三浦さんが「名刺の写真を、名刺のサイズで切り出して、整形して表示できませんか」と依頼）。**名刺の位置と向きは、項目の読み取りとは別の「位置と向きの問い」で、高性能のモデルに答えさせる**（第 0.197.0 版。2026-09-30、2 枚並べて撮った名刺の切り出しがずれた。標準のモデルに項目と一緒に尋ねると、座標の x と y を取り違え、囲む範囲もずれた）。写っている名刺ごとに、氏名（どの名刺かを見分けるため）・名刺を囲む範囲・紙の四隅の点・英数字の行の向きを答えさせる。座標は **Gemini がよく使う `[y, x]` の形**（範囲は `[ymin, xmin, ymax, xmax]`。画像の高さと幅をそれぞれ 1,000 とした割合）で答えさせ、こちらで `[x, y]` に直す。四隅は順を問わずに答えさせ、英数字の行の向きに合うように、こちらで左上・右上・右下・左下に並べ直す。四隅が使えなければ囲む範囲の四隅を使う（傾きは直らないが、名刺の範囲は切り出せる）。読み取った名刺との対応は氏名で取り、合わなければ枚数が同じときに限り並びで取る。切り出しと直しは**ブラウザで行う**（サーバーでは画像を作り直さない。元の写真は残す）。四隅が無い・画像の外に出る・形がおかしい（面積が写真の 2% 未満、へこんだ四角形）ときは、これまでどおり写真全体を回して出す。詳細の画面では、名刺の画像を押すと元の写真に切り替わる（切り出しがずれたときに確かめられるように） |
| 読み取りの限界 | 手書きの書き込みは読まない。四隅の位置は推論の答えであり、ずれることがある（元の写真に切り替えて確かめる） |

### 27.6 同じ人の見分け

名刺は同じ人から何度ももらう。異動や昇進で中身も変わる。**同じ人を 1 つの連絡先にまとめるのは AI が行う**。人に選ばせない（ADR-0028）。

| 場合 | 扱い |
|---|---|
| メールアドレスが同じ | 同じ人とみなし、1 つの連絡先にまとめる |
| 氏名と会社名が同じで、メールアドレスが無いか違う | 同じ人かどうかを AI が判断する。**確かなときだけまとめる**。確かでなければ別の連絡先として登録する |
| 同じ人で中身が違う（異動・昇進・社名変更） | **新しい名刺の中身を連絡先の現在の値にする**。古い名刺と以前の会社・役職は、名刺の履歴として残す。メールの署名から分かったときも新しくする（第27.6.1節） |
| 範囲が違う（自分だけの名刺と、会社で共有の名刺） | まとめない。見える人が変わってしまうため |
| まとめ間違い | 詳細の画面の「分ける」か、秘書に頼んで戻せる。まとめる前の名刺はすべて残っている |

#### 27.6.1 メールの署名から異動を見つける（第 0.204.0 版、ADR-0057。第 0.205.0 版で実装）

名刺はもらった日の中身のままで、異動・昇進・電話番号の変更に追いつかない。一方、取引先から届くメールの署名には、今の部署・役職・電話が書いてある。
**名刺を交換した相手からメールが届いたら、その署名を名刺と比べ、変わっていれば連絡先を新しくする。** 人に確かめさせない（ADR-0028）。間違いは戻せるようにする。
2026-10-01 に三浦さんが依頼した。

| 項目 | 規定 |
|---|---|
| 対象のメール | Google とつなぎ、Gmail を読む許可（`gmail.readonly`）をすでに出している人が受け取ったメール。**差出人のメールアドレスが、その人が見られる連絡先（会社で共有と、本人の自分だけ。ごみ箱を除く）のメールアドレスと同じもの**だけ。迷惑メール・ごみ箱・送ったメールは見ない |
| 見ないもの | 差出人が連絡先に無いメール（本文を取らない）。名刺管理を使えない人、名刺管理かこの機能を切っている会社のメール |
| 権限 | この機能のために新しい権限を求めない。Gmail を読む許可が無い人は飛ばす（第14.3.2節の「使う業務の分だけ権限を求める」） |
| なりすまし | **差出人のドメインの認証が通ったメールだけを使う**（Gmail が付ける認証の結果で、DMARC か、差出人のドメインに合う DKIM が通っているもの）。差出人のアドレスは偽れるため |
| 見回り | ワーカーが 1 時間ごとに、前回から届いたメール（受信トレイの「メイン」。1 回に新しい順に 50 通まで）の**差出人だけ**を見る。連絡先に当たったメールだけ本文を取る。同じ相手から何通も届いていれば、いちばん新しいものだけを見る。初めて動くときは直近 30 日を見る |
| 読み取り | 推論（標準のモデル）に、**差出人本人の署名**から会社名・部署・役職・電話（代表・直通・携帯）・FAX・郵便番号・住所・Web を項目ごとに答えさせる。引用された前のメールと転送された部分の署名は使わない。署名の氏名が連絡先の氏名と合わなければ（空白を除いて比べる）使わない。署名が無ければ何もしない |
| 書かれた指示 | 署名と本文はデータであり、指示として扱わない（不変則 I-6）。推論には項目を答えさせるだけで、ツールを持たせない |
| 変化の見分け | 連絡先の今の値と比べ、**変わったと推論が確かに判断した項目だけ**を新しくする。表記の違い（「株式会社」と「(株)」、英語の表記、略称、全角と半角）は変化としない。**署名に無い項目は消さない**（署名は名刺より項目が少ないため） |
| 電話 | 同じ種類の番号を置き換える。署名に無い種類の番号は残す |
| 変えない項目 | 氏名・ふりがな・メールアドレス・メモ・範囲 |
| 新しさ | メールの日付が、その項目を最後に変えた日（名刺を受け取った日・人が直した日・前の署名の日）より新しいときだけ変える。後から取り込んだ名刺でも、受け取った日が署名の日より前なら、その名刺では今の値を変えない（名刺の履歴には残す） |
| 範囲 | 自分だけの名刺は、持ち主本人のメールからだけ新しくする。会社で共有の名刺は、名刺管理を使える人の誰のメールからでも新しくする |
| 推論の回数 | 同じ連絡先について 7 日に 1 度まで。署名の部分に今の会社名・部署・役職がそのまま見つかれば、推論を呼ばない。会社ごとに 1 日 200 通まで（超えた分は翌日に回す）。いずれも初めの値であり、動かして直す |
| 変更の記録 | 変えた項目の前と後を、出どころ「メールの署名」とメールの日付とともに残す（第27.11節）。**メールの件名・本文・署名の全文は残さない**。どのメールかを示す ID は 7 日で消す（第14.3.2節） |
| 監査ログ | `contact.update_from_signature`。「何に対して」は「名刺」とだけ出す（第27.10節） |
| 見せ方 | 詳細の「以前の会社・役職」に、名刺の履歴と並べて「メールの署名から（10 月 1 日）」と出す。**誰のメールからかは出さない**（会社で共有の名刺で、誰が誰とやり取りしているかを広めないため）。**「戻す」で前の値に戻せる** |
| 戻したとき | 戻した項目は、署名が同じ値を示している間は署名から変えない（出向先の会社名で署名する人のように、署名と名刺が違うのが正しい場合があるため）。署名の値がさらに変わったら、改めて比べる。人が詳細で直したときも同じ |
| 知らせ | メールを受け取った本人の週次ブリーフ（第9.5.5節）に、名刺が新しくなった人を 1 行ずつ載せる（「〇〇社 田中さん: 課長 → 部長」）。その場では知らせない（知らせが増えすぎるため）。秘書に「最近異動した人は？」と聞けば、変更の記録から答える（`contacts.changes`。第27.9節） |
| 会社の設定 | 管理者ページの名刺管理の設定に「メールの署名から名刺を新しくする」の切り替えを 1 つ置く。**既定は入**。本人ごとの設定は置かない |
| Google のデータの保持 | 署名から得た値は連絡先の今の値になり、**連絡先がある間残す**（第14.3.2節の 7 日の決まりの例外。Q-152 を第 0.205.0 版で決定）。Google の連携を解除しても戻さない。**本人か会社から Google のデータの削除を求められたら、その人のメールから変えた値を前の値に戻し、変更の記録を消す**（その後にほかの出どころで変わった項目は戻さない）。管理者が「ユーザーと権限」のその人の行の「メールから得た名刺の変更を削除」で行う |
| 見本の会社 | 見本の接続口（Google とつないでいない会社）では動かさない |

### 27.7 持ち主の範囲（会社で共有・自分だけ）

**名刺は会社の資産として共有するのを既定にする。** 中小企業では、担当が替わっても取引先との関係を会社に残したいためである。
一方で、私的な付き合いや、社内に出したくない相手の名刺もある。そのため、1 枚ずつ「自分だけ」にできる。

| 範囲 | 見られる人 | 直せる人 | 範囲を変えられる人 | 消せる人 |
|---|---|---|---|---|
| 会社で共有 | 名刺管理の利用範囲の全員 | 見られる人の全員（直した人と日時を残す） | 取り込んだ本人。ただし、ほかの人が受け取った名刺もまとまっている連絡先は自分だけにできない（その人から見えなくなるため。第 0.144.0 版） | 取り込んだ本人と管理者 |
| 自分だけ | 取り込んだ本人だけ。**管理者も見られない** | 本人 | 本人 | 本人 |

| 項目 | 規定 |
|---|---|
| 既定の範囲 | 会社で共有。会社は管理者ページで「自分だけ」を既定にできる（1 つの切り替え） |
| 取り込むときに選ぶ | 撮る画面とファイルを選ぶ画面に「自分だけ」の切り替えを置く。**選ばなければ既定の範囲**。毎回選ばせない |
| 消す | 消した名刺はごみ箱に 30 日置き、そのあと画像ごと消す。**名刺の相手から消去を求められたとき（個人情報保護法）に応えられるよう、消去は本当に消す**。第16.4節の「完全削除は実装しない」は、AI のツールが行う操作についての決まりであり、人が画面で行う消去には当たらない。**ごみ箱では、名刺を選んで（すべて選ぶこともできる）まとめて戻す・完全に削除できる**（第 0.199.0 版。2026-09-30 に三浦さんが依頼）。範囲は画面で「会社で共有」「自分だけ」の 2 つの言葉だけで示し、詳細と管理者ページの既定は切り替えで変える（「自分だけにする」のような言い方を混ぜない。第 0.199.0 版、三浦さんの指示）。完全に削除は元に戻せないため、件数を示して 1 度だけ確かめる。戻せない・削除できない名刺（削除できるのは取り込んだ本人と管理者）があっても、ほかは進め、できなかった件数を示す |
| 退職 | 会社で共有の名刺は残る（取り込んだ人の名前は残す）。**自分だけの名刺は、利用者を止めて（退職）から 30 日で画像ごと削除する**（第 0.200.0 版、Q-94 を決定。個人記憶と同じ考え方）。在籍中に本人が会社で共有へ移せる。止めたときは、その人の自分だけの名刺の件数と、30 日後に削除されることを、管理者に結果の文で示す（管理者は中身を見られないため件数だけ）。30 日のうちに利用者を戻せば削除しない |
| 権限区画 | Phase 1 では名刺を区画に入れない。人事などの区画の相手の名刺は「自分だけ」で持つ |

### 27.9 秘書と業務から使う

| 依頼の例 | 秘書の動き |
|---|---|
| 「〇〇社の田中さんの電話番号は？」 | 名刺を探して答える（`contacts.search`）。見つからなければそう言う |
| 「先週名刺交換した人を教えて」 | 交換の記録から探して一覧にする。大きければ秘書のキャンバスに出す |
| 「田中さんにお礼のメールを書いて」 | 名刺のメールアドレスで、メールの下書きを作る（`gmail.create_draft`、draft）。**送るのは本人が承認してから**（第9.4.0節） |
| 「田中さんの電話番号を 03-… に直して」「この人は展示会で会った、とメモして」 | 連絡先を直す（`contacts.save`、write-internal） |
| 「佐々木さんの名刺は 9 月 25 日の展示会でもらった」 | 本人が受け取った名刺の日付を直す（`contacts.save` の `receivedOn`。第 0.145.0 版）。ほかの人が受け取った名刺の日付は直さない |
| 名刺の画像を渡す | 業務「名刺の取り込み」に取り次ぎ、登録したことを伝える |
| 「最近異動した人は？」 | メールの署名から新しくした変更の記録から答える（`contacts.changes`。第27.6.1節） |

お礼のメールの下書きは、本人が頼んだとき（詳細の「メールを書く」か秘書への依頼）にだけ作る。**名刺を取り込んだあとに秘書が先回りして下書きを作ることは行わない**（第 0.201.0 版で取りやめ。第27.13節）。

| ツール | 危険度 | 内容 |
|---|---|---|
| `contacts.search` | read | 名刺（連絡先）を探す。**呼んだ人が見られる範囲だけ**を返す |
| `contacts.get` | read | 1 件の連絡先と、名刺の履歴・交換の記録を返す |
| `contacts.save` | write-internal | 連絡先を登録・更新する。範囲は呼んだ人が変えられるものだけ。受け取った日（`receivedOn`）は、呼んだ人が受け取った名刺のものだけを直す |
| `card.read` | read | 名刺の画像から項目を取り出す（第27.5節） |
| `contacts.changes` | read | 連絡先の変更の記録（メールの署名からの更新。第27.6.1節）を新しい順に返す。呼んだ人が見られる連絡先だけ。「本人のメールからのもの」に絞れる（週次ブリーフが使う）。第 0.205.0 版で実装 |

| 業務 | 内容 |
|---|---|
| 名刺の取り込み（公式・付属） | 入力はファイル（`fileId`）。`card.read` で読み取り、同じ人を見分けて（第27.6節）`contacts.save` で登録する。最上位の危険度は write-internal。メニューには出さない（名刺の画面と秘書から使う） |
| 名刺の修正（公式・付属。第 0.144.0 版） | 秘書に頼まれた修正とメモ（「田中さんの携帯を…に直して」「展示会で会った、とメモして」）。`contacts.search`・`contacts.get` で探し、`contacts.save` で直す。決められなければ候補を挙げて尋ねる。最上位の危険度は write-internal。メニューには出さない |

#### 27.9.1 名刺の相手へのまとめてのメール（第 0.206.0 版、ADR-0058、Q-95。第 0.207.0 版で実装）

「9 月 25 日の発表会で名刺を交換した人にお礼のメールを送って」のように、**名刺の相手に同じ趣旨のメールを 1 人ずつ宛名を変えてまとめて送る**。
2026-10-01 に三浦さんが依頼した（発表会の参加者へのお礼を一括で送りたい）。
**社外への送信なので、送る前に必ず人が承認する**（第9.4.0節）。承認は 1 回の配信につき 1 回とし、宛先ごとには求めない。
宣伝を含むメールは特定電子メール法に従い、送ってよい相手・本文に入れる表示・配信の停止を M2Office が守る（人に法律を確かめさせない）。

**頼み方と流れ**

| 段 | 規定 |
|---|---|
| 頼む | **画面から**: 名刺管理の画面で名刺を選んで（一覧の選択）「まとめてメール」を押すか、上の帯の「まとめてメール」で交換した日・検索の言葉から宛先を探す。**秘書から**: 「発表会で名刺交換した人にお礼を送って」「〇〇社の人に新製品の案内を送って」と話すと、業務「まとめてのメール」（公式・名刺管理に付属）に取り次ぐ（第 0.207.0 版。三浦さんが「秘書からの指示以外でも、UI でできることが必要」と依頼） |
| 宛先を集める | 依頼の言葉から、名刺を交換した日（その日の予定の題名も手がかりにする）・会社名・検索の言葉で連絡先を集める（`contacts.search`）。依頼した人が見られる連絡先だけ（自分だけの名刺は持ち主だけ） |
| 除く | 配信を停止した人、メールアドレスの無い人、ごみ箱の名刺、同じアドレスの重なり。**宣伝のメールでは、名刺を交換していない連絡先（表から取り込んだだけのもの。第27.4節）も除く**（送ってよい根拠が確かめられないため）。除いた人は理由とともに承認の画面に出す |
| 宛先を確かめる | **画面では、宛先の候補を一覧（氏名・会社名・メールアドレス・交換した日・範囲）で出し、1 人ずつ外せる**。除いた人も理由とともに並べる。予定していない人が混じっていないかを、送る前に人が一覧で確かめるため（第 0.207.0 版。三浦さんが「メール先の抽出が間違いないかを確認したいし、予定しない人が混じっていないかをチェックする必要がある」と依頼）。秘書から頼んだときも、承認の画面に同じ一覧を出す |
| 本文を作る | 1 つの文面を作り、宛名（会社名・氏名）だけを人ごとに差し込む（本文の `{会社名}`・`{氏名}`。画面では差し込むボタンで入れる）。人ごとに違う文を推論に書かせない（承認する人が 1 つの文面を見て判断できるように）。画面では見本（1 人目に差し込んだもの）をその場で出す |
| 宣伝かの見分け | 推論が本文を読み、商品・サービス・催しの案内など宣伝を含むかを決める。**お礼やあいさつだけなら宣伝ではない**。一言でも案内を添えれば宣伝とする。迷えば宣伝とする |
| 承認 | 依頼した本人が承認する（`approver: requester`）。画面では「承認へ進む」で承認待ちにし、承認トレイへ移る。承認の画面には、1 人目に差し込んだ本文の見本・宛先の人数と一覧・除いた人と理由・宣伝かどうかと末尾の表示を出す。**承認した宛先と文面だけを送る**（承認の後に下書きが変わっていれば送らない）。直したいときは却下して、名刺管理の画面で直す |
| 送る | 承認されたら、**本人の Gmail から 1 人に 1 通ずつ**送る（宛先に他の人のアドレスを並べない。BCC の入れ忘れで宛先が見える事故を防ぐ）。間を空けて送り、進み具合を出し、終わったら送れた数と送れなかった人を本人に知らせる |
| 記録 | 送った記録（誰が・いつ・どの連絡先へ・題名・宣伝かどうか・送ってよい根拠）を残す。名刺の詳細に、自分が送ったものを「まとめてのメール（10 月 1 日・題名）」と出す。まとめてのメールの下書きと記録は、作った本人だけが見られる |

**数の上限**（初めの値。動かして直す）

| 上限 | 値 | 理由 |
|---|---|---|
| 1 回の配信の宛先 | **100 人まで**。超える依頼は、日付や会社で分けるよう秘書が伝える | 誤りがあったときの範囲を抑える。法律の線ではない（特定電子メール法に人数の基準は無く、1 通でも決まりを守る） |
| 1 人の 1 日 | **300 人まで**（まとめてのメールの合計） | Gmail の送信の上限と、迷惑メールと判定されることを避ける |
| 送る間隔 | 1 通ごとに数秒あける | 同上 |

**管理者の承認**: 既定では要らない（本人の承認だけ。ADR-0028）。会社が望めば、管理者ページの名刺管理の設定の「まとめてのメールは管理者も承認する」を入れると、本人の承認のあとに管理者の承認を加える（1 つの切り替え。第 0.217.0 版で実装。第9.2.3節の `adminAlsoWhen`）。

| 項目 | 規定 |
|---|---|
| 流れ | 本人が承認すると、承認トレイに管理者向けの承認が出て、管理者に知らせる。管理者が承認したら送る。どちらかが却下したら送らない |
| 管理者が見るもの | 本人が見たのと同じ中身（宛先の一覧・除いた人と理由・見本・宣伝かどうかと末尾の表示）に、「〇〇さん（依頼した人）が承認しました」を添える |
| 本人が管理者のとき | 本人の承認で足りる（管理者が 1 人の会社で止まらないため） |
| 設定を変えたとき | 加えるかは本人が承認した時点の設定で決める。待っている承認は変えない。設定の変更は監査ログに残す |

**宣伝のメールの決まり（特定電子メール法）**

| 項目 | 規定 |
|---|---|
| 送ってよい相手 | 名刺を交換した人（自分のメールアドレスを書面で知らせた人。法の例外）。表から取り込んだだけの連絡先には送らない |
| 本文の末尾の表示 | **会社の正式名称・住所・問い合わせ先（送った人のメールアドレス）・配信の停止ができることとその方法**を自動で入れ、承認の画面にも出す。会社情報に正式名称か住所が無ければ宣伝のメールは送れず、管理者に会社情報の登録を求める（第6.6.1節） |
| 配信の停止 | 本文に配信の停止の URL を入れ、メールの見出しにも入れる（`List-Unsubscribe` と、押すだけで止まる `List-Unsubscribe-Post`）。URL を開くと、ログインなしに「配信を停止する」を押せる画面を出す。**返信で「配信停止」と書かれたときも止める**（送った人が Gmail を読む許可を出していれば、署名の見回り（第27.6.1節）と同じ見回りで見つける） |
| 停止したら | そのメールアドレスを会社の「配信の停止」に入れ、**以後は誰が送るまとめてのメールからも外す**（名刺を削除して取り込み直しても外す）。お礼など宣伝でないまとめてのメールからも外す（停止を申し出た人に送らない） |
| 停止の記録 | 停止したアドレス・日時・経路（URL か返信か）を残す。消さない（停止を守るため）。管理者は名刺管理の設定で件数を見られる |
| 停止を外す | **管理者だけ**が、名刺管理の設定の「配信の停止」で、停止したアドレスの一覧（アドレス・日時・経路）を見て、アドレスで探し、本人から「また送ってほしい」と求められたときに「停止を外す」で外せる（第 0.217.0 版で実装）。外すと、また宛先に入る。外したこと（誰が・いつ・どのアドレスか。アドレスは停止のときと同じく、そのものではなく照らし合わせの印で）は監査ログに残す。本人が自分で外す口は作らない（停止の URL は止めるためだけに使う） |
| 個人情報の利用目的 | 名刺の利用目的（第27.10節）に「案内・宣伝」を含めて、プライバシーポリシーに書く（Q-09） |

**宣伝でないメール**（お礼・あいさつ・日程の連絡）にも、1 回 100 人・1 日 300 人・1 人に 1 通ずつ・停止した人を外す、は同じく当てる。末尾の表示と停止の URL は入れなくてよいが、入れても差し支えない。

| ツール | 危険度 | 内容 |
|---|---|---|
| `contacts.bulk_draft` | write-internal | 秘書から頼まれたとき、集めた連絡先と文面で、まとめてのメールの下書きを作る（送らない） |
| `contacts.bulk_preview` | read | 下書きの宛先から除く人を除き、本文に宛名を差し込んだ見本と、宣伝かどうか・末尾の表示を返す |
| `mail.bulk_send` | external-send | 承認された宛先と文面で、本人の Gmail から 1 人に 1 通ずつ送る（後ろで進める）。承認の段の後でしか呼べない |

**秘書の取次（第 0.144.0 版）**: 名刺管理を使える人の「〇〇さんの電話番号は？」「先週名刺交換した人は？」は推論に選ばせずに秘書の調べもの（`contacts.search`・`contacts.get` を持つ）へ、尋ねる言い回しの無い名詞の形（音声の秘書が画面に出すよう渡す「佐々木さんの連絡先（メールアドレス・住所など）」。第 0.166.0 版）も同じく名刺を探す問いとして、「直して・メモして」は「名刺の修正」へ回す（名刺の問いに「分かりません」と答えないため）。名刺の画面は、名刺の画像を画面から渡す取り込み（待ち行列）を使い、付属の業務を通さない（数百枚をまとめて渡すため）。

**名刺の中身を、秘書の記憶や会社の知識にしない**（第11.2節・第11.3節、不変則 I-10。他人の個人情報のため）。その場の学び（第10.13節）の「覚えないもの」に、名刺から分かる他人の電話番号・メールアドレス・住所を加えた（第 0.144.0 版）。
秘書は名刺が要るたびにツールで探す。会話ログには、会話に出た範囲で名前が残る（第11.9.4.1節）。

### 27.10 個人情報とデータの扱い

| 項目 | 規定 |
|---|---|
| 性質 | 名刺は取引先の担当者の個人情報である。利用目的は「取引・連絡・営業・案内と宣伝」とし、プライバシーポリシーに書く（Q-09。案内と宣伝は第 0.206.0 版で加えた。第27.9.1節） |
| 社内の共有 | 会社の中での共有であり、第三者への提供ではない。会社の外へ出るのは、本人が承認したメールと、書き出しだけ |
| 推論へ渡すもの | 読み取りのときに画像を Gemini に渡す。Limited Use を守り、学習に使わない（第14.3.2節） |
| 画像の保持 | 名刺の画像は、**連絡先がある間は残す**（秘書に渡したファイルの 4 週の決まり（第10.10.5節）の例外）。名刺を消したら画像も消す |
| 書き出し | 1 件の vCard は見られる人が書き出せる。**会社の名刺をまとめて書き出すのは管理者だけ**とし、監査ログに残す。**第 0.202.0 版で実装**: 名刺の画面の「書き出し」から、会社で共有の名刺（ごみ箱のものを除く）を CSV（BOM 付きの UTF-8。Excel で開いても化けない）か Excel（xlsx）で書き出す。自分だけの名刺は、管理者も見られないため入れない。列は氏名・ふりがな・会社名・部署・役職・郵便番号・住所・電話（代表・直通・携帯・FAX）・メールアドレス・Web・そのほか・メモ・最後に交換した日・取り込んだ人で、見出しはそのまま取り込み直せる言い方にする。監査ログ `contact.export`（件数と形式。相手の名前は入れない） |
| メールから得た値 | メールの署名から新しくした値（第27.6.1節）は連絡先の値として、連絡先がある間持つ。件名・本文は持たない（Q-152） |
| 監査ログ | 取り込み、範囲の変更、まとめる・分ける、ごみ箱・戻す・消去、まとめての書き出し、メールの署名からの更新とその取り消しを残す。**見ただけでは残さない**（名刺は日々引くもので、残すと量が多すぎるため。権限区画の参照とは違う）。**監査ログの「何に対して」には相手の名前を出さず「名刺」とだけ出す**（自分だけの名刺の相手を管理者に知らせないため。第 0.144.0 版）。操作の種類に「名刺」を足す（第6.6.8.1節） |
| テナント境界 | すべての名刺はテナント ID で絞る（不変則 I-2）。自分だけの名刺は、さらに持ち主で絞る（データベースの行単位の制限。第19.2節）。問い合わせのたびに会社と利用者（`app.user_id`）を設定し、行単位の制限が「会社で共有」と「自分の自分だけ」だけを返す。会社と持ち主をまたぐのは、読み取りの待ち行列の確保と、期限を過ぎたものの消去だけで、データベースの関数に閉じる（移行 036） |
| 解約 | ほかのデータと同じく、30 日は閲覧と持ち出しができ、そのあと消す（第19.3節） |

### 27.11 データモデル

第19.1節に次を加える。

| エンティティ | 主な項目 |
|---|---|
| `contact`（連絡先） | tenant_id、範囲（company／personal）、持ち主、氏名、ふりがな（推定かどうか）、会社名、部署、役職、住所、電話（種類つき）、メール、Web、メモ、まとめた先、状態（有効・ごみ箱）、作った人・直した人と日時 |
| `bulk_mail`（まとめてのメール。第 0.206.0 版） | tenant_id、送った人、題名、本文の文面、宣伝かどうか、末尾の表示、宛先ごとの連絡先・アドレス・状態（待ち・送った・送れなかった）と送った日時、承認の実行 |
| `mail_opt_out`（配信の停止。第 0.206.0 版） | tenant_id、メールアドレス（小文字）、停止した日時、経路（URL・返信）。名刺を削除しても消さない |
| `contact_change`（変更の記録。第 0.204.0 版） | tenant_id、contact_id、出どころ（メールの署名）、変えた項目ごとの前と後、メールの日付、メールを受け取った人、メールの ID（7 日で消す）、戻した人と日時 |
| `contact_card`（名刺） | tenant_id、contact_id、表と裏の画像（`file`）、表と裏の四隅（第 0.195.0 版。1 枚の写真に何枚も写っていれば、同じ画像を名刺ごとの四隅で指す）、読み取り結果、人が直した項目、受け取った人、受け取った日、取り込んだ日時 |

名刺の画像は `file` に置き、出どころを「名刺」とする（第19.1節の `file` の出どころに加える）。

**実装（第 0.144.0 版、移行 036）**: 名刺には、読み取りの状態（待ち・読み取り中・登録済み・読み取れなかった）、取り込んだまとまり（進み具合と終わりの知らせに使う）とその中の順番、表と裏の向き（回す角度）、撮るときに組にしたかを持つ。
読み取りは待ち行列で、ワーカーが 1 枚ずつ確保して読み取る（3 回まで。読めなければ「読み取れませんでした」）。
受け取った日の初めの値は、取り込んだ人のタイムゾーンでの取り込んだ日とする（データベースの時計（世界標準時）で決めると、日本時間の 0〜9 時に取り込んだ名刺が前の日になっていた。第 0.145.0 版で修正）。
会社の設定に「名刺管理」の区分（使うか・取り込んだ名刺の既定の範囲）を足す。

### 27.13 行わないこと

| 行わないこと | 理由 |
|---|---|
| 名刺の相手の、ネット上の情報を勝手に集める | 本人が頼んだとき以外に第三者の情報を集めない。頼まれたら秘書が調べもの（第10.11節）として行う |
| 名刺の相手へ、承認なしにメールを送る | 社外への送信は承認が要る（第9.4.0節） |
| 手書きの書き込みの読み取り | 誤りが多く、確かなものとして扱えないため |
| 名刺の交換の場の音声や写真の保存 | 目的を超える |
| 表から取り込んだだけの連絡先に、宣伝のメールを送る | 名刺を交換した（自分のアドレスを書面で知らせた）人かを確かめられず、特定電子メール法の例外に当たるか分からない（第27.9.1節） |
| まとめてのメールで、人ごとに違う文を推論に書かせる | 承認する人が 1 つの文面を見て判断できなくなる。宛名だけを差し込む（第27.9.1節） |
| 名刺の無い人のメールの署名から、連絡先を作る | 会ったことの無い人や、宣伝のメールの差出人が会社の連絡先に大量に入る。署名から新しくするのは、名刺を交換した人に限る（第27.6.1節） |
| メールの本文の「異動のお知らせ」「転職しました」から、別のアドレスの人を同じ人とみなす | 差出人のアドレスが違うと、同じ人かを確かめられない（なりすましの余地がある）。新しい会社の名刺を取り込んだときの見分け（第27.6節）に任せる。事例が出たら決める |
| 名刺を取り込んだあとに、秘書がお礼のメールの下書きを先回りして作る | 取り込むたびに下書きが増え、どれを送ったか・送るべきかの管理がかえって難しくなる（2026-10-01 に三浦さんが判断して取りやめ。以前は秘書の提案の積極性が「積極的」の人に作る案だった）。お礼のメールは、本人が詳細の「メールを書く」か秘書に頼んだときに作る |
