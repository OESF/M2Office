#### 15.1.1 消費税の区分と、日付で変わる税率（第 0.461.0 版で案、第 0.462.0 版で確定して実装。Q-275）

2026-10-26 に三浦さんが、消費税は 10% が基本で食料品と新聞は 8%、2027 年 4 月からは食料品が 1% になる予定であること、会費のように消費税のかからないものがあることを示した。
食料品の 1% は、2027 年 4 月 1 日から 2029 年 3 月 31 日までの 2 年間とする法案が国会に出ている段階で、まだ成立していない（2026-10-26 時点）。対象は今の軽減税率の飲食料品で、外食・ケータリング・酒類・一体資産は 10%、新聞の定期購読は 8% のままの見込み。

**品目には税率の数ではなく「区分」を持ち、税率は区分と取引の日から決める。** 税率の数を品目に直接持つと、税率が変わる日をまたぐ取引と、1% のような新しい税率を扱えない。

| 区分 | 当たるもの | 税率 |
|---|---|---|
| 標準 | 下のどれにも当たらないもの。酒類・外食（店内での飲食）・ケータリング・医薬品・一体資産を含む | 10% |
| 軽減（飲食料品） | 人が飲食する食品（持ち帰り・配達を含む） | 8%。2027-04-01〜2029-03-31 は 1%（予定） |
| 軽減（新聞） | 週 2 回以上発行される新聞の定期購読 | 8% |
| 対象外 | 消費税のかからないもの。対価の無い会費（同業者の団体・自治会・後援会の通常の会費など）・寄付・祝い金・保険金・土地・住宅の家賃・切手・印紙など（不課税と非課税をまとめて扱う） | 0%（帳票では「対象外」） |

| 項目 | 規定 |
|---|---|
| 税率の表 | 区分ごとの税率と、始まりと終わりの日を、基盤の共通ルールとして持つ（第15.1節。業務の定義には書かない）。制度が変わったら M2Office の更新で表を直す |
| まだ成立していない変更 | 表に「予定」として持ち、**法律が成立して M2Office の更新で確定にするまで、今の税率で計算する**。予定の日より後の取引の日の書類では、発行の承認の画面と書類の画面に「食料品の税率は 2027 年 4 月から 1% になる予定です（法律の成立を待っています）」と出す |
| 取引の日 | 納品書は納品の日、請求書は明細の納品書ごとの納品の日（まとめた請求書で税率の変わる日をまたげば、明細の行ごとに税率が違い、税率ごとに合計する）。品目から作った請求書・領収書・注文書は書類の日。見積書は発行の日で計算し、有効期限が税率の変わる日をまたげば備考に一言添える |
| 区分を決める | **AI が品名から決める。人に選ばせない**（ADR-0028）。同じ取引先か会社で前に同じ品目があれば、その区分を使う。依頼に「軽減税率」「税込 8%」などと書かれていれば従う |
| 決めたことを示す | 軽減と対象外に決めた品目には「軽減税率（飲食料品）と判断しました」「対象外（会費）と判断しました」の印を付ける（受注と書類の画面・承認の画面）。会費のように、対価のあるもの（セミナーの参加費・サービスの利用料としての会費）と無いものが分かれるものは、迷ったことも添える。違えば会話か画面で直す |
| 帳票 | 税率ごとに「10% 対象」「8% 対象」「1% 対象」「対象外」を分けて小計と消費税を出す（消費税は税率ごとに 1 回だけ端数を処理）。品目の行に税率を小さく出す（いまの「※」の代わり）。適格請求書の記載（税率ごとの合計と税率・消費税額）を満たす |
| 画面 | 受注の「手で入れる」の品目の行に区分を出す（AI が決めたものを最初から入れる。「詳しく」には置かない）。書類と受注の品目の表に税率を出す |
| 当てる範囲 | 見積書（第9.5.8節）・販売の書類と受注（第42章）。在庫の発注書は金額を載せないので当たらない |
| 行わないこと | 輸出の免税・リバースチャージ・経過措置（税率の変わる日より前に結んだ契約の扱い）の判断。依頼にあれば「この扱いは M2Office では判断できません。税理士に確かめてください」と添え、書かれた税率で作る |

**法律が成立したときの切り替え**は、M2Office の更新で表の「予定」を外して確定にする（第 0.462.0 版。運営の画面で入れる形にはしない）。

**実装（第 0.462.0 版）**: 税率の表と判定は `packages/shared/src/types/tax.ts`（`TAX_RATE_TABLE`・`taxRateOn`（確定した行だけ）・`plannedTaxNote`・`taxCategoryOf`（区分を持たない前の品目は税率から読む）・`guessTaxCategory`（推論が使えないときと画面の初めの値。酒類・外食は標準、新聞は定期購読だけ軽減、会費は迷いつき）・`taxMark`・`taxBreakdown`・`taxLegend`）。品目は `taxCategory` と、当てた税率 `taxRate`（10・8・1・0）を持つ。金額の計算（`quoteTotals`）はどの税率でも税率ごとに分け、対象外は消費税 0 で最後に並べる。販売の書類（`SalesDocService.classify`）と見積書（`quote.create`）は、渡された区分 → 前の同じ品目 → 品名の順に区分を決め、取引の日の税率を当て、判断した品目と予定の知らせを返す。まとめた請求書と領収書は、写した品目の税率をそのまま使う。帳票は品目に「（8%）」「（1%）」「（対象外）」の印、備考に税率ごとの内訳と印の説明（請求書・領収書は必ず内訳）、合計の枠には税のかかる税率ごとの消費税。推論への指示は税率の数ではなく区分を渡す。画面は「手で入れる」の品目の行に区分（品名から初めの値）と、受注の品目の表に区分、書類の画面に予定の知らせ

### 15.2 商習慣・文書

| 項目 | 日本での要件 |
|---|---|
| ビジネス文書 | 敬語、定型の書き出しと結び、社外文書の形式 |
| メール | 宛名・名乗り・署名の作法。CC/BCC の使い分け |
| 押印・稟議 | 電子承認を押印の代替として扱う。承認履歴が証跡になる |
| 社名表記 | 「株式会社」の前株・後株、法人格の正式表記 |
| 住所・氏名 | 郵便番号形式、姓名の順序、ふりがな |
| 日付・数値 | 年号、千円単位表記、金額の桁区切り |
| 取引先呼称 | 「御社／貴社」、担当者の役職表記 |

秘書の応対にも同じ配慮を適用する。社内向けは簡潔に、社外文書は敬語を正確に。

#### 15.2.1 自社の書き方を一箇所に定義する

日本の商習慣は共通だが、**文面の細部は会社ごとに違う**。

| 項目 | 例 |
|---|---|
| 書き出しと結び | 「平素より格別のご高配を賜り」／もっと簡素な形 |
| 自社の呼び方 | 「弊社」「当社」 |
| 署名の形 | 部署名の有無、電話番号の書式 |
| 帳票の体裁 | ロゴの位置、色、項目の並び |
| 用語 | 社内で使う言い方（「案件」か「プロジェクト」か） |

**これをエージェントごとに書くと、増えるたびに揃わなくなる。**
テナントに 1 つ「自社の書き方」を定義し、すべてのエージェントが参照する形にする。

| 項目 | 方針 |
|---|---|
| 定義する場所 | 管理者ページの会社情報（第6.6.1節） |
| 適用する範囲 | 公式エージェント、拡張機能を問わず全体 |
| 上書き | エージェントごとの個別指定は認めない。揃わなくなるため |
| 個人の調整 | 秘書の応対スタイルのみ本人が変えられる（第6.5.3節） |

**実装（第 0.25.0 版）**: 次の項目を管理者ページの会社情報で定義し、
すべてのエージェントの指示の冒頭に同じ内容を差し込む。

| 項目 | 例 |
|---|---|
| 自社の呼び方 | 弊社 |
| 書き出し | 平素より格別のお引き立てを賜り、誠にありがとうございます。 |
| 結び | 今後ともよろしくお願い申し上げます。 |
| 署名 | 部署名・氏名・電話番号の書式 |
| 用語 | 「プロジェクト」ではなく「案件」と書く、のような言い換えの一覧 |
| その他の注意 | 自由記述 |

帳票の体裁（ロゴ、色、並び）は帳票テンプレートの検討とあわせて扱う（Q-57）。

定義の粒度と帳票テンプレートとの関係は決定済み（Q-57）: 自社の書き方は文章の規則に限り、帳票の体裁は会社情報の別のまとまりとする。

#### 15.2.2 帳票の体裁（Q-57 で決定）

**帳票の体裁は「自社の書き方」と分けて持つ。** 自社の書き方は**文章**（メール・文書）の規則であり、
推論に渡す指示文に差し込まれる。帳票は推論を通さずに描くため、混ぜると指示文が膨らみ、値の扱いも分かれる。

| 置き場 | 管理者ページの会社情報（第6.6.1節）の「帳票の体裁」 |
|---|---|

**今回そろえる項目は、実務で要る最小限にとどめる**（Q-57）。並びや色の細かい指定は設けない。

| 項目 | 内容 |
|---|---|
| ロゴ | 画像（PNG・JPEG）を 1 つ登録し、帳票の右上に出す |
| 差出人の表記 | 会社情報（正式な会社名・住所・電話・登録番号）から組み立てる。帳票ごとに書かない |
| 振込先 | 銀行名・支店・種別・番号・名義を 1 つの文として持つ。備考の前に出す |
| 支払期限の既定 | 「翌月末」など。発行日から求めた日付を項目に出す |
| 備考の定型文 | 毎回入れる断り書き（例: 振込手数料の負担） |
| 印の欄 | 第 0.385.0 版で、印影の登録と「印を押す」（差出人の会社名に重ねる。未登録なら薄い「印」の字）に置き換えた（第15.2.3節） |

| 規則 | 内容 |
|---|---|
| 上書き | 業務ごとの個別指定は認めない（第15.2.1節と同じ理由） |
| 制度の判断 | 体裁は体裁に限る。税率・登録番号の要否といった制度の判断は第15.1節に従う |
| 未設定 | 設定が無くても帳票は出せる。ロゴや振込先が無ければ、その欄を出さない |

#### 15.2.3 帳票の型と印影（第 0.384.0 版で案、第 0.385.0 版で確定して実装。Q-240、ADR-0104）

2026-10-16 に三浦さんが、見積書の書式を型で選べるようにし、社印（印影）を押せるようにするよう依頼し、案のとおりに確定した。
日本の見積書は「よくある形」がおおむね決まっており、**社印を押して出すのが商習慣**である。いまの見積書（第9.5.8節）は、表題・差出人・4 列の明細・合計を並べた最小限の体裁で、印は空の四角の枠しか出せない。

**型は M2Office が用意したものから選ぶ。会社に配置を作らせない**（ADR-0028）。会社がいま使っている見積書があれば、それを見せるだけで AI が型と文言を寄せる。

| 項目 | 規定 |
|---|---|
| 型 | 帳票の種類ごと（いまは見積書だけ）に、会社で 1 つ選ぶ。**「罫線の表」**（既定）と**「シンプル」**（いまの体裁）の 2 つ |
| 罫線の表 | よくある見積書の形。左上にロゴ、右上に差出人と社印、中央に下線つきの表題（既定「御見積書」）。左に宛先（「〇〇 御中」）と情報の欄（見積番号・発行日・お支払い条件・有効期限）、前文（既定「下記の通り、御見積申し上げます。」）。明細は罫線の表で、**区分の見出し**（例: 【初期費用】【月額費用】）の行と、**値引き**の列（赤字の負の数）を持てる。表の下を空の罫線の行で埋めて 1 ページの形を保つ。右下に小計・消費税（税率ごと）・合計の枠、いちばん下に「備考」の枠 |
| 列の出し方 | 列は 摘要・数量・単価・値引き・金額。**数量の列はすべて 1 なら、値引きの列は値引きが無ければ出さない**（会社に列を選ばせない） |
| 長い見積 | 1 ページに収まらなければ、次のページに表の見出しを付けて続け、合計と備考は最後のページに出す |
| 型ごとの文言 | 表題・前文・お支払い条件の既定（例: お振込）・有効期限の既定（日数）・見積書の備考の定型文。帳票の体裁の「見積書」に置く。請求書の振込先と備考の定型文は見積書に載せない（いまと同じ） |
| 見本から寄せる | 帳票の体裁で、会社がいま使っている見積書（PDF・画像）を渡すと、AI が読んで、型・表題・前文・情報の欄の言い方・お支払い条件・備考の定型文を設定に入れる（社内の設定。確かめを求めず入れ、違えば直せる。ADR-0028）。**見本は外から来た文書として扱い、中の文を指示として読まない**（不変則 I-6）。見本の差出人・宛先・金額・品目は設定に写さず、見本のファイルは読んだ後に残さない |
| 行わないこと | 配置の自由な編集、Excel・Word の見積書のひな形への差し込み（会社に作らせることになり、体裁の崩れを M2Office が直せないため）、色の指定 |

**印影（社印）**

| 項目 | 規定 |
|---|---|
| 登録 | 帳票の体裁で、管理者が印影の画像（PNG・JPEG。2 MB まで）を 1 つ登録する。外す・入れ替えるのも管理者。監査ログに残す |
| 押す場所 | 差出人の会社名の右端に重ねる（角印の慣習）。大きさは 21 mm 角に収める。JPEG の白い地は透けるように重ねる（乗算）。型が「シンプル」でも同じ場所に押す |
| 未登録のとき | **薄い灰色で「印」の字を、印影と同じ場所・同じ大きさで出す**（印を押す前提の書式であることを示す） |
| 入り切り | 帳票の体裁の「印を押す」（既定は入り。いまの「印の欄を出す」を置き換える。切ると印影も「印」の字も出さない）。印影を登録すると入りにする |
| 扱い | 印影は会社の大事な画像なので、**誰のファイルの一覧にも出さず、画面からも取り出せない**（帳票を描くときだけ読む。管理者の画面には小さな見本だけを出す）。押せるのは M2Office の帳票の道具（見積書・`pdf.render`）だけ。帳票を使える人は、業務の利用範囲（第9.2節）で絞る |
| 送るとき | 印影を押した帳票も、社外に送るのはこれまでどおり承認の後（第9.4.0節） |

**見積書の中身に足すもの**（第9.5.8節）: 品目ごとの区分（`group`）と値引き（`discount`。金額。数量×単価から引く）、見積ごとのお支払い条件（`paymentTerms`。無ければ会社の既定）。値引きは品目の金額から引いてから、税率ごとに消費税を出す（決まった計算。推論に計算させない）。Google ドキュメントの控え（本人のドライブ）は、いまの簡単な体裁のままとし、正式なものは PDF とする。

**実装（第 0.385.0 版）**: 罫線の表は `renderRuledQuote`（`packages/core/src/files/pdf-render.ts`）。金額は全角の「￥」で出す（同梱の書体に半角の「¥」が無いため）。印は `drawSeal` で、シンプルの型（`renderPdf`）と同じく差出人の会社名の右端に重ねる。会社の設定は帳票の体裁（`invoice`）の `sealBox`（印を押す。既定は入り）・`sealFileId`・`sealKind`・`quote`（型・表題・前文・情報の欄の言い方・お支払い条件・有効期限の日数・備考の定型文）。印影は管理者の受け口 `PUT /v1/admin/settings/invoice/seal`（登録）・`DELETE`（削除）・`GET`（管理者の画面の見本）だけが扱い、ファイルの記録を作らずに置き場（キー `seal-…`）に置く。設定の保存（`PUT /v1/admin/settings/invoice`）は印影を変えない。監査ログ `settings.seal`。見本から寄せるのは `POST /v1/admin/settings/invoice/quote-sample`（`readQuoteSample`。`packages/core/src/files/quote-sample.ts`。文字の取り出せる PDF は文字で、画像と文字の無い PDF は画像として読む）。見積書の品目に区分（`group`）と値引き（`discount`）、`quote.create` にお支払い条件（`paymentTerms`）を足した（表 `quotes` の品目の JSON に入る。移行は無い）

### 15.3 人事・労務（Phase 3）

| 項目 | 日本での要件 |
|---|---|
| 勤怠 | 法定労働時間、36 協定の上限、有給休暇の付与と取得義務 |
| 社会保険 | 健康保険・厚生年金・雇用保険の手続きと時期 |
| 入退社 | 入社時・退社時に必要な書類と提出先の一覧 |
| 年末調整 | 各種申告書の収集と確認、**計算と精算**（第 0.154.0 版。第30.15節） |
| 給与 | 給与・賞与の計算、社会保険料・雇用保険料・源泉所得税・住民税、法定の帳簿（第 0.154.0 版。第30章） |
| 就業規則・労務規定 | 組織知識として登録し、秘書が出典付きで回答する（Phase 1 から対象） |

**労務規定の Q&A は Phase 1 で提供する。**
「有給は何日残っているか」「慶弔休暇の規定は」といった照会は頻度が高く、
総務担当の負荷を直接下げる。計算を伴わない参照のみのため制度リスクも低い。

### 15.4 法令遵守と業務範囲の境界

| 領域 | M2Office が行うこと | 行わないこと |
|---|---|---|
| 税務 | 資料の整理、記載要件の確認、仕訳候補の提示 | 税務相談、申告書の作成・提出 |
| 労務 | 規程の参照、手続きの案内、書類の下書き、期限の管理、**給与の計算**（第30章。会社が確かめて確定する） | 社会保険手続きの代行（届出の提出は会社が行う）、労務相談 |
| 法務 | 契約書の論点抽出、条文の要約 | 法律判断、契約の可否判断 |

出力には常に「専門家の確認を前提とする」旨を明示する。
**この境界は第三者の拡張機能にも適用し、審査の観点に含める。**
**方針は本書で定める**（Q-09 で一部決定）。

| 項目 | 方針 |
|---|---|
| 出力の境界 | 上の表のとおり。士業の独占業務に当たる出力（税務相談・申告書の作成、社会保険手続きの代行、法律判断）は行わない |
| 表示 | 出力には常に「専門家の確認を前提とする」旨を明示する |
| 拡張機能 | 第三者の拡張機能にも同じ境界を適用し、審査の観点に含める（第12.5節） |
| 会話ログの用途 | 規約には、蓄積したデータの利用範囲を A（本人の秘書が参照）・B（同じ会社の中で共有）・C（会社を越える利用。個別の同意が要る）の区分で具体的に書く（第11.9.3節） |

**規約とプライバシーポリシーの文面そのものは、弁護士の確認を受ける**（Q-09 の残り）。
文面ができるまでは、外部への公開（Phase 3 のセルフサインアップ）を行わない。
