## 第 I 部　背景と位置づけ

なぜ作るのか。市場のどこに空白があり、どういう形で応えるか。

## 1. 背景と市場機会

**この章で決めること**: なぜ今これを作るのか。市場のどこに空白があるのか。
**本章は事業の前提であり、以降のすべての設計判断の根拠となる。**

### 1.1 日本の中小企業における AI 利用の現状

2026 年の各種調査（出典は付録 C）から、以下の事実が確認できる。

#### 利用率は 2〜3 割台にとどまり、企業規模が小さいほど低い

| 調査 | 対象 | 結果 |
|---|---|---|
| 中小企業基盤整備機構（2026年3月） | 全国の中小企業 10,000 社 | AI 導入 20.4%（検討中を含め 39.0%） |
| 商工中金（2026年1月調査） | 中小企業 3,892 社 | 積極活用層 31.1% |
| 帝国データバンク（2026年3月） | 企業 10,312 社 | 中小企業 32.4%、小規模企業 28.0%、大企業 46.5% |
| 中小企業庁「2026年版 中小企業白書」 | 省力化投資に取り組む中小企業 | AI 活用は約 3 割 |

#### 導入の中心は「個人判断」であり、組織としての導入はほとんど存在しない

商工中金調査による生成 AI の導入形態は以下のとおり。

| 導入形態 | 割合 |
|---|---|
| 会社導入なし・個人判断に任せる | 64.9% |
| 個人利用を推奨 | 14.9% |
| 一部部署でパッケージ導入 | 11.2% |
| **全社的にパッケージ導入** | **4.1%** |
| 禁止・制限 | 1.4% |
| 自社専用モデルを導入 | 0.9% |

**全社的な導入は 4.1% にすぎない。**
総務省の調査でも、業務変革に「組織的な取組はない」と答えた中小企業は 45.6%（大企業 18.1%）であり、
国際比較では日本 27.0% に対し米国 1.4%、ドイツ 4.9%、中国 2.6% と、
**組織的な取組の欠如は日本固有の課題**である。

#### 用途は文章の作成・要約に集中している

| 積極活用層の利用内容（商工中金） | 割合 |
|---|---|
| メール・報告書・議事録の作成・要約 | 74.0% |
| デスクワークの支援・自動化 | 48.7% |
| 戦略・計画策定、アイデア出し | 30.0% |
| デザイン生成 | 29.3% |
| リサーチ業務の効率化 | 20.2% |

業務分野別の導入率（中小機構）は、総務・管理部門 68.3%、営業・販売・サービス部門 60.3%、
経営・企画部門 58.5%、製造・生産部門 34.9% と、**バックオフィスから導入が進んでいる**。
導入目的は「業務効率化・作業時間の短縮」が 87.0% で突出する。

#### 効果は出ているが、入口で止まっている

| 指標 | 数値 |
|---|---|
| 生成 AI 活用企業のうち「効果あり」 | 86.7% |
| AI 導入企業が挙げた効果「業務効率化」 | 83.2% |
| 積極活用層のうち「目立った効果なし」 | 19.3% |

一方、活用していない理由は以下のとおり。

| AI を活用していない理由（中小企業白書） | 割合 |
|---|---|
| **活用する業務がイメージできていない** | **63.4%** |
| 推進人材の不足 | 40.0% |
| 社内ルールが未整備 | 26.2% |
| セキュリティへの不安 | 14.5% |
| 予算の確保が困難 | 13.8% |

導入済み・未導入を問わず、生成 AI に対して抱かれている懸念は以下のとおり。

| 生成 AI への懸念（帝国データバンク・3つまで） | 割合 |
|---|---|
| 情報の正確性 | 50.4% |
| 専門人材・ノウハウの不足 | 41.3% |
| 活用すべき業務範囲が不明確 | 40.0% |
| 情報漏洩のリスク | 33.5% |
| トラブル時の責任所在・ルール整備 | 25.5% |

#### 求められている支援は「費用」と「事例」

| 中小企業が求める支援（中小機構） | 割合 |
|---|---|
| 導入費用への助成 | 77.9% |
| 事例情報の提供 | 70.5% |

また、情報面で不足しているとされる項目は以下のとおり。

| 不足している情報 | 割合 |
|---|---|
| 成功事例 | 83.3% |
| ベンダー選定 | 79.8% |

公的支援としては中小企業庁「デジタル化・AI 導入補助金 2026」（旧 IT 導入補助金）があり、
通常枠・インボイス枠・複数者連携デジタル化・AI 導入枠・セキュリティ対策推進枠が設けられている。

**注記**: 上記の各調査は対象・定義・時期が異なるため、数値を単純比較することはできない。

### 1.2 現状の構造的な読み取り

| # | 読み取り |
|---|---|
| S-1 | AI は**個人の道具**としては使われ始めたが、**組織の仕組み**にはなっていない。全社導入 4.1% がそれを示す |
| S-2 | 使われ方はチャット画面での文章作成・要約にとどまり、**社内の情報システムと統合されていない** |
| S-3 | 技術的には統合が可能になった。スキルやコネクタの追加、MCP による外部システム接続の標準化が進んだ |
| S-4 | しかし**中小企業がそれを自力で行うことは事実上不可能**である。CLI の導入、定義ファイルの作成、権限設計を担える人材がいない（推進人材の不足 40.0%） |
| S-5 | 結果として、リテラシーの高い一部の個人がチャットで翻訳や下書きに使う段階で止まっている |
| S-6 | 導入の最大の障壁は技術ではなく「**活用する業務がイメージできていない**」63.4% という**入口の問題**である |
| S-7 | 個人が AI に蓄えたノウハウは**その個人に閉じ、会社に残らない**。人が辞めれば消える |
| S-8 | 供給側も行き詰まっている。個社の要望に**毎回ゼロからシステムを作る**慣行が、費用と期間の両面で成り立たなくなっている（第2.3.1節） |

### 1.3 事業機会

S-1 から S-7 が示すのは、**「技術は成立したが、中小企業に届く形になっていない」という空白**である。

| 観点 | 現状 | M2Office が埋めるもの |
|---|---|---|
| 個人 → 組織 | 個人判断 64.9%、全社導入 4.1% | 組織として導入できる形（権限・承認・監査を備えた製品） |
| チャット → 業務統合 | 文章作成・要約が中心 | 社内システムと接続された業務遂行 |
| 技術者向け → 非技術者向け | CLI とファイル編集が前提 | ブラウザだけで完結する GUI |
| 汎用 → 業務単位 | 「何に使えるか分からない」63.4% | 業務名の付いたエージェントと、専属の秘書 |
| 個人の経験 → 会社の資産 | ノウハウが個人に閉じる | 使うほど組織知識が蓄積される構造（第11章） |
| 米国制度 → 日本制度 | 既存スキルは米国前提 | 日本の会計・税務・労務・商習慣に合わせた設計 |

### 1.4 競争優位の源泉

M2Office の優位は機能の数ではなく、**顧客企業の中に蓄積される情報と学習**にある。

| # | 優位の源泉 | 内容 |
|---|---|---|
| A-1 | 組織知識の蓄積 | 議事録、規程、価格表、過去案件、決定事項が統合されて検索可能になる |
| A-2 | 個人の働き方の学習 | 各従業員の秘書エージェントが本人の流儀を学び、使うほど的確になる |
| A-3 | 業務手順の資産化 | 繰り返しがエージェント定義として形式知になり、人が辞めても残る |
| A-4 | 制度対応 | 日本の会計・税務・労務への適合が参入障壁として働く |
| A-5 | エコシステム | 第三者が拡張を提供する構造（第12章・第13章） |
| A-6 | **共通基盤＋拡張の形** | 個社の事情に、フルスクラッチではなく積み上げで応える（第2.3節） |
| A-7 | **GUI で拡張を扱えること** | 作る人は技術者でも、入れる人は業務担当者でよい（第2.3.3節） |

A-1 から A-3 は時間とともに厚みを増し、**乗り換えコストとして働く**。
「会社としての情報が蓄積・統合されること」が最大の武器になるという前提を、
第11章で具体的な構造として設計する。

### 1.5 調査データと設計判断の対応

| 調査で分かったこと | M2Office の設計への反映 | 該当章 |
|---|---|---|
| 全社導入 4.1%、64.9% は個人判断任せ | 個人向けではなく「組織として導入する」製品に振り切る | 第16章 |
| 活用していない理由の最多が「業務がイメージできない」63.4% | 業務名の付いたエージェントを並べ、さらに秘書に話しかければ使える形にする | 第10章、第6.1節 |
| 推進人材の不足 40.0%、社内ルール未整備 26.2% | 既定値のまま動く設計。ルールを製品側が持つ | 原則 p4 |
| 懸念の最多が「情報の正確性」50.4% | 根拠と出典の提示を必須化。取得できない値は推測しない | 第8.3節、第9.2節 |
| 活用すべき業務範囲が不明確 40.0%、責任所在 25.5% | 危険度に応じた承認ゲートの強制と、全行動の監査ログ | 第9.4節、第16.6節 |
| 情報漏洩のリスク 33.5% | テナント分離、最小権限、モデル学習に用いないことの明記、個人記憶の本人管理 | 第16章、第11.5節 |
| 積極活用層の用途はメール・報告書・議事録が 74.0% | Phase 1 のエージェントをこの領域に集中させる | 第9.5節 |
| 業務分野別の導入率は総務・管理 68.3% が最多 | バックオフィス起点で導入する設計 | 第2.5節 |
| 導入目的は効率化 87.0%、一方で効果測定ができない | 削減時間の計測をダッシュボードの必須項目とする | FR-413 |
| 求める支援は費用助成 77.9%、不足情報は成功事例 83.3% | 補助金対象ツールとしての登録と、自社導入の事例化 | 第21.5節 |
| 顧客ごとにニーズが異なり、提供側だけでは埋められない | 第三者が拡張できるオープンなプラットフォームとして設計する | 第12章、第13章 |
| 個人に閉じたノウハウが会社に残らない | 個人記憶から組織知識への昇華の仕組みを設ける | 第11章 |

### 1.6 解決したい課題

| # | 課題 | 現状 | 目指す状態 |
|---|---|---|---|
| P-1 | 定型事務の人手依存 | 見積・請求・経費・勤怠が手作業と転記の連続 | エージェントが下書きまで自動生成し、人は承認のみ |
| P-2 | 情報の散在 | メール・チャット・共有ドライブに分散 | 横断検索と自動要約で必要な情報に即到達 |
| P-3 | 属人化 | 担当者しか手順を知らない | 業務手順がエージェント定義として明文化・実行される |
| P-4 | IT 専任者の不在 | 導入・運用を誰も担えない | サインアップとウィザードで完結、専任者不要 |
| P-5 | AI 導入の断絶 | 個人が AI を使うが業務システムに繋がらない | 業務データに接続された状態で AI が動く |
| P-6 | 用途が思いつかない | 何に使えるか分からず着手できない | 秘書に話しかければ始められる |
| P-7 | ニーズの多様性 | 各社固有の業務は既製品では埋まらない | 第三者や顧客自身がエージェントを追加できる |
| P-8 | 知識が会社に残らない | 退職とともにノウハウが失われる | 個人の学習が組織知識に昇華される |

### 1.7 プロダクトの目的

M2Office は、中小企業のオフィス業務を **AI エージェント群が代行・支援する Web サービス**であり、
**各従業員に専属の秘書エージェントを提供し**、
同時に**第三者がエージェントを追加できるオープンなプラットフォーム**である。

利用者は専門知識を持たずブラウザだけで利用でき、
使うほど会社としての知識が蓄積・統合されていく。

### 1.8 プロダクト原則

| # | 原則 | 意味 |
|---|---|---|
| p1 | 人間が最終承認者 | 対外影響・金銭影響のある操作は必ず人の承認を経る |
| p2 | GUI で完結 | ファイル編集・コマンド実行を利用者に一切要求しない |
| p3 | 説明可能 | エージェントの全行動は根拠と履歴を伴って監査できる |
| p4 | 既定値で動く | 設定しなくても使える。設定は後から詰められる |
| p5 | 選んで使える | 不要な機能は見せない。有効化したものだけが画面に出る |
| p6 | 誰でも拡張できる | 第三者・顧客自身が追加できる。**作る人は技術者でも、入れる人は業務担当者でよい** |
| p7 | 使うほど賢くなる | 個人の働き方を学び、組織の知識として蓄積する |
| p8 | Google で完結する | 共通基盤は Google プラットフォームに一本化し、手を広げない |
| p9 | 日本の制度に合わせる | 会計・税務・労務は日本の制度を前提に設計する |
| p10 | 情報は顧客のもの | 学習利用・外部送信の範囲を顧客が制御できる |

### 1.9 非目標（やらないこと）

- 会計・給与計算の法定計算そのものを内製すること。
- 大企業向けの高度なワークフロー統制・多階層組織管理。
- **Google プラットフォーム以外のグループウェアへの標準対応**（第14.5節。拡張機能として後から対応する）。
- 自社ですべての業務機能を提供しようとすること（第12章・第13章の拡張機構に委ねる）。
