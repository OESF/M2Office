## 37. 会議室・社用車・備品の予約（第 0.271.0 版。第 0.271.1 版で確定。第 0.273.0 版で段 1、第 0.277.0 版で段 2 を実装）

この章で決めること: 会議室・社用車・プロジェクターなどの**会社で共有するものを、画面か秘書に頼むだけで予約し、重なりを防ぐ**しくみ。
予約できるものの持ち方、予約の決まり、Google カレンダーとのつなぎ、秘書からの頼み方、画面、権限と記録、データモデル、段階。

**この章は確定した**（2026-10-06 に三浦さんが、中小企業の事務で便利な機能の提案から選び、「これの仕様を作成してください」と依頼した。2026-10-06 に三浦さんが「案のとおりで確定してください」と依頼し、第 0.271.1 版で確定した）。
「（案）」と書いた値は、確定のときに案のとおりとした値である。方針の判断の記録は [ADR-0070](../docs/adr/0070-reservations.md)。

**2026-10-06 に三浦さんが選んだ形**

- 予約できるものと予約は **M2Office に持ち、予約した人の Google カレンダーにも予定を入れる**（Google Workspace の管理コンソールの「リソース」は使わない。管理の設定と権限の追加が要らないため）。
- 社用車は**予約だけ**にする（走行距離・行き先・給油などの使った記録は持たない）。

### 37.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 会議室や社用車を、ホワイトボードや表計算・口頭で取り合っていて、重なる・取ったつもりで取れていない | 予約を 1 か所に持ち、**同じものの同じ時間の予約を断る**。空いている時間と、ほかの空いているものを示す |
| 予約のために表を開くのが面倒で、結局取らずに使う | **秘書に一言で頼める**（「明日 10 時から 1 時間、会議室を取って」）。どの会議室かを言わなければ、空いているものを AI が選ぶ |
| 予約したことを忘れる・ほかの予定と重ねる | 予約した人の Google カレンダーに予定として入れる。変えれば予定も変わり、取り消せば予定も消える |

#### 37.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 従業員 5〜100 人ほど。会議室 1〜5 室、社用車 1〜10 台、貸し出す備品（プロジェクター・カメラ・ノートパソコンなど）がいくつか |
| 予約する人 | 社員の誰でも。専任の管理者はいない（総務の兼務） |

### 37.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「予約」（ID `reservations`） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（案） |
| 左のメニュー | 「予約」 |
| 利用範囲 | 拡張機能の「利用できる人」（第12.13節）。既定は会社の全員 |

### 37.3 用語

| 用語 | 意味 |
|---|---|
| 予約できるもの | 会議室・社用車・備品など、会社で共有して時間で取り合うもの。名前・種類・定員（会議室だけ。任意）・場所（任意）を持つ |
| 種類 | 会議室・社用車・備品・そのほか。並べ方と、「会議室を」のような頼み方に使う |
| 予約 | 予約できるもの・始め・終わり・用件（任意）・予約した人 |

### 37.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 入り切り | 管理者ページの「拡張機能」 | 切り |
| 予約できるもの | 管理者が画面の「予約できるもの」で足すか、秘書に「会議室 A と B、社用車のプリウスとハイエースを予約できるようにして」と頼む。**種類は名前から AI が決める**（違えば直す） | 無し |

### 37.5 予約の決まり

| 項目 | 規定 |
|---|---|
| 重なり | **同じものの、時間が重なる予約は作らない**（断る）。断るときは、そのものの次に空いている時間と、同じ種類で空いているほかのものを示す。終わりと始めが同じ時刻なら重ならない |
| 時間の刻み | 分の単位で受ける（画面は 15 分の刻みで選ぶ） |
| 長さと先の日数 | 1 件は 14 日まで。90 日先まで予約できる（案。Q-183） |
| 定員 | 会議室に定員があり、頼みに人数があれば、定員が人数以上の会議室から選ぶ。定員を超える予約も断らない（定員は目安のため）。答えに「定員 6 名の会議室です」と添える |
| 選び方 | 「会議室を」のように**どれかを言わなければ、空いているものを AI が選び**、どれを取ったかを答える（確かめを求めない。ADR-0028）。選ぶ順は、定員が人数に近いもの、そのあと並びの順 |
| 変える・取り消す | 予約した本人と管理者ができる。ほかの人の予約は変えられない（「〇〇さんが 10 時から使っています」と示す） |
| 承認 | **挟まない**（社内の共有のものの取り合いで、社外に出るものでもお金の確定でもないため。ADR-0028。案。Q-181） |
| 繰り返し | 段 1 では作らない（毎週の定例などは、段 2 で「毎週月曜 10 時に会議室 A」を作る） |
| 使い終わり | 早く終われば、予約した人が「終わった」で終わりの時刻を今にする（次の人が使える）。使ったかどうかの確かめ（チェックイン）はしない |
| 止めたもの | 管理者が予約できるものを止めると、新しく予約できなくなる。これからの予約は残し、予約した人に知らせる |

### 37.6 Google カレンダーとのつなぎ

| 項目 | 規定 |
|---|---|
| 予定を入れる | 予約したら、**予約した人の Google カレンダー**に予定を入れる（題は「会議室 A」や「社用車 プリウス」と用件。場所の欄に予約できるものの名前と場所）。いまの権限（`calendar.events`）で入れる。新しい権限は求めない |
| 変える・取り消す | 予約を変えれば予定も直し、取り消せば予定も消す。M2Office は予定の ID を覚えておく |
| Google につないでいない人 | 予約は M2Office にだけ持つ。予定は入れない（答えにそう書く） |
| 予定のほうを直したとき | Google カレンダーで予定を消したり時刻を変えたりしても、**予約は変わらない**（予約の正は M2Office）。予約を直すのは画面か秘書 |
| 会議と一緒に取る | 段 2。秘書の日程調整（第10章）で会議の日時が決まったとき、「会議室も」と言われていれば、その時間に空いている会議室を取り、会議の予定の場所に入れる |
| Workspace のリソース | 使わない（三浦さんの選択）。管理コンソールで会議室をリソースとして登録している会社とのつなぎは後で考える（Q-182） |

### 37.7 秘書と業務から使う

秘書の欄の本人の発言を見分けて、その場で行う（店頭サイネージの秘書と同じ形。第31.11.1節）。日時は推論が読み、予約できるものの名前は会社の一覧と突き合わせる。

| 依頼の言い方の例 | 動き |
|---|---|
| 「明日 10 時から 1 時間、会議室を取って」「金曜の午後、社用車を使いたい」 | 空いているものを選んで予約し、「会議室 A を 10/7 10:00〜11:00 で取りました（定員 6 名）」と答える。空きが無ければ、その種類の次に空いている時間を示す |
| 「会議室 A、明日 10 時から 6 人で」 | そのものを予約する。重なれば断り、空いている時間とほかの会議室を示す |
| 「明日の会議室は空いてる？」「今週の社用車の予約は？」 | 種類ごと・ものごとの空きと予約（予約した人・時間・用件）を答える |
| 「さっきの予約を 30 分延ばして」「明日の会議室の予約を取り消して」 | 本人のいちばん近い予約を直す・取り消す。いくつもあれば挙げて尋ねる |
| 「会議室 C を予約できるようにして」 | 管理者なら足す（種類は AI が決める）。管理者でなければ管理者に頼むよう答える |

| 項目 | 規定 |
|---|---|
| 推論が使えないとき | 「明日」「金曜」「10 時から 11 時」「1 時間」などの決まった言い方だけで読む |
| 記録 | 秘書から行ったことを監査ログ `secretary.reservation` に種類だけ残す |

### 37.8 画面

| 項目 | 規定 |
|---|---|
| 予約の表 | 左のメニューの「予約」。**日ごとの表**（縦に時刻、横に予約できるもの。種類で絞れる）。空いている所を押すか、なぞって選ぶと、その時間で予約の欄が開く（用件は任意）。週の表に切り替えられる |
| 予約の 1 件 | 押すと、予約した人・時間・用件。本人と管理者には「変える」「取り消す」「終わった」 |
| 自分の予約 | これからの自分の予約の一覧 |
| 予約できるもの | 管理者だけ。足す・名前と種類と定員と場所を直す・並べ替え（行の左のつまみをつかんで動かす。個人設定のメニューの並びと同じ操作。第6.5.6節）・止める（行のスライドのスイッチ）。第 0.330.0 版で、1 段ずつ動かすボタンと「止める」「使う」のボタンから改めた |
| スマホ | 同じ表を縦に並べて出す（今日と明日） |
| 説明文 | 常に出さない（原則 u11） |

### 37.9 AI に任せること（ADR-0028）

| AI が決める | 人がすること |
|---|---|
| 予約できるものの種類（名前から）、空いているものの選び方、頼みの日時の読み方 | 予約できるものを足す（管理者）、予約を頼む |

### 37.10 権限と記録

| 操作 | 利用範囲の人 | 管理者 |
|---|---|---|
| 予約の表を見る・予約する | できる | できる |
| 自分の予約を変える・取り消す | できる | できる |
| ほかの人の予約を変える・取り消す | できない | できる（予約した人に知らせる） |
| 予約できるものを足す・直す・止める | できない | できる |

| 項目 | 規定 |
|---|---|
| 監査ログ | 予約できるものを足した・直した・止めた、ほかの人の予約を管理者が変えた・取り消した（`reservation.item.*`・`reservation.admin_change`）。ふだんの予約・変更・取り消しは数が多いので監査ログに入れず、予約の行に作った人と時刻を残す |
| 知らせ | 管理者がほかの人の予約を変えた・取り消したとき、予約できるものを止めたときに、予約した人へ知らせる（通知の種類「予約」。第6.5.5節に足す） |

### 37.11 人の情報

| 項目 | 規定 |
|---|---|
| 見えるもの | 予約した人の名前・時間・用件は、利用範囲の人に見える（社内で共有するものの取り合いのため） |
| 用件 | 任意。書かなくても予約できる |
| 残す期間 | 終わった予約は 1 年で消す（案） |
| 外部の AI | 秘書の頼みの読み取りに使う（日時と予約できるものの名前だけ）。予約の一覧は推論に渡さず、空きの計算はプログラムが行う |

### 37.12 データモデル（案）

| 表 | 列 |
|---|---|
| `reservable_items`（予約できるもの） | tenant_id、ID、名前（会社の中で重ならない。40 字まで）、種類（room・car・equipment・other）、定員（任意）、場所（任意）、並び、状態（使う・止めた）、作った人と時刻 |
| `reservations`（予約） | tenant_id、ID、予約できるもの、始め、終わり、用件（120 字まで）、予約した人、Google カレンダーの予定の ID（任意）、状態（予約・取り消し）、作った人・直した人と時刻。**同じものの予約の時間が重ならないことを、データベースの制約（期間の重なりを断る制約）で守る**（画面と秘書が同時に取っても重ならない） |

行単位の制限（tenant_id）を付ける（不変則 I-2）。

### 37.13 API（案）

| API | 内容 |
|---|---|
| `GET /v1/reservations/items` ／ `POST`・`PATCH`・`DELETE` | 予約できるものの一覧 ／ 足す・直す・止める（管理者だけ） |
| `GET /v1/reservations?from=&to=&kind=` | 期間の予約と空き |
| `POST /v1/reservations` | 予約する（重なれば 409 と、空いている時間・ほかのもの） |
| `PATCH` ／ `DELETE /v1/reservations/:id` | 変える ／ 取り消す（本人と管理者） |
| `POST /v1/reservations/:id/finish` | 早く終わったので、終わりを今にする |

### 37.14 段階

| 段 | 行うこと |
|---|---|
| 段 1 | 予約できるもの（足す・種類を AI が決める）、予約（重なりを断る・空きを示す・選ぶ）、Google カレンダーに予定を入れる・直す・消す、予約の表（日・週・スマホ）、秘書からの頼み、権限と記録 |
| 段 2 | 繰り返しの予約、秘書の日程調整で会議と一緒に会議室を取る、管理コンソールのリソースとのつなぎ（Q-182） |

### 37.15 行わないこと

| 行わないこと | 理由 |
|---|---|
| 社用車の使った記録（走行距離・行き先・給油・アルコールチェック） | 三浦さんが「予約だけ」を選んだ（2026-10-06）。アルコールチェックの記録は法令の決まりが細かく、別に考える |
| 鍵の受け渡し・入退室の管理 | 物の管理の仕組みが要り、予約の目的を超える |
| 社外の人の予約・貸し会議室の料金 | 社内の共有のものに限る。お金は扱わない（第38章と同じ。2026-10-06 の三浦さんの方針） |
| 承認の流れ | 社内の取り合いに承認を挟まない（Q-181） |
| 使ったかの確かめ（チェックイン）と、使わなかった予約の自動の取り消し | 小さな会社では運用が重い |

### 37.17 段 1 の実装の決まり（第 0.273.0 版）

2026-10-06 に三浦さんが「第37章の予約を実装してください」と依頼した。段 1（第37.14節）を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張「予約」（`reservations`。既定は切り・無償）。左のメニューに「予約」。ツールと付属の業務は持たず、画面と秘書の欄の本人の発言から行う |
| 重なり | 同じものの、時間が重なる予約は作らない。PostgreSQL の期間の重なりを断る制約（`btree_gist`。取り消した予約は数えない）で守り、画面と秘書が同時に取っても重ならない。断ったときは、使っている人と時間、そのものの同じ長さで次に空く時間（90 日先まで）、同じ種類でその時間に空いているほかのもの（5 つまで）を返す。画面はそれを押せばその時間・そのもので取る |
| 時間 | 1 件は 14 日まで、90 日先まで。終わりが過ぎた時間と、始めが 15 分より前の時間は取れない（いまの枠は取れる）。使っている途中の予約は、始めが過ぎていても終わりを延ばせる。画面は 15 分刻み、秘書は分の単位 |
| 選び方 | どれかを言われなければ、その種類（言われなければ全部）の空いているものから選ぶ。人数を言われれば、定員が人数以上で近いもの、定員の無いもの、定員の足りないものの順。そのあと並びの順。空きが無ければ、その種類でいちばん早く空くものと時間を答える |
| 変える・取り消す・終わった | 本人と管理者だけ。管理者がほかの人の予約を変えた・取り消したら、予約した人に知らせ（お知らせの種類「予約」）、監査ログ `reservation.admin_change` に残す。「終わった」は、使っている途中なら終わりをいま（分の単位で切り上げ）にし、まだ始まっていなければ取り消す |
| 予約できるもの | 管理者が画面か秘書で足す（名前は会社の中で重ならない。200 まで）。種類は名前から決まった言葉で決め、決まらなければ推論に 1 語で答えさせる（使えなければ「そのほか」）。直す・並べ替え・止める・使うに戻す。止めたら、これからの予約は残し、予約した人に知らせる。監査ログは `reservation.item.create`・`reservation.item.update`・`reservation.item.stop` |
| カレンダー | 予約したら、予約した人の Google カレンダーに予定を入れる（題は「会議室 A（用件）」「社用車 プリウス」、場所は名前と場所、説明に「予約を変えるときは M2Office で」）。予定の ID を覚え、変えれば直し（予定が消されていれば入れ直す）、取り消せば消す。つないでいない人の予約は M2Office にだけ持ち、答えにそう書く。カレンダーの接続口の予定の作成と変更に、場所と説明（任意）を足した |
| 秘書 | 秘書の欄の本人の発言から、予約する・選んで取る・空きと予約に答える・自分の予約・延ばす・時間を変える・取り消す・予約できるものを足す（管理者）を見分けてその場で行う。予約できるものの名前は会社の一覧と突き合わせ、名前も種類の言葉も無ければ扱わない（「レストランの予約」など）。会議の予定の頼み（「会議室で打ち合わせを入れて」）は予定の業務に回す。日時は推論が読み（本人の発言と予約できるものの名前だけを渡す）、使えなければ決まった言い方（今日・明日・曜日・M 月 D 日、10 時から 11 時・10 時から 1 時間・午前・午後・終日）で読む。時刻が読めなければ聞き返す。変える・取り消すは本人のいちばん近い予約で、日や種類を言われていくつも当たれば挙げて尋ねる。記録は `secretary.reservation`（種類だけ） |
| 画面 | 日の表（縦に時刻 7〜21 時。外にかかる予約があれば広げる。横に予約できるもの。押すと 1 時間、なぞるとその幅で予約の欄）・週の表（月曜から 7 日）・種類の絞り込み・予約の 1 件・自分の予約・予約できるもの（管理者）。幅の狭い画面では、今日と明日を縦に並べる。秘書が答えたら読み直す |
| 片付け | ワーカーが 1 日に 1 回、終わって 1 年を過ぎた予約を消す |
| API | `GET /v1/reservations`（`from`・`to`。15 日まで）、`GET /v1/reservations/mine`、`POST /v1/reservations`（重なれば 409 と `conflict`）、`PATCH`／`DELETE /v1/reservations/:id`、`POST /v1/reservations/:id/finish`、`GET`／`POST /v1/reservations/items`、`PATCH /v1/reservations/items/:id`、`PUT /v1/reservations/items/order` |

### 37.18 段 2 の実装の決まり（第 0.277.0 版）

2026-10-06 に三浦さんが「次に進んでください」と依頼し、次の作業の候補から「予約の段 2」を選んだ。段 2（第37.14節）のうち、繰り返しの予約と、日程調整で会議と一緒に会議室を取ることを、次の決まりで実装した。管理コンソールのリソースとのつなぎ（Q-182）は行っていない。

| 項目 | 規定 |
|---|---|
| 繰り返しの決まり | 毎週・隔週・毎月（第 n 何曜。5 は最後の週）。始めの日・始めと終わりの時刻（同じ日の中）・終わりの日（任意。無ければ続ける）・用件。隔週は、始めの日から数えた最初の回から 2 週ごと。画面の「毎月」は、選んだ日と同じ週の同じ曜日 |
| 回の作り方 | 90 日先までの回を、1 回ずつの予約（繰り返しの印つき）として作る。重なった日・止めたものの日は飛ばして記録し、作った人に答える。その先は、ワーカーが 1 日に 1 回、90 日先まで足し、取れなかった日があれば予約した人に知らせる（お知らせの種類「予約」）。終わりの日を過ぎたら繰り返しを止める。各回は予約した人の Google カレンダーに予定を入れる |
| どれを取るか | 名前を言われればそれ。言われなければ、はじめの回に空いているもの（定員が人数に近いもの）を選び、その後の回も同じものを取る |
| 止める | 繰り返しの 1 回は「この回だけ取り消す」（ふだんの取り消し）と「これから全部取り消す」（繰り返しを止め、これからの回をまとめて取り消し、カレンダーの予定も消す）。本人と管理者だけ。管理者がほかの人の繰り返しを止めたら、予約した人に 1 回だけ知らせ、監査ログ `reservation.admin_change` に残す |
| 秘書 | 「毎週月曜 10 時から 1 時間、会議室 A を取って」「隔週の水曜」「毎月第 2 火曜」「毎月最後の金曜」を見分け、繰り返しの予約を作って、取れた回の数と取れなかった日を答える |
| 会議と一緒に | 日程調整（AG-03）に「会議室（任意）」の入力を足した。予定を作るツール `calendar.create` に `room`（会議室の名前か「会議室」）を足し、**承認の後に予定を作ったあとで**、名前のものか、参加する人数（招く人 + 本人）に定員が近い空いている会議室を取り、会議の予定の場所に入れる。予約の側では予定を作らない（会議の予定がそのまま会議室の予定になる）。取れなかったときは会議の予定はそのままで、理由を結果に添える。予約を使っていない会社と利用範囲の外の人では取らない |
| API | `POST /v1/reservations/series`、`GET`／`DELETE /v1/reservations/series/:id` |
| 表 | `reservation_series` と、予約の繰り返しの印 `reservations.series_id`（移行 096） |

**段 2 で行っていないこと**: 管理コンソールのリソースとのつなぎ（Q-182）、繰り返しの決まりそのものを後から変えること（止めて作り直す）、Google カレンダーの繰り返しの予定としてまとめること（回ごとの予定にしている）。
