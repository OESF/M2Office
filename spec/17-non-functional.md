## 17. 非機能要件

想定規模は「1 テナント 10 名程度、同時実行は数件」であり、
過剰な分散設計よりも**運用の単純さ**を優先する。

| 分類 | 要件 | 目標値 |
|---|---|---|
| 性能 | **秘書の初期応答** | **3 秒以内に応答を開始** |
| 性能 | 音声認識から応答開始まで | TBD: 2 秒以内 |
| 性能 | 定型エージェントの完了 | TBD: 中央値 60 秒以内 |
| 性能 | 画面表示 | 主要画面の初期表示 2 秒以内 |
| 性能 | 知識検索 | 1 秒以内に結果を返す |
| 性能 | API 応答 | ジョブ作成は 1 秒以内に ID を返す |
| 規模 | 1 テナントのユーザー数 | 標準 10 名、上限 TBD: 50 名 |
| 規模 | テナント数 | Phase 2 で 10、Phase 3 で TBD: 100 |
| 規模 | 同時実行 | 1 テナントあたり 5 件、全体 TBD |
| 規模 | 組織知識の文書数 | 1 テナント 10,000 件を想定 |
| 可用性 | 稼働率 | TBD: 99.5%（計画停止を除く） |
| 信頼性 | 実行の再開 | ワーカー障害後、未完了の実行を自動的に再開する |
| 信頼性 | 二重実行防止 | 同一ジョブの重複実行を防ぐ（冪等キー） |
| 運用性 | 障害検知 | 失敗率・遅延・連携切断を検知し通知する |
| コスト | 推論コスト | TBD: 1 シートあたり月額原価の上限を設定 |
| コスト | 上限制御 | テナント・ユーザー・アプリ・実行の 4 階層で設定できる |
| 保守性 | エージェント追加 | コード変更なしに追加できる（第12章） |
| データ所在地 | 保管場所 | 日本国内リージョン |
| 到達時間 | サインアップから初回実行成功まで | **30 分以内** |

**秘書の応答速度は体験の根幹である。**
「話しかけて 3 秒待たされる」と秘書としては使われなくなる。
定型の照会は LLM を介さずに即答する（第10.9節の層 1）。
