### 5.2 代表ユースケースの詳細

#### UC-01 秘書への口頭での照会

| 項目 | 内容 |
|---|---|
| 主アクター | 従業員 |
| 事前条件 | ログイン済み。Google カレンダーへの認可が済んでいる |
| トリガー | 画面下部の秘書バーのマイクを押し「今日の午後からのスケジュールをチェックして」と話す |
| 基本フロー | 1. 音声を文字に変換 2. 秘書が意図を解釈し、照会と判断 3. カレンダーから本人の午後の予定を取得 4. 要約して音声で答える 5. 関連する準備事項（未読の関連メール、未完了タスク）が多ければ、その答えに添えて秘書のキャンバスに出す（第6.2.0節） |
| 例外フロー | 3a. 認可が未済の場合は、その場で認可を求める |
| 承認ゲート | なし（読取のみ） |
| 成功条件 | 3 秒以内に回答が始まり、画面と音声の両方で確認できる |
| 設計上の含意 | 秘書は**本人の権限を超えない**。他人の予定は本人が見られる範囲でのみ答える |

#### UC-04 会議の議事録作成と共有

| 項目 | 内容 |
|---|---|
| 主アクター | 従業員（会議の主催者） |
| トリガー | Meet の会議終了を検知、または秘書に「さっきの会議をまとめて」と依頼 |
| 基本フロー | 1. Meet の文字起こしを取得 2. 議題・決定事項・保留事項・担当と期限を構造化 3. Google ドキュメントとして生成し、所定のドライブフォルダへ保存 4. **承認ゲート**: 内容を確認 5. 決定事項を Google Tasks へ起票 6. **承認ゲート**: 共有範囲を確認 7. Google Chat の該当スペースへ共有 8. **組織知識として登録**し、以後の検索対象にする |
| 承認ゲート | ステップ 4（内容）、ステップ 6（共有範囲） |
| 成功条件 | 会議終了から 10 分以内に、共有可能な議事録が用意される |
| 設計上の含意 | ステップ 8 が第11章の知識蓄積の入口になる。**議事録は最も価値の高い組織知識**であり、会議のたびに自動で厚みが増す |

#### UC-08 秘書による手順化の提案

| 項目 | 内容 |
|---|---|
| 主アクター | 従業員 |
| トリガー | 秘書が同種の依頼の繰り返しを検知する（例: 毎週同じ形式の報告書作成） |
| 基本フロー | 1. 秘書が繰り返しパターンを抽出 2. 「この作業を定型化しませんか」と提案 3. 承諾されたら手順の草案を生成 4. 本人が内容を確認・修正 5. 個人用エージェントとして登録 6. 有用なら管理者へ全社展開を申請 |
| 承認ゲート | ステップ 4（本人）、ステップ 6（管理者） |
| 成功条件 | 本人が定義を一から書くことなく、繰り返し作業が自動化される |
| 設計上の含意 | **これが「使うほど賢くなる」（原則 p7）の中核**。個人の経験が形式知となり、会社の資産になる |

### 5.3 ユースケース記述テンプレート

新しいユースケースは 5.2 と同じ表形式で記述する。項目は
`主アクター / 事前条件 / トリガー / 基本フロー / 代替フロー / 例外フロー / 承認ゲート / 成功条件 / 設計上の含意`。
