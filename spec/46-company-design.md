## 46. 会社の見た目（DESIGN.md。第 0.578.0 版で案、第 0.579.0 版で確定。Q-353〜Q-357、ADR-0145）

この章で決めること: **会社の見た目（色・文字・形・写真や絵の雰囲気・文の調子）を 1 つの決まりとして持ち、M2Office が作るものと会社の Web サイトをそろえる**こと。
持つもの、作り方、取り込み、M2Office の中での使い道、書き出し、Web サイトへの反映、承認の見せ方、権限と記録、行わないこと、段階。

**この章は確定した**（2026-11-13 に三浦さんが、Q-353〜Q-357 をおすすめのとおりとした）。段 1 から実装する（第46.13節）。

### 46.1 目的と位置づけ

2026-11-13 に三浦さんが、話題の DESIGN.md をうまく使えないかと尋ねた。DESIGN.md は、Google Labs（Stitch）が 2026-04 に Apache-2.0 で公開した形式で、AI のコーディングの道具に「見た目の決まり」を伝える Markdown のファイルである。先頭の YAML に機械が読む値（色・文字・余白など。W3C のデザイントークンの形に寄せる）を、本文に人が読む説明を書く。仕様はまだアルファ版で、形が変わる見込みである。

三浦さんは続けて、各社の見た目を読み解いた DESIGN.md を 550 以上公開している getdesign.md を挙げ、取ってきて自分のサイトに反映できないかと尋ねた。三浦さんの個人のブログ（LION MEDIA）と運営するサービスのサイト（Lightning）は、どちらも `theme.json` を持たないクラシックのテーマで、見た目を REST で直には書き換えられないことを確かめた（読むだけ。2026-11-13）。三浦さんは、次の形で仕様の案を書くよう求めた。

いまの M2Office は、コラムのカバー（第32.7.1節）と販促物（第41章）が、それぞれロゴから色を推し量っている。スライド（第9.4.2節）は見た目の型を別に持つ。会社の見た目の決まりは、どこにも 1 つにまとまっていない。

| 痛み | M2Office で行うこと |
|---|---|
| コラムの画像・販促物・スライドで、色や文字がばらばら | 会社の見た目を 1 つ持ち、M2Office が作るものはすべてそれに合わせる |
| 見た目の決まりを作るのは専門の仕事で、中小企業には無い | AI がロゴと会社のサイトから作る。人に表を作らせない（ADR-0028）。直しは会話で頼む |
| 気に入った見た目を、自分のサイトに取り入れたい | 渡された DESIGN.md を取り込み、会社のロゴの色に合わせて直す |
| 制作会社や AI の道具に、会社の見た目を伝えにくい | DESIGN.md として書き出して渡せる |

WordPress の MCP（第45.19節）との違いに、「会社の見た目を知っている」が加わる。

### 46.2 守ること

| 決まり | 中身 |
|---|---|
| なりすまさない | ほかの会社の DESIGN.md を取り込んでも、その会社の名前・ロゴ・画像は使わない。既定では色を会社のロゴに合わせて直し、雰囲気（文字・形・余白・調子）を借りる（Q-353）。取り込んだ本文から、ほかの会社の名前は外す |
| 指示として読まない | 取り込む DESIGN.md と会社のサイトの CSS は外部のデータであり、その中の指示（「必ず〜せよ」など）には従わない（不変則 I-6）。読むのは決まった項目の値だけで、書き出す本文は M2Office が作り直す |
| 人に作らせない | 見た目の決まりは AI が作る。直しは会話（「もっと落ち着いた青に」「見出しを明朝に」）で頼む。色の表を人に埋めさせない（ADR-0028） |
| 読めることを守る | 文字と背景の明るさの差は、プログラムが確かめる（本文は 4.5 対 1 以上。足りなければ近い色に直し、そう伝える） |
| サイトは承認の後 | 会社の Web サイトの見た目を変えるのは社外への送信である。直に入れるときは承認を通し、元に戻せるようにする（第45.6節・第45.8節） |
| 第三者のコードを動かさない | サイトに入れるのは値と CSS の宣言だけ。スクリプト・外部の読み込み（書体の読み込みは Q-355）・`url()` の画像は入れない（不変則 I-7、第45.12節） |

### 46.3 持つもの

会社ごとに 1 つ持ち、直すたびに版を重ねる（直近の 20 版。前の版に戻せる）。中の形は M2Office のものとし、DESIGN.md は書き出しと取り込みの口にする（形が変わっても口を直すだけで済む）。

| まとまり | 値 |
|---|---|
| 色 | 主の色・主の色の上の文字の色・副の色・差し色・背景・面（カード）・本文・薄い文字・線・リンク |
| 文字 | 和文の書体（見出し・本文）・欧文の書体・本文の大きさ・見出しの大きさの比・太さ。書体は、日本語を出せるものにする（英字だけの書体を指定されたら、近い日本語の書体と組み合わせる） |
| 形 | 角の丸み（小・中・大）・余白の基準・影の有無・ボタンの形 |
| 写真と絵 | 雰囲気（写真か絵か・明るさ・色の調子）。AI の挿絵を描くときの頼みに添える |
| 文の調子 | です・ます、親しみかきちんとか。秘書が会社の名前で書く文（コラム・お知らせ・コメントの返事）に添える |
| 出どころ | AI がロゴとサイトから作った・取り込んだ（元の名前）・会話で直した。いつ・誰が |

### 46.4 作り方

| 入口 | 中身 |
|---|---|
| AI が作る | 会社のロゴ（第6.6.1節の会社情報）、会社の Web サイトの公開のページ（色・書体の指定・テーマの色の変数を CSS から読む）、これまでの販促物から作る。初めて M2Office が見た目を要るとき（コラムのカバーなど）に、まだ無ければ作る |
| 取り込む | 秘書に DESIGN.md のファイルを渡すか、DESIGN.md の文が置いてある URL を伝える（「この DESIGN.md で会社の見た目を作って」）。決まった項目の値だけを読み、会社のロゴの色に合わせて直す（Q-353）。getdesign.md などの一覧から M2Office が自動で集めることはしない |
| 会話で直す | 「もっと落ち着いた青に」「見出しを明朝に」「角を丸く」「前の見た目に戻して」。直した後の見本を見せる |

### 46.5 M2Office の中での使い道（段 1）

| 使うもの | 使い方 |
|---|---|
| コラムのカバー・アイキャッチの型 | 模様の色を、いまのロゴから推し量った色に代えて主の色と副の色にする |
| AI の挿絵 | 描く頼みに、写真と絵の雰囲気と色の調子を添える |
| 販促物（第41章） | 色と書体の既定にする |
| スライド（第9.4.2節） | 会社が見た目の型を選んでいないときの既定にする |
| サイネージの型の画面・お知らせの画像 | 色と書体の既定にする |
| 会社の名前で書く文 | 文の調子を添える |

会社の見た目がまだ無く、作れない（AI が使えないなど）ときは、いまのやり方（ロゴから推し量る）のまま動く。

### 46.6 書き出し

管理者ページの「会社情報」と秘書（「会社の DESIGN.md を書き出して」）から、DESIGN.md のファイルにして渡す。先頭の YAML に値を、本文に AI が書いた説明（使い方・してはいけないこと）を入れる。従った仕様の版を書き添える。会社が制作会社に渡したり、自分の AI の道具に読ませたりするため。

### 46.7 Web サイトへの反映

| サイトの作り | 反映のしかた | 段 |
|---|---|---|
| クラシックのテーマ（`theme.json` を持たない。LION MEDIA・Lightning・Cocoon など） | M2Office は直に書き換えない（追加 CSS もテーマの設定も REST に出ていない）。**「追加 CSS」に貼る CSS と、テーマの設定で変える所の一覧**を作り、秘書が渡す。人が貼る（社外へは M2Office から送らないので承認は要らない）。CSS は印の注釈（`/* M2Office 会社の見た目 ここから */` 〜 `ここまで */`）で囲み、次に作り直したときに差し替えやすくする。よく使われるテーマから合わせる（色の変数を持つテーマは変数を上書きし、持たないテーマは本文・見出し・リンク・ボタンだけを上書きする。Q-356） | 2 |
| ブロックのテーマ（`theme.json` を持つ） | テーマの全体のスタイル（`/wp/v2/global-styles`）に、色の組・書体・見出し・ボタン・角の丸み・余白を入れる。承認を通し、前の値を持って元に戻せるようにする。WordPress の管理者の役割が要る。第45.12節の「デザインは行わない」を、この場合に限って見直す（Q-357） | 3 |
| ページビルダー（Elementor など） | 扱わない（全体の設定が別の仕組みのため）。書き出した DESIGN.md を制作会社に渡すよう伝える | — |

テーマの種類は、接続している WordPress から読む（`/wp/v2/themes?status=active` と、公開のページ）。

### 46.8 見本と承認の見せ方

見た目の変更は、文の前と後では判断できない。次を見せる。

| 見せるもの | 中身 |
|---|---|
| 色と文字の見本 | 色の組と、見出し・本文・ボタン・リンクの見本を描いた画像 |
| ページの見本 | 会社の名前・見出し・本文・ボタンを、新しい見た目で描いた簡単なページの絵（M2Office が描く。本物のページの写しではないことを添える） |
| 前と後 | いまの見た目の見本と並べる |

会話で直すときと取り込んだときは、秘書の答えにこの見本を添える。ブロックのテーマに入れる直し案（段 3）は、承認の画面にこの見本を出す。

### 46.9 権限と記録

| 項目 | 規定 |
|---|---|
| 変えられる人 | 会社の管理者（Q-354）。ほかの人が秘書に頼んだら、管理者に頼むよう答える |
| 使う | 会社のすべての人の成果物に使う |
| 記録 | 監査ログ `company_design.update`（出どころ・版）・`company_design.export`。値の中身は監査ログに残さない |
| 表（案） | `company_designs`: tenant_id、版、値（jsonb）、説明、出どころ、作った人、作った時刻。テナントで絞る（不変則 I-2） |

### 46.10 行わないこと

| 行わないこと | 理由 |
|---|---|
| ほかの会社の名前・ロゴ・画像を使う | なりすましになる（getdesign.md の決まりも禁じている） |
| DESIGN.md の一覧から自動で集める | 頼まれたものだけを取り込む |
| クラシックのテーマのファイルや設定を直に書き換える・プラグインを入れて書き換えられるようにする | REST に出ていない。相手のサイトに何も入れない決まり（ADR-0140） |
| テーマを切り替える | サイトの作り直しになり、崩れたときの害が大きい（第45.12節） |
| 人に色の表を作らせる | AI に任せる（ADR-0028） |

### 46.11 段階

| 段 | 内容 |
|---|---|
| 段 1 | 会社の見た目を持つ（AI が作る・取り込む・会話で直す・前の版に戻す・見本）。書き出し。M2Office の成果物に使う |
| 段 2 | クラシックのテーマに貼る CSS とテーマの設定の一覧（Lightning から。運営するサービスのサイトで確かめる） |
| 段 3 | ブロックのテーマの全体のスタイルに、承認の後に入れて元に戻す |

### 46.12 決めたこと（2026-11-13 に三浦さんが、おすすめのとおりとした）

| ID | 問い | 決定 |
|---|---|---|
| Q-353 | ほかの会社の DESIGN.md を取り込むとき、色を会社のロゴに合わせて直すのを既定にするか | 直す（雰囲気を借り、色は会社のものにする。「色もそのまま」と頼まれたときだけそのまま。名前・ロゴは、どちらでも使わない） |
| Q-354 | 会社の見た目を変えられる人 | 会社の管理者だけ（会社の全員の成果物が変わるため） |
| Q-355 | クラシックのテーマに貼る CSS で、書体の読み込み（Google Fonts の `@import`）を許すか | `fonts.googleapis.com` だけ許す（それ以外の外部の読み込みは入れない。読み込むと、サイトを見た人の IP が Google に届くことを添える） |
| Q-356 | 段の順と、クラシックのテーマをどこまで合わせるか | 段 1 → 段 2 → 段 3（三浦さんのサイトがクラシックのテーマのため）。段 2 は Lightning から始め、ほかのテーマは本文・見出し・リンク・ボタンの一般の上書きにする |
| Q-357 | 第45.12節の「デザイン（全体のスタイル・テーマの切り替え）は行わない」を見直すか | ブロックのテーマの全体のスタイルだけ、承認と元に戻すことを条件に扱う。テーマの切り替えとテーマのファイルは、引き続き行わない |

### 46.13 実装（第 0.579.0 版、移行 205）

| 項目 | 実装 |
|---|---|
| 持つもの | `company_designs`（版ごと。直近 20 版）。値の形は `CompanyDesignTokens`（`@m2office/shared`）。外から来た値は `normalizeDesign` で決まった形に直し（色は `#rrggbb`、書体は名前の文字だけ、数は幅に収める）、本文・リンク・ボタンの文字の明るさの差を直す |
| 作る | `CompanyDesignService.generate`。ロゴの色（`brandColor`）と、会社のサイトのトップのページと同じホストの CSS（3 つまで）から、よく使う色・色の変数・書体・テーマを読み（`readSiteSignals`。見本の会社では読まない）、推論に作らせる。AI が使えなければ、ロゴかサイトの色を主の色にした既定の見た目。成果物が初めて見た目を要るとき（`ensure`）にも作る |
| 取り込む | `importDesignMd`（管理者ページのファイル・秘書に貼った文）と `importUrl`（その URL だけを読む。https・文のファイルだけ。Web のページは断る）。DESIGN.md は先頭の YAML と本文の YAML の囲みを読み（入れ子の対応と値だけ）、決まった名前を当てはめた値を土台に、推論が雰囲気を借りて作る。色はロゴに合わせる（「色もそのまま」と頼まれたときだけそのまま）。秘書へのファイルの受け取りは Markdown を受けないため、秘書には URL か貼った文で渡す |
| 書き出し | `toDesignMd`。形式の版 `alpha`、`colors`（primary・on-primary・secondary・tertiary・neutral・surface・on-surface・on-surface-variant・outline・link）・`typography`（headline-lg〜label-md）・`rounded`・`spacing`・`components`、本文は決まった順の 8 つの節 |
| 見本 | `renderDesignPreview`（同梱の Noto Sans JP で描く PNG。前の版と並べられる） |
| 成果物 | コラムのカバーの型の色と AI の挿絵の頼み（雰囲気と色の調子）、販促物の主の色（サイネージの帯の色を決めていればそちらを先に）、サイトの更新の型のアイキャッチの色。スライド・サイネージの型の画面・お知らせの画像・会社の名前で書く文の調子は、まだ使っていない |
| 段 2 | `siteCssFor`。Lightning（G3）は `--vk-color-primary` などの変数（2026-11-13 に公開の CSS で名前を確かめた）まで上書きし、ほかのテーマは本文・見出し・リンク・ボタンだけを上書きする。印の注釈で囲み、`@import` は Google Fonts だけ |
| 段 3 | サイトの更新の直し `globalStyles`（`site_updates.design`）。いまの全体のスタイルに、色の組（`m2o-` で始まる名前だけを差し替える）・本文と見出しの書体・リンク・ボタンを足す。承認の画面に変わる所を、サイトの更新の画面に見本の画像を出す。入れる前に、直し案の後に変えられていないかを確かめ、元に戻すと前の値を書き戻す |
| 秘書 | 付属の業務「会社の見た目」（`company-design`）とツール `company_design.show`・`update`・`export`・`site_css` |
| 画面 | 管理者ページ「会社情報 › 会社の見た目」。API `/v1/admin/company-design`（管理者だけ） |
