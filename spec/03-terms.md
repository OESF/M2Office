## 3. 用語定義

| 用語 | 定義 |
|---|---|
| テナント | 契約企業ごとに分離されたデータおよび設定の単位 |
| ワークスペース | 従業員個人の作業画面 |
| **秘書エージェント** | 各従業員に専属で付く常駐エージェント。依頼の受付、照会、取次、記録、学習を担う |
| 業務エージェント | 特定業務を遂行するエージェント。秘書から起動されるか、メニューから直接起動される。「スキル」と呼ばれるものに当たる（第12.1.1節） |
| コネクタ | 外部の業務システム（freee など）への接続。MCP サーバとして M2Office の外で動き、ツールを提供する |
| エージェント定義 | エージェントの目的・手順・利用ツール・入力フォーム・承認要件を記述したデータ |
| ペルソナ | 従業員の役割・権限範囲・応対スタイルの設定。秘書の振る舞いを規定する |
| **個人記憶** | 秘書が学習した、その従業員の働き方に関する情報。本人に閉じる |
| **組織知識** | 全社で共有される知識。規程、議事録、価格表、決定事項、定型手順 |
| **昇華** | 個人記憶を組織知識へ引き上げること。秘書がほかの人にも役立つものを選んで行う（第11.3節） |
| 拡張機能 | エージェント定義・コネクタ・資源をまとめた配布単位。「プラグイン」「アドイン」と呼ばれるものに当たる（第12.1.1節） |
| マーケット | 拡張機能を探して導入する画面 |
| ジョブ | エージェントに対する 1 件の依頼 |
| 実行（ラン） | ジョブを処理する 1 回の実行単位 |
| ステップ | 実行を構成する最小単位。LLM 呼び出し、ツール呼び出し、承認ゲートのいずれか |
| 承認ゲート | 次のステップへ進む前に人の明示的承認を必須とする制御点 |
| ツール | エージェントが呼び出す機能。内部ツールと MCP ツールがある。**画面・ヘルプ・仕様書では「ツール」と書き、「道具」とは書かない**（第 0.208.1 版。三浦さんの依頼で「道具」から改めた） |
| キャンバス | 画面中央の主作業領域。成果物・対話・フォームを表示する |
| 秘書のキャンバス | 画面右の、**秘書が結果を見せる**領域。いちばん新しい結果だけを出し、会話の履歴は並べない。折りたためる（第6.2節）。旧称「会話ペイン」「サッシパネル」 |
| MCP | Model Context Protocol。外部システムのツールを標準化して接続する規格 |
| クレジット | AI の利用量を顧客に示すための単位。内部的にトークン数と換算する（第21.2節） |
| BYOK | Bring Your Own Key。顧客が自社の LLM 契約（API キー）を設定して使う方式。AI の利用料は顧客が AI 事業者へ直接支払う（第21.3節） |
| 監査ログ | 誰が・いつ・何を根拠に・何を実行したかの不可変記録 |
| **ダッシュボード** | テナントの管理者が、利用者の状態と業務の流れをリアルタイムかつ視覚的に把握する画面（第6.7節）。運営側の画面（マスター管理画面）とは別のもの |
| **ヘルプセンター** | 使い方の記事を一覧・検索できる場所。業務の記事はエージェント定義から自動で作る（第6.10節） |
| **マスター管理画面** | M2Office 運営が、全契約企業（テナント）の割り当て・ライセンス・請求・稼働を一元的に管理する画面。運営バックヤード（第23章）の入口（第23.8節） |
| ライセンス | テナントとの契約内容。プラン・契約シート数・契約期間・支払条件の組（第23.8.5節） |
| 運営者 | マスター管理画面を使う M2Office 運営側の担当者。顧客テナントの利用者とは別に管理する |
