## 43. 意思決定支援（AI の討論で経営者の判断を支える。第 0.516.0 版で案、第 0.517.0 版で確定して段 1 を実装。Q-294〜Q-299、ADR-0121）

この章で決めること: **経営者が出したお題について、慎重の立場と推進の立場の 2 人の AI が討論し、判定の AI が結果をまとめて報告する**しくみ。
お題の受け方、材料の集め方（添付と社内のデータ）、討論の進め方とターン数の指定、**決着していない論点の深掘り**、**2 つの討論の突き合わせ**、**討論の順次の表示（ストリーム）**、**討論の推移（どんな論理を展開し、どこで流れが変わったか）の残し方と見せ方**、報告の形、AI の費用の抑え方、見せる範囲、外部の AI の扱い、データモデル、段階。

**この章は確定した**（2026-11-04 に三浦さんが、相談相手のいない中小企業の経営者のために、AI が経営層の代わりに討論して経営判断を支援するしくみの仕様を依頼した。同日、深掘りと突き合わせを足して「ほかは案のとおりで進めてください」と依頼し、第 0.517.0 版で確定した）。
「（案）」と書いた値は、確定のときに案のとおりとした値である。**中小企業の経営者の孤独な判断を支えることが目的であり、費用を抑えることより判断の質を優先する**（三浦さん「AI だからこそできる処理なので、いい結果を期待したい」）。方針の判断の記録は [ADR-0121](../docs/adr/0121-decision-debate.md)。

**決めるのは経営者である。** この章のしくみは判断の材料と論点の整理を出すだけで、AI が決めたり、決めたことを実行したりしない（第43.12節）。
人に判断を求めるのは社外への送信とお金の確定だけ、という方針（ADR-0028）は、AI が業務の中で決めてよいことの範囲であり、経営の判断そのものは経営者のものである。

### 43.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 大きな会社なら役員で議論することを、中小企業の経営者は 1 人で決めている。相談相手がいない | 慎重の立場と推進の立場の AI が、経営者の代わりに**賛否の両方から議論する** |
| 1 人で考えると、自分の思いつきに都合のよい理由ばかりが目に入る | 慎重の側が**反対の理由を本気で探し**、推進の側がそれに答える。どちらにも都合のよくない論点を残す |
| 議論の材料（売上・在庫・お客様の声・競合の動き）が散らばっていて、集める時間が無い | お題に要る**社内のデータを AI が自分で集め**、2 人が同じ材料で議論する |
| 議論が長くなると、結局どうすればよいかが分からない | 判定の AI が、論点ごとの整理・確かめていない前提・第三の案・進めるときの条件とやめる目安を**1 枚の報告にまとめる** |

#### 43.1.1 想定する会社と使う人

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・小規模事業者・店舗・士業。役員会や経営企画の部署が無い |
| 使う人 | 経営者（社長）。ほかに、経営者が共有した役員・幹部 |
| お題の例 | 「主力商品を 10% 値上げしたい」「2 店舗目を出すか」「営業の人を 1 人増やすか」「この取引先との取引を続けるか」「サブスクの料金を始めるか」 |

### 43.2 形: 内蔵の拡張（既定は切り）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「意思決定支援」（ID `decisions`） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 拡張機能は使うかどうかに関わらず同じ料金（第2.1.1節、ADR-0118）。AI の費用は会社の月の上限に数える（第43.8節） |
| 左のメニュー | 「意思決定支援」 |
| 利用範囲 | 拡張機能の「利用できる人」。**既定は管理者だけ**（Q-297） |

### 43.3 用語

| 用語 | 意味 |
|---|---|
| 相談 | 1 つのお題についての、材料集め・討論・報告のひとまとまり |
| お題 | 経営者が書いた元の文（「この商品の値上げを 10% 考えているが、いかがでしょうか？」） |
| 判断の問い | お題を AI が「何を決めるのか」の形に言い直したもの（「主力商品 A を、来月から 10% 値上げするか」） |
| 観点 | 判断の問いを考えるときに見る切り口（売上・粗利・客離れ・競合・ブランド・現場の手間など）。AI が決める |
| 慎重の役（エージェント A） | 判断の問いに**反対の立場**から、危うさ・見落とし・失敗したときの損を挙げる |
| 推進の役（エージェント B） | **賛成の立場**から、慎重の役の指摘に 1 つずつ答え、機会と得るものを挙げる |
| 判定の役（エージェント C） | どちらの立場にも立たず、討論を見届けて終わりを決め、報告をまとめる |
| ターン | 慎重の役と推進の役が 1 回ずつ発言すること（1 往復）。討論の回数はこの数で数え、相談ごとに指定できる |
| 材料 | 討論の前に集めた事実（添付・社内のデータ・会社の知識・会社情報）。番号を振り、発言は番号で根拠を示す |
| 本討論 | 判断の問い全体についての討論 |
| 深掘り | 本討論で決着しなかった論点 1 つだけに絞った、短い討論（第43.6.3節） |
| 突き合わせ | 同じ問いと材料で、始め方を変えた 2 つの討論を別々に行い、結果を比べること（第43.6.4節） |

### 43.4 相談の始め方

| 項目 | 規定 |
|---|---|
| 入口 | 「意思決定支援」の画面の「新しい相談」、または秘書への頼み（第43.10節） |
| 入れるもの | **お題の文だけが要る**。添付（任意）・ターン数（既定 10）・突き合わせ（既定は切り）を足せる |
| 判断の問いと観点 | AI がお題から作り、相談の画面の上に出す。**人に確かめを求めない**（ADR-0028）。違えば、討論の途中でも会話で直せる（「値上げは 10% ではなく 8% で考えて」） |
| お題がはっきりしない | 何を決めるのかが読み取れないときだけ、秘書と同じく 1 つだけ聞き返す（「どの商品の値上げですか？」）。分かることは聞かない |
| 討論の向き | お題が「やりたい」形でも「やめたい」形でも、推進の役は**お題の案を進める側**、慎重の役は**進めない側**に立つ |

### 43.5 材料を集める

討論の前に、判断の問いと観点に要る材料を、**AI が自分で選んで集める**（人に材料を選ばせない。ADR-0028）。2 人の役は同じ材料で議論する。

#### 43.5.1 添付

| 項目 | 規定 |
|---|---|
| 受けるもの | PDF・Excel・CSV・Word・画像（PNG・JPEG）・Google ドキュメント／スプレッドシート（ドライブから選ぶ）。試算表・決算書・見積・企画書・お客様の声の一覧など |
| 数と大きさ | 1 つの相談に 10 個まで、1 つ 20 MB まで（案） |
| 読み方 | 文書を扱う共通ツール（第9.4.1節。`pdf.extract`・`sheet.read`・画像の読み取り）で読み、要約と、討論に要る数（表の形のまま）を材料にする。読めなかったものは「読めなかった」と材料の一覧に出す（推測で埋めない） |
| 途中で足す | 討論の途中でも足せる。足した材料は次の発言から使う |

#### 43.5.2 社内のデータ（Q-296）

| 出どころ | 材料にするもの（例） |
|---|---|
| 会社情報（第6.6.1節） | 業種・所在地・人数の目安・創業の年 |
| 会社の知識（第11章） | 規程・サービスと料金の説明・方針（知識の検索。出典つき） |
| 販売の書類と受注（第42章） | 商品・取引先ごとの受注と売上の推移（月ごとの集計）、値引きの傾向 |
| 在庫管理（第29章） | 在庫の量・回転・欠品、仕入れの値の推移、売れ行きの予測 |
| 会員とポイント（第40章） | 会員の数と増減、来店・購入の回数の分布（個人は渡さない。集計だけ） |
| 問い合わせの記録（第33章） | 問い合わせの種類と件数、不満の傾向 |
| Webの分析（第34章）・競合の分析（第36章） | 直近のレポート（アクセスの推移・競合の値上げや新しいサービスの動き） |
| 契約の管理（第38章） | 関係する契約の期限・更新・解約の条件 |
| Google ドライブ | お題に関係しそうな文書を、頼んだ人が見られる範囲で検索して読む |

| 項目 | 規定 |
|---|---|
| 選び方 | 入っている拡張の読み出しのツール（危険度 `read`）のうち、判断の問いに関係するものを AI が選んで呼ぶ。入っていない拡張は使わない |
| 権限 | **相談を始めた人の権限で読む**。その人が見られないデータは材料にしない |
| 人事・給与 | **使わない**。人事区画（第30章）の中身は、相談を始めた人が区画の人でも材料にしない（報告を共有したときに、区画の外の人へ漏れるため）。人の数が要るときは、会社情報の人数の目安を使う（案。Q-296） |
| 個人の情報 | お客様・社員の個人を特定する情報は材料に入れない。集計と傾向だけにする |
| 量 | 材料は相談ごとに要約し、討論に渡す材料の文は 8,000 字までにする（案。第43.8節）。元の数は材料の番号から開ける |
| 足りないとき | 判断に要るのに無い材料（原価・粗利など）は、「材料に無いもの」として一覧に出し、報告の「確かめていない前提」に残す |

### 43.6 討論の進め方

| 項目 | 規定 |
|---|---|
| 順番 | 材料集め → 本討論（慎重の役 → 推進の役 → … を繰り返す）→ 深掘り（第43.6.3節）→ 判定の役の報告。突き合わせを使うときは、本討論と深掘りを 2 つ同時に行い、最後に突き合わせる（第43.6.4節） |
| 最初の発言 | 慎重の役は、判断の問いの危うさを観点ごとに挙げる。推進の役は、それに 1 つずつ答え、機会を挙げる |
| 2 回目からの発言 | 相手の直前の発言に答える。**同じことを繰り返さない**。新しい論点か、相手への反論か、材料による裏づけを出す |
| 根拠 | 数は材料にあるものだけを使い、材料の番号を付ける。材料に無い数を言うときは「推測」と書く（取得に失敗した値を推測で埋めない、と同じ扱い） |
| 立場を保つ | 2 人は、材料で裏づけられたときだけ相手の主張を認める。**議論のために相手に合わせない**（AI は相手に同調しやすいため、役の指示で強く求める） |
| 1 回の発言 | 600 字まで（案）。**主張の単位に分けて書く**（第43.6.2節） |
| 途中のまとめ | 判定の役が、3 ターンごとに論点の表（出た論点・どちらが優勢か・残った問い）と、主張ごとの状態（第43.6.2節）を更新する。画面にも出す |
| 人の割り込み | 経営者は討論の途中で一言足せる（「原価はここ 1 年上がっていない」「競合は先月値上げした」）。**事実の訂正・材料の追加として扱い**、次の発言から使う。人の発言も討論の記録に残す |
| 止める | 経営者はいつでも「止める」を押せる。そこまでの討論で判定の役が報告をまとめる |

#### 43.6.1 ターン数と早めの終わり（Q-294）

| 項目 | 規定 |
|---|---|
| ターン数 | **相談ごとに数で指定する**（1〜30 ターン）。本討論と深掘りを合わせた数（第43.6.3節）。**既定は 10 ターン**（三浦さんが決めた）。秘書への頼みでも「15 ターンで討論して」と言える。討論の途中で、残りを増やす・減らすこともできる |
| 早めの終わり | 指定したターン数は上限として扱う。判定の役が、**2 ターン続けて新しい論点も新しい根拠も出なかった**と見たら、指定の前でも本討論を終え、残りのターンを深掘りに回す。論点が出尽くした後の繰り返しで費用を使わないため。終えた理由と、そう見た根拠（どの 2 ターンで新しい主張が無かったか）を討論の記録に残し、画面に出す |
| 費用で終わる | 1 つの相談の AI の費用が、実行ごとの上限（業務の定義の `limits`。第6.6.2節）に当たったら、そこで終えて報告をまとめる |
| 続ける | 報告の後に「続ける」（ターン数を指定して討論を足す。既定は 10）と「この論点を掘り下げる」（論点を 1 つ選んで、その論点だけで討論する）ができる |
| 記録 | 終わった理由（指定のターン数・出尽くした・人が止めた・費用の上限）を報告に書く |

#### 43.6.2 発言の形と推移の記録（第 0.516.0 版。三浦さんの指示）

**討論の推移は、報告と同じくらい大事な成果である**（2026-11-04 に三浦さんが「どんな論理を展開したかなど、ディベートの推移が非常に大事」と指示した）。
経営者が、結論だけでなく「どの主張に、どの材料でどう反論し、どこで流れが変わったか」をたどれるように、発言を**主張の単位**で記録し、主張どうしのつながりを残す。

| 項目 | 規定 |
|---|---|
| 主張 | 1 回の発言は 1〜4 個の主張からなる。主張ごとに番号を振る（`A3-2` は慎重の役の 3 ターン目の 2 つ目、`B3-1` は推進の役、`人2` は人の割り込み） |
| 種類 | **新しい論点**・**反論**（相手の主張を崩す）・**再反論**（反論を崩す）・**裏づけ**（自分の側の主張に材料を足す）・**譲歩**（相手の主張を認める。理由を必ず書く）・**修正案**（条件を変えて案を直す。「全品ではなく 3 品だけ」） |
| 対象 | 新しい論点のほかは、**どの主張に向けたかを番号で示す**。新しい論点は、どの観点かを示す |
| 根拠 | 材料の番号・相手の主張の番号・「推測」のどれか（複数可） |
| 要旨 | 主張ごとに 1 行の要旨を、役が本文とは別に書く（推移の見せ方と、役に渡す主張の一覧に使う） |
| 状態 | 判定の役が、3 ターンごとと終わりに、主張ごとの状態を付ける: **立っている**（崩されていない）・**崩された**（どの主張で崩されたかを番号で）・**認められた**（相手が譲歩した）・**答えが無い**（相手が答えずに残った）。付け替えたら、その理由を 1 行残す |
| 論点 | 主張は観点ごとの論点に属する。判定の役が、論点ごとの優勢（慎重・推進・互角・決着前）を 3 ターンごとと終わりに付け、変わったときは**どの主張で変わったか**を残す |
| 分かれ目 | 判定の役が、終わりに、**議論の流れを変えた主張を 3 つまで**選び、変わる前と後の優勢と一緒に残す |
| 形の確かめ | 役の出力の形（主張・種類・対象・根拠・要旨）は基盤が確かめる。崩れていたら、その発言だけを 1 回書き直させる。対象の番号が無い主張を指していたら、対象を外して「新しい論点」として残す（推測でつながりを作らない） |
| 本文 | **すべての発言の全文を残し、画面で略さない**。費用を抑えるための絞り込み（第43.8節）は役に渡すものだけで、記録と表示には及ばない |

#### 43.6.3 決着していない論点の深掘り（第 0.517.0 版。三浦さんが足した）

同じ 2 人で長く話し続けても、新しい論点は出ず、AI は相手に同調しやすくなる。**ターンは長さではなく深さに使う。**
本討論で決着しなかった論点を、判定の役が選び、その論点だけに絞った短い討論を自動で行う。

| 項目 | 規定 |
|---|---|
| 配り方 | 指定したターン数を、本討論と深掘りで分けて使う。本討論は**指定の 7 割まで**（切り上げ。10 なら 7）。本討論が早めに終わったら、残りをすべて深掘りに回せる |
| 選ぶ論点 | 本討論の終わりに、判定の役が、優勢が「互角」「決着前」の論点と、「答えが無い」主張が残った論点から、**判断への影響の大きい順に 3 つまで**選ぶ |
| 1 つの深掘り | 判定の役が、まず「この論点で決着させたい問い」を 1 行で示す（「値上げ後 3 か月の客離れは 5% を超えるか」）。残りのターンを論点の数で分け、その論点だけで討論する。役には、その論点の主張の一覧を全文で渡す |
| 早めの終わり | 深掘りごとに、1 ターン新しい主張が無ければ終える |
| 結果 | 深掘りの終わりに、判定の役がその論点の優勢と決め手の主張を付け直す。本討論から変わったら、分かれ目の候補にする |
| 選ぶ論点が無い | すべての論点が決着していれば、深掘りをせずに報告へ進む（残りのターンは使わない） |
| 少ないターン | 指定が 3 ターン以下なら深掘りをしない（本討論だけ） |
| 番号と見せ方 | 主張の番号は続きの番号（`A8-1`）。論点の流れの同じ列に「深掘り」の区切りを入れて続け、発言の順にも「深掘り: 客離れ」の見出しを挟む |
| 人が選ぶ | 報告の後の「この論点を掘り下げる」は、これと同じ形で、人が論点を選び、ターン数を指定する |

#### 43.6.4 2 つの討論の突き合わせ（第 0.517.0 版。三浦さんが足した）

1 回の討論の見立ては、始め方の偶然に左右されうる。**同じ問いと材料で、始め方を変えた 2 つの討論を別々に行い、結果を比べる。** 見立てがそろえば確からしく、割れればそこが本当の争点である。

| 項目 | 規定 |
|---|---|
| 使うか | 新しい相談で「突き合わせ」を入れたときだけ使う（**既定は切り**。AI の費用がおよそ 2 倍になるため）。秘書への頼みでも「突き合わせて」と言える |
| 2 つの討論 | 討論 1 と討論 2 を同時に動かす。材料・判断の問い・観点は同じ。討論 2 は始め方を変える: **推進の役から先に話す**、観点を逆の順に挙げる |
| 別々に | 2 つの討論は互いの発言を見ない。判定の役も、それぞれの途中のまとめと深掘りを別々に行う |
| ターン数 | 指定したターン数は、それぞれの討論の数（10 なら 10 ターンずつ）。深掘りもそれぞれで行う |
| 主張の番号 | 討論 2 の主張には `2:` を付ける（`2:A3-1`） |
| 突き合わせ | 2 つが終わったら、判定の役が比べる: 見立てがそろったか、論点ごとの優勢が一致したか、片方にしか出なかった論点、割れた論点と、割れた理由（どの主張の差か） |
| 報告への使い方 | 両方の見立てがそろえば「2 つの討論で同じ見立て」と書く。割れたら見立てを「割れた」とし、**割れた論点を「本当の争点」として報告の上のほうに出す**。報告は 1 つにまとめる |
| 割り込み | 人の割り込みは両方の討論に届ける（事実の訂正なので） |

### 43.7 報告（判定の役）

判定の役は、**どちらの立場にも立たず、材料の裏づけの強さで論点を比べる**。両方の言い分を足して 2 で割らない。

| 報告の欄 | 中身 |
|---|---|
| 見立て | 一言（「条件つきで進めてよい」「見送るのが妥当」「材料が足りず決められない」など）と、そう見た理由を 3 行まで。**決めるのは経営者**であることを前提に書く。突き合わせを使ったときは、2 つの討論でそろったか割れたかも書く |
| 本当の争点 | 突き合わせを使ったときだけ。2 つの討論で優勢が割れた論点と、割れた理由（第43.6.4節） |
| 議論の流れ | 論点ごとに、どの主張から始まり、どの反論・再反論・譲歩で動き、どう決着したか（または残ったか）を、主張の番号つきの数行で書く。深掘りした論点は、深掘りで何が分かり、優勢がどう変わったかも書く |
| 分かれ目 | 流れを変えた主張（3 つまで）と、それで何が変わったか（第43.6.2節） |
| 論点の表 | 論点ごとに、慎重の役の主張・推進の役の主張・材料の裏づけ（材料の番号か「推測」）・どちらが強いか・決め手になった主張の番号 |
| 確かめていない前提 | 材料が無く推測で議論した点と、それを確かめる方法（「主力商品の原価を確かめる」「上位 10 社に事前に聞く」） |
| 第三の案 | 討論から出た、折衷や別の打ち手（「全品ではなく、利益の薄い 3 品だけ値上げ」「値上げと同時に付加価値を足す」） |
| 進めるなら | 条件・最初の一歩・見る数字・**やめる目安**（「3 か月で客数が 15% 以上減ったら戻す」） |
| 専門家に確かめること | 税・法務・労務に関わる点があれば、相談先（税理士・弁護士・社会保険労務士）と一緒に挙げる。断定しない |
| 材料の一覧 | 使った材料と出どころ、読めなかったもの、材料に無かったもの |
| 討論の記録 | 終わった理由、本討論と深掘りのターンの数、深掘りした論点、使った AI（社内・外部）、AI の費用の目安 |

### 43.8 AI の費用を抑える

| 項目 | 規定 |
|---|---|
| モデル | 慎重の役と推進の役は**標準**、判定の役（途中のまとめと報告）は**高性能**のモデル（第20.2.2節のモデルの選び方）。早めの終わりの見立ては**高速** |
| 渡すもの | 各発言に渡すのは、判断の問い・観点・材料の要約（8,000 字まで）・途中のまとめ・**すべての主張の一覧**（番号・種類・対象・要旨・状態。本文は入れない）・**直近 2 ターンの発言の本文**。前の主張にも番号で答えられるので論理のつながりは切れず、ターンが増えても 1 回の発言の費用は大きく膨らまない |
| 突き合わせ | 使ったときは、AI の費用がおよそ 2 倍と少しになる（2 つの討論と突き合わせ）。既定は切りにして、大きな判断のときに使う |
| 数え方 | AI の利用の記録（第6.6.2節）に、用途「意思決定支援」で残し、会社の月の上限と 1 人の上限に数える |
| 目安 | 報告に、その相談の AI の費用の目安を出す。始める前に費用を見せて確かめることはしない（ADR-0028。上限で止まる） |
| 上限に当たったとき | 会社か 1 人の月の上限に当たったら、新しい相談は始めず、討論の途中なら第43.6.1節の「費用で終わる」と同じく、そこまでで報告をまとめる |

### 43.9 見せる範囲（Q-297）

| 項目 | 規定 |
|---|---|
| 既定 | **始めた人だけ**が見られる（経営の相談には、人員・取引先・お金の話が入るため） |
| 共有 | 始めた人が、名前を挙げて会社の人に共有できる（見るだけ）。「会社で共有」は置かない |
| 管理者 | ほかの人の相談の中身は、管理者でも見られない（件数と AI の費用だけが利用状況に出る） |
| 消す | 始めた人が消せる。消したものはゴミ箱に 30 日置き、その後に消す |

### 43.10 秘書から使う

| 依頼の言い方の例 | 動き |
|---|---|
| 「値上げを 10% 考えているけど、どう思う？ 討論して」「2 店舗目を出すか相談したい」 | 相談を始め、「討論を始めました。終わったらお知らせします」と答える。終わったら報告の見立てと、相談の画面へのリンクを知らせる |
| 「この見積書も材料に足して」 | 直前の相談に添付を足す |
| 「さっきの相談、原価は上がっていないよ」 | 討論中なら割り込み、終わっていれば材料に足して「続ける」 |
| 「さっきの相談の結論は？」「やめる目安は？」 | 報告から答える |
| 「客離れの点をもっと議論して」 | 「この論点を掘り下げる」 |
| 「出店の件、突き合わせで討論して」 | 突き合わせを入れて相談を始める |

| 項目 | 規定 |
|---|---|
| 振り分け | ただの「どう思う？」は秘書が自分で答える。**「討論して」「相談したい」「賛否を出して」**、または経営の判断の問い（値上げ・出店・採用・撤退・取引の見直し）に関わる頼みで、拡張が入っていれば、相談として始める |
| ツール | `decisions.start`（危険度 `write-internal`。相談を始める）、`decisions.add_material`（`write-internal`）、`decisions.interject`（`write-internal`）、`decisions.find`（`read`。報告を引く） |

### 43.11 画面

| 新しい相談 | お題の入力欄 1 つ・添付（置く・選ぶ）・ターン数（数の欄。既定 10）・突き合わせ（スイッチ。既定は切り）・「始める」 |

| 報告 | 討論が終わったら、相談の画面の上に報告を出す（第43.7節の欄の順）。「続ける」「この論点を掘り下げる」「共有」 |

#### 43.11.1 討論の推移の見せ方（第 0.516.0 版。三浦さんの指示）

討論の推移を、3 つの見せ方で切り替えて見られるようにする。どの見せ方でも、主張を押すと本文と根拠の材料を開き、つながった主張へ移れる。

| 見せ方 | 中身 |
|---|---|
| 論点の流れ（既定） | 論点ごとに 1 列。論点を立てた主張から、反論・再反論・裏づけ・譲歩・修正案を、**つながりの線**で順にたどれる形で並べる。返しが 1 つだけ続くあいだは字下げせずに縦に続け、返しが分かれたときだけ下げる（2 段まで）。応酬が長く続いても列の幅が狭くならないようにする（どの主張への返しかは「↩ 番号」で示す）。主張は要旨・種類（色と印）・根拠（材料の番号・「推測」）・状態（崩された主張は線で消し、どの主張で崩されたかを添える）。列の終わりに論点の決着（「推進が優勢: B4-1 が材料 5 で客離れの懸念を崩した」）。**答えが無いまま残った主張**は目立たせる |
| 発言の順 | 発言をターンの順に**全文**で並べる。慎重の役と推進の役を左右に分け、人の割り込みと判定の役の途中のまとめを間に挟む。主張ごとに種類と対象の印（「↩ A2-1 への反論」）を付け、対象を押すとその主張へ移る。反論を受けた主張には「反論 2 件」を付け、そこから返しへ移れる |
| 優勢の推移 | 行が論点、列が途中のまとめの区切り（3 ターンごと）と終わりの表で、論点ごとの優勢（慎重・推進・互角・決着前）の移り変わりを色で見せる。優勢が変わったところには、変えた主張の番号を出す。**どこで流れが変わったかが一目で分かる**ようにする |
| 分かれ目 | 3 つの見せ方のどれでも、分かれ目に選ばれた主張に印を付ける。報告の「分かれ目」から押すと、その主張へ移る |
| 討論中 | 第43.11.2節のとおり、発言を書かれるそばから流して見せる。途中のまとめのたびに、主張の状態と優勢の推移が更新される |
| 全文 | **AI の発言はすべて全文で見られる**。発言の順は既定で全文を出す。論点の流れと優勢の推移では、主張を押すとその発言の全文を開く。判定の役の途中のまとめ・早めの終わりの見立て・報告も全文を残して見せる。書き直させた発言（第43.6.2節「形の確かめ」）は、書き直した後のものを出し、書き直したことを印で示す |
| 深掘り | 論点の流れでは同じ列に「深掘り」の区切りと、決着させたい問いを入れて続ける。優勢の推移の表では、本討論の終わりの後に深掘りの列を足す |
| 突き合わせ | 「突き合わせ」の見せ方は、行が論点、列が討論 1 と討論 2 の終わりの優勢の表。割れた論点を目立たせ、押すと両方の討論のその論点の流れを並べて見せる |
| 狭い画面 | 論点の流れは論点ごとに縦に積み、論点の見出しで畳める。優勢の推移の表は横に送れる |

#### 43.11.2 順次の表示（ストリーム。三浦さんの指示）

討論は数分かかるので、**結果だけを最後に出すのではなく、進むそばから順に見せる**（2026-11-04 に三浦さんが指示した）。

| 項目 | 規定 |
|---|---|
| 流すもの | 材料集めの進み（どの出どころを読んでいるか、集めた材料が 1 つずつ並ぶ）→ 判断の問いと観点 → 各発言（**書かれるそばから文字を流す**）→ 判定の役の途中のまとめ → 報告（これも流す） |
| 発言の流し方 | 役は、主張ごとに見出しの行（番号・種類・向けた主張・根拠）を書いてから本文を書く形で出す。見出しの行が届いたら主張の枠と印を出し、本文を流す。要旨は発言の終わりにまとめて書く。発言が終わったら、つながり（論点の流れの線）と状態を付ける |
| いまの様子 | 画面の上に、いま誰が話しているか（「慎重の役が考えています」など）と、何ターン目か（「4 / 10 ターン」「深掘り 1 / 2: 客離れ」）を出す |
| 突き合わせのとき | 2 つの討論を同時に流す。切り替えで見ている討論を流し、もう一方は進み（何ターン目か）だけを出す |
| 推論のストリーム | 推論の口（第20.2節の抽象化層）に、文を少しずつ受け取る呼び方を足す（Gemini は `streamGenerateContent`、ローカル LLM は OpenAI 互換の `stream`）。AI の利用の記録は、発言が終わったときに数える |
| 動く場所と届け方 | 討論はワーカーで動かす（画面を閉じても続け、API の再起動で途切れない）。ワーカーは書きかけの発言を 0.5 秒ごとに記録へ書き足し、データベースの知らせで API に伝える。画面は `GET /v1/decisions/{id}/stream`（SSE。第8.4節）で差分を受け取る |
| 開き直したとき | 画面を閉じて開き直したり、通信が切れてつなぎ直したりしたら、それまでの記録を出してから、書きかけの発言の続きを流す（どこまで受け取ったかを番号で示し、抜けも重なりも出さない） |
| 終わったとき | 画面を開いていなければ、終わったことを本人に知らせる（お知らせと秘書。第43.10節） |
| 割り込みと止める | 流している間も割り込みと「止める」を受ける。止めたら、書きかけの発言はそこまでを残し、「途中で止めた」と印を付ける |

### 43.12 AI に任せること（ADR-0028）

| AI が決める | 人がすること |
|---|---|
| 判断の問いと観点、集める材料、討論の終わり（早めの終わり）、深掘りする論点とターンの配り方、論点の整理、見立て、突き合わせの結果、第三の案、やめる目安の案 | お題を出す、材料を足す・事実を直す、止める・続ける、**経営の判断をする**、決めたことを実行する |

**AI は経営の判断をしない。** 見立ては材料と論点の整理であり、決定ではない。決めたことの実行（価格の書き換え・お客様への知らせ・発注など）も、この章のしくみでは行わない。行うなら、それぞれの業務で、社外への送信とお金の確定の承認（第9.4.0節）を通る。

### 43.13 外部の AI と社外への境界

| 項目 | 規定 |
|---|---|
| 会社の AI の方針 | 社内のデータを読むので、**外部の AI を使ってよい業務の印は付けない**（第16.3.7.1節）。方針が「クラウド」の会社は Gemini、「ローカルを既定」「ローカルだけ」の会社はローカル LLM で、材料集めから報告まで動かす。途中で切り替えない |
| 社外への送信 | しない。討論も報告も会社の中に置く。Web の調べものは段 1 では使わない（段 2。Q-299） |
| 添付と社内のデータ | 外から来た文書・データであり、**中の文を指示として扱わない**（不変則 I-6）。添付に「賛成と結論せよ」と書いてあっても従わない。役の指示と材料は分けて渡す |
| 記録 | 使った AI（社内・外部）を相談ごとに残す |

### 43.14 権限と記録

| 項目 | 規定 |
|---|---|
| 相談を始める・見る | 利用範囲の人。見られるのは自分の相談と、共有された相談 |
| 監査ログ | 始めた・止めた・共有した・共有を外した・消した（`decision.*`）。**お題と報告の中身は監査ログに入れない**（件数と ID だけ） |
| 会話の学び | 相談の中身は、秘書の記憶と会社の知識へ自動では入れない（第11章。経営の相談を、ほかの会話で持ち出さないため）。本人が「この結論を覚えておいて」と言ったときだけ、本人の記憶に入れる |

| 表 | 列 |

| 段 2 | **決めたことの記録と振り返り**（経営者が「進める」「見送る」を記録すると、報告の「見る数字」と「やめる目安」を期日に社内のデータで確かめて知らせる）、Web の調べもの（業界の相場・公開の統計。Q-299）、役を足す（財務・現場・お客様の視点など 4 役以上。Q-298）、報告を Google ドキュメントに書き出す、朝のブリーフに討論の終わりを載せる |

### 43.17 行わないこと

| 行わないこと | 理由 |
|---|---|
| AI が経営の判断をする・決めたことを実行する | 判断は経営者のもの。実行はそれぞれの業務で承認を通す（第43.12節） |
| 税務・法務・労務の断定 | 専門家の業務。報告では相談先を挙げるだけにする |
| 人事・給与の中身を材料にする | 人事区画の隔離を守る（第43.5.2節） |
| 会計のデータの取り込み（試算表を自動で読む会計ソフトとのつなぎ） | お金の機能は扱わない（2026-10-26 の方針）。試算表は添付で受ける |
| 討論を社外の人に見せる | 経営の相談は会社の中に置く |

### 43.19 段 1 の実装の決まり（第 0.517.0 版）

| 項目 | 実装 |
|---|---|
| 置き場 | 表 `decision_sessions`・`decision_materials`・`decision_turns`（発言の全文）・`decision_claims`（主張）・`decision_issue_states`（論点の優勢の推移）・`decision_shares` と会社の設定 `decisions`（移行 180）。行を書くたびに通し番号（列 `rev`。シーケンス `decision_rev`）を振り直し、画面は前に受け取った番号より大きい行だけを受け取る。`packages/core/src/decisions/store.ts` |
| 討論を進める | `packages/core/src/decisions/engine.ts`（`DecisionEngine`）。進み具合は置き場から作り直す（書きかけの発言は消して書き直す）ので、止まったワーカーの相談は別のワーカーが続きから受け持つ。ワーカーの `DecisionRunner` が 2 秒ごとに相談を受け持ち、裏で進める（同時に 3 つまで。受け持つ印は 30 秒ごとに新しくし、90 秒より古い印は受け持ち直す） |
| 発言の形 | 主張ごとの見出しの行 `【A3-1｜反論｜対象 B2-2｜論点 客離れ｜根拠 材料 4・推測】` と本文、終わりに `要旨:` の行（`format.ts`）。番号が違えば頭から振り直し、無い主張を指す返しは対象を外して「新しい論点」にする。崩れていたら 1 回だけ書き直させ、それでも読めなければ発言の全文を 1 つの主張として残す。返しの主張は、向けた主張の論点に属する |
| 早めの終わり | 判定の役の推論ではなく、主張の形から決まりで見る: そのターンに「新しい論点」「修正案」も、まだ使っていない材料の番号を根拠にした主張も無ければ、そのターンは新しくない。本討論は 2 ターン続けて、深掘りは 1 ターンで終える（推論を呼ばずに済み、理由を数で示せる） |
| 判定の役 | 途中のまとめ・深掘りの選び・突き合わせは JSON で返させ、主張の状態・論点の優勢・分かれ目を記録に入れ、読める文にした「まとめ」を発言として残す（全文を見せる）。報告は `## 見出し` の形で書かせ、書かれるそばから流してから見出しで分ける。見立ては「見立て」の 1 行目。論点の表は、判定の役に書かせず、記録（主張と優勢）から画面が作る |
| 材料集め | 付属の業務「意思決定支援の材料集め」（`decisions:gather`）を、相談を始めた人の依頼として業務の実行で動かし、終わるまで待つ（2 秒ごと、12 分まで）。利用範囲・会社の AI の方針・監査の記録をそのまま守る。持つツールは会社の知識・販売・在庫・問い合わせ・競合・Webの分析・契約・ドライブ・添付を読むものだけで、**人事・給与と、会員の個人を返すツールは持たない**（会員の集計は、集計の口ができるまで使わない）。集められなかったときは会社情報だけで討論し、集められなかったことを「材料に無いもの」に残す |
| お題が読み取れないとき | 画面から始めた相談では聞き返さず、読み取れなかった点を終わりの説明に残して進める（判断の問いは画面の上に出るので、違えば一言で直せる）。秘書からの頼みは、秘書がお題を確かめてから始める |
| 推論 | 会社の推論（`llmFor`。ローカルの方針の会社ではローカル AI）を相談の始めに決め、最後まで変えない。推論の口に、文を少しずつ受け取る呼び方 `completeStream` を足した（Gemini の OpenAI 互換の窓口とローカル AI の `stream: true`。`llm/stream.ts`）。使った量が応答に無いときは文字数で多めに見積もる。AI の利用は、相談を始めた人の分（用途 `worker:decisions`）として記録と上限に数える |
| 費用の上限に当たったとき | 上限のため推論を呼べないので、報告はまとめられない。「止めた」にし、上限に当たったことと報告をまとめられなかったことを終わりの説明に残す（推測で埋めない） |
| 順次の表示 | ワーカーは書きかけの発言を 0.5 秒ごとに置き場へ書き足す。API の `GET /v1/decisions/{id}/stream` は 0.5 秒ごとに差分を読み、変わったものだけを送る（`id` に通し番号。15 秒ごとに合図。30 分で閉じ、画面がつなぎ直す）。データベースの知らせ（LISTEN/NOTIFY）は使わず、読み直しで足りるとした |
| 画面 | `packages/web/src/Decisions.tsx`。左のメニュー「意思決定支援」、道は `/decisions` と `/decisions/{id}`。動いている間だけ差分を受け取る |
| 秘書 | 付属の業務「意思決定支援」（`decisions:consult`）とツール `decisions.start`・`add_material`・`interject`・`find`。「？」を含む頼みは照会として扱われるので、作業を頼む言い回しに「討論」「議論して」「賛否を」「相談したい」「突き合わせ」を足した（第10.9.4.1節） |
