## 31. 店頭サイネージ（第 0.165.0 版、ADR-0051。案。段 1・段 2 の実装の決まりと、2026-09-30 の三浦さんの決定を足した草稿。段 1 は第 0.190.0 版、段 2 は第 0.191.0 版で実装。実装で決まりから変えたことは第31.16.2節）

この章で決めること: 店頭・待合に置いた画面に画像・動画・HTML を流し、スタッフ・秘書・外のシステムからの依頼で案内を割り込ませる、
小さなサイネージのしくみ。形（内蔵の拡張）、画面の登録、通常の流し、割り込み（ジングルつき）、割り込みの入口、画面の側のページ、
人の情報と社外への境界。段 1・段 2 の実装の決まり（各節の「段 N の…の決まり」、第31.15節のデータモデルと API、第31.16節の段階）。

**この章は案である。** **汎用のサイネージとして作る。** 特定の導入先・業種の条件に合わせた作りにしない（三浦さんの方針）。
会社ごとの違いは、**導入のときに会社が設定する項目**（第31.4節）で吸収する。残りの確かめる事項（第31.17節）の答えで直してから実装する。
**「（案）」と書いた値は、会社（三浦さん）の判断を待つ値である。** 決まったら「（案）」を外す。

**2026-09-30 に三浦さんが決めたこと**

| 決めたこと | 中身 | 節 |
|---|---|---|

| 画面の数 | **1 台の端末に 1 画面。1 社で 3 台まで。** 縦と横の両方（Q-141） | 第31.1.1節・第31.4節 |
| 料金 | **料金を取らない。標準の機能に含める**（「こんなレベルのサイネージはお金を取る対象じゃない」。Q-141） | 第31.2節 |
| 素材 | **画像（JPEG・PNG）・動画（MP4）・HTML・PowerPoint（アニメーションつき）** | 第31.6節 |
| 読み上げ | **声は出さない。** 代わりに注意を引く短い音（ジングル）を出す（Q-139） | 第31.7.3節 |
| 会話の記録 | 秘書に頼んで割り込みを出した会話の記録は、**ふつうの会話と同じに扱う**（24 時間で消さない） | 第31.13節 |

### 31.1 目的と位置づけ

小さな店・医院では、店頭や待合に画面を置き、お知らせや案内を出したいという声が多い。
これまでの製品は多数の画面を前提にした大規模向けで、**機能が多すぎて運用が続かない**。

| 痛み | M2Office で行うこと |
|---|---|
| 設定が多くて使いこなせない | 画面は 1 社 3 台まで、流すものは素材（画像・動画・HTML）の並びだけにする。画面の分割・予定表・天気の帯などは持たない（第31.18節） |
| 画面の登録が面倒 | 画面に出る QR をスマホで読むだけで登録する（第31.5節） |
| 呼び出しに別の仕組みが要る | **流している途中に、案内を割り込ませる**（「12番の患者様、レントゲン室にお入りください」「〇〇パンが焼き上がりました」）。ジングルを鳴らし、15 秒ほどで元の流れに戻る（第31.7節） |
| 受付のシステムとつながらない | 外のシステムから呼べる受け口を持つ（第31.8節）。スタッフのスマホと秘書からも呼べる |

#### 31.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 業種 | 店舗・飲食・医院・美容など、店頭か待合に画面を置く業種 |
| 画面 | **1 台の端末に 1 画面。1 社で 3 台まで**（2026-09-30 決定。第31.4節）。16:9 の横（1920×1080）と縦（1080×1920）の両方 |
| 端末 | 小型の Windows PC。Chrome か Edge のキオスクで開き、有線 LAN か Wi-Fi でつなぐ（2026-09-30 決定。Q-137。第31.9.1節） |
| 流すもの | 画像（JPEG・PNG）・動画（MP4）・HTML。PowerPoint は動画にして流す（案。第31.6.4節） |
| 使う人 | 流すものを変える人（店長など）と、割り込みを出すスタッフ |
| 使い方の例 | ふだんは設定した素材を繰り返し流す。パンが焼き上がったら、そのパンの画像と案内（HTML）をすぐに割り込ませる。順番待ちで「12 番でお待ちの方、入り口にお進みください」と出す（どれも汎用の例） |

### 31.2 形: 内蔵の拡張（既定は切り）

サイネージは、画面の登録・素材の置き場・画面の側で動くページを持つ。拡張機能（第12.10.1節）では作れないため、
在庫管理（第29章）と同じく**内蔵の拡張**（第12.13節）として作る。

| 項目 | 規定 |
|---|---|
| 入り切り | 管理者ページの「拡張機能」に「公式・内蔵」として並べ、会社ごとに入り切りする。**既定は切り** |
| 利用範囲 | ほかの拡張機能と同じく、使える人をグループや人で絞れる（第16.7.3節） |
| 画面 | 左ペインの「業務」の並びに「サイネージ」を置く（第6.1.1節）。スタッフ用のスマホのページ（`/m/signage`）を持つ（第31.9節） |
| 範囲 | 画面と素材は**会社で共有**する |
| 課金 | **料金を取らない。標準の機能に含める**（2026-09-30、三浦さんが決定。Q-141）。入り切りは残し、使う会社だけが入れる |
| 切ったとき | 画面・ツール・受け口を止める。**画面の登録・素材・流れは消さない**（入れ直せば戻る。第12.13節）。登録した画面は無地の表示にし、鍵は残す（第31.9.1節） |

### 31.3 用語

| 用語 | 意味 |
|---|---|
| 画面 | 店頭・待合に置いた表示の端末 1 台。向き（横・縦）と名前（「入口」「待合」）を持つ |
| 素材 | 流す画像・動画・HTML の 1 つ |
| 流れ | 画面ごとの、素材の並び。最後まで流したら最初に戻る |
| 割り込み | 流れの上に全画面で重ねて出す案内。決めた秒数のあと、元の流れに戻る |
| 割り込みの素材 | 割り込みに使うために登録した画像か HTML（「〇〇パンが焼き上がりました」） |
| HTML の素材 | 会社が作った 1 つの HTML の文書。画像などを文書の中に入れ、外とは通信しない（第31.6.3節） |
| 文字の割り込み | 送られた文を、画面に合わせて大きな文字にして出す割り込み |
| ジングル | 割り込みを出すときに鳴らす、注意を引く短い音（ピンポーン）。声では読み上げない（Q-139） |
| 呼び出しの受け口 | 外のシステムから割り込みを頼むための URL（第31.8節） |
| 登録の番号 | 登録する前の端末が出す 6 桁の番号。10 分で切れる（第31.5.1節） |
| 画面の鍵 | 登録した端末だけが持つ、推測されにくい値。端末はこれで M2Office に名乗る（第31.5.1節） |
| 再生のページ | 端末のブラウザで開く `/signage/play`。ログインしない（第31.9.1節） |
| よく出す案内 | スタッフのページに自動で並ぶボタン（第31.9.3節） |

### 31.4 導入のときに会社が設定すること

設定は管理者ページの「拡張機能」のサイネージの欄に置く。**どれも既定のままで使える。** 変えたいときは、秘書に頼むか、その欄で変える。

| 項目 | 既定 | 規定 |
|---|---|---|
| 画面の数の上限 | 3 | **1 社で 3 台まで**（2026-09-30 決定）。1 台の端末に 1 画面。全社共通の決まりで、会社は変えられない |
| 素材の容量の上限 | 会社の合計で 2 GB（案） | 標準の機能の範囲の上限（Q-141）。会社は変えられない |
| 画像と HTML を出す秒数 | 10 秒 | 3〜120 秒。流れの 1 行ごとに変えられる |
| 割り込みを出す秒数 | 15 秒 | 5〜60 秒。割り込みごとに変えられる |
| ジングル | 入り。音は「ピンポーン」 | 割り込みごとに切れる。音は、M2Office が持つ音から選ぶか、会社が短い音のファイルを入れる（第31.7.3節）。割り込みの素材ごとにも音を変えられる。音の大きさは画面ごと |
| 呼び出しの言い回し | 「{番号}番の方、{場所}へお越しください」 | 番号と場所だけを送る受け口の文（第31.8.1節）。秘書に「言い回しを『〇番の患者様、〇〇にお入りください』にして」と頼めば変わる。人に表を作らせない |
| 場所の無い言い回し | 「{番号}番の方、お越しください」 | 番号だけが届いたときの文。直し方は上と同じ |
| 店の色 | 会社のロゴ（第6.6.1節）から決まった計算で選んだ色。ロゴが無ければ濃い青（案） | 文字の割り込みの背景に使う。秘書に「店の色を緑にして」と頼めば変わる |

| 項目 | 規定 |
|---|---|
| 変えたとき | すぐ画面に届く。いま出している割り込みは、そのままの見た目で終える |
| 記録 | 変えたことを監査ログに残す（第31.12節） |

### 31.5 画面の登録

| 項目 | 規定 |
|---|---|
| 登録の手順 | 端末のブラウザで再生のページ（`/signage/play`）を開くと、**6 桁の番号と QR** を出す。**管理者**がスマホで QR を読むか、管理の画面に番号を入れると、その会社の画面として登録される。番号は 10 分で切れる（第31.12節・第31.14節。登録は管理者だけ） |
| 画面の鍵 | 登録のときに画面ごとの鍵を発行し、端末に置く。M2Office は**鍵のハッシュだけを持つ**（予約の受け口と同じ。第29.13.1節）。端末でログインはしない |
| 向き | 登録のとき、端末の画面の縦横から横か縦を**自動で決める**。端末の側で縦にできない場合に備え、**ページの側で 90 度・180 度・270 度回せる** |
| 外す | 管理の画面で画面を外すと、鍵が効かなくなり、端末は登録の番号の表示に戻る |
| 画面の状態 | 画面は 1 分ごとに「生きている」ことと、いま出している素材を知らせる。管理の画面に、最後に通信した時刻と、いま出しているものの小さな見本を出す |
| つながらないとき | **ふだん動いている時間帯に 5 分つながらなければ、利用範囲の管理者に知らせる**（通知の種類「サイネージ」。第6.5.5節）。同じ画面について、つながるまで二度は知らせない |

#### 31.5.1 段 1 の画面の登録の決まり（第 0.189.0 版。案）

**端末は会社のアドレス（`https://{会社}.m2office.online/signage/play`）を開く。** 会社はアドレスで決まり、登録の番号はその会社の中だけで使う（案。第31.17節 #5）。

| 順 | 端末（再生のページ） | 管理者のスマホ・パソコン | M2Office |
|---|---|---|---|
| 1 | 鍵を持っていなければ、登録を始める。推測されにくい「登録の合言葉」を端末で作り、画面の縦横と一緒に送る | | 6 桁の番号を作り、合言葉のハッシュ・縦横・期限（10 分）と一緒に置く。番号を返す |
| 2 | 番号と QR を大きく出す。QR には `/m/signage/pair?code={番号}` の URL を入れる | | |
| 3 | 5 秒ごとに、合言葉で「登録されたか」を尋ねる | QR を読むか、管理の画面で番号を入れる。ログインしていなければログインし、終わったら戻る（第29.11.1節と同じ） | |
| 4 | | 開いたページに「登録する」だけを出す。名前と向きは尋ねない | 画面を作る。名前は「画面 1」「画面 2」のように自動で付け、向きは端末の縦横から決める。番号を「登録した」にする |
| 5 | 次に尋ねたとき、画面の鍵を受け取り、端末に置く | 登録した画面の名前・向き・回し方を、その場で直せる（直さなくてよい） | **このときに鍵を作り**、ハッシュだけを画面に置いて、鍵を 1 度だけ返す。番号は消す |
| 6 | 流れを読み、流し始める（第31.9.1節） | | |

| 項目 | 規定 |
|---|---|
| 番号 | 数字 6 桁。会社の中で、切れていない番号と重ならない。10 分で切れる。切れたら、端末は自動で新しい番号を出す（人の操作は要らない） |
| 作れる数 | 登録を待つ番号は、会社ごとに 5 つまで（超えたら古い番号から消す）。同じ接続元からは 1 時間に 20 回まで（超えたら断る。429） |
| 番号を入れ間違えたとき | 同じ人が 10 分に 5 回間違えたら、10 分入れられなくする（番号を当てずっぽうで探させない） |
| 上限 | 画面の数が上限（第31.4節）に達していたら登録しない。スマホに「上限に達しています」と、外せる画面の名前を出す |
| 画面の鍵 | 24 バイトの乱数を base64url にした 32 字（予約の受け口と同じ形）。ハッシュは SHA-256。**期限は無く、外すまで効く**。端末はブラウザの保存の場所に置く |
| 鍵の渡し方 | 端末は鍵を `Authorization: Bearer` の見出しで送る。**URL に載せない**（アクセスの記録に残るため） |
| 名前 | 20 字まで。会社の中で重ならない。使う人（利用範囲の全員）が直せる |
| 外す | 管理者が管理の画面か秘書で外す。**確認を挟まない**（ADR-0028）。鍵のハッシュを消し、その画面の即時の知らせの経路をすぐ切る。端末は次の問い合わせで鍵が効かないと知り、取り置きを消して登録の番号の表示に戻る |
| 間違えて外したとき | 同じ端末でもう一度登録する。**外してから 30 日以内の画面があれば、新しい画面を作らずに、いちばん最近外した画面として登録し直し、名前と流れを引き継ぐ**（尋ねない。違えば名前と流れを直す）。30 日を過ぎたら、外した画面の流れを消す |
| 盗まれた端末 | 画面を外せば、鍵はその場で効かなくなる。画面の鍵でできることは狭い（下の表）ため、鍵で割り込みを出したり、ほかの画面や会社のデータを読んだりはできない。端末に取り置いた素材は、店頭に出していた素材だけである |
| 記録 | 登録と外すことを監査ログに残す（第31.12節） |

**画面の鍵でできること**

| できる | できない |
|---|---|
| その画面の流れ・会社の割り込みの素材・再生に要る会社の設定（店の色・会社の名前）を読む | ほかの画面の流れ・状態を読む |
| その画面の流れの素材と、割り込みの素材の中身を読む | 割り込みを出す・消す、流れを変える、素材を足す |
| その画面の状態（生きている・いま出しているもの・音が出せるか・取り置けたか）を知らせる | 会社のファイル・人の情報・ほかの拡張のデータを読む |
| その画面の割り込みを受け取り、出し始め・出し終わりを知らせる（段 2） | 割り込みの文を後から読み返す |

**画面の状態と、つながらないときの知らせ**

| 項目 | 規定 |
|---|---|
| 生きている知らせ | 1 分ごと。いま出しているもの（素材か割り込み）・流れの版・取り置けた素材の数と取り置けなかった素材・音が出せるか・ページの版・端末の画面の縦横・取り置きの場所の空き（`navigator.storage.estimate()` で分かれば） |
| つながっていない | 最後の知らせから 3 分を過ぎたら、管理の画面で「つながっていない」と出す |
| ふだん動いている時間帯 | 画面ごとに、過去 14 日の生きている知らせから、**30 分ごとの時間帯**のうち、知らせがあった日が半分以上ある時間帯を「ふだん動いている」とする（決まった計算。推論を使わない）。記録が 3 日に満たない間は、日本時間の 7 時から 22 時をふだん動いている時間帯とする（案）。店を閉めて電源を切る夜に、毎晩知らせないため。人に営業時間を入れさせない（ADR-0028） |
| 知らせる | ふだん動いている時間帯に 5 分つながらなければ、通知の種類「サイネージ」で知らせる。**相手は利用範囲の中の管理者。いなければ会社の管理者**。同じ画面は、つながるまで二度は知らせない。つながったことは知らせない（管理の画面で分かる） |
| 見本 | いま出している素材の**縮小画像**を出す（端末の画面を写したものではない。第31.6.1節の縮小画像を使う）。割り込みを出している間は「割り込み中」と出し、文は出さない |

### 31.6 通常の流し

| 項目 | 規定 |
|---|---|
| 素材の形式 | 画像は JPEG・PNG（1 つ 20 MB まで）。動画は **MP4（H.264）**（1 つ 200 MB まで、長さ 10 分まで（案））。**HTML**（会社が作ったもの。第31.6.3節）。**PowerPoint** は動画にして入れる（案。第31.6.4節）。会社の合計の上限は Q-141 で決める |
| 変換 | サーバーで動画の形式を変えない（第31.18節）。H.264 でない動画は、読み込むときに断り、理由を伝える。画像は読み込むときに画面の大きさまで縮める（ブラウザで行う） |
| 流す時間 | 画像と HTML は既定で 10 秒（流れの 1 行ごとに変えられる）。動画は最後まで流す。**動画と HTML の音は出さない**（割り込みのジングルだけを鳴らす） |
| 並べ方 | 画面ごとに流れを持つ。同じ素材を両方の画面に並べられる。ドラッグで並べ替える |
| 向きの合わない素材 | 横の素材を縦の画面に出すとき（逆も）は、**素材をぼかして引き伸ばした背景の上に、素材を切らずに収める**。切れたり歪んだりさせず、人に作り直させない |
| 変えたとき | 流れを変えると、すぐ画面に届く。いま出している素材は最後まで出し、次から新しい流れにする |
| 空のとき | 流れが空なら、会社の名前だけを出す（真っ黒にしない） |
| 端末への取り置き | 素材は端末に取り置き、**通信が切れても流し続ける**。つながったら差分を取り直す |

#### 31.6.1 段 1 の素材の決まり（第 0.189.0 版。案）

**素材はブラウザで確かめてから送り、サーバーでも確かめ直す**（画面の値を信じない）。サーバーで画像や動画を作り直さない。

| 項目 | 画像 | 動画 |
|---|---|---|
| 形式 | JPEG・PNG。拡張子と中身の先頭の両方で確かめる（第9.4.1節と同じ考え） | MP4。映像は **H.264**（映像の符号の印が `avc1`・`avc3`）に限る。H.265・VP9・AV1 などは断り、「H.264 の MP4 にして渡してください」と伝える（直し方はヘルプと秘書が案内する） |

| 動く画像 | 最初の 1 枚になる（描き直すため）。動かしたいものは動画で渡す | ― |
| 音 | ― | 音の入った動画も受ける。**流すときは常に消す** |
| 縮小画像 | ブラウザで長い辺 320 の JPEG を作って一緒に送る（100 KB まで） | ブラウザで 1 秒目（1 秒より短ければ最初）の絵から、同じ形で作って一緒に送る |

| 項目 | 規定 |
|---|---|
| 置き場 | 素材の中身は会社ごとのファイルの置き場（第20.4.2節）に、素材の ID を名前にして置く。**会社のファイル（`files`）の表には入れない**（`files` は持ち主本人と承認者だけが読めるため、会社で共有する素材と画面の鍵からの読み出しに合わない）。表は `signage_assets`（第31.15節） |

| 出し方 | 部分の読み出し（`Range`）に応じる。`content-type` は形式どおり、`x-content-type-options: nosniff`、画面の中で何も動かさない（`content-security-policy: default-src 'none'; sandbox`） |

| 数 | 流れの行は画面ごとに 100 まで。割り込みの素材は会社で 50 まで |
| 消す | 使う人が素材を消せる。**流れに入っていても断らない**。流れからも外し、外した画面の名前を返す（確認を挟まない。ADR-0028）。中身は置き場からも消す |
| 同じ中身 | 同じ中身（SHA-256 が同じ）をもう一度送ったら、新しく置かずに前の素材を返す |

#### 31.6.3 段 2 の HTML の素材の決まり（第 0.189.0 版。案）

**会社が作った HTML を、流れと割り込みの素材として受け取る**（2026-09-30 決定）。
パンの焼き上がりのように、画像と文を組み合わせた案内を会社の見た目で出せる。
**外の URL・外の Web ページは、これまでどおり入れない**（第31.14節）。HTML は、外と通信できない囲い（サンドボックス）の中で出す。

| 項目 | 規定 |
|---|---|
| 受け取る形 | 1 つの HTML の文書（`.html`）。画像・CSS・スクリプト・字体は**文書の中に入れる**（`data:` の URL と、`<style>`・`<script>` の中） |
| 中に入れる作業 | 人にさせない（ADR-0028）。管理の画面に、HTML と一緒に画像などのファイル（か、それらをまとめた ZIP）を落とすと、**ブラウザが決まった計算で、HTML と CSS の中の参照（`src`・`href`・`url()`）を文書の中に入れる**。入れられなかった参照は、ファイルの名前を挙げて示す。スクリプトの中で組み立てる参照は入れられない |
| 大きさ | 中に入れた後で 10 MB まで（案。第31.17節 #7）。動画は HTML に入れない（動画は MP4 の素材にする） |
| 外への参照 | `http:`・`https:`・`//` で始まる参照（画像・スクリプト・CSS・字体・`iframe`・フォームの送り先・`meta` の移動）が残っていれば**受け取らず**、参照の一覧を返す。出すときも下の囲いで止める（二重に止める） |
| スクリプト | 許す（案。第31.17節 #7）。動きや時計のような表示のため。囲いの中だけで動き、外と通信できず、再生のページや M2Office のデータに触れられない |
| 囲い | 再生のページは HTML を `<iframe sandbox="allow-scripts" allow="autoplay 'none'">` で開く。`allow-same-origin`・`allow-top-navigation`・`allow-popups`・`allow-forms`・`allow-modals` を付けない。音は出させない |
| 見出し | HTML の中身を返すときは、`content-security-policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; font-src data:; media-src data:; connect-src 'none'; form-action 'none'; frame-src 'none'` と `x-content-type-options: nosniff` を付ける。**源（オリジン）の無い文書として開くため、直接開かれても M2Office のログインの状態や保存の場所に触れられない** |
| 移動を止める | 再生のページの `content-security-policy` を `frame-src 'self'` にし、HTML が自分を外の URL に移そうとしても止める（第 0.191.0 版の実装: 再生のページを開いたときに、そのページにだけ `frame-src 'self'; child-src 'self'; object-src 'none'; base-uri 'self'` の見出しを足す。ワークスペースの画面には足さない） |
| 取り置き | HTML の中身はほかの素材と同じく端末に取り置く。**第 0.191.0 版の実装**: 再生のページが取り置いた中身を読み、先頭に外と通信させない見出し（`<meta http-equiv="Content-Security-Policy">`。上の見出しと同じ中身）を入れて、`iframe` の `srcdoc` で開く（`serviceWorker` に `iframe` の読み込みを答えさせる形にしなかった。`srcdoc` の文書は源（オリジン）を持たず、つながらないときも同じに開けるため） |
| 大きさと向き | 囲いは画面の大きさ（回した後）にする。HTML は画面の大きさ（1920×1080 か 1080×1920）で作ることを勧める（ヘルプ）。はみ出しは切る |
| 秒数 | 流れでは画像と同じ（既定 10 秒）。割り込みでは割り込みの秒数 |
| 割り込みの間 | 流れの HTML を出しているときに割り込みが来たら、HTML は囲いごと残し、画像と同じく残りの秒数を止める（HTML の中の動きは止めない） |
| 止まったとき | 囲いの中が重く、再生のページが進まなくなったら、見張り（第31.9.1節）の対象にする。同じ HTML で 3 回続けて止まれば、その素材を飛ばし、画面の状態で伝える |
| 縮小画像 | HTML の中の最初の画像。無ければ HTML の印 |
| 名前 | `<title>`。無ければファイルの名前。割り込みの素材にした HTML に名前が無ければ、AI が見える文から付ける（AI が付けるのは第 0.191.0 版では未実装。名前は管理の画面で直せる） |
| 管理の画面の見本 | 管理の画面でも、同じ囲いと見出しで開く。**ワークスペースの画面の中で HTML を直に描かない**（ログインしている人の画面で、会社の人が書いたスクリプトを動かさないため） |
| 入れられる人 | 利用範囲の人が、管理の画面とスタッフのページから入れる。**受け口と秘書からは HTML を入れられない**（受け口は名前で選ぶだけ。外から届いた文書を HTML の素材にしない。不変則 I-6） |
| 不変則 I-7 | HTML とスクリプトは画面の端末のブラウザで動き、M2Office のサーバーでは動かさない（第29.11節の読み取りの部品と同じ考え） |
| 文や番号の差し込み | 割り込みの HTML に、送られた文や番号を差し込む形（会社の見た目で番号を呼ぶ）は後の段で考える（第31.17節 #14） |

### 31.7 割り込み

**通常は流れを流し、依頼があれば割り込みを全画面で出し、ジングルを鳴らし、決めた秒数のあと元の流れに戻る。**

| 項目 | 規定 |
|---|---|
| 種類 | **割り込みの素材**（登録した画像か HTML をそのまま出す）と、**文字の割り込み**（送られた文を大きな文字にして出す） |
| 出し方 | 流れの上に全画面で重ねる。動画は止め、割り込みが終わったら**止めた所から続ける** |
| 秒数 | 既定 15 秒（会社の設定。割り込みごとに 5〜60 秒） |
| ジングル | 出すときに 1 回鳴らす（既定は入り）。**声では読み上げない**（Q-139。2026-09-30 決定）。音は、M2Office が持つ音（画面の側で合成する。音の素材の権利を持たずに済む）か、会社が入れた短い音のファイル（第31.7.3節）。音を出せない端末では、音なしで出し、画面の状態に「音が出せません」と出す（第31.9節） |
| 出す先 | すべての画面か、選んだ画面（「待合だけ」） |
| 続けて来たとき | **来た順に並べて 1 つずつ出す**。同じ画面に同じ文がすでに待っていれば 1 つにまとめる。待ちが 3 件を超えたら、1 件の秒数を 8 秒まで縮めて早く回す |
| 消す | スマホ・管理の画面の「消す」で、秒数を待たずに次の割り込みか元の流れに戻る。待っているものも消せる |
| 決めた時刻に出す | 行わない（決まった時刻の案内は、流れの素材にする） |

#### 31.7.1 文字の割り込みの見た目

#### 31.7.2 段 2 の割り込みの決まり（第 0.189.0 版。案）

**割り込みは画面ごとに並べる。** 「すべての画面」に出す割り込みは、出す先の画面ごとに 1 行の「出す先」を作り、画面ごとに待ち・出している・済みを持つ。画面どうしで出す時刻をそろえない。

| 項目 | 規定 |
|---|---|
| 出す先 | 「すべての画面」は、**割り込みを作った時点で登録されている画面**。後から登録した画面には出さない |
| 並び | サーバーが受け取った順。優先の順は持たない |
| まとめる | 同じ画面に、**中身（文、または割り込みの素材）が同じ割り込みが待っているか出している**ときは、新しく足さない（スタッフが二度押したときのため）。出し終わった後なら、新しく足す |
| 待ちの上限 | 画面ごとに 20 件。超えたら断る（スタッフのページは「待ちがいっぱいです」、受け口は 429） |
| 早く回す | 待ちが 3 件を超えている間は、これから出すものの秒数を 8 秒にする（8 秒より短く指定したものはそのまま） |
| 古い割り込み | **作ってから 2 分のうちに出し始められなかった割り込みは出さない**（「出せなかった」にする）。つながっていなかった画面が、後から古い呼び出しを出さないため。スタッフのページと管理の画面に「出せなかった」を出す |

| 消す | 「消す」は、その割り込みを出しているすべての画面から消し、次の割り込みか元の流れに戻す。待っているものは待ちから外す。**「すべて消す」**で、画面（か全画面）の、出しているものと待っているものをまとめて消す。消した人を記録する（監査ログには入れない。第31.12節） |
| 文を消す | 文と番号は、**出し終えて（済み・消した・出せなかった）から 24 時間で消す**。1 時間ごとの見回りで消す。行は残し、種類・出す先・秒数・出どころ・状態・時刻だけにする。行は 90 日で消す |
| 決めた時刻 | 受けない（第31.7節） |

#### 31.8.1 呼び出しの受け口

| 項目 | 規定 |
|---|---|
| URL | 管理者が「拡張機能」のサイネージの設定で作る。`/v1/hooks/signage/{鍵}`。**鍵は作ったときに一度だけ見せ、M2Office はハッシュだけを持つ**（予約の受け口と同じ。第29.13.1節） |
| 標準の形 | `{"text": "文"}`、または `{"number": "12", "place": "レントゲン室"}`（呼び出しの言い回しで文にする。第31.4節）、または `{"image": "割り込みの素材の名前"}`。任意で `screens`（画面の名前）・`seconds`・`chime`・`jingle`（音の名前） |
| 違う形 | 初めて届いたときに、**AI が項目の骨組み（名前と値の種類）だけから対応を推測して受け口に覚える**。値は推論に渡さない（予約の受け口と同じ） |
| 送り方 | JSON のほか、フォームの形（`application/x-www-form-urlencoded`）も受ける。**URL の問い合わせの部分に文を載せる呼び方（GET）は受けない**（文がアクセスの記録に残るため） |

| 大きさと回数 | 本文は 4 KB まで。受け口ごとに 1 分に 30 回まで |
| 断るとき | 知らない鍵・止めた受け口・サイネージを切った会社は、どれも 404（鍵の有無を探らせない）。読めない形は 422 |
| 送れないシステム | 受け口を呼べないシステムからは、スタッフのスマホか、手元の自動操作（Q-140）で出す |

#### 31.8.2 段 2 の呼び出しの受け口の決まり（第 0.189.0 版。案）

**受け口は、会社の判定とログインより前に置き、鍵から会社と受け口を引く**（予約の受け口と同じ。`POST /v1/hooks/signage/{鍵}`）。中身はデータとして扱い、指示として読まない（不変則 I-6）。

| 項目 | 規定 |
|---|---|
| 鍵 | 24 バイトの乱数を base64url にした 32 字。形の違う鍵は引かずに 404。**URL の代わりに `Authorization: Bearer {鍵}` の見出しでも受ける**（相手のシステムが見出しを付けられるなら、そちらを勧める。案。第31.17節 #9）。見出しで送るときの URL は `POST /v1/hooks/signage` |
| アクセスの記録 | 受け口の経路は、**記録に残すときに鍵の部分を伏せる**（`/v1/hooks/signage/***`）。本文は記録に残さない |
| 会社の状態 | 会社が利用の停止中（通常の停止・緊急停止・解約）なら 404（第23.8.6節）。会社の判定より前に置くため、受け口の処理で確かめる |
| 受ける形 | `application/json` と `application/x-www-form-urlencoded`（`charset` は UTF-8 だけ）。ほかは 415。`POST` 以外は 405 |
| 項目 | `text`（文）・`number`（番号。8 字まで）・`place`（場所。30 字まで）・`image`（割り込みの素材の名前。画像でも HTML でもよい。`asset` と書いてもよい）・`screens`（画面の名前の配列か、読点・カンマで区切った文字列）・`seconds`（5〜60。外れたら近いほうに寄せる）・`chime`（真偽。`"0"`・`"false"`・`"off"` は切り）・`jingle`（音の名前。知らなければ既定の音）・`requestId`（64 字まで。任意） |
| 文にする | `text` があれば `text`。無くて `number` があれば、呼び出しの言い回し（`place` が無ければ場所の無い言い回し）に当てはめる。`image` があれば割り込みの素材（名前は、全角と半角・大文字と小文字を区別せずに、完全に同じものだけ）。どれも無ければ 422 |
| 出す先 | `screens` が無ければすべての画面。名前は同じく区別せずに完全に同じものだけ。**知らない名前だけなら 422**（勝手に全画面にしない）。知らない名前が混じれば、分かる画面にだけ出す |
| 同じ呼び出し | 同じ受け口で同じ `requestId` が 10 分のうちに届いたら、新しく足さずに 200 を返す（相手の送り直しのため） |
| 違う形の推測 | 標準の形で読めなければ、骨組み（項目の名前と値の種類。値は渡さない）から、文・番号・場所・素材・出す先・秒数・ジングルの入り切りと音・`requestId` に当たる項目の道を推測する。**推測した道で、実際に届いた本文から文か番号か素材が読めたときだけ覚える**。推論が使えなければ覚えずに 503（相手の送り直しに任せる） |
| 推測の直し | 読めない呼び出しが続けば、管理者の設定の欄の受け口に「読めない呼び出しが届いています」と出す。**管理者は「推測し直す」を押すか、秘書に「受付の受け口の番号は ticket.no だよ」と伝える**。人に対応表を作らせない（ADR-0028） |
| 回数の上限 | 受け口ごとに 1 分に 30 回まで。超えたら 429（`retry-after` を付ける）。画面の待ちの上限（第31.7.2節）を超えたときも 429 |
| 答え | 受け付けたら 200 と `{"ok": true}`。割り込みの中身や ID は返さない。断るときも理由の細部は返さない（404 は本文も同じにする） |
| 記録 | 受け口の最後に受け取った日時と、今日受け付けた数・断った数（理由の種類ごと）を持つ。**本文は残さない**。監査ログには、受け口の作成・停止・再開・推測し直しだけを入れる |
| 答えの番号 | 下の表 |

| 番号 | いつ |
|---|---|
| 200 | 受け付けた（同じ `requestId` の送り直しを含む） |
| 404 | 知らない鍵・形の違う鍵・止めた受け口・サイネージを切った会社・停止中の会社 |
| 405 | `POST` 以外 |
| 413 | 本文が 4 KB を超える |
| 415 | JSON・フォームの形でない |
| 422 | 読めない形・文が 80 字を超える・文が空・知らない割り込みの素材・知らない画面の名前だけ |
| 429 | 回数の上限・画面の待ちの上限 |
| 503 | 形の推測が要るが、推論が使えない |

| 音の許可 | ブラウザは、人が一度も触れていないページで音を出させない。**Windows の端末の Chrome か Edge を、自動再生を許す設定で開く**（第31.9.1節）。できない端末では、画面を一度押せば音が出る。どちらもできない端末は音なし（第31.7節） |
| スタッフのページ（`/m/signage`） | スマホ用。よく出す案内のボタン・文を打つ欄・番号を打つ欄・出す先・「消す」・いま各画面に出ているもの。在庫管理のスマホのページ（第29.11.1節）と同じく、パソコンの画面から QR で開ける |

#### 31.9.1 段 1 の再生のページの決まり（第 0.189.0 版。案）

**再生のページは、ワークスペースとは別の軽いページとして作る。** ログインの確かめ（`/v1/me`）を通さず、左のメニューや秘書の欄を持たない。
画面を開いたまま何か月も動かす前提で作る。

| 項目 | 規定 |
|---|---|
| 端末 | 小型の Windows PC（2026-09-30 決定。Q-137）。1 台の端末に 1 画面。有線 LAN か Wi-Fi でつなぐ。Raspberry Pi・Android の STB などは勧めない（動けば使えるが、確かめない） |
| 開き方 | Windows に自動でサインインし、スタートアップから Chrome か Edge を、会社のアドレスの `/signage/play` でキオスク（全画面）に開く。自動再生を許す（Chrome は起動の設定 `--kiosk --autoplay-policy=no-user-gesture-required`、Edge はキオスクの起動の設定とポリシー `AutoplayAllowed`）。画面の電源を切らない・スリープしない設定にする。Windows の更新による再起動は夜中にし、再起動の後も自動で開く。手順はヘルプに置き、秘書が案内する（端末の用意を楽にする形は第31.17節 #13） |
| 鍵が無いとき | 登録の番号と QR を出す（第31.5.1節）。ほかには何も出さない（原則 u11） |
| 鍵があるとき | 流れと設定を読み、取り置いてから流す。取り置きが終わる前でも、取り置けた素材から流し始める |
| 全画面 | ページは常に画面いっぱいに描く（ブラウザの全画面の機能は人の操作が要るため、キオスクの設定に任せる）。マウスの矢印を隠す。スクロールと選択をさせない |
| 回す | 設定の回し方（0・90・180・270 度）で、ページ全体を回して描く。流れの素材の「向きが合わない」の判断は、**回した後の縦横**で行う |
| 消灯させない | `navigator.wakeLock` で画面を点けたままにする。ページが隠れて戻ったら取り直す。使えない端末は、端末の電源の設定に任せる（ヘルプ） |
| ページの取り置き | ページそのもの（HTML・スクリプト）を `serviceWorker` で端末に取り置く。**つながらないまま電源を入れ直しても、取り置いた流れを流せる**ようにする |
| 素材の取り置き | 素材はブラウザの取り置きの場所（`caches`）に、素材の ID と SHA-256 で置く。鍵を見出しに付けて読み、**URL に鍵を載せない**。流すときは取り置いた中身から流す |
| 取り置く範囲 | その画面の流れの素材と、会社の割り込みの素材（段 2）。流れから外れた素材は、新しい流れにした後で消す |
| 取り置けないとき | 取り置きの場所が足りなければ、取り置けなかった素材を生きている知らせで伝え、つながっている間はサーバーから直接流す。つながっていなければ飛ばす |
| つながらないとき | 取り置いた流れを**そのまま流し続ける**。即時の知らせが切れたら、10 秒ごとにつなぎ直す。つながったら流れの版を比べ、違えば差分を取り直す |
| 流れの変化 | 即時の知らせ（`GET /v1/signage-play/events`）で「流れが変わった」を受けたら読み直す（第31.6.2節） |
| 生きている知らせ | 1 分ごと（第31.5.1節）。答えにサーバーの時刻・流れの版・ページの版を返す |
| 時計 | **端末の時計を使わない。** 秒数は端末の経過時間（`performance.now()`）で数える。夜中の読み直しの時刻は、生きている知らせの答えのサーバーの時刻との差から決める |
| 夜中の読み直し | 日本時間の 3 時台に 1 回。**素材と素材の切り替えの時**に行い、割り込みの途中では行わない。**サーバーとつながっているときだけ**行う（つながらないまま読み直して真っ白にしないため） |
| 版が変わったとき | ページの版がサーバーの版と違えば（第6.1.1.1節）、次の切り替えの時に読み直す |
| 止まったときの見張り | 素材が決めた時間を 10 秒過ぎても進まない・流せない（動画が開けないなど）ときは、次の素材に進み、流せなかった素材を生きている知らせで伝える。3 回続けて流せなければ、ページを読み直す |
| 鍵が効かない | 答えが 401 なら、鍵と取り置きを消して登録の番号の表示に戻る（外された。第31.5.1節） |
| 会社が切った・停止した | 答えが 404（サイネージを切った）か 403（緊急停止・解約）なら、**無地の画面**にする（会社の名前も出さない）。鍵と取り置きは残し、5 分ごとに尋ね直す。通常の停止の間は流し続ける（下の「停止中」） |
| 停止中 | 会社が通常の停止（閲覧だけ。第23.8.6節）の間も、画面は流れを流し、生きている知らせも受ける。流れの変更と割り込みは、利用者の操作と同じく受けない |
| 素材の読み込み | 素材は `URL.createObjectURL` で流し、使い終えたら放す（長く動かしたときに記憶があふれないため） |

#### 31.9.2 段 2 の再生のページの決まり（第 0.189.0 版。案）

| 項目 | 規定 |
|---|---|

| 音の大きさを変えたとき | 管理の画面で音の大きさを変えると、その画面でジングルを 1 回鳴らす（試す専用のボタンを置かない） |
| 動画の音 | 常に消す（第31.6節） |

#### 31.9.3 段 2 のスタッフのページの決まり（第 0.189.0 版。案）

| 項目 | 規定 |
|---|---|
| 入り方 | パソコンのサイネージの画面の「スマホで開く」の QR を読む／ホーム画面に追加して開く。ログインはワークスペースと同じ（利用範囲の人だけ）。ログインしていなければログインし、終わったら戻る |
| 形 | 左のメニュー・秘書の欄を出さない。上に出す先、真ん中によく出す案内のボタン、下に文を打つ欄と「出す」、その下に各画面のいまの状態 |
| 出す先 | 「すべて」と画面ごと。選んだものを端末に覚える（次に開いたときも同じ） |
| よく出す案内 | 割り込みの素材（縮小画像つき）と、よく出す文（下の「よく出す案内の決まり」）を、最近 14 日の回数の多い順に 8 つまで。番号の入った案内は「{番号}番の方、レントゲン室へ…」のように番号を空けて出し、**押すと数字の打つ欄が開く** |
| 文を打つ | 80 字まで。打った文をそのまま文字の割り込みにする。先頭が番号なら大きく出る（第31.7.1節） |
| 秒数・ジングル | 既定のまま出す。変えたいときだけ、出す前に開いて変える |
| いまの状態 | 画面ごとに、出しているもの（割り込みなら文か画像）・待っている数・「消す」「すべて消す」。**「出せなかった」割り込み**（第31.7.2節）も 10 分の間は出す。音が出せない画面・つながっていない画面には印を付ける |
| 外す | よく出す案内のボタンは、長押しで外せる（外したものは、また 3 回使うまで出さない） |
| 素材を足す | スマホで撮った写真・動画を、画面の流れの最後に足せる（形式と大きさの決まりは第31.6.1節）。流れから外すこともできる。並べ替えはパソコンで行う |
| 更新 | 開いている間、3 秒ごとに状態を読み直す |
| 説明文 | 常に出さない（原則 u11） |

**よく出す案内の決まり**（番号や名前を残さないため）

| 項目 | 規定 |
|---|---|
| 形を作る | 出した文の**先頭の番号を空けた形**（「{番号}番の方、レントゲン室へお越しください」）を作る。受け口から番号と場所で届いたものは、言い回しに場所だけを入れた形 |
| 数える | 形ごとに、**形のハッシュ（会社ごとの塩を入れた SHA-256）だけで**、日ごとの回数を数える。文そのものは持たない |

| 消す | 90 日使わなかった形は消す。外した形は、回数を 0 に戻す |
| 割り込みの素材 | 画像は人の情報を含まないため、回数をそのまま数える |

### 31.11 秘書と業務から使う

| 依頼 | 動き |
|---|---|
| 「12番の患者様をレントゲン室に呼んで」 | 文字の割り込みを出す（すべての画面、既定の秒数、ジングルつき）。出したことを短く答える |
| 「待合の画面だけに『本日は 18 時で受付を終了します』を出して」 | 出す先を選んで出す |

| 「入口の画面の流れに、この画像を足して」 | 渡された画像を素材にして流れの最後に足す |

#### 31.11.1 段 2 の秘書の決まり（第 0.189.0 版。案）

| 依頼の言い方の例 | 動き |
|---|---|
| 「12番の方を呼んで」「12番、レントゲン室」 | 番号と場所が分かれば、会社の言い回しに当てはめた文を出す。場所が無ければ場所の無い言い回し |
| 「『〇〇』を出して」（かぎかっこつき） | かぎかっこの中を**そのまま**文にする（秘書が言い換えない） |
| 「本日は早めに閉店しますって出して」（かぎかっこなし） | 秘書が 80 字までの丁寧な短い文にして出す |
| 「待合だけに」「入口に」 | 出す先の画面を選ぶ。**名前の合う画面が無ければ出さず**、画面の名前を挙げて答える（違う画面に出さないため） |
| 「30 秒出して」「音なしで」 | 秒数・ジングルを変える |
| 「焼き上がりの案内はベルにして」 | その割り込みの素材の音を変える（第31.7.3節） |
| 「PowerPoint を流したい」 | 動画にする操作を案内する（第31.6.4節） |
| 「焼き上がりの案内を出して」 | 割り込みの素材の名前から合うものを選ぶ。無ければ文字の割り込み |
| 「呼び出しを消して」「全部消して」 | いま出しているものを消す／すべて消す |
| 「入口の画面の流れに、この画像を足して」 | 渡された画像を素材にして、その画面の流れの最後に足す（画像だけ。秘書に渡せるファイルの決まり（第9.4.1節）の範囲） |
| 「サイネージの画面はつながってる？」 | 画面ごとに、つながっているか・最後の通信・音が出せるかを、表を引いてその場で答える（推論に作らせない） |
| 「言い回しを『〇番の患者様、〇〇にお入りください』にして」 | 管理者なら、呼び出しの言い回しを変える（番号と場所を差し込む形にする）。管理者でなければ、管理者に頼むよう答える |
| 「入口の画面を外して」 | 管理者なら外す（確認を挟まない）。外したことと、戻し方（第31.5.1節）を答える |

| 項目 | 規定 |
|---|---|
| 答え | 出したら、**出した文（か画像の名前）と出す先を 1 行で**答える（「入口と待合に『12番の方、レントゲン室へお越しください』を出しました」）。違っていれば「消して」で消せる |
| 人から頼まれたときだけ | 割り込みを出すツール（`signage.show`・`signage.clear`）は、**秘書の欄で本人が話した回（音声を含む）にだけ使える**。業務の実行・定時実行・ブリーフ・会話から学ぶ処理・メールや文書を読んだ結果からは使えない（基盤がツールを渡さない）。メールや文書に「サイネージに出して」と書かれていても出さない（不変則 I-6） |
| 自動化ポリシー | 会社の自動化ポリシーで「社内への書き込みに承認が必要」にしている会社では、秘書から出すときに本人の操作の確認を挟む（第9.4.0節。案。第31.17節 #8）。スタッフのページと受け口には関わらない |
| 使えない人 | サイネージを切っている会社と、利用範囲の外の人には「使えません」と答える |

| ツール | 危険度 | 内容 | 段 |
|---|---|---|---|
| `signage.status` | read | 画面ごとの状態（つながっているか・最後の通信・いま出しているもの・音が出せるか）。割り込みの文は返さない | 2 |
| `signage.show` | write-internal | 文字の割り込みか割り込みの素材を出す（文・番号と場所・素材の名前・出す先・秒数・ジングル） | 2 |
| `signage.clear` | write-internal | いま出している割り込み、またはすべてを消す（出す先を選べる） | 2 |
| `signage.add_to_flow` | write-internal | 渡された画像を素材にし、画面の流れの最後に足す | 2 |
| `signage.configure` | write-internal | 呼び出しの言い回し・店の色・既定の秒数とジングルを変える。画面を外す。**管理者だけ** | 2 |

**第 0.191.0 版の実装（上の決まりから変えたこと）**: 秘書は、サイネージへの依頼を**ツールの一覧（`signage.*`）に載せず、秘書の欄の本人の発言を決まった言い方で見分けて、その場で行う**（在庫・人事の直接の答えと同じ形）。
推論にツールを渡さないため、業務の実行・定時実行・ブリーフ・メールや文書を読んだ結果から割り込みを出す道が、そもそも無い（「本人が話した回にだけ」を、ツールを渡さない形で満たす）。
見分けるのは、番号の呼び出し・かぎかっこの文・「〜って出して」（**言い換えずにそのまま出す**。推論に文を渡さない）・出す先の画面の名前・秒数と「音なし」・割り込みの素材の名前・素材の音・消す・つながっているか・呼び出しの言い回し（管理者）・画面を外す（管理者）。
名前の合う画面が無ければ出さず、画面の名前を挙げて答える。合う割り込みの素材が無ければ、ふつうの会話に回す。出したこと（種類だけ）を監査ログ `secretary.signage` に残す。
**未実装**: 渡された画像を流れに足す（`signage.add_to_flow`。スタッフのページと管理の画面からは足せる）、店の色と既定の秒数・ジングルを会話で変える、自動化ポリシーでの確認（第31.17節 #8）、「PowerPoint を流したい」への案内（ふつうの会話とヘルプで答える）。

### 31.13 人の情報

| 項目 | 規定 |
|---|---|
| 呼び方 | 名前ではなく**番号で呼ぶことを勧める**（ヘルプと秘書の答え）。名前を出すかは会社が決める |
| 割り込みの文 | 出し終えてから **24 時間で消す**（理由は下の表）。監査ログ・動作のログには文を残さない（件数と出した画面だけ） |
| 推論 | 受け口と画面から出す割り込みの文は**推論を通らない**（見た目は決まった計算。第31.7.1節。受け口の推測は骨組みだけ） |
| 秘書 | 秘書に頼むときは会話として推論を通る。**会話の記録は、ふつうの会話と同じに扱う**（2026-09-30 決定。24 時間で消さない）。医院などでは、秘書にも番号で頼むことを勧める |
| 記憶と知識 | 割り込みの文は、秘書の記憶にも会社の知識にもしない |

**割り込みの文を 24 時間で消す理由**（残す期間は第31.17節 #11 で見直せる）

| 理由 | 中身 |
|---|---|
| 使い道が無い | 割り込みの文は、画面に出している間だけ要る。出し終えた後に読み返す用事は、その日のうちに「何を出したか」を確かめるくらいである |
| 溜めない | 番号や名前の入った呼び出しを残すと、誰がいつ呼ばれたか（来店・来院の記録）が M2Office に溜まる。それは受付のシステムの役割で、M2Office が持つ理由が無い（在庫で人の情報を持たないのと同じ考え。第29.17節） |
| 会話とは別 | 秘書に頼んだ会話は、本人が秘書と話した記録であり、ふつうの会話と同じに扱う。割り込みの表の文は、画面に出すための写しなので、役目を終えたら消す |

**段 2 の人の情報の決まり（第 0.189.0 版。案）**

| 項目 | 規定 |
|---|---|
| 動作のログ | 割り込みの ID・種類・文の字数・出す先の数・出どころだけを残す。文・番号・場所を残さない。受け口の本文も残さない |
| 会話から学ぶこと | `signage.show`・`signage.clear` を使った会話の回は、会話から学ぶ処理（第11.5.2節）・会社の知識にする判断（第11.3節）の**対象にしない**（呼び出しはその場かぎりで、覚えても役に立たないため） |
| よく出す案内 | 文をそのまま残さない。番号を空けた形を、3 回以上使ったものだけ残す（第31.9.3節） |
| 割り込みの素材の名前 | 画像から AI が付ける名前は、店頭に出す画像についてだけ（第31.6.1節）。人の写った画像を割り込みの素材にしないことを勧める（ヘルプ） |
| 見本 | 管理の画面の見本は素材の縮小画像だけで、割り込みの文は出さない（第31.5.1節）。管理の画面の「最近の割り込み」は、文を 24 時間の間だけ出す |

### 31.14 社外への境界（ADR-0051）

**会社が登録した画面に出すことは、「社外への送信」に当たらないとし、承認を挟まない。**
画面は会社の店頭・待合に置いた会社の端末で、社内の掲示と同じ扱いにする。割り込みは呼び出しのためのもので、承認を待つと役に立たない。

その代わり、次を守る。

| 守ること | 理由 |
|---|---|
| 出す先は、管理者が QR で登録した画面だけ | 画面を勝手に増やして外に出させない |
| 秘書は人から頼まれたときだけ出す | 秘書が自分の判断でお客様の目に触れるものを出さない |
| 受け口から出せるのは文字と登録した割り込みの素材だけ | 鍵が漏れても、外の画像・HTML・Web ページを出されない |
| 外の Web ページ・URL を、流れにも割り込みにも入れない。会社の HTML は、外と通信できない囲いの中で出す（第31.6.3節） | 画面を外の中身の入口にしない |

在庫の Web への公開（第29.12節）は誰でも見られる所へ出すため承認を挟むが、サイネージは会社の中に置いた画面に出すため挟まない。

**実装で確かめること（段 1・段 2）**

| 確かめること | どこで |
|---|---|
| 画面の登録は、ログインした**管理者**が番号を確かめたときだけ起きる。番号を URL で開いただけでは登録しない（「登録する」を押す） | 第31.5.1節 |
| 再生のページは、素材と割り込みの文字と店の色・会社の名前だけを描く。外の URL を読み込まない。会社の HTML は第31.6.3節の囲いと見出しの中だけで開く。再生のページの `content-security-policy` で、読み込み先を M2Office の同じ場所だけにし、`frame-src 'self'` にする | 第31.9.1節・第31.6.3節 |
| 受け口の `image` は割り込みの素材の名前だけを受け、URL を受けない。`text` は文字としてだけ出す | 第31.8.2節 |
| 管理の画面で HTML をワークスペースの画面に直に描かない。HTML の中身の答えに、源の無い文書にする見出しを付ける | 第31.6.3節 |
| 秘書の割り込みのツールは、本人が話した回にだけ渡す | 第31.11.1節 |
| 割り込みの文を推論に渡さない（受け口の推測は骨組みだけ。秘書の会話を除く） | 第31.8.2節・第31.13節 |

### 31.18 行わないこと

| 行わないこと | 理由 |
|---|---|
| 画面の分割（ゾーン）・天気やニュースの帯・時計の部品 | 大規模向けの機能で、運用を重くする |
| 細かい予定表（曜日・時刻ごとの流れ）・再生の実績の報告 | 同上。時間帯で流れを変えることだけ段 3 で考える |
| 多数の画面の一括管理・端末の電源の遠隔操作 | 1 社 3 台まで（第31.4節） |
| 1 台の端末に画面を 2 つ以上つなぎ、別々に流す | 1 台の端末に 1 画面と決めた（2026-09-30） |
| 外の Web ページ・URL を流れや割り込みに入れる | 画面を外の中身の入口にしない（第31.14節）。会社の HTML は、中に入れて外と通信させずに出す（第31.6.3節） |
| サーバーで動画の形式を変える | 重い処理と変換の部品を持たないため。H.264 の MP4 で渡してもらう |
| サーバーで PowerPoint を変換する | アニメーションが崩れる。外から来た文書を変換の部品に通さない（第31.6.4節） |
| サーバーで画像を縮める・作り直す | 同上。縮めるのはブラウザで行う（第31.6.1節） |
| 動画と HTML の音を流す | 割り込みのジングルと重なり、店内で邪魔になる |
| 割り込みを声で読み上げる | 番号や名前を、声で店内に広げない。ジングルで注意を引く（Q-139） |
| Raspberry Pi・Android の STB などを勧める端末にする | 勧める端末を Windows に絞り、確かめる手間を減らす（Q-137） |
| 割り込みの文を推論に渡す・残す | 番号や名前が入りうる（第31.13節） |
| 秘書が自分の判断で割り込みを出す | お客様の目に触れるものは、人の依頼で出す（第31.14節） |
| 端末の画面を写して送る | 見本は素材の縮小画像で足りる。割り込みの文を写さないため |
| 端末の時計で割り込みの古さを決める | 端末の時計はずれうる。経過はサーバーが数える（第31.9.2節） |
| 受け口から画像や URL を受け取って出す | 鍵が漏れても、勝手な画像を出されないため（第31.8.1節） |
