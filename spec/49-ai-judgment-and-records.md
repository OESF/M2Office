## 49. 推論に任せることと、M2Office が確かめること（言葉の一覧で意味を決めず、行ったことは記録で言う。第 0.601.0 版で案、第 0.602.0 版で決定。Q-382〜Q-388、ADR-0150）

この章で決めること: **頼みの意味は推論が読み、行ったことは M2Office が記録で言う**という、秘書と業務に共通する分け方。
なぜ決めるか、いまの作り、考え方、残す言葉の一覧、頼みの読み取り、覚えることの分け方、行ったことの記録、指示の書き方、見張り、確かめ方、行わないこと、段階。

2026-11-16 に三浦さんが、Q-382〜Q-388 をおすすめのとおりとした（第 0.602.0 版）。段 1 から順に実装する（第49.12節）。

### 49.1 目的と位置づけ

2026-11-16 の 1 日に、次のことが続けて起き、そのたびに直した。

| 起きたこと | その場の直し |
|---|---|
| 秘書の文字の答えが、音声の話し方の指示を外した後も方言のままだった | 方言の言葉（「〇〇弁」「方言」「標準語」）の一覧で記憶を外し、「弁護士」「代弁」などを外さない一覧も足した（第 0.599.2 版・第 0.599.3 版） |
| 「Slack の #general の内容をまとめて」が、調べものに回らなかった | 調べものに回す言葉の一覧に「まとめ」「要約」「内容」を足した（第 0.599.3 版） |
| 調べものが、読んでいないチャンネルを「まとめました」と書いた | 指示から例のチャンネル名を外し、「読んでいないものを『まとめました』と書かない」と足した（第 0.600.0 版） |
| 接続の業務が、画像を送れないまま、サイトにあった前の記事の画像をアイキャッチにして「設定しました」と書いた | 呼び方の受け付けを足し、送れなかったときは M2Office が答えにそう書くようにした（第 0.600.1 版） |
| 承認の前の確かめの文が方言になっていた | 業務に渡す好みからも、話し方の好みを外した（第 0.600.1 版） |

どれも特定の会社や相手に寄せた直しではない。ただ、**推論が 1 回まちがえるたびに、その形を 1 つずつ塞ぐ直し**が混ざっていた。三浦さんは、このままでは「どんどん特殊化していく」と指摘した。

第48章で、接続の業務の手順を相手の道具の説明に任せ、M2Office は境目だけを受け持つ形にした。この章は、同じ考え方を秘書と業務の全体に広げる。

**この章の考え方**: 言葉の揺れを読むのは推論が得意で、M2Office が言葉の一覧で追いかけると終わりがない。反対に、何をしたかは M2Office の記録に確かにあり、推論の言い分に任せると食い違う。**得意なほうに任せる。**

### 49.2 いまの作り（2026-11-16 に調べたこと）

秘書と記憶のまわり（`secretary/`・`memory/`）に、言葉の一覧（正規表現）が 98 ある。外れたときに何が起きるかで分けると、次のとおりである。

| 種類 | 数 | 例 | 外れたときに起きること |
|---|---|---|---|
| 形を読む | 約 10 | 日付・数量・URL・かぎかっこ・頼みの長さ | 読めなかった形が推論に回るだけ |
| 安全の側にだけ倒す | 約 5 | 秘密（パスワードなど）を覚えない・「やめて」で止める・「もう知らせないで」 | 当たりすぎても、止まる・覚えない側に倒れるだけ |
| 頼みの全体の定型 | 約 6 | 「1 人の AI の上限を 3 割に」「〇〇グループの共有先は…」 | 定型に合わなければ推論に回るだけ |

| 名前を照らす | 2 | 「クリニック」「株式会社」を外して比べる | 業種の言葉が増えるたびに足すことになる |

困るのは「頼みの意味を決める」「記憶を分ける」「推論の答えを言葉で見張る」の 3 つである。どれも、外れた言い方が見つかるたびに言葉を足し、当たりすぎた言い方が見つかるたびに外す言葉を足してきた（「メールアドレスには当てない」「弁護士は方言ではない」など）。

もう 1 つ、**行ったことを推論の言葉で伝えている**所がある。

| 所 | いま |
|---|---|
| 接続の業務の結果（第48章） | 推論が書いた答えを、そのまま結果として出す。預けたファイルが届いたかだけは、M2Office が記録で書く（第 0.600.1 版） |
| 業務から業務へ頼んだときの親（第48.8節） | 子の答えの文と、子が失敗したかで、親の状態を決める |
| 秘書の調べもの（第10.11.5節） | 推論が「〇〇をまとめました」と書く。何を読んだかは答えに出ない |
| 秘書の答え（層 3） | 推論が「表示しました」と書いたかを言葉で見張る |

### 49.3 考え方

| # | 決まり | なぜ |
|---|---|---|
| 1 | **頼みの意味は推論が読む。** 言葉の一覧で、どこに回すか・何をするかを決めない | 言い方の揺れは無限にあり、一覧は追いつかない。推論は、いまの話の流れ（第10.7.4節）も合わせて読める |
| 2 | **行ったことは M2Office が記録で言う。** 「入れた」「送った」「読んだ」を、推論の言い分で決めない | 道具の呼び出しと、その成否は M2Office の記録に確かにある。推論は、していないことを「しました」と書くことがある |
| 3 | **推論の失敗は、問題集の 1 問にする。** 指示に、起きた事故の例を書き足さない | 例を足すと、推論は例に引きずられる（2026-11-16 に、例のチャンネル名を読んだと作り話をした）。指示は一般の決まりだけにし、直しが効いたかは問題集で測る |
| 4 | 言葉の一覧は、**外れても当たりすぎても害がないもの**だけに残す | 害がなければ、言い方の揺れを追いかけなくてよい |

境界（承認・社外への送信・お金の確定・テナント境界）は、いままでどおり道具の危険度と承認で守る（第9.4.0節、ADR-0028）。推論の読み取りが外れても、境界は越えない。

### 49.4 残す言葉の一覧

次の 3 種類だけを残す。新しく足すときも、この 3 種類のどれかに当てはまるものだけにする。

| 種類 | 決まり | 例 |
|---|---|---|
| 形を読む | 日付・数量・URL・番号のような、言葉の意味ではなく形を読む | 「11 月 3 日」「3 箱」「https://…」 |
| 安全の側にだけ倒す | 当たりすぎても、止まる・覚えない・送らない側に倒れるだけのもの | 秘密を覚えない・「やめて」で止める |
| 頼みの全体の定型（層 1） | 頼みの**全体**が決まった形のときだけ当て、外れたら推論に回す。頼みの一部の言葉には当てない | 「今日の予定」「承認待ちは？」「文字を大きくして」 |

次のものは残さない。

| 残さないもの | 代わりに |
|---|---|
| 頼みの一部の言葉で、回す先や答え方を決めるもの | 頼みの読み取り（第49.5節） |
| 「〇〇には当てない」という、外すための一覧 | 同じ（外すための一覧が要るのは、意味を言葉で決めている印） |
| 記憶の種類を言葉で決めるもの | 覚えるときに推論が種類を付ける（第49.6節） |
| 推論の答えの言い方を見張るもの | 行ったことの記録（第49.7節） |
| 業種や会社の言葉の一覧（「クリニック」「医院」など） | 推論が名前を照らす。照らせなければ聞き返す（第10.11.5.2節） |

### 49.6 覚えることの分け方（Q-387）

| 項目 | 決まり |
|---|---|
| 覚えるとき | 覚える推論（第11.13節）が、覚えるものごとに種類を付ける。いまの種類（事実・好み・取り次ぎの好み）に、**秘書の話し方**と**その時だけの失敗**を足す |
| 足した 2 つの扱い | 秘書の話し方は記憶にしない（話し方は、個人設定の「話し方の指示」と応対スタイルで決める。第11.2節）。その時だけの失敗は、やりかけの頼みとしてだけ残す |
| いまある記憶 | 1 度だけ、高速モデルで種類を付け直す。秘書の話し方と分かったものは、答え・本人の像・要約・業務に使わない印を付ける。付け直しのときに消すことはせず、消すのは本人が行う（記憶とデータの画面・会話。第11.5節。Q-387） |
| 言葉の一覧 | 付け直しが済んだら、記憶を分ける言葉の一覧（第 0.599.2 版・第 0.599.3 版の方言の一覧など）を外す |
| 実装（第 0.603.0 版） | 覚える推論は、行の頭に「- 話し方: 」「- その時だけ: 」を付け、M2Office はその印の行を覚えない。その時だけのことには、すぐ変わる数や状態（在庫の数など）も含める。いまある記憶の付け直しは、その人が次に学ぶときに 1 度だけ行い（確かめた日時を本人の設定に残す）、本人の像の行と会話の要約（60 日ぶん）の文も同じ推論で確かめ、秘書の話し方の行と文だけを外す。推論は番号と種類だけを返し、文を書き換えない。記憶は消さずにしまい（理由「秘書の話し方」「その時だけのこと」）、しまったものの一覧から本人が削除できる。週 1 回の整理（第11.11.4節）で、確かめた後に覚えた記憶（本人が「覚えて」と頼んだものなど）も確かめる |

### 49.7 行ったことの記録

| 項目 | 決まり |
|---|---|
| 記録するもの | 業務ごとに、見える状態を変えた呼び出し（危険度が下書き・社内への書き込み・社外への送信のもの）と、その成否・相手が返した印（記事の番号・URL など）、預けたファイルの送信と、それを相手が受け付けたか（第48.8.1節）。読む呼び出しは、道具と指したもの（チャンネル・ページ・ファイルなど） |
| 結果の伝え方 | 業務の結果を人に伝えるとき（業務の結果・通知・秘書の報告）、**行ったことは M2Office が記録から書く**。推論の文は、その後ろに説明として置く。推論には「行ったことは M2Office が書くので、あなたは書かない」と伝える。推論の文だけを出して食い違いを後で直す形は取らない（Q-385） |
| 行っていないとき | 作る・入れる・送る頼みで、見える状態を変えた呼び出しが記録に 1 つも無ければ、「行っていません」と M2Office が書く |
| 親と子 | 親の業務は、子の答えの文ではなく、子の記録で状態を決める。たとえばコラムは、下書きを作る呼び出しが成功していれば「入れた」にする。預けたカバー画像が届いていなければ、そう添える |
| 調べもの | 答えに、読んだもの（記録にある道具と指したもの）を添える。出し方は、調べたページの出典（第10.11.5節）と同じにする。読んだものに無いものを「まとめた」と書かせない |
| 秘書の答え（層 3） | 秘書が道具で行ったことも、同じ記録から書く。推論の答えの言い方を見張る言葉の一覧（第49.2節）は外す |

記録は、いまの業務の記録（`run_steps` の道具の記録）と監査ログを使う。新しい表は作らない。

実装（第 0.603.0 版）:

| 項目 | 中身 |
|---|---|
| 1 件の記録 | 道具の名前・危険度・接続の道具の役割・人に見せる言い方（接続なら「接続の名前（相手の道具の名前）」、内蔵なら道具の説明の最初の文）・指したもの（引数のうち短い文字と数を 3 つまで）・成否と理由・相手が返した印。段の出力の `record` に残す |

| 相手が返した印 | 相手の JSON の上の段の、名前が `id`・`_id`・`Id` で終わる項目（2 つまで）と、最初の https の URL（形を読む） |
| 行ったことの書き方 | 「**行ったこと**（M2Office の記録）」の下に、見える状態を変えた呼び出しを 1 行ずつ（役割があれば「準備しました」「行いました」「元に戻しました」、無ければ危険度で「下書きを作りました」「書き込みました」「送りました」）、行えなかったものは理由と、預けたファイルの送信、読んだもの（8 件まで）。見える状態を変えた呼び出しも、送れたファイルも無ければ「見える状態を変える操作は、行っていません」と書く。人が却下した呼び出しは「行えませんでした」と理由を書く |
| 当てる所 | 接続の業務の結果（1 本の会話の段）と、秘書の調べものの答え（「まとめる」の段の後ろに「**読んだもの**（M2Office の記録）」。段の定義の `record: 'reads'`）。秘書の層 3 は設定の変更も業務の実行もしないため、行ったことは調べものを始めたかだけで、それは道具の呼び出しで決める（第10.11.5.1節） |
| 段の型のほかの業務 | 承認の画面と操作の確認で、行うことを M2Office が書いている（第9.3.3節・第9.4節）。段 2 で、結果の伝え方をそろえるかを決める |

### 49.8 指示の書き方

| 項目 | 決まり |
|---|---|
| 指示に書くもの | 一般の決まりだけ（「頼んだ名前のものが無ければ探し直す」など） |
| 指示に書かないもの | 起きた事故の例（具体のチャンネル名・画像の番号など） |
| 事故が起きたら | 問題集に 1 問として足し、直した後に測る（第49.10節） |
| M2Office の道具の名前 | 推論に渡す M2Office の道具（`tools_load`・`files_send` など）の名前を、接続の道具と同じ形にそろえ、推論が名前を推し量らなくてよいようにする。第 0.600.1 版の呼び方の受け付けは、そろえた後に外す |

### 49.9 見張り（特殊化を止める仕組み）

| 項目 | 決まり |
|---|---|
| 台帳 | 言葉の一覧には、種類（形を読む・安全の側にだけ倒す・頼みの全体の定型）の印を、宣言のすぐ上のコメント（`// @wordlist 形を読む`・`安全の側`・`定型`）で付ける。印の無いものの数は、ファイルごとに台帳（`scripts/word-lists-baseline.json`）に持つ |
| 点検 | 自動のテスト（`npm test` の `scripts/check-word-lists.mjs`）で、秘書（`secretary/`）・記憶（`memory/`）・業務（`engine/`）のファイルの上の段の言葉の一覧を数える。印の無いものが台帳を超えたら・知らない印があれば失敗にする。減ったら台帳を下げる（上げない） |
| 数の報告 | 外した数と残った数を、段ごとに変更の履歴に書く |

### 49.10 確かめ方

| 項目 | 決まり |
|---|---|
| 取り次ぎの問題集 | 秘書への頼みと、回すべき先・してはいけないことの組を問題にする。開発の会話の記録から作り、個人の情報と社外の名前は落とす。これまでに言葉の一覧を足した頼み（「〇〇のメールを探して」「#general をまとめて」など）は必ず入れる |
| 合格の目安 | 9 割、かつ、これまでに言葉の一覧を足した頼みはすべて合格（Q-386） |
| ほかの問題集 | 続きの頼みの問題集（第10.7.4.8節。いま 96／100）と、接続の業務の問題集（第48.9節）を下げない |
| 速さ | 層 2 の答えの時間を、言葉の一覧で答えていた頼みについて測る |

### 49.11 行わないこと

- 会社ごと・相手ごと・業種ごとの言葉の一覧を足すこと
- 推論の読み取りで、承認・社外への送信・お金の確定を決めること（境界は道具の危険度と承認のまま）
- 層 1（定型の答え）をやめること。頼みの全体が定型のときは、推論を使わずに答える（第10.9.4節。事実の誤りが入らない）
- 推論の失敗を、その場で指示の文に書き足して直すこと
