## 29. 在庫管理（第 0.149.0 版、ADR-0045。案）

この章で決めること: 品目・場所・在庫の数（ロットと使用期限を含む）を持ち、入庫・使用・移動を記録し、スマホでバーコードを読んで棚卸しをし、
在庫を Web に公開し、AI が欠品を防ぐしくみ。形（内蔵の拡張）、汎用にするための入り切り、最初の範囲と後の段階、秘書と業務からの使い方、お金と社外への境界、医療で使うときの線引き。

**この章は案である。** 最初のお客様（第29.1.1節）の依頼を受けて範囲を決めた。**特定のお客様の専用の作りにはせず、会社ごとの入り切りだけで、いろいろな業種に使える汎用の在庫管理にする**（三浦さんの方針）。
残りの確かめる事項（第29.22節）の答えで直してから実装する。

### 29.1 目的と位置づけ

物販・製造・医療などの中小企業では、在庫を Excel や紙で持ち、**実際の数と帳簿の数が合わない**。
棚卸しは紙に書いて数え、Excel に打ち直す。欠品に気づくのは、無くなってからである。

| 痛み | M2Office で行うこと |
|---|---|
| 棚卸しに時間がかかる | スマホで棚と品目のバーコードを読むだけで数える。数えた端から帳簿との差が分かる |
| 入庫の入力の手間 | バーコード（医薬品は使用期限とロットも一緒に）を読むか、**納品書の写真から AI が読み取って**入庫にする |
| 在庫をお客様に伝えられない | **在庫を Web ページにそのまま公開する**。入出庫のたびに、すぐ変わる |
| 欠品に気づくのが遅い | **AI が常に在庫を見張り**、残りわずか・無くなる見込みの日・使用期限の近いものを知らせ、発注の案を作る |

### 29.2 形: 内蔵の拡張（既定は切り）

在庫管理は、表とスキャン・棚卸し・公開の画面を持つ。拡張機能（第12.10.1節）では作れないため、名刺管理（第27章）と同じく**内蔵の拡張**（第12.13節）として作る。

| 項目 | 規定 |
|---|---|
| 入り切り | 管理者ページの「拡張機能」に「公式・内蔵」として並べ、会社ごとに入り切りする。**既定は切り**（物販・製造・医療には要るが、どの会社にも要るわけではない） |
| 利用範囲 | ほかの拡張機能と同じく、使える人をグループや人で絞れる（第16.7.3節） |
| 画面 | 左ペインの「業務」の並びに「在庫管理」を置く（第6.1.1節）。切っている会社と利用範囲の外の人には出さない |
| 範囲 | 在庫は**会社で共有**する |
| 課金 | TBD（Q-112） |

### 29.3 用語

| 用語 | 意味 |
|---|---|
| 品目 | 管理する物の 1 種類。名前・バーコード・単位を持つ |
| 場所 | 物を置く所。「倉庫」とその中の「棚」の 2 段 |
| ロット | 同じ品目の、製造の単位。使用期限を持つ |
| 在庫 | 場所・ロットごとの数（帳簿の数）。入出庫の記録から求める |
| 使える数 | 在庫から、**予約で取り置いた数（引き当て）**と使用期限の切れた数を引いたもの。公開と欠品の判断はこの数で行う |
| 入り数 | 仕入れの単位と使う単位の換算（「1 本 = 5 回分」「1 箱 = 10 本」） |
| 入出庫の記録 | 入庫・使用・移動・調整の 1 件ずつの記録。**消さない**。取り消しは逆の記録を足す |
| 棚卸し | 実際の数を数え、帳簿の数との差を合わせる作業 |
| 公開 | 在庫を Web ページに出すこと（第29.12節） |

### 29.4 汎用にするための入り切り

業種ごとの違いは、**会社ごとの機能の入り切り**と品目ごとの項目で吸収する。お客様ごとの作り分けはしない。

| 機能 | 入れると | 既定 |
|---|---|---|
| ロットと使用期限 | 入庫でロットと使用期限を記録し、期限の近いものから使う。期限切れは使える数から外す（第29.8節） | 切り |
| 単位の換算 | 品目に入り数を持たせ、仕入れの単位で入れて使う単位で減らす（第29.9節） | 切り |
| 公開 | 在庫を Web に出す（第29.12節） | 切り |
| 予約との引き当て | 予約で使える数を減らす（第29.13節） | 切り |
| 発注の案 | 残りわずか・無くなる見込みで、発注の案とメールの下書きを作る（第29.14節） | 入 |

| 項目 | 規定 |
|---|---|
| 置き場所 | 管理者ページの「拡張機能」の在庫管理の欄（名刺管理の既定の範囲と同じ所。第12.13節） |
| AI の提案 | 品目を取り込んだとき、中身から入れたほうがよい機能を**秘書が提案する**（「ワクチンと薬があります。ロットと使用期限を使いますか」）。入れるのは管理者。人に一から考えさせない（ADR-0028） |
| 切ったとき | 記録は消さない。入れ直せば戻る |

### 29.6 品目

| 項目 | 規定 |
|---|---|
| 持つもの | 名前、公開する名前（例: 病名「MR ワクチン」と商品名「ミールビック」を分けて出すため）、自社のコード（任意）、バーコード（1 つの品目にいくつでも）、分類（例: 国産ワクチン・輸入ワクチン・薬・ドリンク・化粧品）、単位、入り数、販売価格（任意。税込か税抜か）、写真（任意）、**残りわずかの目安**（既定は会社の値。最初のお客様は 3）、メモ、使うか止めたか |
| 作り方 | 画面で 1 件ずつ、**CSV・Excel で取り込み**（今の Excel から。列の見出しを AI が読む。人に対応表を作らせない。ADR-0028）、知らないバーコードを読んだときにその場で作る |
| 名前を埋める | 写真のパッケージの文字から名前を読み取って埋める。**読めなければ空にし、推測で埋めない**。JAN の外部の台帳は Q-111 |
| 販売価格 | **公開の表に出すための値**で、在庫の金額（評価）ではない（第29.18節） |
| 止める | 使わなくなった品目は止める（記録は残す）。在庫が残っていれば止められない |

### 29.7 場所

| 項目 | 規定 |
|---|---|
| 形 | 倉庫とその中の棚の 2 段。棚を持たない倉庫もよい |
| 棚のラベル | 棚ごとに QR を作り、A4 に並べた印刷用の PDF を出す。貼らなくても画面で棚を選べる |
| 既定の場所 | 場所を 1 つしか持たない会社は、場所を選ばずに使える（最初のお客様はこれに当たる見込み） |

### 29.8 ロットと使用期限（入り切り）

| 項目 | 規定 |
|---|---|
| 入庫 | ロットと使用期限を記録する。**医薬品の箱の GS1 のバーコード（GS1 データバー・GS1-128）を読めば、商品のコード・使用期限・ロットを 1 回で取り出す**。付いていなければ手で入れるか、納品書の写真から読み取る |
| 使う順 | 使う・出すときは、**使用期限の近いロットから**減らす（先に選ばれるロットを画面に出す。別のロットを選び直せる） |
| 期限切れ | 使用期限を過ぎたロットは**使える数から外し**、公開にも出さない。廃棄の記録（調整）を促す。**自動で消さない** |
| 知らせ | 使用期限の 30 日前・7 日前に、残っているロットを知らせる（第29.14節） |
| 棚卸し | ロットごとに数える（GS1 を読めばロットが決まる） |

### 29.9 在庫の増減と単位の換算

**在庫の数は、入出庫の記録の合計で決まる。** 記録は足していくだけで、取り消しは逆の記録を足す。誰がいつ何をしたかが残る。

| 記録の種類 | 内容 |
|---|---|
| 入庫 | 数を足す（仕入・返品の戻りなど） |
| 使用（出庫） | 数を引く（接種・販売・使用・廃棄など）。理由を選べる |
| 移動 | 場所から場所へ |
| 調整 | 棚卸しの確定と数の直し。理由を必ず残す |

| 項目 | 規定 |
|---|---|
| 単位の換算（入り切り） | 在庫は**いちばん小さい使う単位**（例: 回）で持つ。入庫は仕入れの単位（箱・本）で入れ、入り数で換算する（「2 本」→「10 回」）。画面は両方で出す（「10 回（2 本）」） |
| 入れ方 | 画面で品目と数を選ぶ、バーコードを読む、**納品書の写真**（AI が行ごとに品名・品番・数・ロット・使用期限を読み、品目に照らして入庫にする。確認を挟まず、照らせない行だけを残す。ADR-0028。金額は使わない） |
| マイナスの在庫 | 記録は受け付け、画面と秘書で知らせる |
| 取り消し | 自分の記録はその日のうちなら「取り消す」で逆の記録を足せる。それ以外は調整 |
| すぐ反映 | 記録と同じトランザクションで使える数を直し、**公開にもすぐ反映する**（第29.12節） |
| 書かれた指示 | 納品書の文はデータであり、指示として扱わない（不変則 I-6） |

### 29.10 棚卸し

| 順 | 内容 |
|---|---|
| 1 | 棚卸しを始める。対象を選ぶ（全体・棚・分類）。選ばなければ全体 |
| 2 | スマホで棚を読む（または選ぶ）→ 品目のバーコードを読む。読むたびに 1 つ足す。箱で数えるときは数を入れる（単位の換算が効く） |
| 3 | 何人でも同時に数えられる（最初のお客様は 1 人）。同じ棚の同じ品目・ロットを別の人が数えたら足す |
| 4 | 数えた端から帳簿との差を出す（多い・少ない・数えていない）。差の大きいものから並べる |
| 5 | 確定する。差の分を「調整」にする。**数えていない品目は 0 にしない**。数えていない品目があれば確定の前に件数を示す |

| 項目 | 規定 |
|---|---|
| 数えている間の入出庫 | 止めない。棚卸しの行は数えた時点の帳簿の数と比べる |
| 確定できる人 | 始めた人と管理者。数だけを扱うため承認を挟まない（第29.18節） |
| 差の説明 | 確定の前に、秘書が差の大きい品目について最近の入出庫から考えられる理由を添える。**推測であることを書き、帳簿を勝手に直さない** |

### 29.11 バーコードの読み取り

| 項目 | 規定 |
|---|---|
| 方式 | スマホのブラウザでカメラを開き、続けて読む（アプリは入れない）。読めたら音と振動で知らせる |
| 端末 | Android の Chrome は標準の読み取り機能、iPhone の Safari は**読み取りの部品（ZXing など Apache 2.0 のもの）を画面に同梱**する。利用者のブラウザで動く部品であり、サーバーで第三者のコードを動かすのではない（不変則 I-7 に当たらない）。実機で確かめる（Q-110） |
| 読める種類 | JAN（EAN-13・EAN-8）、UPC、Code128、Code39、ITF、**GS1 データバー・GS1-128（医薬品。使用期限とロットを取り出す）**、QR（棚のラベル） |
| 読めないとき | 数字を手で入れるか、名前で探して選ぶ。暗い所のためにライトの入り切りを置く |
| 知らないバーコード | その場で「新しい品目にする」か「既にある品目に結び付ける」を選ぶ |
| パソコン | USB のバーコードリーダー（キーボードとして入力するもの）でも同じに動く |
| 安全 | カメラは画面を開いている間だけ使い、映像を送らない・残さない |

#### 29.11.1 画面

左ペインの「在庫管理」から開く。**説明文を常に出さない**（原則 u11）。**スマホで片手で使えることを先に考える**（第6.9節）。

| 部分 | 規定 |
|---|---|
| 一覧 | 品目の写真の縮小・名前・使える数（在庫・引き当て）・単位・残りわずかと期限の近いものの印。検索（名前・コード・バーコード）と「読む」（バーコードで探す） |
| 品目の詳細 | 項目（その場で直せる）、場所とロットごとの数と使用期限、入出庫の履歴、引き当て、バーコードの一覧、無くなる見込みの日 |
| 入出庫 | 「入庫」「使用」「移動」の 3 つ。読むか選ぶかで品目、数（単位の換算）、場所、ロット。**納品書を渡す**（写真・ファイル） |
| 引き当て | 予約の日時と品目と数。今日と明日の引き当てを上に出す |
| 棚卸し | 始める・続きを数える・差の一覧・確定。数える画面は、カメラと直前に読んだ品目と数だけを大きく出す |
| 公開 | 公開する品目と項目を選び、見本（実際に出る表）を見て承認する。埋め込みのコード（iframe）と JSON の URL を出す |
| 書き出し | 在庫の一覧・入出庫の記録・棚卸しの結果を CSV で |

### 29.12 公開（Web への反映。入り切り）

**在庫を Web ページにそのまま出す。** お手本（第29.1.1節）と同じく、Web サイトには**一度貼るだけ**で、あとは入出庫のたびにすぐ変わる。

| 項目 | 規定 |
|---|---|
| 出し方 | **① 埋め込みのページ**: M2Office が会社ごとの公開用のページ（表）を出し、Web サイトに iframe で貼る（WordPress に貼るのは制作会社）。**② 公開のデータ**: 同じ中身を JSON で出し、サイトの側で好きな見た目に組める（制作会社が自分で作るとき）。どちらもログインは要らない。WordPress の管理の鍵を M2Office に預からない |
| 出すもの | 公開すると決めた品目だけ。分類ごとに、公開する名前・商品名・**使える数か状態**・販売価格・最終更新の日時。**数を出すか、状態（在庫あり・残りわずか・終了）だけを出すかは会社が決める**（お手本は数を出している） |
| 色と状態 | 使える数が残りわずかの目安（最初のお客様は 3）以下なら「残りわずか」、0 なら「終了」。目安は品目ごとに変えられる |
| すぐ反映 | 入出庫・引き当て・期限切れのたびに、公開の中身を作り直す。ページは開くたびに最新を読む |
| **承認** | 公開は**社外に出るもの**である（第9.4.0節）。**何を公開するか（品目・出す項目・数か状態か）を、管理者が一度承認する**。承認した範囲での数の変化は、承認なしに自動で流す（1 件ずつ承認させると、すぐ反映できないため）。公開する品目・項目を変えたときは承認し直す。承認と変更は監査ログに残す |
| 出さないもの | 仕入れ値、ロット、場所、記録した人、内部のコード、**予約した人**。公開のデータに入る項目は、承認した項目だけ |
| 止める | 公開を止めると、埋め込みのページは「表示できません」になる。止めたことを監査ログに残す |
| 負荷 | 公開のページとデータは作り直したものを置いて配り、見る人が多くても在庫の表を直接読まない |

### 29.13 予約との引き当て（入り切り）

お手本では「予約が入るたびに減る」。予約で取り置いた数を、使える数から引く。

| 項目 | 規定 |
|---|---|
| 引き当て | 予約 1 件ごとに、品目と数（例: MR ワクチン 1 回）を取り置く。在庫は減らさず、**使える数だけを減らす**（公開もこの数） |
| 使ったとき | 来院して使ったら、引き当てを消して使用の記録を足す（引き当てた品目を選ぶだけで済む） |
| 取り消し・来なかった | 予約の取り消しで引き当てを消す。予約の日を過ぎた引き当ては、翌朝に秘書が「使った・取り消し」を尋ねる |
| **予約システムとのつなぎ** | 最初のお客様はメディカル革命 by GMO を使う。**予約の出し入れを受け取れる口（API・通知）があるかを確かめ（Q-113）、あれば会社の接続（第12.11節）としてつなぐ**。無ければ、受付が画面か秘書（「明日 10 時の MR ワクチン 1 回を取り置いて」）で引き当てる |
| 個人の情報 | 引き当てに**患者の氏名などを持たない**。予約の番号と日時だけを持つ（第29.17節） |

### 29.14 AI の見張り（欠品を防ぐ）

**AI が常に在庫を見張る。** 入出庫・引き当てのたびと、毎朝に見直す。

| 見張ること | 動き |
|---|---|
| 残りわずか | 使える数が目安以下になった品目を、**その場で**在庫管理を使う人に知らせる（お知らせ）。朝のブリーフにもまとめる |
| 無くなる見込み | 最近の使う速さ（過去 4 週）と引き当てから、**あと何日で無くなるか**を出す。仕入れにかかる日数（品目か仕入先ごと。分からなければ 7 日）より短ければ知らせる |
| 使用期限 | 期限の 30 日前・7 日前のロットを知らせる。使う順（第29.8節）を守れていないときも知らせる |
| 発注の案 | 知らせに**発注の案**（品目・数・仕入先）を添える。数は使う速さと仕入れにかかる日数から決め、理由を 1 行添える |
| 発注のメール | 仕入先がメールで受けるなら、発注のメールの**下書き**を作る（Gmail）。**送るのは承認のあと**（社外への送信。第9.4.0節）。Web で発注する仕入先には、発注の案と仕入先のページへのリンクを出す。電話の仕入先には、伝える内容をまとめて出す |
| 需要の予測 | Phase 2（Q-116）。季節と流行（インフルエンザの流行の情報など。Web の調べもの）から、残りわずかの目安と発注の数を AI が決める |

知らせる相手は、在庫管理の利用範囲の人のうち、在庫管理を最近使った人（入出庫・棚卸し）とする。**知らせる人の一覧を人に作らせない**（ADR-0028）。

### 29.15 秘書と業務から使う

| 依頼の例 | 秘書の動き |
|---|---|
| 「MR ワクチンの在庫は？」 | 使える数・在庫・引き当て・期限の近いロットを答える（`inventory.search`） |
| 「先週のトリビックの使用を教えて」 | 入出庫の記録から一覧にする（`inventory.history`） |
| 「ミールビックを 2 本入庫して」「化粧水を 1 本使った」 | 記録する（`inventory.move`、write-internal）。品目が決められなければ候補を挙げて尋ねる |
| 「明日 10 時の MR ワクチン 1 回を取り置いて」 | 引き当てる（`inventory.reserve`、write-internal） |
| 納品書の写真を渡す | 付属の業務「納品書から入庫」に取り次ぐ |
| 「足りなくなりそうなものは？」 | 無くなる見込みの早い順に答え、発注の案を添える |
| 「〇〇を発注して」 | 付属の業務「発注の下書き」に取り次ぐ（メールの下書きまで。送るのは承認のあと） |

| 道具 | 危険度 | 内容 |
|---|---|---|
| `inventory.search` | read | 品目と使える数・在庫・引き当て・ロットを探す |
| `inventory.history` | read | 入出庫の記録を期間で探す |
| `inventory.forecast` | read | 無くなる見込みの日と発注の案 |
| `inventory.move` | write-internal | 入庫・使用・移動を記録する |
| `inventory.reserve` | write-internal | 引き当てを足す・消す |
| `inventory.read_slip` | read | 納品書の画像から、行ごとの品名・品番・数・ロット・使用期限を取り出す |

| 業務 | 内容 |
|---|---|
| 納品書から入庫（公式・付属） | `inventory.read_slip` で読み、品目に照らして `inventory.move` で入庫する。照らせない行は残す。メニューには出さない |
| 発注の下書き（公式・付属） | 発注の案から、仕入先への発注のメールを作る（`gmail.create_draft` → 承認 → `gmail.send`）。送るのは承認のあと |

### 29.16 権限と記録

| 項目 | 規定 |
|---|---|
| 見られる人・記録できる人 | 在庫管理の利用範囲の全員 |
| 品目・場所の作成と変更 | 利用範囲の全員（直した人と日時を残す）。品目の止め・場所の削除は管理者 |
| 棚卸しの確定 | 始めた人と管理者 |
| 公開の承認・機能の入り切り | 管理者 |
| 監査ログ | 品目の取り込み、棚卸しの確定、調整、品目の止め、場所の削除、公開の承認・変更・停止、機能の入り切り、書き出し。**入出庫の 1 件ずつは監査ログに入れない**（入出庫の記録そのものが誰がいつを持ち、消せないため） |
| テナント境界 | すべての表をテナント ID で絞る（不変則 I-2）。公開のページとデータは会社ごとの推測されにくい URL で出し、承認した項目だけを入れる |

### 29.17 医療で使うときの線引き

| 項目 | 規定 |
|---|---|
| 患者の情報 | **持たない。** どの患者にどのロットを使ったか（接種の記録）は電子カルテの役割であり、要配慮個人情報に当たる。使用の記録と引き当てには、日時・数・ロット・予約の番号だけを持つ |
| 法令 | 医薬品の保管や記録の義務に合っているかの判断はしない。記録を出せる（CSV）ようにするまでにする |
| 公開の言葉 | 在庫の表に効能や接種の可否を書かない（医療の広告の決まりに関わるため）。出すのは名前・数か状態・価格・更新の日時だけ。説明の文はサイトの側で書く |

### 29.18 お金と社外への境界

| 項目 | 規定 |
|---|---|
| 数の記録 | 入出庫・引き当て・棚卸しの確定は**数だけ**を扱い、お金の確定に当たらない。承認を挟まない |
| 販売価格 | 公開の表に出す値。在庫の評価ではない。公開は第29.12節の承認の範囲で出す |
| 在庫の金額 | Phase 2（Q-108）。扱うときは、棚卸しと評価の確定を「お金の確定」として承認の対象にする |
| 発注 | 発注のメールを仕入先へ送るのは社外への送信。承認のあと |
| 公開 | 社外に出るもの。何を出すかを一度承認し、その範囲の数の変化は自動で流す（第29.12節） |

### 29.19 データモデル

第19.1節に次を加える。

| エンティティ | 主な項目 |
|---|---|
| `inventory_item`（品目） | tenant_id、名前、公開する名前、自社のコード、分類、単位、入り数、販売価格、写真、残りわずかの目安、仕入先、仕入れにかかる日数、メモ、状態 |
| `inventory_code`（バーコード） | tenant_id、item_id、値、種類。会社の中で重ならない |
| `inventory_location`（場所） | tenant_id、倉庫、棚、ラベルの値（QR） |
| `inventory_lot`（ロット） | tenant_id、item_id、ロット、使用期限 |
| `inventory_move`（入出庫の記録） | tenant_id、種類、item_id、lot_id、場所（元・先）、数（使う単位）、理由、元になったもの（納品書・棚卸し・引き当て）、記録した人と日時。**追記のみ** |
| `inventory_stock`（いまの数） | tenant_id、item_id、location_id、lot_id、数。入出庫の記録と同じトランザクションで直す |
| `inventory_reservation`（引き当て） | tenant_id、item_id、数、予約の番号と日時、状態（取り置き・使った・取り消し）、出どころ（画面・秘書・予約システム）。**患者の情報を持たない** |
| `inventory_count`・`inventory_count_line`（棚卸し） | 対象・状態・始めた人と確定した人。行は品目・ロット・場所・数えた数・数えた時点の帳簿の数・数えた人 |
| `inventory_publication`（公開） | tenant_id、承認した品目と項目、数か状態か、承認した人と日時、公開の URL の鍵、状態（公開中・停止） |

### 29.20 ほかのシステムとの関係

| 相手 | 関係 |
|---|---|
| Web サイト（WordPress） | 公開の埋め込みのページか JSON を、制作会社が一度貼る（第29.12節）。WordPress の管理の鍵は預からない |
| 予約システム（メディカル革命 by GMO） | 予約の出し入れを受け取れる口があれば、会社の接続としてつなぎ、引き当てにする（Q-113） |
| 仕入先（問屋） | メールは発注のメールの下書き（承認のあと送る）。Web は案とリンク。電話は伝える内容 |
| 販売管理・会計・EC | Phase 2。いまの最初のお客様は Excel のため、**M2Office を在庫の正とする** |

### 29.23 行わないこと

| 行わないこと | 理由 |
|---|---|
| 患者の情報を持つ | 電子カルテの役割。要配慮個人情報（第29.17節） |
| 会計の帳簿そのもの | 会計のソフトの役割 |
| 発注のメールを承認なしに送る | 社外への送信は承認が要る（第9.4.0節） |
| 承認していない品目・項目を公開する | 社外に出るもの（第29.12節） |
| 数えていない品目を 0 にする | 数え忘れで在庫を消さないため |
| 期限切れのロットを自動で消す | 廃棄は人が確かめて記録する |
| カメラの映像を送る・残す | 読み取ったバーコードの値だけで足りる |
| お客様ごとの作り分け | 会社ごとの入り切りと品目の項目で吸収する（第29.4節） |
