## 42. 販売の書類と受注（第 0.457.0 版で案、第 0.458.0 版で確定し段 1 を実装。Q-272・Q-273、ADR-0112）

この章で決めること: **注文書・納品書・請求書・領収書を作り、受け取った注文書を読み込んで受注として整理する**しくみ。
方針の見直し、書類の流れとつながり、4 つの書類の作り方、納品書と請求書の連動、受注の取り込みと管理、残し方（電子帳簿保存法）、秘書からの頼み方、権限と記録、データモデル、段階。

**この章は確定した**（2026-10-26 に三浦さんが案のとおりに決めた）。2026-10-26 に三浦さんが「注文書の作成、請求書の作成、納品書の作成、領収書の作成。この新たな項目の作成をお願いします。請求書と、納品書は連動して欲しいです。また、受注の管理として、受け取った発注書を読み込んで、整理する機能の実装もお願いします」と求めた。

### 42.1 方針の見直し（お金の機能との境）

2026-10-06 に、M2Office はお金の機能を扱わず、請求・経費・入金・支払いは税理士と会計パッケージで扱うと決めた（第9.5節）。
今回の依頼を受けて、**書類を作るところまでを扱い、お金の動きは引き続き扱わない**に改める（ADR-0112）。

| 扱う | 扱わない（これまでどおり） |
|---|---|
| 注文書・納品書・請求書・領収書を作る・発行する・送る・残す・探す | 入金の確かめと消込（AG-09）、支払いの予定と振込、経費の精算、証憑の整理（AG-08） |
| 受け取った注文書を読み込み、受注として整理する。納品・請求の進み具合を追う | 売掛金・買掛金の残高、入金の催促、仕訳と会計への書き込み、会計システムとの連動（第24.5節） |
| 書類の金額を、数量と単価から決まった計算で出す | 値付け・値引き・利益の判断、資金繰り |

**入金があったかどうかは、M2Office は確かめない。** 領収書は、本人が「入金があった」と伝えたときに作る（第42.4.4節）。
請求書を発行したあとの入金の管理は、会社の会計パッケージで行う。

### 42.2 書類の流れとつながり

```
（見積書 第9.5.8節）
      │ 見積から受注にする
      ▼
  受注 ◀── 受け取った注文書を読み込む（第42.5節）
      │
      ▼
  納品書 ──（まとめて／そのまま）──▶ 請求書 ──（本人が入金を伝える）──▶ 領収書

  注文書（こちらから仕入先・外注先へ出す。上の流れとは別）
```

| つながり | 規定 |
|---|---|
| 見積書 → 受注 | 見積書から「受注にする」で、宛先と品目と単価を引き継ぐ。受け取った注文書を読み込んだときは、同じ取引先の見積書を AI が探してつなぐ（品目と単価の違いは印にする） |
| 受注 → 納品書 | 受注の品目と数を引き継ぐ。一部だけ納めるときは、納めた数だけの納品書を作り、受注に残りの数を出す |
| 納品書 → 請求書 | 第42.4.2節（連動） |
| 請求書 → 領収書 | 請求書の宛先と金額（一部の入金なら伝えられた額）を引き継ぐ |
| 書類の間を開く | どの書類からも、つながった前後の書類を開ける（受注の画面に、納品書・請求書・領収書を並べる） |

**つながりは AI が決める。人に選ばせない**（ADR-0028）。「〇〇社の今月分を請求して」と頼めば、その取引先の未請求の納品書を集める。違っていれば会話で直す。

### 42.3 4 つの書類に共通すること

| 項目 | 規定 |
|---|---|
| 起動 | 秘書への依頼（「〇〇社に納品書を作って」）、メニューの業務、受注の画面のボタン |
| 書式 | 会社の帳票の体裁（第15.2.2節）と型・印影（第15.2.3節）を使う。**型は見積書で選んだものを 4 つの書類にも使う**（書類ごとに会社に選ばせない）。表題と前文の既定は M2Office が書類ごとに持つ（御注文書・納品書・御請求書・領収書。前文は「下記の通り、注文いたします。」「下記の通り、納品いたします。」「下記の通り、ご請求申し上げます。」）。会社がいま使っている書類を見本として渡せば、見積書と同じく AI が表題・前文・備考を寄せる |
| 宛先 | 会社名・部署・担当・住所。名刺（第27章）・前の書類・受注から AI が埋める。取引先の台帳を人に作らせない |
| 品目 | 品名・数量・単位・単価・**税の区分**（標準・軽減（飲食料品）・軽減（新聞）・対象外。税率は区分と取引の日から決める。第15.1.1節。第 0.462.0 版で実装）・区分の見出し・値引き。単価の無い品目は、同じ取引先の前の書類と見積書の同じ品目から引く。それでも無ければ空けて作り、「単価が入っていない品目があります」と示す（聞き返さない） |
| 金額の計算 | **推論に計算させない。** 見積書と同じ決まった計算（`quoteTotals`）で、小計・税率ごとの消費税・合計を出す。端数は会社の設定。税率ごとに 1 回だけ端数を処理する（第15.1節） |
| インボイスの記載 | 請求書・領収書は、適格請求書の記載事項（登録番号・取引の日・内容と軽減税率の対象である旨・税率ごとの合計と税率・税率ごとの消費税額・宛先）を満たす。登録番号が会社情報に無ければ、作れるが「登録番号が会社情報にありません」と示す |
| 番号 | 書類の種類ごとの頭文字と日本時間の日付と連番（注文書 `O-`、納品書 `D-`、請求書 `I-`、領収書 `R-`。見積書の `Q-` と同じ形）。在庫の発注書の `PO-`（第29.14.5節）とは分ける |
| 残すもの | PDF を会社のファイルとして残す。**Google ドキュメントには写さない**（発行した書類を手で書き換えられる写しを作らないため。見積書とは違う） |
| 送る | 本人が「送って」と言えば、宛先のメールの下書きに PDF を添える。**送るのは承認の後**（社外への送信）。承認の画面では金額を目立たせる（第9.4.0節） |
| 持ち帰る | 送らずに PDF を開いて、印刷・FAX・郵送に使ってもよい |

#### 42.3.1 発行と承認

| 書類 | 作ったとき | 発行 |
|---|---|---|
| 納品書 | すぐ発行済み（見積書と同じ）。番号が付く | — |
| 注文書 | **下書き**（PDF に薄く「下書き」と入れ、番号は「発行時に付けます」） | **本人の承認で発行する**（仕入先への支払いを約束する書類のため） |
| 請求書 | 同上 | **本人の承認で発行する**（請求の確定。危険度 `financial`。第9.4.0節） |
| 領収書 | 同上 | **本人の承認で発行する**（お金を受け取ったことを示す書類のため） |

| 項目 | 規定 |
|---|---|
| 承認の画面 | PDF と、宛先・合計・税率ごとの内訳・支払期限を出す。送るなら、メールの宛先と本文も同じ画面に出し、**1 回の承認で発行と送信を行う**（2 回押させない） |
| 承認する人 | 依頼した本人（`approver: requester`）。会社の自動化ポリシーで、経理の役割の人に回すこともできる（第9.2.3節） |
| 番号 | 発行したときに付ける（下書きのうちに番号を使わず、番号が飛ばないようにする） |
| 却下 | 下書きのまま残す。会話で直して、もう一度発行に回せる |

#### 42.3.2 直す・取り消す

| 場面 | 規定 |
|---|---|
| 下書きを直す | 会話で直す（「単価を 5,000 円に」）。同じ下書きを書き換える。下書きは削除できる |
| 発行した書類を直す | **前の版を消さずに、同じ番号の新しい版を作る**（版 2。PDF の番号の横に「訂正」）。前の版は書類の画面から開ける。注文書・請求書・領収書は、新しい版も承認で発行する |
| 取り消す | 発行した書類は削除せず「取り消し」にし、理由を残す。請求書を取り消すと、まとめた納品書は未請求に戻る |
| 記録 | 発行・訂正・取り消しは監査ログに残す（誰が・いつ・どの版） |

### 42.4 書類ごとのこと

#### 42.4.1 注文書

こちらから仕入先・外注先に出す書類。

| 項目 | 規定 |
|---|---|
| 載せるもの | 注文番号・注文日・宛先（「御中」）・自社の差出人と印影・品目（品名・数量・単位・単価・金額）・小計・消費税・合計・納期・納品場所・支払い条件・備考 |
| 業務の委託 | 相手に作業や製造を委託する注文で、相手が中小の受託事業者に当たるときは、明示する事項（委託の内容・代金の額・支払期日・納める日と場所）を欠かさない（中小受託取引適正化法。2026 年 1 月に下請法から改められた）。欠けていれば「支払期日が入っていません」と示す。当たるかどうかは AI が依頼から推し量り、分からなければ欠けている項目を示すだけにする |
| 在庫の発注との分け方 | 在庫管理の品目の補充は、これまでどおり在庫の発注（金額を載せない発注書・入荷の消し込み。第29.14.4節）で行う。注文書は金額を載せて出す注文（外注・在庫で数えない物品）に使う。秘書は依頼の品目が在庫の品目かで振り分ける |

#### 42.4.2 納品書と請求書の連動

**納品書と請求書は、同じ品目と金額を二度書かせない。** どちらから始めても、もう一方はつながったものから作る。

| 頼み方 | 動き |
|---|---|
| 「〇〇社に納品書を作って」 | 受注（あれば）から納品書を作る。請求はまだしない（未請求の納品書として残る） |
| 「納品書と請求書を作って」 | 同じ品目で納品書を作り（発行済み）、その納品書を明細にした請求書の下書きを作る。請求書は承認で発行する |
| 「〇〇社の今月分を請求して」（まとめて請求） | その取引先の、締め日までの**未請求の納品書をすべて集めて** 1 枚の請求書の下書きを作る。明細は納品書ごとに区分の見出し（「10/3 納品 D-20261003-001」）を付けて並べる。合計の欄に「今回のご請求額」を出す |
| 「この納品書を請求して」 | その 1 枚だけで請求書の下書きを作る |
| 請求書から始めたとき（「〇〇社に請求書を作って」） | 未請求の納品書があれば、それを集めて作る。無ければ、依頼の品目で請求書を作り、**同じ品目の納品書を作るかは聞かない**（作らない）。あとから「納品書も」と頼めば、その請求書の品目で納品書を作ってつなぐ |

| 決まり | 規定 |
|---|---|
| 状態 | 納品書は **未請求** → **請求済み**（請求書を発行したとき）。請求書の下書きにまとめた納品書は、発行するまで未請求のまま |
| 重ねない | 1 枚の納品書は 1 枚の請求書にしか入らない。すでに請求済みの納品書をまとめようとしたら外し、「D-… はすでに I-… で請求しています」と示す |
| 金額の一致 | 請求書の明細は納品書の品目・数量・単価をそのまま使い、金額は請求書の側で決まった計算をし直す（税率ごとの端数は請求書で 1 回） |
| 納品書を直したとき | 未請求なら、そのまま直せる。請求済みの納品書を訂正したら、請求書は自動では直さず、請求書の画面と作った人への知らせに「納品書 D-… が訂正されました。請求書の訂正版を作りますか」と出す（発行した請求書を勝手に変えない） |
| 締め日 | 会社の既定は月末締め。取引先ごとの締め日・支払い条件は、会話（「〇〇社は 20 日締めの翌月末払い」）か、受け取った注文書・前の請求書から AI が覚える。表を作らせない |
| 支払期限 | 取引先の支払い条件、無ければ会社の帳票の体裁の支払期限の既定から、日付を求めて載せる |
| 振込先 | 会社の帳票の体裁の振込先を請求書に載せる（納品書・領収書には載せない） |

**締めの知らせ（段 2）**: 締め日の翌朝、未請求の納品書がある取引先ごとに請求書の下書きを作っておき、作った人に「〇〇社ほか 3 社の請求書の下書きができています」と知らせる。発行は承認で行う（下書きを作るのは社内のことなので、確かめを挟まない）。

#### 42.4.3 請求書

| 項目 | 規定 |
|---|---|
| 載せるもの | 請求番号・請求日・宛先・自社の差出人と登録番号と印影・件名・今回のご請求額・品目（まとめた納品書ごとの区分）・税率ごとの小計と消費税・合計・支払期限・振込先・備考 |
| 前回の残り | 前回の請求の入金の有無・繰越の額は**載せない**（入金を管理しないため）。載せたい会社は会計パッケージの請求書を使う |
| 源泉徴収 | 士業などへの報酬で源泉徴収が要る請求は、段 1 では扱わない（第15.1節の TBD のまま）。依頼にあれば「源泉徴収のある請求書は、まだ作れません」と答える |

#### 42.4.4 領収書

| 項目 | 規定 |
|---|---|
| 作るとき | 本人が「〇〇社から入金があったので領収書を」と伝えたとき。**M2Office は入金を確かめない**（本人の言葉による） |
| 元の請求書 | その取引先の発行済みの請求書から AI が探してつなぐ。一部の入金なら、伝えられた額で作る。請求書が無い取引（店頭の売上など）は、依頼の内容だけで作る |
| 載せるもの | 領収番号・日付・宛名（「様」「御中」）・金額（「￥」と「-」で挟む）・但し書き（請求の内容から。「〇〇代として」）・税率ごとの内訳と消費税額・登録番号・差出人と印影 |
| 収入印紙 | 紙で渡す領収書は、記載された金額（税抜の額が書いてあればその額）が 5 万円以上だと収入印紙が要る。**PDF をメールで送るときは要らない。** 発行のときに、紙で渡しそうな頼み方（「印刷して」）で 5 万円以上なら、承認の画面に一言出す。印紙の欄は作らない |
| 請求書の状態 | 請求書に「領収書 R-… を発行」とつなぐだけにし、入金済みかどうかの状態は持たない |

### 42.5 受注の管理

受け取った注文書を読み込み、受注として整理し、納品と請求まで追う。

#### 42.5.1 取り込み

| 入り口 | 規定 |
|---|---|
| 受注の画面 | 注文書のファイル（PDF・画像・Excel・Word）を置く。いくつも置ける |
| 秘書 | 注文書を渡して「受注に入れて」、または「さっきのメールの注文を取り込んで」（メールの本文と添付） |
| メール（段 2） | メールの整理（AG-01）で、取引先からの注文書らしい添付・本文を見つけたら、自動で取り込み、受け付けた人に知らせる（確かめを挟まない。違えば受注の画面で削除する） |

| 読み取る項目 | 内容 |
|---|---|
| 取引先 | 会社名・部署・担当・住所・電話・メール |
| 相手の注文 | 相手の注文番号・注文日 |
| 品目 | 品名・品番・数量・単位・単価・金額 |
| 条件 | 希望の納期・納品先・支払い条件（締め日・支払日）・備考 |
| 相手の合計 | 相手が書いた小計・消費税・合計（こちらの計算と比べるため） |

##### 42.5.1.1 手で入れる（電話などで受けた注文。第 0.459.0 版で案、第 0.460.0 版で確定して実装。Q-274）

2026-10-26 に三浦さんが、受注を手でも入れられるよう求めた。中小企業では電話で受ける注文も多い。注文書が無い注文も、同じ受注として納品書・請求書につなぐ。

| 入り口 | 規定 |
|---|---|
| 秘書（主な入り口） | 電話を受けながら・受けた後に話すか書く。「見本商事の山田さんから電話。ケーブル 3m を 10 本、11 月 5 日までに」。AI が取引先・品目・数・納期・納品先を読み取り、受注にする。**足りない項目は聞き返さずに空けて作り**、「単価が入っていません」のように印を付ける（第42.5.2節と同じ）。取引先の名前は、名刺・前の受注と書類・見積書から AI が正式な名前に寄せる（「見本商事」→「株式会社見本商事」） |
| 受注の画面 | 「注文書を取り込む」の隣に「**手で入れる**」。取引先・品目（品名・数量・単位・単価）・納期だけの短い欄を開く。注文日は今日、税率は 10% を既定にし、ほかの項目（相手の注文番号・納品先・支払い条件・備考・軽減税率）は「詳しく」を開いたときだけ出す |
| 入れやすくすること | 取引先は、前の受注と書類の取引先から候補を出す。品名は、その取引先の前の受注・書類・見積書の品目から候補を出し、選ぶと単位と単価が入る。単価を空けて保存すれば、注文書の取り込みと同じく前の単価を補う |
| 記録 | 入り口は「手で入れた」（画面）か「秘書」で残す。元の注文書は無い。入れた人と日時を残す |
| 二重 | 同じ取引先・同じ注文日・同じ品目と数の受注が既にあれば、作らずにその受注を示す（同じ日に同じ品目を数を変えて頼むことはあるため、数も比べる）。手で入れた受注（注文書も相手の注文番号も無い）と同じ品目と数の注文書が 14 日のうちに届いたら、新しく作らずにその受注に注文書をつなぎ、相手の注文番号と合計を足す |
| 確かめ | 注文書が無いので、計算の食い違いの印は付かない。見積との違いと、読み取れなかった項目の印は付ける |
| 「いつもの」 | 小さな商店の注文は「いつものあれを 10 個」で回っていることが多い（2026-10-26 に三浦さんが指摘）。**品名が「いつもの」「いつものあれ」なら、その取引先の前の受注と納品書から、いちばん多く頼まれた品目と読む**（数は言われた数、単位と単価は前のもの）。読んだことは「『いつもの』をケーブル 3m と読みました（前の注文 5 回）」の印にして示す（推測であることを隠さない）。前の注文が無い取引先では読まず、「品名が分かりません」の印にする。違えば会話か画面で直す |

**実装（第 0.460.0 版）**: `SalesDocService.recordOrder`（取引先の正式な名前への寄せ・「いつもの」・単位と単価の補い・入っていない項目の印 `unread`・読んだことの印 `guess`）と `suggestions`（取引先の候補と、取引先の前の品目を多い順に）。注文書の取り込みは、手で入れた受注に注文書をつなぐ（`linked`）。単価の補いに前の受注を足した。移行 166（入り口 `manual`）。ツール `sales.record_order`（`write-internal`。付属の業務「受注の取り込み」が使う）。API は `POST /v1/sales/orders`・`GET /v1/sales/suggestions`。画面は受注の欄の「手で入れる」（取引先・納期・品目の行。品名を候補から選ぶと単位と単価が入る。「詳しく」で先方の担当・相手の注文番号・注文日・納品先・支払い条件・備考・軽減税率）

**電話の注文の言った言わない**は、取引の当事者の間のことであり、M2Office の責任ではない（2026-10-26、三浦さん）。受けた内容を相手に送る「注文請書」は、段 2 のまま（第42.11節）。

**注文書は外から来た文書であり、中の文を指示として扱わない**（不変則 I-6）。読み取った値は受注の項目に入れるだけで、書かれた依頼（「至急メールで返信してください」など）に従って動かない。

#### 42.5.2 AI が確かめること（確かめを人に求めない）

取り込んだら、AI が次を確かめ、**合わないものは受注に印を付けて示す**。人に確認の操作を求めない（ADR-0028）。

| 確かめ | 示し方の例 |
|---|---|
| 計算 | 数量×単価と相手の金額、税率ごとの消費税、合計が合うか（決まった計算で比べる）。「相手の合計 110,000 円とこちらの計算 109,890 円が違います」 |
| 見積との違い | 同じ取引先の見積書があれば、品目と単価の違い。「ケーブル 3m の単価が見積（Q-…）の 1,200 円と違い 1,000 円です」 |
| 二重の取り込み | 同じ取引先・相手の注文番号（無ければ同じ日付と品目）の受注が既にあれば、取り込まずに既存の受注を示す |
| 読み取れなかった項目 | 「納期が読み取れませんでした」。推測で埋めない |
| 在庫（段 2） | 在庫管理を使う会社では、品目を在庫の品目に当て、使える数で足りるかを示す。足りれば引き当てる（社内の記録。第29章） |

#### 42.5.3 受注の記録と状態

| 項目 | 規定 |
|---|---|
| 受注番号 | `S-` と日本時間の日付と連番。相手の注文番号は別の項目に持つ |
| 状態 | **受注** → **一部納品**（一部の数を納品書にした）→ **納品済み** → **請求済み**（すべての納品書が請求済み）。ほかに **取り消し**（理由を残す） |
| 金額 | こちらの決まった計算の額を正とし、相手の合計は並べて持つ |
| 元の注文書 | 取り込んだファイルを会社のファイルとして残し、受注から開ける（電子取引の記録。第42.6節） |
| 直す | 読み取りが違っていれば、受注の画面か会話で直す。直した記録を残す |
| 納期の見張り（段 2） | 納期が明日の受注と、納期を過ぎて納品済みにならない受注を、毎朝、受注を取り込んだ人に知らせる |

#### 42.5.4 画面

**受注**（左のメニューの「受注と販売の書類」。使える人にだけ出す。道は `/sales`、1 件は `/sales/<受注か書類の ID>`）

| 部分 | 中身 |
|---|---|
| 置き場 | 注文書のファイルを置く欄（ドラッグでも選んでも） |
| 一覧 | 受注番号・取引先・相手の注文番号・注文日・納期（過ぎたら赤）・合計・状態・印（合わないところがあれば）。状態と取引先で絞り、取引先・品名・番号で探せる |
| 詳細 | 読み取った項目と明細、印の中身、元の注文書を開く、つながった見積書・納品書・請求書・領収書。操作は「納品書を作る」「請求書を作る」「取り消し」 |

**書類**（同じ画面の 2 つ目の欄。発行した書類の一覧）

| 部分 | 中身 |
|---|---|
| 一覧 | 種類・番号・日付・宛先・合計・状態（下書き・発行済み・未請求・請求済み・取り消し）。種類で絞り、**取引の日付の範囲・金額の範囲・取引先で探せる**（第42.6節） |
| 操作 | 1 通の画面で PDF を見ながら行う。PDF を保存・送る（送り先を入れて業務に頼む。送るのは承認の後）・直す／訂正版を作る（直したいことを書いて業務に頼む）・取り消し。下書きは「**発行**」（本人が押す。番号が付き、書き換えられなくなる）・「発行して送る」・「削除」。発行済みの納品書は「請求書を作る」、発行済みの請求書は「領収書を作る」。未請求の納品書は一覧で選んで「選んだ納品書で請求書を作る」 |

画面に説明の文は常に出さない（原則 u11）。分からなければ秘書に聞く。

### 42.6 残し方（電子帳簿保存法）

| 項目 | 規定 |
|---|---|
| 残すもの | 発行した書類の PDF（すべての版）と、受け取った注文書のファイル（メールで来たものを含む）。電子で送った・受け取った書類は電子取引の記録になる |
| 書き換えない | 発行した書類は書き換えず、訂正は新しい版、取り消しは状態で表す（第42.3.2節）。受け取った注文書のファイルも書き換えない。受注の読み取りを直しても、元のファイルはそのまま |
| 探せること | 取引の日付・金額・取引先で探せる（日付と金額は範囲で。2 つ以上を組み合わせて）。書類の画面と秘書（「先月の 10 万円以上の請求書」）から |
| 残す期間 | **10 年を既定とする**（法人の帳簿書類は 7 年、欠損金のある年度は 10 年のため、長いほうに合わせる）。実行の記録の保存期間（第19.3節）とは別に持ち、期間の中は削除しない（下書きと取り消し前の削除は除く） |
| 会社をやめるとき | 書類と元の注文書を、取引の日付・取引先・番号の索引を付けて書き出せる（第19.3節のデータの持ち出しに含める） |

### 42.7 秘書と業務から使う

| 依頼の例 | 秘書の動き |
|---|---|
| 「A 社から注文書が来たので受注に入れて」（ファイルを渡す） | 受注の取り込みの業務に回し、取り込んだ受注と印を答える |
| 「A 社の注文、納期はいつ？」「納品していない受注は？」 | 受注を引いて答える（読むだけ） |
| 「A 社の受注分、納品書を作って」 | 納品書の業務に回す |
| 「A 社の今月分を請求して」 | 請求書の業務に回す（未請求の納品書をまとめて下書き。発行は承認） |
| 「B 社から入金があったので領収書を送って」 | 領収書の業務に回す（請求書を探し、下書き → 承認で発行と送信） |
| 「C 社に部品の加工を 30 万円で注文書を」 | 注文書の業務に回す |
| 「先月 A 社に出した請求書は？」 | 書類を引いて答える（番号・日付・合計・状態） |

### 42.8 業務とツール

| 業務 | ID | 段 | 最上位の危険度 |
|---|---|---|---|
| 注文書の作成 | `sales-docs:purchase-order` | 作成 → 発行（承認）→ 送る | `financial`（発行）・`external-send`（送る） |
| 納品書の作成 | `sales-docs:delivery-note` | 作成 → 送る（承認） | `external-send`（送るとき）。作るだけなら `draft` |
| 請求書の作成（AG-06） | `sales-docs:invoice` | 作成 → 発行（承認）→ 送る | `financial`・`external-send` |
| 領収書の作成 | `sales-docs:receipt` | 作成 → 発行（承認）→ 送る | `financial`・`external-send` |
| 受注の取り込み | `sales-docs:order-intake` | 読む → 整理 | `write-internal` |

| ツール | 危険度 | 内容 |
|---|---|---|
| `sales.create_document` | draft | 書類を作る（種類・宛先・品目・つなぐ受注と納品書）。単価の補い・決まった計算・PDF。注文書・請求書・領収書は下書き、納品書は発行済み |
| `sales.issue` | financial | 下書きを発行する（番号を付け、「下書き」を外した PDF を作り直し、つないだ納品書を請求済みにする）。承認の段の後だけ呼べる |
| `sales.revise` / `sales.cancel` | draft / write-internal | 訂正版を作る・取り消す（理由を残す） |
| `sales.documents` | read | 書類を探す（種類・取引先・日付と金額の範囲・状態）。秘書の調べものも使う |
| `sales.prepare_mail` | read | 送るメールの宛先・件名・本文と添付を組み立てる（見積書の `quote.prepare_mail` と同じ。送り先が無ければ「取得できなかった」形で返す） |
| `sales.import_order` | write-internal | 注文書を読み、受注を作る（確かめと印を含む） |
| `sales.orders` | read | 受注を探す |
| `sales.update_order` | write-internal | 受注を直す・取り消す |
| `sales.remember_party` | write-internal | 取引先の締め日と支払い条件を覚える（「A 社は 20 日締め翌月末払い」） |

送るのは、これまでどおり `gmail.send`（添付つき）。発行と送信は同じ承認の段にまとめる（第42.3.1節）。

### 42.9 権限

| 操作 | できる人 |
|---|---|
| 入り切り | 内蔵の拡張「販売の書類と受注」（ID `sales-docs`。第12.13節）として、管理者が拡張機能の画面で入れる。既定は切り |
| 書類を作る・受注を取り込む・見る | 拡張機能の利用範囲（第16.7節）の中の人。**初めて入れたときは管理者だけ**にし、管理者が「利用できる人」で経理・営業などのグループに広げる（会社に経理・営業の役割は無いため、グループで表す。第 0.458.0 版で改めた） |
| 発行 | 業務では依頼した本人の承認（会社の自動化ポリシーで経理の役割に回せる）。画面では、使える人が下書きを見て「発行」を押す（本人の判断） |
| 書類と受注の一覧 | 使える人は会社の書類と受注をすべて見られる（取引先とのやりとりは会社のもの）。取り消しは作った人と管理者 |

### 42.10 データモデル

| 表 | 主な項目 |
|---|---|
| `sales_orders`（受注） | 会社・受注番号・取引先（名前・部署・担当・住所・連絡先）・相手の注文番号・注文日・納期・納品先・支払い条件・品目・こちらの計算の額・相手の合計・状態・印・元の注文書のファイル・つないだ見積書・取り込んだ人・入り口（画面・秘書・メール） |
| `sales_documents`（書類） | 会社・種類（注文書・納品書・請求書・領収書）・番号（下書きは空）・版・前の版・状態・取引先・品目・小計・税率ごとの消費税・合計・取引の日・支払期限または納期・つないだ受注・請求書（納品書と領収書から）・PDF のファイル・取り消しの理由・実行・作った人 |
| `sales_parties`（取引先の覚え） | 会社・取引先の名前・宛名の敬称・締め日・支払い条件・覚えた出どころ（会話・注文書・前の書類）。AI が書き、人に表を作らせない |

すべて会社ごとの行単位の分離（不変則 I-2）。番号は会社と種類と日付ごとの連番。

### 42.11 段階

| 段 | 中身 |
|---|---|
| 段 1 | 4 つの書類（作る・発行の承認・送る・訂正・取り消し）、納品書と請求書の連動（1 枚・まとめて）、受注の取り込み（画面・秘書）と確かめと一覧、書類の一覧と検索、残し方 |
| 段 2 | メールに届いた注文書の自動の取り込み、締めの知らせと請求書の下書き、納期の見張り、在庫との連動（受注の引き当て）、注文請書 |

**実装（第 0.458.0 版、段 1）**: 内蔵の拡張「販売の書類と受注」（`packages/core/src/sales-docs/`）。移行 165（`sales_orders`・`sales_documents`・`sales_parties` と会社の設定の `sales_docs`。会社ごとの行単位の分離）。決まった計算（`calc.ts`。金額は見積書の `quoteTotals`、支払期限は「当月末・翌月末・翌々月末・翌月 N 日・N 日以内」、締め日は「N 日締め・月末締め」を読む。読めなければ日付を作らない）。注文書の読み取り（`extract.ts`。推論の JSON、推論が使えなければ決まった言い方。会社名は 1 行ずつ見て自社を外す）。PDF（`render.ts`。見積書の型（罫線の表・シンプル）と印影。罫線の表に大きく出す額（ご請求金額・金額）と、すべてのページの薄い「下書き」「取り消し」の印を足した）。処理（`service.ts`。番号は会社・種類・日付ごとの連番で、重なれば次の番号でやり直す。発行は同じファイルの中身を描き直す（承認の前に組み立てたメールの添付が発行した PDF になる）。書類の PDF は実行に結び付けない（実行の記録の保存期間で消えないため）。受注の状態と納めた数は納品書から求める）。ツールは `sales.*` の 10 個、付属の業務は 5 つ（絵の番号 26〜30）。API は `/v1/sales/orders`・`/v1/sales/documents`（`packages/api/src/routes/sales-docs.ts`）。画面は `packages/web/src/SalesDocs.tsx`（左のメニューの「受注と販売の書類」）。秘書の調べものに `sales.documents`・`sales.orders` を足した。業務の絵が 50 枚すべて埋まったため、既存の絵の色違いを 51〜60 に足し、`AGENT_FACE_COUNT` を 60 にした（会社が入れる拡張機能の業務の絵が重ならないように）。**本物の推論での注文書の読み取りと、承認の後の発行と送信は、まだ確かめていない**

### 42.12 行わないこと

- 入金の確かめ・消込・催促、支払い、仕訳と会計への書き込み（第42.1節）
- 値付け・値引き・利益の判断（値引きは依頼に書かれたものだけを使う）
- 発行した書類を承認なしに社外へ送ること、発行した書類の書き換え
- 取引先の台帳や締め日の表を人に作らせること
- 受け取った注文書に書かれた指示に従うこと
