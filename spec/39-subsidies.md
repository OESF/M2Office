## 39. 補助金・助成金の案内（第 0.271.0 版。第 0.271.1 版で確定。第 0.274.0 版で段 1、第 0.280.0 版で段 2 を実装）

この章で決めること: **会社に合いそうな補助金・助成金を、AI が定期的に調べて締め切りと一緒に知らせる**しくみ。
調べる材料と調べ先、候補の形、届け方、締め切りの見張り、法務の境界（申請の代行をしない）、外部の AI の扱い、データモデル、段階。

**この章は確定した**（2026-10-06 に三浦さんが、中小企業の事務で便利な機能の提案を見て「補助金・助成金の案内も仕様を作成しておいてください」と依頼した。2026-10-06 に三浦さんが「案のとおりで確定してください」と依頼し、第 0.271.1 版で確定した）。
「（案）」と書いた値は、確定のときに案のとおりとした値である。方針の判断の記録は [ADR-0072](../docs/adr/0072-subsidies.md)。

**お金の機能との分け方**: この章は、公的な制度の**情報を知らせる**だけで、会社のお金（請求・経費・入金・支払い）は扱わない（2026-10-06 の三浦さんの方針）。申請の書類も作らない（第39.6節）。

### 39.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 使える補助金・助成金があるのに、知らないまま締め切りが過ぎる | 会社の業種・所在地・人数から、**合いそうな制度を月に 1 回調べて知らせる** |
| 国・都道府県・市区町村・厚生労働省の助成金と調べ先が散らばり、探す時間が無い | 調べ先をまとめて AI が調べ、**合う理由と締め切りと出典**を並べる |
| 気になった制度の締め切りを忘れる | 「気になる」にした制度の締め切りの前に知らせる |

**補助金と助成金**: 補助金（経済産業省・中小企業庁・自治体など。公募で審査がある）と、助成金（厚生労働省の雇用関係など。条件を満たせば受けられることが多い）の両方を扱う。

#### 39.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・小規模事業者・店舗・医院・士業。専任の担当はいない |
| 見る人 | 経営者・総務。申請は、自分で行うか、商工会・認定支援機関・社会保険労務士・行政書士などに頼む |

### 39.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「補助金・助成金の案内」（ID `subsidies`） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（案。Q-190） |
| 左のメニュー | 「補助金・助成金」 |
| 利用範囲 | 拡張機能の「利用できる人」。既定は管理者だけ（案） |

### 39.3 調べる材料（会社のこと）

| 材料 | 出どころ | 推論に渡すか |
|---|---|---|
| 業種 | 会社情報（第6.6.1節）と、Web サイト・会社の知識の公開してよいもの（サービス）から AI がまとめる | 渡す |
| 所在地 | 会社情報の住所の**都道府県と市区町村だけ**（番地は渡さない） | 渡す |
| 従業員の数 | 人事・給与（第30章）を使っていればその人数を**幅で**（「10〜20 人」）。無ければ会社情報の人数の目安 | 幅だけ渡す |
| 会社の関心 | 管理者が拡張機能の設定に一言で書ける（任意。「IT の導入」「人の採用」「省エネの設備」など） | 渡す |
| 創業の年 | 会社情報にあれば | 渡す |

**人に業種の分類表や条件の一覧を作らせない**（ADR-0028）。会社のことは AI がまとめ、違えば会話で直す（「うちは小売ではなく卸」）。
**個人の情報（社員の名前・給与など）は渡さない。**

### 39.4 調べ先と調べ方

| 項目 | 規定 |
|---|---|
| 国の補助金 | 公的な補助金の申請の窓口（jGrants）の**公開の API**（ログイン不要）から、受け付け中と近く始まる公募を引く（案。Q-187）。所在地・業種・従業員の数の条件で絞る |
| 自治体の制度 | 所在地の都道府県と市区町村の制度を、Web の調べもの（第9.4.2節。Gemini の Google 検索）で調べる（案。Q-188） |
| 助成金 | 厚生労働省の雇用関係の助成金と、所在地の都道府県労働局の案内を、Web の調べもので調べる |
| 合うかの見立て | 推論が、材料と制度の対象・要件を照らし、**合いそう**・**条件を確かめたい**の 2 つに分ける。合わないものは出さない。**受けられると断定しない** |
| 頻度 | **月に 1 回**（毎月 1 日の朝。案。Q-189）。画面の「いま調べる」と、秘書の「使える補助金ある？」でも調べる（同じ会社は 1 日 1 回まで。費用を抑えるため） |
| 数 | 1 回に新しい候補を 5 件まで。前に出した制度は、締め切りや中身が変わらなければ出し直さない |

### 39.5 候補の形

| 項目 | 規定 |
|---|---|
| 1 件 | 制度の名前・実施する所（国・県・市・厚生労働省）・補助金か助成金か・**合う理由**（会社のどの点が対象に合うか）・確かめたい条件・上限額と補助率・受付の期間と締め切り・**出典（題名と URL）**。金額と日付は**出典に書かれたとおり**にし、書かれていなければ「不明（出典で確かめてください）」とする（推測で埋めない） |
| 見立て | 「合いそう」「条件を確かめたい」のどちらか。冒頭に「公募の中身は変わることがあります。申請の前に出典で確かめてください」の旨を置く（結果の一部で、常に出す説明文ではない） |
| 状態 | 新しい・気になる・見送り。人が「気になる」「見送り」にする。見送りにした制度は出し直さない |
| 締め切りの過ぎたもの | 一覧から外す（「過ぎたもの」で見られる） |

### 39.6 法務の境界

**案内にとどめ、申請の書類は作らない・申請を代わりに行わない。**
官公署に出す書類を報酬を得て作ることは行政書士の業務であり、雇用関係の助成金の申請書類は社会保険労務士の業務である。M2Office は次の線を守る。

| 行うこと | 行わないこと |
|---|---|
| 制度を探し、合う理由・確かめたい条件・締め切り・出典を示す | 申請書・事業計画書を作る、申請を代わりに出す |
| 相談先（商工会・商工会議所・よろず支援拠点・認定支援機関・社会保険労務士・行政書士）を案内する | 「受けられます」と断定する、採択の見込みを示す |
| 締め切りの前に知らせる | 会社の代わりに要件を満たすかを判断する |

### 39.7 届け方と締め切りの見張り

| 項目 | 規定 |
|---|---|
| 月の案内 | 月の調べものが終わったら、利用範囲の管理者に知らせる（種類「補助金・助成金」。第6.5.5節に足す。個人設定で切れる）。題は「合いそうな補助金・助成金が 3 件あります」、本文ははじめの 3 件の名前と締め切り。新しい候補が無ければ知らせない |
| 締め切り | 「気になる」にした制度は、締め切りの **14 日前と 3 日前**に、気になるにした人へ知らせる（案） |
| 朝のブリーフ | 締め切りが 7 日以内の「気になる」制度があれば、管理者の朝のブリーフに 1 行で載せる（案） |

### 39.8 秘書と業務から使う

| 依頼の言い方の例 | 動き |
|---|---|
| 「使える補助金ある？」「人を雇うときの助成金は？」 | 候補を引いて答える。無いか古ければ調べる（1 日 1 回まで）。頼みに関心があれば、それを材料に足す |
| 「IT 導入補助金の締め切りは？」 | 候補にあれば出典どおりに答える。無ければ調べて答える |
| 「さっきの補助金、気になるにして」「見送りにして」 | 状態を変える |
| 「申請書を書いて」 | 書かない。申請の書類は作らないことと、相談先を答える（第39.6節） |

| 項目 | 規定 |
|---|---|
| ツール | `subsidies.find`（危険度 `read`。候補を引く）、`subsidies.search`（危険度 `read`。調べる。外の公開の情報だけを読む）、`subsidies.mark`（危険度 `write-internal`。気になる・見送り） |

### 39.9 画面

| 項目 | 規定 |
|---|---|
| 一覧 | 左のメニューの「補助金・助成金」。締め切りの近い順に、制度の名前・実施する所・見立て・合う理由・締め切り・出典。「気になる」「見送り」。「いま調べる」。「過ぎたもの」「見送ったもの」 |
| 会社のこと | 調べるのに使った会社のこと（業種・所在地・人数の幅・関心）を一覧の上に 1 行で出し、違えば直せる（会話でも直せる） |
| 説明文 | 常に出さない（原則 u11） |

### 39.10 AI に任せること（ADR-0028）

| AI が決める | 人がすること |
|---|---|
| 会社のことのまとめ、調べ先、合うかの見立て、合う理由と確かめたい条件 | 気になる・見送りを決める、申請するかを決める、申請する（自分か専門家に頼む） |

### 39.11 外部の AI と社外への境界

| 項目 | 規定 |
|---|---|
| 推論に渡すもの | 業種・所在地（市区町村まで）・従業員の数の幅・関心・創業の年だけ。**社員・お客様の情報、会社の非公開の知識は渡さない**。そのため、外部の AI を使ってよい業務とする（第16.3.7.1節） |
| 外への読み出し | jGrants の公開の API と、Web の調べもので公開のページを読むだけ。会社のことを外に送らない（検索の言葉に業種と地域が入る程度） |
| 調べた結果 | 外のデータであり、指示として扱わない（不変則 I-6） |
| 「ローカルだけ」の会社 | Web の調べものが使えないため、jGrants の API だけで調べ、ローカル AI で見立てる（案） |

### 39.12 権限と記録

| 項目 | 規定 |
|---|---|
| 見る・状態を変える・いま調べる | 利用範囲の人 |
| 会社の関心を直す | 管理者 |
| 監査ログ | 調べた（件数）・状態を変えた・関心を直した（`subsidy.*`） |

### 39.13 データモデル（案）

| 表 | 列 |
|---|---|
| `subsidy_candidates`（候補） | tenant_id、ID、制度の名前、実施する所、補助金か助成金か、見立て、合う理由、確かめたい条件、上限額と補助率（出典の文のまま）、受付の始めと締め切り、出典の題名と URL、見分けの鍵（制度の URL か名前から作る。同じ制度を 2 度出さない）、状態、状態を変えた人、見つけた日、中身の印（変わったら出し直す） |
| 会社の設定 `subsidies` | 入り切り、関心（一言）、最後に調べた日時 |

行単位の制限（tenant_id）を付ける（不変則 I-2）。

### 39.17 段 1 の実装の決まり（第 0.274.0 版）

2026-10-06 に三浦さんが「第39章の補助金・助成金の案内を実装してください」と依頼した。段 1（第39.14節）を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張「補助金・助成金の案内」（`subsidies`。既定は切り・無償）。左のメニューに「補助金・助成金」。付属の業務は「補助金・助成金の案内」1 つ（秘書から）。初めて入れたときは、利用範囲をそのときの管理者だけにする（「利用できる人」で広げられる） |
| 会社のこと | 業種は、管理者が直したもの。無ければ推論が会社の名前と Web サイトの住所から短い言葉でまとめる（分からなければ空）。所在地は会社情報の住所から都道府県と市区町村だけを取り出す（政令市は市まで。番地は持たない）。従業員の数は、人事・給与を使っていれば在籍している人数を幅（1〜5・6〜20・21〜50・51〜100・101〜300・301 人以上）にする。関心は管理者が一言で書く。調べた時の会社のことを設定に残し、画面に 1 行で出す。創業の年は会社情報に無いため使っていない |
| 国の補助金 | jGrants の公開の一覧の API（`api.jgrants-portal.go.jp`。受付中だけ・締め切りの近い順）を、関心と業種の言葉 2 つと「中小企業」で引き、ID で 1 つにまとめ、対象の地域が「全国」か所在地の都道府県を含む、締め切りの過ぎていないものを 30 件まで見立てに渡す。名前・実施する所・上限額・受付の期間・出典の URL は API の値をそのまま使う（推論に書かせない）。読みに行く所は決まっていて、利用者の入力で変えない。15 秒・2 MB で打ち切る |
| 自治体と助成金 | Web の調べもの（第9.4.2節）で、所在地の自治体の制度と、厚生労働省の雇用関係の助成金と都道府県労働局の案内を 1 回調べる。見本の会社と、Web の調べものが使えない会社（ローカルだけの方針・未設定）では使わない |
| 見立て | 推論に会社のこと・国の公募の一覧・Web の調べものの結果と出典の一覧を渡し、合うものだけを JSON で返させる（合いそう・条件を確かめたい、補助金・助成金、合う理由、確かめたい条件）。Web の調べものの制度は、渡した出典の番号を指したものだけを残し（出典の無い制度は捨てる）、締め切りの過ぎた制度も捨てる。推論が使えなければ、地域の合う国の公募を「条件を確かめたい」で出す |
| 入れ方 | 見分けの鍵（jGrants の ID か、制度の名前）で 1 件にする。見送りは出し直さない。中身の印（名前・締め切り・上限額・補助率）が変われば置き換えて出し直す（気になるは気になるのまま）。新しく出すのは、合いそうを先に締め切りの近い順で 5 件まで |
| 頻度 | ワーカーが 1 時間ごと（`SUBSIDY_INTERVAL_MS`）に見て、毎月 1 日の 8 時（日本時間）を過ぎたら月に 1 回だけ調べる。画面の「いま調べる」（後ろで調べ、画面は 4 秒ごとに読み直す）と秘書は、同じ会社で 1 日 1 回まで。秘書の頼みに関心があるときは、その日のうちでも調べ直す |
| 知らせ | 月の調べもので新しい候補があれば、利用範囲の管理者に「合いそうな補助金・助成金が N 件あります」とはじめの 3 件の名前と締め切りを知らせる（お知らせの種類「補助金・助成金」）。「気になる」にした制度は、締め切りの 14 日前と 3 日前に、気になるにした人（受け取れなければ管理者）へ 1 回ずつ知らせる |
| 秘書 | ツール `subsidies.find`・`subsidies.search`（危険度 `read`。結果は外のデータとして `untrusted`）、`subsidies.mark`（危険度 `write-internal`）。答えに「公募の中身は変わることがあります。申請の前に出典で確かめてください」と、申請書を作らないことと相談先を添える。申請書・事業計画書を頼まれたら作らず、相談先を答える |
| 画面 | 会社のこと（管理者は「直す」で業種と関心を直せる）・いま調べる・最後に調べた日時・候補（制度の名前は出典へのつなぎ、補助金か助成金か、見立て、実施する所、合う理由、確かめたい条件、上限額と補助率と締め切り（無ければ「不明」）、締め切りまでの日数）・気になる・見送り・戻す・過ぎたもの・見送ったもの。管理者ページの拡張機能の設定でも、関心と業種を直せる |
| 記録 | `subsidy.search`（候補の数・新しく出した数・調べ先ごとの数）・`subsidy.status`・`subsidy.settings` |
| API | `GET /v1/subsidies`、`POST /v1/subsidies/search`（後ろで調べる。202、今日調べていれば 409）、`PATCH /v1/subsidies/:id`（`status`）、`PUT /v1/admin/extensions/subsidies/settings`（`interest`・`industry`。管理者） |
| 表 | `subsidy_candidates` と会社の設定 `subsidies`（移行 094） |
| 開発の環境 | 見本の会社では、見本の国の公募（今日から数えた締め切りの 3 件）を使い、外には読みに行かない |

**段 1 で行っていないこと**（段 2 以降）: 朝のブリーフへの掲載、採択の結果や公募の変更を出典から読み直して知らせること、相談先の地域の窓口の案内、本物の jGrants と Web の調べものでの確かめ（開発の環境は見本で確かめた）。

### 39.18 段 2 の実装の決まり（第 0.280.0 版）

2026-10-06 に三浦さんが「次に進んでください」と依頼し、次の作業の候補から「補助金・助成金の段 2」を選んだ。段 2（第39.14節）のうち、次を実装した。

| 項目 | 規定 |
|---|---|
| 朝のブリーフ | ツール `subsidies.brief`（危険度 `read`。結果は外のデータとして `untrusted`）。「気になる」にした制度のうち、締め切りが今日から 7 日のうちのものを、締め切りの近い順に 5 件まで返す（名前・補助金か助成金か・締め切り・締め切りまでの日数・出典）。朝のブリーフは、返したものがあるときだけ「補助金・助成金の締め切り」の見出しで載せる。補助金・助成金の案内を使えない人には「使えない」と返し、ブリーフに書かない |
| 公募の変更の読み直し | ワーカーが 1 時間ごとに見て、毎日 8 時（日本時間）を過ぎたら 1 日 1 回、「気になる」にした国の公募を jGrants の公開の API（1 件の口 `/v1/public/subsidies/id/{id}`。ID は英数字だけ。15 秒・20 MB で打ち切る）で 1 件ずつ読み直す。締め切りが過ぎても 14 日のうちは読む（延長に気づくため）。名前・上限額・受付の期間は API の値のまま、見立て・理由・補助率は前のまま。見つからない公募は、推測で「終わった」とせずそのままにする |
| 変更の知らせ | 締め切り・上限額・補助率・名前のどれかが変わったら、置き換えて（「気になる」のまま）、気になるにした人（受け取れなければ管理者）に「〇〇: 公募の中身が変わりました」と、変わったところ（「締め切り: 前 → 後」）と出典を知らせる（お知らせの種類「補助金・助成金」）。締め切りが変わったら 14 日前と 3 日前の知らせをもう一度行い、変わらなければ知らせた印はそのまま。自治体の制度と助成金（Web の調べもので見つけたもの）は、月の調べもので同じ制度が見つかって中身が変わったときに、同じように知らせる。監査ログ `subsidy.changed` |
| 相談先の地域の窓口 | 調べもののときに、所在地が変わったときか前に探してから 90 日たったときだけ、Web の調べもので所在地のよろず支援拠点・商工会議所か商工会・都道府県労働局の窓口を探し、推論が出典のあるものだけを 4 つまで選ぶ（出典の無い窓口・民間の有料の申請代行は出さない）。社会保険労務士（助成金の申請）と行政書士（補助金の申請）を後ろに足して、会社の設定に残す。見本の会社・Web の調べものか推論が使えない会社・見つからなかったときは、所在地から決まった形（「〇〇県よろず支援拠点」「〇〇市の商工会議所か商工会」「〇〇労働局」と専門家。URL は作らない）で出す |
| 画面と秘書 | 補助金・助成金の画面の候補の下に「相談先」（開くと窓口の名前と何を相談できるか。出典の URL があれば名前から開く）。`subsidies.find` が窓口を返し、秘書は申請書を頼まれたときと「どこに相談すればいい？」と聞かれたときに、それをそのまま答える（無い窓口を推測で足さない） |
| API | `GET /v1/subsidies` が `contacts` を返す |
| 設定 | 会社の設定 `subsidies` に `refreshedOn`（読み直した日）・`contacts`・`contactsRegion`・`contactsAt`（移行は要らない） |

**段 2 で行っていないこと**: 採択の結果を読むこと（公募ごとに公表の場所と形が違い、決まった公開の出どころが無いため）、Web の調べもので見つけた制度を毎日読み直すこと（月の調べもので読み直す）、本物の jGrants の 1 件の口と Web の調べものでの確かめ（開発の環境は見本で確かめた。1 件の口の答えの形は公開の API で確かめた）。
