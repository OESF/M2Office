## 38. 契約の管理（第 0.271.0 版。第 0.271.1 版で確定。第 0.272.0 版で段 1、第 0.279.0 版で段 2 を実装）

この章で決めること: **結んだ契約を台帳にし、更新・解約の申し出の期限を見張って知らせる**しくみ。契約書チェック（第28章）の先につなぎ、チェックした契約書を結んだらそのまま台帳に入れる。
台帳の項目、入れ方、契約書の置き場、期限の見張り、秘書からの頼み方、画面、権限と機密、データモデル、段階。

**この章は確定した**（2026-10-06 に三浦さんが、中小企業の事務で便利な機能の提案から選び、「すでに契約書のチェックはあるので、その先に管理がつながって欲しい」と依頼した。2026-10-06 に三浦さんが「案のとおりで確定してください」と依頼し、第 0.271.1 版で確定した）。
「（案）」と書いた値は、確定のときに案のとおりとした値である。方針の判断の記録は [ADR-0071](../docs/adr/0071-contract-management.md)。

**2026-10-06 に三浦さんが選んだ形**

- 結んだ契約書のファイルは**会社の Google ドライブ**に置き、台帳には契約の項目と、ファイルへのつなぎだけを持つ（第28.11節の「M2Office で文書管理を作らない」を守る）。
- 台帳は、拡張機能の**利用範囲の人が全員**見られる。
- **お金（契約の金額・支払い）は台帳で扱わない**（お金のことは税理士と会計パッケージで行う。2026-10-06 の三浦さんの方針）。

### 38.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 自動更新の解約を申し出る期限を過ぎ、使わないソフト・リース・保守の契約が 1 年延びる | **解約の申し出の期限**を契約書から取り出し、期限の前に担当へ知らせる |
| どの取引先と何の契約（NDA・業務委託など）を結んでいるか、すぐに分からない | 台帳に持ち、秘書に「〇〇社と NDA を結んでいる？」と聞けば答える |
| 契約書がメール・紙・個人のフォルダに散らばる | 会社のドライブの決まったフォルダに集め、台帳から開く |
| 契約書チェックで読んだ契約を、結んだ後に誰も追いかけない | 契約書チェックの結果から「結んだので台帳に入れる」で、そのまま台帳に入れる |

**契約書チェック（第28章）との分け方**: 契約書チェックは**結ぶ前**に読んで論点を示す。契約の管理は**結んだ後**に期限を追いかける。チェックは公式の拡張機能（スキル）で台帳を持たない。管理は台帳を持つので内蔵の拡張にする。

#### 38.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・店舗・医院・士業など。結んでいる契約は数十件〜数百件（取引の基本契約・NDA・業務委託・賃貸借・リース・保守・ソフトの利用・業務の委託先との契約） |
| 見る人 | 総務・経営者・部門の責任者。専任の法務はいない |

### 38.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「契約の管理」（ID `contracts`） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（案） |
| 左のメニュー | 「契約」 |
| 利用範囲 | 拡張機能の「利用できる人」（第12.13節）。**利用範囲の人は全員、会社の契約をすべて見られる**（三浦さんの選択）。総務と役員だけにしたい会社は、利用範囲を絞る |
| 契約書チェックとの関係 | 契約書チェック（公式の拡張機能）を入れていなくても使える。入れていれば、チェックの結果から台帳に入れられる（第38.6節） |

### 38.3 用語

| 用語 | 意味 |
|---|---|
| 契約 | 台帳の 1 件。相手・種類・件名・期間・更新の決まり・担当・契約書のファイルを持つ |
| 自動更新 | 期間の終わりまでに申し出なければ、同じ条件で次の期間に延びる決まり |
| 解約の申し出の期限 | 自動更新を止めるために、相手に申し出なければならない最後の日（「期間満了の 3 か月前までに書面で」なら、終わりの 3 か月前の日） |
| 担当 | その契約の期限の知らせを受ける社内の人。決めなければ台帳に入れた人 |

### 38.4 台帳の項目

| 項目 | 内容 | 決め方 |
|---|---|---|
| 相手 | 相手の会社名（個人なら氏名）。名刺管理を使っていれば、会社で共有の連絡先の会社名とつなぐ | 契約書から AI が取り出す |
| 種類 | NDA・取引基本契約・売買・業務委託・請負・賃貸借・リース・保守・ソフトの利用・そのほか | 同上 |
| 件名 | 契約書の題名（「業務委託基本契約書」）と、何についての契約かの一言 | 同上 |
| 締結日・始め・終わり | 日付。期間の無い契約（終わりの無い基本契約など）は終わりを空にする | 同上 |
| 自動更新 | あり・なし。ありなら、更新の期間（「1 年」）と、解約の申し出の期限の決まり（「満了の 3 か月前まで」）と、その日付 | 同上。期限の日付は、決まりと終わりの日から**プログラムが計算する** |
| 状態 | 有効・解約を申し出た・終了 | 終わりの日と更新の決まりから決まる。解約を申し出たかは人が言う |
| 担当 | 社内の人 | 入れた人。直せる |
| 契約書 | 会社のドライブのファイル（第38.7節） | 入れたときに置く |
| 契約書チェックの結果 | チェックから入れたときは、その実行へのつなぎ | 自動 |
| メモ | 自由な一言 | 人 |

| 項目 | 規定 |
|---|---|
| 読めなかった項目 | **推測で埋めない**。「不明」とし、台帳の一覧で「確かめてください」と目立たせる（開発規約の決まり） |
| 金額 | **項目にしない**（お金は扱わない方針）。契約書の中の金額は、契約書を開けば分かる |
| 期限の計算 | 「満了の〇か月前」「〇日前」「満了日の前月末」などの決まりから、プログラムが日付を出す。読めない書き方なら「不明」とし、担当に日付を入れてもらう |

### 38.5 入れ方

| 入れ方 | 規定 |
|---|---|
| ① 契約書チェックの結果から | 契約書チェックの実行の詳細（第6.2.2節）に「結んだので台帳に入れる」を出す（契約の管理を使っている会社だけ）。押すと、チェックした契約書を台帳に入れる。**結んだ版が手元の版と違えば**（修正して結んだなど）、結んだ版のファイルを渡すよう促す |
| ② 契約書を渡して | 画面の「契約書を入れる」でファイル（PDF・Word・画像）を渡すか、秘書に渡して「この契約を台帳に入れて」と頼む。AI が項目を取り出して台帳に入れ、何を入れたかを答える（**確かめを求めない**。違えば会話か画面で直す。ADR-0028） |
| ③ 手で | 紙だけの古い契約など。画面の欄に、相手・種類・期間・更新の決まりを入れる（撮った写真を ② で渡してもよい） |
| まとめて | 段 2。ドライブのフォルダにある契約書をまとめて読み、台帳を作る（はじめて使うとき） |
| 同じ契約 | 相手・種類・締結日が同じものがあれば、2 件目を作らず、同じ契約の新しい版（変更契約・覚書）として前の版につなぐ |

| 項目 | 規定 |
|---|---|
| 読み方 | 全文を取り出し（第9.4.1節。画像は OCR）、推論が項目を JSON で答える。更新の決まりは**条文の言葉をそのまま短く引いて**台帳に添える（「第 12 条: 期間満了の 3 か月前までに書面で申し出がないときは、1 年間延長する」）。人がそれを見て確かめられるようにする |
| 書かれた指示 | 契約書の文はデータであり、指示として扱わない（不変則 I-6） |

### 38.6 期限の見張り

| 項目 | 規定 |
|---|---|
| 解約の申し出の期限 | 自動更新ありの契約は、申し出の期限の **60 日前・30 日前・7 日前**に担当へ知らせる（案。Q-186）。題は「〇〇社の保守契約: 解約の申し出の期限まであと 30 日（12/31）」。本文に更新の決まりの引用と、「更新するなら何もしなくてよい。やめるなら期限までに申し出る」 |
| 終わり | 自動更新なしの契約は、終わりの 30 日前に担当へ知らせる（更新の話をするか決めるため） |
| 自動更新したとき | 終わりの日を過ぎ、解約を申し出ていなければ、次の期間に進める（始め・終わり・申し出の期限を計算し直す）。進めたことを担当に知らせる |
| 解約を申し出たとき | 担当が画面か秘書に「〇〇社の保守契約は解約する（申し出た）」と言うと、状態を「解約を申し出た」にし、期限の知らせを止める。終わりの日を過ぎたら「終了」にする |
| 申し出の文 | 「解約の申し出の文を書いて」と頼めば、秘書が相手へのメールか書面の下書きを作る（送るのは本人の承認の後。社外への送信。第9.4.0節）。**相手に送るかどうか・いつ送るかは人が決める** |
| 知らせる相手 | 担当。担当が止めた・利用範囲から外れたら、利用範囲の管理者 |
| 知らせの種類 | 「契約」（第6.5.5節に足す。個人設定で切れる） |

### 38.7 契約書の置き場（会社の Google ドライブ）

| 項目 | 規定 |
|---|---|
| 置き場 | 管理者が拡張機能を入れるときに、**M2Office が、その管理者のドライブに「契約書（M2Office）」のフォルダを作る**。台帳に入れた契約書を、このフォルダに「相手_種類_締結日.pdf」の名前で置く。いまの権限（`drive.file`。M2Office が作ったファイルだけを扱う）で作れる。新しい権限は求めない |
| 共有ドライブ | 共有ドライブを使っている会社は、管理者がそのフォルダを共有ドライブへ移してよい（M2Office が作ったフォルダなので、移しても扱える。案。Q-184） |
| 開き方 | 台帳から開くと、**M2Office がドライブから読んで見せる**。利用範囲の人は、ドライブの共有の設定が無くても開ける（ドライブの共有を人ごとに設定させない） |
| 預けた管理者が止まったとき | その管理者の Google の許可が無くなると、ドライブから読めなくなる。管理者に知らせ、別の管理者が「置き場をつなぎ直す」で引き継ぐ（フォルダを自分のドライブにコピーし直す） |
| ドライブで消された・動かされた | 開けなければ「契約書が見つかりません（ドライブで消されたか、置き場から動かされました）」と出し、台帳の項目は残す |
| Google につないでいない会社 | 使えない（案。ローカルの形の会社は Q-184 で考える） |

### 38.8 秘書と業務から使う

| 依頼の言い方の例 | 動き |
|---|---|
| 契約書を渡して「この契約を台帳に入れて」「結んだので台帳に」 | 台帳に入れ、相手・種類・期間・自動更新と申し出の期限を答える。読めなかった項目は「不明」と答える |
| 「さっきチェックした契約、結んだ」 | 本人がいちばん新しくチェックした契約書（契約書チェックの実行）を台帳に入れる |
| 「〇〇社と NDA を結んでいる？」「〇〇社との契約は？」 | 台帳を引いて、契約の一覧（種類・期間・状態）を答える |
| 「今月と来月に期限が来る契約は？」「自動更新の契約を一覧にして」 | 台帳を引いて答える |
| 「〇〇社の保守契約は解約する」 | 状態を「解約を申し出た」にする。申し出の文が要るかを答えに添える（「申し出の文を書いて」で下書き） |
| 「この契約、もう一度チェックして」 | 台帳の契約書で、契約書チェックを実行する（契約書チェックを入れている会社だけ） |

| 項目 | 規定 |
|---|---|
| 学ばない | 契約の中身を秘書の記憶と会社の知識に入れない（第28.3節の「学ばない業務の印」と同じ扱い） |
| 秘書の答え | 台帳の項目（相手・種類・期間・状態・期限）だけを答える。契約書の本文を長く写さない |
| ツール | `contracts.find`（危険度 `read`。台帳を引く）、`contracts.register`（危険度 `write-internal`。契約書から台帳に入れる）、`contracts.update`（危険度 `write-internal`。状態・担当・項目を直す） |

### 38.9 画面

| 項目 | 規定 |
|---|---|
| 一覧 | 左のメニューの「契約」。**期限の近い順**（解約の申し出の期限か、終わりの日の早いほう）に、相手・種類・件名・期間・自動更新・次の期限・状態・担当。検索と、種類・状態・担当での絞り込み。「不明」の項目のある契約に印 |
| 1 件 | 項目をその場で直せる。更新の決まりの引用、契約書を開く、契約書チェックの結果を開く、前の版（変更契約・覚書）、「解約を申し出た」、削除 |
| 入れる | 「契約書を入れる」（ファイルを選ぶか落とす）、「手で入れる」 |
| 名刺の詳細 | 段 2。名刺管理の連絡先の詳細に、その会社との契約を並べる |
| 説明文 | 常に出さない（原則 u11） |

### 38.10 AI に任せること（ADR-0028）

| AI が決める | 人がすること |
|---|---|
| 契約書からの項目の取り出し、種類、更新の決まりの引用、期限の日付の計算（プログラム）、同じ契約の版のつなぎ | 結んだら入れる（ファイルを渡す）、読めなかった項目を確かめる、解約するかを決めて申し出る |

### 38.11 権限と機密

| 操作 | 利用範囲の人 | 管理者 |
|---|---|---|
| 台帳を見る・契約書を開く | できる | できる |
| 入れる・直す | できる | できる |
| 削除 | 入れた人だけ | できる |
| 置き場をつなぐ・つなぎ直す | できない | できる |

| 項目 | 規定 |
|---|---|
| 機密 | 契約書は機密である。台帳と契約書は利用範囲の人だけが見られる（ほかの会社には見えない。不変則 I-2） |
| 外部の AI | 契約書を読むために推論に渡す（契約書チェックと同じ。第28.9節）。会社の AI の方針が「ローカルを既定」なら、ローカル AI で読む（第16.3.7.1節） |
| 残す期間 | 終わった契約も台帳に残す（消すのは人。案。Q-185）。契約書はドライブに残る |
| 監査ログ | 入れた・直した・状態を変えた・削除した・契約書を開いた・置き場をつないだ（`contract.*`）。**相手の名前と契約の中身は残さない**（種類と、どの項目を直したかだけ） |

### 38.12 データモデル（案）

| 表 | 列 |
|---|---|
| `contracts`（台帳） | tenant_id、ID、相手、名刺管理の連絡先の会社（任意）、種類、件名、締結日、始め、終わり、自動更新（あり・なし）、更新の期間、申し出の決まり（引用）、申し出の期限、状態、担当、ドライブのファイルの ID、契約書チェックの実行の ID（任意）、前の版の ID（任意）、メモ、「不明」の項目、知らせた期限（60・30・7 日前のどれを知らせたか）、作った人・直した人と時刻 |
| 会社の設定 `contracts` | 入り切り、置き場（ドライブのフォルダの ID・つないだ管理者） |

行単位の制限（tenant_id）を付ける（不変則 I-2）。

### 38.13 API（案）

| API | 内容 |
|---|---|
| `GET` ／ `POST /v1/contracts` | 一覧（検索・絞り込み）／ 手で入れる |
| `POST /v1/contracts/import` | 契約書のファイルか、契約書チェックの実行の ID から入れる（AI が項目を取り出す） |
| `GET` ／ `PATCH` ／ `DELETE /v1/contracts/:id` | 1 件 ／ 直す（状態・担当を含む）／ 削除 |
| `GET /v1/contracts/:id/file` | 契約書を開く（ドライブから読んで返す） |
| `PUT /v1/admin/extensions/contracts/storage` | 置き場をつなぐ・つなぎ直す（管理者だけ） |

### 38.14 段階

| 段 | 行うこと |
|---|---|
| 段 1 | 台帳（項目・状態・担当）、入れ方（契約書チェックから・契約書を渡して・手で）、会社のドライブの置き場、期限の見張りと自動更新の繰り越し、秘書からの頼み、画面、権限と記録 |
| 段 2 | ドライブのフォルダの契約書をまとめて読んで台帳を作る、名刺の詳細に契約を並べる、更新の前に契約書チェックで見直す提案、相手の修正版との差分（第28.11節の段 2 と一緒に） |

### 38.15 行わないこと

| 行わないこと | 理由 |
|---|---|
| 金額・支払い・請求の管理 | お金は扱わない（2026-10-06 の三浦さんの方針。税理士と会計パッケージで行う） |
| 解約するか・更新するかの判断、法律の判断 | 会社が決める。法務の境界（第28.2節） |
| 解約の申し出を相手に送ること | 社外への送信。下書きまでにし、送るのは本人の承認の後 |
| 電子署名・押印 | 第28.11節と同じ |
| M2Office の中の文書管理 | 契約書は会社のドライブに置く（第28.11節） |

### 38.17 段 1 の実装の決まり（第 0.272.0 版）

2026-10-06 に三浦さんが「第38章の契約の管理から実装してください」と依頼した。段 1（第38.14節）を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張「契約の管理」（`contracts`。既定は切り・無償）。左のメニューに「契約」。付属の業務は「契約の台帳」1 つ（秘書から台帳を引く・入れる・直す。学ばない業務の印） |
| 入れる | ① 契約書チェックの実行の画面に「結んだので台帳に入れる」（チェックを頼んだ本人・終わった実行だけ）。② 画面か秘書に契約書（PDF・Word・画像）を渡す。③ 手で入れる（相手は必須）。①②は契約書を文字にし（画像と文字の無い PDF は読み取り）、推論が JSON で項目を取り出す。推論が使えなければ決まった言い方（「〇〇（以下「甲」という）」・「〜から〜まで」・末尾の締結日・「申し出」を含む更新の文）で読む。読めない項目は「不明」の印を付け、推測で埋めない。確かめを求めずに入れる |
| 同じ契約 | 相手・種類・締結日が同じ契約がもう台帳にあれば入れない。題名に「変更」「覚書」があれば、同じ相手の有効な契約の新しい版としてつなぐ（`previous_id`） |
| 期限 | 解約の申し出の期限は、終わりの日から申し出の日数を引いてプログラムが計算する（「3 か月前」は 90 日、「1 年前」は 365 日）。直したら計算し直し、直した項目の「不明」の印を外し、知らせ直せるようにする |
| 見張り | ワーカーが 1 時間ごと（`CONTRACT_INTERVAL_MS`）に見る。自動更新の契約は申し出の期限の 60・30・7 日前に、自動更新の無い契約は終わりの 30 日前に、担当に知らせる（お知らせの種類「契約」。個人設定で切れる）。それぞれ 1 回だけ。入れたのが期限の近くなら、近い知らせだけを 1 回。担当が知らせを受けられなければ管理者へ。終わりを過ぎて解約を申し出ていない自動更新の契約は、いまの期間まで進めて知らせる。解約を申し出た契約と自動更新の無い契約は、終わったら「終了」にする |
| 置き場 | 管理者が拡張機能を入れたときに、その管理者の Google ドライブにフォルダ「契約書（M2Office）」を作る（`drive.file` の範囲。つなぎ直しもできる）。契約書は「相手_種類_締結日」の名前で、つないだ管理者の許可で置く。開くときもその許可でドライブから読んで返す（25 MB まで）ので、利用範囲の人はドライブの共有が無くても開ける。置き場が無い・置けないときは台帳にだけ入れ、理由を出す。Google をつないでいない会社では置き場をつなげない |
| 秘書 | ツール `contracts.find`（危険度 `read`）、`contracts.register`・`contracts.update`（危険度 `write-internal`）。答えは台帳の項目だけで、契約書の本文を返さない。解約の申し出は送らない（文の下書きは秘書がふだんの会話で作る） |
| 権限 | 台帳は利用範囲の人が全員見て直せる。削除は入れた人と管理者だけ。置き場をつなぐのは管理者だけ |
| 記録 | `contract.create`・`contract.update`・`contract.status`・`contract.delete`・`contract.open`・`contract.storage`・`contract.renewed`。相手の名前と契約の中身は残さない |
| API | `GET`／`POST /v1/contracts`、`POST /v1/contracts/import`（`fileId` か `runId`）、`GET`／`PATCH`／`DELETE /v1/contracts/:id`、`GET /v1/contracts/:id/file`、`PUT /v1/admin/extensions/contracts/storage` |
| 表 | `contracts` と会社の設定 `contracts`（移行 092） |
| 共通の部品 | ドライブの接続口に、ファイルを置く（`upload`）と読む（`download`。25 MB まで）を足した |

**段 1 で行っていないこと**（段 2 以降）: 名刺管理の連絡先の会社とのつなぎ（第38.12節の任意の列）、ドライブのフォルダの契約書をまとめて読むこと、更新の前に契約書チェックで見直す提案、本物の Google ドライブでの確かめ（開発の環境は見本のドライブで確かめた）。

### 38.18 段 2 の実装の決まり（第 0.279.0 版）

2026-10-06 に三浦さんが「次に進んでください」と依頼し、次の作業の候補から「契約の管理の段 2」を選んだ。段 2（第38.14節）のうち、次を実装した。

| 項目 | 規定 |
|---|---|
| 名刺の詳細に契約を並べる | 名刺の詳細（契約の管理を使える人だけ）に、その会社との契約を、種類・件名・状態・終わり・解約の申し出の期限と一緒に並べ、押すと契約を開く。会社名と相手を、株式会社などの法人の言葉と空白を除いて比べ、どちらかがもう一方を含めば同じとみなす（2 字に満たなければ並べない）。名刺管理の連絡先の会社の列（第38.12節の任意の列）は持たず、名前で引く |
| 更新の前に見直す | 1 件の画面の「契約書チェックで見直す」で、ドライブの契約書を、押した人のファイルとして M2Office に写し（PDF・Word・写真だけ）、契約書チェック（公式の拡張機能）を起こす。押した人が契約書チェックを使えなければ起こさない。監査ログ `contract.review`。自動更新の解約の申し出の期限の知らせに、契約書がドライブにあれば見直せることを添える |
| まとめて入れる | 「契約書を入れる」でいくつもの契約書（30 件まで）を選ぶと、1 つずつ順に読んで台帳に入れ、入れた数と入れられなかったものを出す。**ドライブのフォルダの契約書を読むことはしない**: M2Office のドライブの許可（`drive.file`）は M2Office が作ったファイルしか見られず、人がドライブに置いた契約書は読めないため（読める許可を足すと、会社のドライブ全体を読める強い許可になる） |
| API | `GET /v1/contracts/by-company`、`POST /v1/contracts/:id/review` |
