## 34. Web の振り返り（アナリティクスと Search Console の通訳。第 0.227.0 版。案）

この章で決めること: Google アナリティクス（GA4）と Google Search Console のデータを M2Office が読み、**中小企業の人が画面を覚えなくても**、自社の Web サイトの状態と次にやることが分かるようにするしくみ。

**この章は案である。** **汎用のしくみとして作る。** 特定の導入先・業種の条件に合わせた作りにしない。
まだ確かめる事項（第34.17節）の答えで直してから実装する。**「（案）」と書いた値は、会社（三浦さん）の判断を待つ値である。**
方針の判断の記録は [ADR-0067](../docs/adr/0067-inquiries-and-web-review.md)。

**2026-10-03 に三浦さんが示した狙い**

- アナリティクスと Search Console からデータを引けるようにすれば、多少なりともよい Web マーケティングの判断ができる。
- ただしアナリティクスは機能が豊富すぎて、中小企業が全部を分析するのは難しい。Search Console も、IT の知識があまり無い人には大変である。**それを手伝う道具を作りたい。**
- 三浦さんが、問い合わせの記録（第33章）と別の拡張にすること・管理者（担当）の Google の接続に読み取りの権限を足すこと・問い合わせの記録の後に作ることを、おすすめのとおりに選んだ（2026-10-03。Q-167 決定）。

### 34.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| アナリティクスの画面が難しく、どこを見ればよいか分からない | 見るものを AI が絞り、**月に 1 回、ふつうの言葉で便りを届ける**（第34.4節）。グラフと数字の表を並べない |
| 知りたいことがあっても、出し方が分からない | **秘書に聞けば答える**（「先月、料金のページは何人見た？」。第34.5節） |
| Search Console の指摘の意味と、直し方が分からない | 直すべき所だけを、理由と直し方と、誰に頼めばよいかを添えて出す（第34.6節） |
| アナリティクスや Search Console が入っていない・制作会社が持っている | 状態を確かめ、始めるまでの手順と、制作会社への依頼文の下書きを作る（第34.7節） |

**コラムの作成（第32章）の段 3「効果の振り返り」（第32.12節）は、この章で行う。** コラムの作成が入っていない会社でも、Web の振り返りだけを使える。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「Web の振り返り」。問い合わせの記録（第33章）とは**別の拡張**にする（ADR-0067） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |

| 左のメニュー | 業務の 1 つとして「Web の振り返り」を出す |
| 業務（付属） | 「Web の便り」「Web について聞く」「Web の直すべき所」「Web の始める準備」。秘書が取り次ぐ（第34.10節） |

### 34.3 つなぎ

| 項目 | 規定 |
|---|---|
| 読むもの | GA4 のデータの API（`runReport`）と管理の API（持っているプロパティの一覧）、Search Console の API（検索の結果の数字・サイトの一覧・URL の検査）、PageSpeed Insights の API（表示の速さ。Google の無料の診断） |
| 権限 | アナリティクスの読み取り（`analytics.readonly`）と Search Console の読み取り（`webmasters.readonly`）。**どちらも読むだけ**。Google の区分は「機微」で、「制限付き」ではない（案。Google の審査の要否と合わせて、実装の前に確かめる。第14.3.1節） |
| 誰の許可か | **担当**（管理者が決める。既定は管理者本人）の Google の接続に、上の 2 つの権限を足す（**再同意**が要る。Q-167 決定）。担当が見られるプロパティしか見えない |
| 定期の動き | 月の便りと直すべき所の見回りは、担当の許可で動く（担当が依頼した定時の実行として扱う。不変則 I-9 を守る） |
| 結果を見る人 | 便りと答えは**集計の数字だけ**で、個人の情報を含まない。会社の利用範囲（第16.7節）の中の人が見られる。担当の許可で読んだ集計を会社で共有することを、担当を決めるときに画面で示す |
| サイトの選び方 | 会社の Web サイト（会社の設定の Web の URL）に合うプロパティとサイトを、**AI が一覧から選ぶ**。合うものが無い・いくつもあるときは、担当に一言で聞く。違っていれば秘書に言えば直る |
| 担当が替わる | 担当を替えると、前の担当の許可では読まなくなる。新しい担当が接続し直すまで、便りは「つながっていません」と出す |
| 推し量らない | 取れなかった数字を推論で埋めない。「取得できませんでした」と理由を書く（開発規約） |

### 34.4 月の便り

| 項目 | 規定 |
|---|---|
| 届け方 | 毎月 1 日（案）に、担当と、会社が決めた人（既定は管理者）のお知らせに届く。週次ブリーフにも、要点を 1〜2 行載せる |
| 中身 | ① 先月の要約（見た人の数・問い合わせのページへ進んだ数などを、先月と前の年の同じ月と比べて 3 行で）、② よかったこと、③ 気になること、④ **次にやること 1〜3 つ**（直すべき所・コラムのテーマ・頼む相手） |
| 見る指標 | AI が絞った十数個に限る（下の表）。**会社に指標を選ばせない**（ADR-0028） |
| 数の出し方 | 数字は API の値をプログラムで計算した（比べた率を含む）ものだけを使い、推論に計算させない。推論は、その数字を言葉にし、次にやることを考える |
| 言葉 | 「セッション」「エンゲージメント率」「CTR」などの言葉を使わない（原則 u1）。「サイトに来た回数」「じっくり読まれた割合」「検索で表示されて押された割合」のように言い換える |
| 少ないとき | 月に見た人が少ない（100 人未満。案）サイトでは、率の上下を言わない（数が少なく、たまたまの差が大きいため）。数だけを伝える |

**見る指標（案）**

| 指標 | 出どころ |
|---|---|
| サイトに来た人・回数（新しい人と再び来た人） | アナリティクス |
| どこから来たか（検索・地図・SNS・ほかのサイト・直接） | アナリティクス |
| よく見られたページ・じっくり読まれたページ | アナリティクス |
| 問い合わせ・予約のページへ進んだ数（会社がキーイベントを決めていればその数） | アナリティクス |
| スマホとパソコンの割合、地域（都道府県） | アナリティクス |
| 検索で表示された回数・押された回数・押された割合・平均の順位 | Search Console |
| 押された回数が多い検索の言葉、伸びた言葉 | Search Console |
| Google に登録されていないページの数 | Search Console |

### 34.5 秘書に聞く

| 項目 | 規定 |
|---|---|
| 聞き方 | 「先月、料金のページは何人見た？」「どこから来た人が多い？」「スマホの人は増えてる？」「“〇〇 地名” で検索されてる？」 |
| 動き | AI が質問を、**決まった範囲の指標と切り口の組み合わせ**（許すものの一覧は M2Office が持つ）に直して API を呼び、数字と期間を添えて答える |
| 範囲の外 | 一覧に無い組み合わせ（個人に近い切り口など）は呼ばない。「その切り口は扱っていません」と答える |
| 期間 | 言われなければ先月。「先週」「去年の同じ月と比べて」を日付に直す |
| 答えの形 | 数字・期間・比べた相手を必ず書く。グラフは秘書のキャンバスに出す（任意） |

### 34.6 直すべき所

Search Console とアナリティクスの数字から、**直すと効きそうな所だけ**を出す。見回りは週に 1 回（案）。

| 見つけるもの | 基準（案） | 伝え方 | つなぎ先 |
|---|---|---|---|
| 検索に多く出るのに、押されないページ | 表示が月 500 回以上で、押された割合が同じくらいの順位のほかのページの半分未満 | 「検索の結果に出る題名と説明文を、こう変えると押されやすくなります」と案を添える | コラムなら「編集」。それ以外のページは制作会社への依頼文 |
| あと少しで検索の 1 ページ目に入るページ | 平均の順位が 8〜20 位で、表示が月 100 回以上 | 「この話題を足すと上がりそうです」と、足す見出しの案を添える | コラムなら「書き直しを頼む」 |
| 検索されているのに、合う記事が無い言葉 | 表示はあるが、押されたページが言葉と合っていない | 「次のコラムのテーマにどうですか」 | コラムの作成のテーマ案（第32.6節） |
| Google に登録されていないページ・エラー | Search Console の URL の検査とページの登録の状態 | 何が起きているか、直すと何が良くなるか、**誰に何を頼めば直るか**をふつうの言葉で | 制作会社への依頼文の下書き |
| スマホで遅い・見にくいページ | PageSpeed Insights のスマホの点が 50 未満（よく見られる上位 10 ページだけ測る） | 遅い理由の上位 3 つを、ふつうの言葉で | 制作会社への依頼文の下書き |
| 読まれなくなった記事 | 先の 3 か月と比べて、見た人が半分未満 | 「情報が古くなっていないか見直しませんか」 | コラムなら「書き直しを頼む」 |

**依頼文は下書きまで**。制作会社に送るのは、利用者が自分で送るか、承認の後に送る（社外への送信。第9.4.0節）。

### 34.7 始める前の手伝い

| 状態 | M2Office がすること |
|---|---|
| 担当がまだ権限を足していない | 「Google と接続し直して、アナリティクスと Search Console の読み取りを許してください」と出す |
| 担当のアカウントに、アナリティクスのプロパティや Search Console のサイトが無い | 「制作会社が持っているか、まだ入れていない」ことを伝え、**制作会社に閲覧の権限をもらう依頼文**（担当のメールアドレスを、アナリティクスの「閲覧者」と Search Console の「制限付きユーザー」に足してもらう）を下書きする |
| アナリティクスが入っていない | 入れ方の手順をヘルプで示す。サイトにタグを入れるのは制作会社か WordPress の側で行う（M2Office はサイトを書き換えない） |
| 問い合わせ・予約のキーイベントが無い | 「問い合わせのページへ進んだ数」で代わりに数える。キーイベントを作ると何が良いかと、制作会社への依頼文を示す |

### 34.8 コラムの作成とのつなぎ

| 項目 | 規定 |
|---|---|
| コラムごとの数字 | コラムの作成が入っていれば、WordPress に入れたコラムの URL ごとに、見た人・読まれた時間・検索の言葉を、コラムの画面に出す |
| テーマ案 | 伸びている検索の言葉と、合う記事が無い言葉を、テーマ案の材料に渡す（第32.6節） |
| 書き直し | 直すべき所のうちコラムのものは、コラムの画面から「書き直しを頼む」へつなぐ |

### 34.9 問い合わせの記録との突き合わせ（段 3）

| 項目 | 規定 |
|---|---|
| 並べるもの | 問い合わせの記録（第33章）が入っていれば、月の便りに「問い合わせの件数（どこで知ったかの内訳）」と「Web の数字」を並べる |
| 言い方 | 「Web から来た問い合わせが 12 件（先月 8 件）。料金のページを見た人が増えた月です」のように、**並べて伝える**。因果を言い切らない |
| 渡すもの | 問い合わせの側からは、プログラムで数えた**件数だけ**を受け取る。名前・用件は受け取らない |

| 頼み方 | 動き |

| 「〇〇のページは何人見た？」 | 第34.5節 |
| 「Web で直したほうがいい所は？」 | 直すべき所を答える |
| 「制作会社に頼む文を書いて」 | 直すべき所から依頼文の下書きを作る |

### 34.11 AI に任せること（ADR-0028）

| AI に任せる | 人が行う |
|---|---|
| 見る指標の選び方・サイトとプロパティの選び方・便りの文・質問を指標に直す・直すべき所の見つけ方と案・依頼文の下書き | 担当を決める、Google の権限を許す、制作会社に依頼を送る |

### 34.12 権限と記録

| 項目 | 規定 |
|---|---|
| 使える人 | 利用範囲（第16.7節）の中の人が便りを見て、秘書に聞ける |
| 担当を決める | 管理者だけ |
| 監査ログ | 担当を決めた・替えた、サイトとプロパティを選んだ・直した、依頼文を送った（承認） |

### 34.13 人の情報と社外への境界

| 項目 | 規定 |
|---|---|
| 集計だけ | アナリティクスと Search Console が出す**集計だけ**を使う。個人の閲覧の履歴・端末の識別子・IP アドレスを扱わない（第32.16節と同じ） |
| 外部の AI | 集計の数字は個人の情報ではない。ただし問い合わせの件数を読む段（第34.9節）は会社のデータを読むため、会社の AI の方針が「ローカルを既定」ならローカル AI で書く（第16.3.7.1節。迷うものはローカル）。「ローカルだけ」の会社では、PageSpeed Insights などの社外の API は呼んでよいが、文はローカル AI で書く |
| 書き換えない | M2Office はアナリティクス・Search Console・Web サイトの設定を変えない（読むだけ） |
| 社外への送信 | 制作会社への依頼文は、承認の後にだけ送る（第9.4.0節） |

### 34.14 データモデル（案）

| 表 | 主な列 |
|---|---|
| `web_review_reports`（月の便り） | tenant_id、月、要約の数字（JSON）、文、次にやること、作った日時 |
| `web_review_findings`（直すべき所） | tenant_id、種類、ページの URL、数字（JSON）、案、状態（新しい・見た・済んだ・見送り）、見つけた日時 |
| `web_page_metrics`（ページごとの数字） | tenant_id、URL、日付、見た人、読まれた時間、表示・押された回数・順位（コラムの作成の第32.17節 `web_column_metrics` は、この表で代える） |
| 会社の設定 `webReview` | 入り切り・担当・選んだプロパティとサイト・便りを届ける人 |

| 段 | 行うこと |
|---|---|

### 34.16 行わないこと

| 行わないこと | 理由 |
|---|---|
| アナリティクスの画面をまねたグラフと表を並べる | 中小企業の人が読み解けないことが出発点。言葉で伝え、必要なときだけ見せる |
| 会社に指標・目標・レポートの形を選ばせる | AI が選ぶ（ADR-0028） |
| 推論に数字を数えさせる・取れなかった数字を埋める | 誤った判断につながる。数字はプログラムが API の値から計算する |
| 個人を追いかける解析 | 集計で足りる。人の情報の扱いを広げない |
| アナリティクス・Search Console・サイトの設定を変える | 読むだけにする。権限も読み取りだけを求める |
| 検索の順位だけを狙った手直しを勧める | 読み手の役に立つ直しだけを勧める（第32.20節と同じ考え） |
| 承認なしに制作会社へ依頼を送る | 社外への送信は承認が要る |
