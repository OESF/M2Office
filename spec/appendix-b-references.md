## 付録 B. 参考にした外部資料

`anthropics/knowledge-work-plugins` は、業務手順を宣言的に記述して
AI に実行させる方式の公開実装である。M2Office はこの考え方を継承しつつ、
定義をファイルではなくデータとして扱い、GUI から操作できるようにする（第2.3.3節）。

### B.1 リポジトリの構成

| 区分 | 内容 |
|---|---|
| 職種別プラグイン | productivity、sales、customer-support、product-management、marketing、legal、finance、data、enterprise-search、engineering、design、operations |
| 規模・領域別 | small-business（44 スキル）、human-resources、bio-research |
| 仕組み | cowork-plugin-management（プラグインの作成支援） |
| **パートナー製** | **partner-built（Apollo、Slack、Zoom、Common Room ほか）** |
| その他 | pdf-viewer |

構造はいずれも共通である。

```
plugin-name/
├── .claude-plugin/plugin.json   マニフェスト
├── .mcp.json                    外部ツールへの接続
├── commands/                    明示的に呼び出す操作
└── skills/                      必要なときに引き出される知識と手順
```

### B.3 考え方として取り込むもの

| # | 取り込む考え方 | M2Office での対応 |
|---|---|---|
| 1 | **宣言的な記述だけで業務が形になる**。コードもインフラも要らない | エージェント定義（第9.2節）。任意のコードを含まない |
| 2 | **自動で引き出される知識と、明示的に呼ぶ操作を分ける** | 秘書の取次（第10.9節）とメニューからの実行 |
| 3 | **2 層のメモリ**（作業記憶と深層保存） | 個人記憶・チーム記憶・組織知識の 3 層（第11.1節） |
| 4 | **外部接続は MCP に寄せる** | 第14.4節。コネクタ層で吸収する |
| 5 | **カスタマイズの手段を 4 つに分ける**（接続の置換／社内文脈の追加／手順の調整／新規作成） | 第12.7.1節の変更範囲。ただし M2Office は画面から行う |
| 6 | **パートナーが自社向けに作る区画を設ける** | 第13.7節 |

**第 3 項は独立に同じ結論へ至った点である。**
記憶を層に分ける設計は、別々に検討して同じ形になった。
この方式の妥当性を補強するものとして記録しておく。

##### doc-coauthoring から取り込む発想

文脈を集める → 節ごとに詰める → **文脈を持たない別の推論に読者として検証させる**、
という 3 段階の手順である。

第 3 段階が目を引く。**生成した文書を、経緯を知らない側から読み直させて
曖昧さを指摘させる**という方法である。

M2Office では承認ゲートの手前に置ける。
人が確認する前に機械が一度読み直せば、承認者の負担が減る。
TBD: 費用と効果の見合いを確認する（Q-58）。

### B.6 名刺管理を Claude Code のスキルで行った実例（第 0.139.1 版）

出典: 藤田拳「Claude Codeで名刺管理を自動化したら、「必要な時に漁る」生活から卒業できた」（note、2026-01-28。https://note.com/fujitaken/n/n1b7697ec4a88 、2026-09-27 に確認）。
iPhone で撮った名刺の写真を渡すと、読み取って Excel に追記する仕組みを、3 つのスキル（HEIC から JPEG への変換、1 枚の写真からの名刺の切り出し、Excel への追記）で作り、約 500 枚を取り込んだ記録である。

| 記事で分かったこと | 第27章での扱い |
|---|---|
| 名刺の山を「必要なときに漁る」のが実態で、最初にたまった数百枚を取り込むのが最初の仕事になる | まとめての取り込みを主な場面の 1 つにした（第27.4節） |
| iPhone の写真は HEIC で、そのままでは扱えない | 名刺に限り HEIC・HEIF を受け付ける（第27.4節） |
| 1 枚の写真に並べた名刺を画像の輪郭で切り出すと、縦型が上下に割れる・横に並んだ 2 枚がくっつく・机の汚れを拾う、で 28 回以上の調整を要した | 輪郭による切り出しは採らず、Gemini に範囲を返させる案を Q-93 の候補にした。名刺ごとの画像は確かめ直しのために残す |
| 向きが正しくないと読み取りの精度が落ちる。縦型と横型がある | 向きを見分けて正す（第27.5節） |
| 読み取れなかった項目は空欄にする | 推測で埋めない（第27.5節。もともとの決まり） |
| 表計算（Excel）で名刺を管理したい人が多い | CSV に加えて Excel でも書き出す（第27.12節、Phase 2） |

### B.7 `anthropics/knowledge-work-plugins` の legal プラグイン（第 0.139.2 版。第 0.139.3 版で広げた）

出典: `legal/`（https://github.com/anthropics/knowledge-work-plugins/tree/main/legal 、2026-09-27 に確認）。企業の法務部向けで、既定の観点は米国の実務に寄る（プラグイン自身が、ほかの国では基準を直して使うよう断っている）。スキルは review-contract・triage-nda・legal-risk-assessment・signature-request・vendor-check・compliance-check・brief・legal-response・meeting-briefing の 9 つ。

以下はまず `legal/skills/review-contract/SKILL.md` について。
会社の交渉の基準（プレイブック）に照らして契約書を条項ごとに読み、違いを 3 段階に分け、修正の文案と交渉の進め方を返すスキルである。
**考え方だけを取り込み、文面は写さない**（第9.4.3節の実装上の注意と同じ）。第28章は日本の中小企業向けに書き直した。

| 取り込んだ考え方 | 第28章での扱い |
|---|---|
| 基準に「標準の立場・受け入れられる範囲・専門家に回す条件」の 3 つを持つ | 会社の契約の基準（第28.6.1節）。ただし人に書かせず、秘書に頼んで作る |
| 基準が無ければ一般的な水準で読み、そう明示する | 同じ（第28.5節・第28.7節） |
| 違いを 3 段階（受け入れ・交渉・上へ上げる）に分ける | 「一般的な範囲・交渉したい・専門家に確認したい」（第28.7節） |
| 修正の案に、今の文・案・相手に見せられる理由・優先度・断られたときの案を付ける | 1 件の形（第28.7節） |
| 必ず直したい点から切り出し、譲ってよい点と引き換えにする | 交渉の進め方の案（第28.7節） |
| 全文を読んでから指摘する（条項は互いに効き合う） | 手順の 4（第28.5節） |
| 長い契約は主な条項から読む | Phase 2（第28.11節） |

| 取り込まなかった点 | 理由 |
|---|---|
| 始める前に、自社の立場・期限・背景を聞く | 人に聞かずに AI が見分ける（ADR-0028）。背景は任意の一言で受ける（第28.4節） |
| 契約管理のシステム（CLM）への回付 | 中小企業では使っていないことが多い。M2Office の承認と別物のため |
| 米国の実務に寄った観点（陪審の放棄、GDPR の 72 時間など） | 日本の取引の観点に置き換えた（第28.6節） |
| 「法律の助言はしない」の一文だけで済ませる | 弁護士法第 72 条との関係から、言い回し・表示・紛争時の扱いまで決めた（第28.2節） |

| legal プラグインのほかのスキル | 第28章での扱い |
|---|---|
| triage-nda（NDA の事前の点検。10 の観点、例外 5 つ、紛れ込んだ条項、3 段階の見立て） | **NDA の点検として取り込んだ**（第28.6.2節）。見立ては「一般的な範囲に収まっています」などとし、原典の「標準の決裁で承認」「署名しない」のような結ぶかどうかの指示は書かない（第28.2節）。「NDA でないものが NDA の題で来る」の扱いも取り込んだ |
| legal-risk-assessment（重さ×起きやすさの 5×5 の点数） | 取り込まない。法務部の台帳のための仕組みで、中小企業には 3 段階で足りる。影響は「当社への影響」に書く |
| signature-request（署名の前の確認と電子署名への回付） | 署名の前の確認の項目だけを、次の拡張の候補にした（第28.11節）。電子署名への回付は行わない |
| vendor-check（取引先ごとの既存の契約と期限） | 契約の期限管理とあわせて、次の拡張の候補にした（第28.11節） |
| compliance-check・brief・legal-response・meeting-briefing | 取り込まない。法務部の日常業務（規制の確認、法務の朝会、定型の回答）であり、中小企業の契約書チェックの外。会議の準備は M2Office の「会議の準備」がある |
