## 35. お知らせの作成（1 つの中身を、いくつもの出し先へ。第 0.229.0 版。案）

この章で決めること: 休業・営業時間の変更・新しいサービス・催しなどの**お知らせを 1 つ作り、Web サイト・LINE・メール・店頭の画面に、それぞれに合う形で、1 回の承認でまとめて出す**しくみ。

**この章は案である。** **汎用の発信のしくみとして作る。** 特定の導入先・業種の条件に合わせた作りにしない。
まだ確かめる事項（第35.16節）の答えで直してから実装する。**「（案）」と書いた値は、会社（三浦さん）の判断を待つ値である。**
方針の判断の記録は [ADR-0068](../docs/adr/0068-announcements.md)。

**2026-10-03 に三浦さんが示した狙い**

- LINE で友だち登録しているお客様全員に、お知らせを一斉に送りたい。
- 「本年末 12 月 28 日から 1 月 5 日までは休業とさせていただきます。よいお年をお迎えください」のようなよくあるお知らせは、LINE の友だちだけでなく、**Web ページにも載せたい**。お知らせの作成の機能もあわせて検討する。
- 三浦さんが、Web サイトは承認の後に公開まで行うこと・LINE の一斉配信をこの章で行うこと・休業の期間を覚えること（後の段）を、おすすめのとおりに選んだ（2026-10-03）。

### 35.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 同じお知らせを、Web・LINE・メール・店頭の貼り紙に、それぞれ書き直して出している | **1 つの頼み**から、AI が出し先ごとの文を作る（第35.6節） |
| 出し忘れ・出し先ごとに日付が食い違う | 出し先をまとめて、**1 回の承認**で同時に出す（予約もできる） |
| 期間が終わったお知らせが残り続ける | 期間を持ち、終わったら店頭の画面から外し、Web では終わったことを示す |
| LINE の一斉配信の費用が読めない | 送る数と今月の残りを、承認の前に示す。無料の範囲を超えるときは止めて知らせる |

**問い合わせの記録（第33章）との分け方**: 問い合わせの記録は**お客様との 1 対 1 のやり取り**、お知らせの作成は**会社から多くの人への発信**を扱う。LINE の一斉配信（第14.6節の表の 4）は、この章で行う。

#### 35.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・店舗・医院・士業など。Web サイト・LINE 公式アカウント・店頭の画面のどれか 1 つでもあれば使える |
| 本数 | 月に数本。年末年始・夏季休業・臨時休業・営業時間の変更が多い |
| 作る人 | 専任はいない。総務・店長・院長などの兼務 |

### 35.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「お知らせの作成」（ADR-0068） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（Q-173。第 0.229.1 版で決定） |
| 左のメニュー | 業務の 1 つとして「お知らせの作成」を出す |
| 業務（付属） | 「お知らせの下書き」「お知らせを出す」。秘書が取り次ぐ（第35.9節） |
| 出し先のつなぎ | ほかの拡張でつないだものを使う。WordPress はコラムの作成（第32.10節）の接続、LINE は問い合わせの記録（第33.6.2節）の接続、店頭の画面は店頭サイネージ（第31章）、メールは名刺管理のまとめてのメール（第27.9.1節）。**お知らせの作成のために同じ接続を 2 度預けさせない** |

### 35.3 用語

| 用語 | 意味 |
|---|---|
| お知らせ | 会社から多くの人に伝える 1 つの中身。題名・本文・期間（任意）・画像（任意）を持つ |
| 出し先 | お知らせを出す場所。Web サイト・LINE・メール・店頭の画面 |
| 出し先ごとの文 | 1 つのお知らせから、出し先に合わせて AI が作る文（Web は題名と日付つきの記事、LINE は短い文、店頭の画面は大きな字の 1 枚など） |
| 期間 | お知らせが当てはまる期間（休業なら 12 月 28 日〜1 月 5 日）。終わった後の扱いに使う |
| 予約 | お知らせを出す日時。決めなければ承認したときに出す |

### 35.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 入り切り | 管理者ページの「拡張機能」 | 切り |
| Web サイト | コラムの作成でつないだ WordPress を使う。**承認の後に公開まで行う**か、下書きまでにするか | 公開まで（三浦さんが選んだ） |
| Web のカテゴリー | お知らせを入れる WordPress のカテゴリー | 「お知らせ」（無ければ、初めて出すときに作る） |
| LINE | 問い合わせの記録でつないだ LINE 公式アカウントを使う | つないでいれば使う |
| 店頭の画面 | 店頭サイネージに登録した画面のうち、お知らせを流す画面 | すべての画面 |
| 承認する人 | お知らせを出すことを承認する人 | 管理者と承認者のロール |

出し先を選ぶ表や文の型を会社に作らせない（ADR-0028）。どの出し先に出すかは、AI がお知らせの中身とつないでいる出し先から案を出し、承認の画面で外せる。

### 35.5 流れ

| 段 | AI がすること | 人がすること |
|---|---|---|
| ① 頼む | — | 秘書に「年末年始の休業のお知らせを出して。12/28〜1/5」と頼むか、画面で 1 行書く |
| ② 下書き | 題名・本文・期間を決め、出し先ごとの文を作る。つないでいる出し先から、出す先の案を選ぶ。会社の知識（営業時間・連絡先）と自社の書き方（第15.2.1節）を使う | 直したければ、文をその場で直すか、秘書に「もっと丁寧に」と頼む |
| ③ 承認 | 承認の画面に、**出し先ごとの見え方**・送る数（LINE・メール）・今月の LINE の残り・予約の日時・期間の後の扱いを出す | **承認する**（社外に出るもの。第9.4.0節）。出し先を外してもよい |
| ④ 出す | 予約の日時に、出し先ごとに出す。出せなかった出し先は、理由をつけて知らせる（ほかの出し先は止めない） | — |
| ⑤ 期間の後 | 期間が終わったら、店頭の画面から外し、Web の記事の題名に「（終了しました）」を付ける（第35.6.1節）。**これも ③ の承認に含める** | — |

**人の判断は承認の 1 回だけにする**（ADR-0028）。出し先ごとに承認を求めない。

### 35.6 出し先ごとの決まり

#### 35.6.1 Web サイト（WordPress）

| 項目 | 規定 |
|---|---|
| 形 | 題名・日付・本文の記事。会社の設定のカテゴリーに入れる |
| 公開 | 既定は**承認の後に公開まで**行う（三浦さんが選んだ。ADR-0068）。コラムの作成は下書きまで（Q-162）だが、お知らせは短く、日付どおりに出ることが大事なため。会社の設定で下書きまでにもできる |
| 予約 | 予約の日時があれば、WordPress の予約公開として入れる（M2Office が時刻まで待たない） |
| 期間の後 | 期間が終わったら、記事の題名の頭に「（終了しました）」を付ける。記事は消さない（過去のお知らせとして残る） |
| WordPress が無い | 文を「HTML をコピー」「テキストをコピー」で写して使う。M2Office がお知らせの一覧のページを配る形は後の段（Q-180。第 0.229.1 版で決定） |
| AI の表示 | 付けない（会社の事務のお知らせであり、調べものや意見ではないため。コラムの作成の第32.4節とは扱いを分ける。Q-179。第 0.229.1 版で決定） |

#### 35.6.2 LINE

| 項目 | 規定 |
|---|---|
| 送り方 | 友だち全員への**一斉配信**。年代・地域などで絞る送り方は後の段 |
| 文 | 短い文（目安 200 字まで）。期間・連絡先を入れる。Web にも出すなら、記事の URL を添える |
| 数と費用 | 一斉配信は**友だち 1 人に 1 通**として、LINE の月の無料の数に数えられる。承認の画面に、送る数（いまの友だちの数）・今月の残りの数・超えるかどうかを出す |
| 超えるとき | **無料の範囲を超える一斉配信は、承認できない**（Q-177。第 0.229.1 版で決定。超えて送ると、会社に思わぬ費用がかかるため）。「今月の残り 120 通。このお知らせは 300 通になります」と知らせ、LINE のプランを上げるか、LINE を出し先から外すかを選んでもらう。有料のプランの会社は、プランの上限の内で送れる |
| 予約 | 予約の日時に M2Office が送る。時刻の前に友だちの数と残りの数をもう一度確かめ、超えるなら送らずに知らせる |
| ブロックした人 | LINE がもともと送らない。M2Office で何かする必要は無い |

#### 35.6.3 メール

| 項目 | 規定 |
|---|---|
| 送り方 | 名刺管理の「まとめてのメール」（第27.9.1節）の決まりで送る。宛先の集め方・除く人・宣伝かの見分け・配信の停止・上限（1 回 100 人）はそのまま |
| 宛先 | AI が案を出す（取引先・最近問い合わせのあったお客様など）。承認の画面で 1 人ずつ外せる |
| 差出人 | 窓口のアカウント（第33.6節）があれば、そのアドレスから送る（Q-178。第 0.229.1 版で決定。まとめてのメールの「本人の Gmail から送る」決まり（第27.9.1節）は、お知らせの作成のときだけ窓口のアカウントに読み替える）。無ければ依頼した本人の Gmail から送る |
| 段 | 段 2（第35.14節） |

#### 35.6.4 店頭の画面（店頭サイネージ）

| 項目 | 規定 |
|---|---|
| 形 | 大きな字の 1 枚の画像（1920×1080）。題名と期間と一言。M2Office が字を組む（生成 AI に字を描かせない。第32.7.1節と同じ考え） |
| 流し方 | 店頭サイネージの通常の流し（第31.6節）に、**期間つきの素材**として足す。期間が無ければ 14 日（案）流す |
| 期間の後 | 期間が終わったら流しから外す |
| 割り込み | お知らせの作成からは割り込み（第31.7節）を使わない（割り込みは店頭の呼び出しのためのもの） |

### 35.7 休業の期間を覚える（後の段）

休業のお知らせを出したら、その期間を**会社の休業日**として覚える。

| 使い道 | 動き |
|---|---|
| 問い合わせの返事 | 休業中に届いた問い合わせ（窓口のアカウント・LINE）に、「1 月 6 日から順にお返事します」という返事の下書きを用意する（送るのは承認の後。第33章） |
| 秘書 | 「年末は何日まで営業？」に答える。予定の候補を出すときに休業日を避ける |
| Web の振り返り | 休業の月は、数の上下を休業のせいと添える（第34.4節） |

### 35.8 画面

| 項目 | 規定 |
|---|---|
| 一覧 | 上に 1 行の欄（「年末年始の休業 12/28〜1/5」と書けば下書きを作る）。その下に、お知らせを新しい順に並べ、状態（下書き・承認待ち・予約・出した・終わった）と出し先の印を出す |
| 1 件 | 題名・本文・期間・予約を直せる。出し先ごとのタブで、**それぞれの見え方**（Web の記事・LINE の吹き出し・店頭の画面の 1 枚・メール）を出す。下に「承認へ進む」 |
| 出した後 | 出し先ごとの結果（Web の記事を開く・LINE に送った数・メールを送った数・流している画面）を出す |
| 説明文 | 常に出さない（原則 u11） |

### 35.9 秘書と業務から使う

| 頼み方 | 動き |
|---|---|
| 「年末年始の休業のお知らせを出して。12/28〜1/5」 | 下書きと出し先ごとの文を作り、承認を待つ |
| 「夏季休業のお知らせ、LINE だけで」 | 出し先を LINE だけにして下書きを作る |
| 「さっきのお知らせ、もっと丁寧に」 | 開いているお知らせの文を直す |
| 「来週月曜の朝 9 時に出して」 | 予約の日時を入れる |
| 「LINE の友だちは何人？今月あと何通送れる？」 | 答える |

### 35.10 AI に任せること（ADR-0028）

| AI に任せる | 人が行う |
|---|---|
| 題名と本文・期間の読み取り・出し先ごとの文・出す先の案・店頭の画面の 1 枚の組み立て・メールの宛先の案・期間の後の扱い | 頼む、文を直す（任意）、**出すことの承認** |

### 35.11 権限と記録

| 項目 | 規定 |
|---|---|
| 作れる人 | 利用範囲（第16.7節）の中の人が下書きを作れる |
| 承認 | 会社が決めた人（既定は管理者と承認者のロール）。作った本人が承認者なら、本人の承認で足りる |
| 出し先の設定 | 管理者だけ |
| 監査ログ | 承認・出した（出し先ごと）・予約の変更と取り消し・期間の後の扱い・出せなかった出し先 |

### 35.12 社外への境界

| 項目 | 規定 |
|---|---|
| 承認 | Web への公開・LINE の一斉配信・メールは、すべて社外への送信である。**承認の後にだけ出す**（第9.4.0節）。承認の後に文が変わったら出さない（版の指紋。コラムの作成と同じ形） |
| 取り消し | 予約したお知らせは、出す前なら取り消せる。出した後は、Web の記事は WordPress で、LINE とメールは取り消せない（承認の画面に書く） |
| 外部の AI | お知らせは社外に出す前提の文で、個人の情報を扱わない。**外部の AI を使ってよい業務**（第16.3.7.1節）とする。ただしメールの宛先を集める段は会社のデータを読むため、名刺管理の決まりのまま動かす |
| 人の情報 | お知らせに、お客様の名前・事例を入れない。秘書から頼むときに個人を特定する情報が入っていれば除く |

### 35.13 データモデル（案）

| 表 | 主な列 |
|---|---|
| `announcements`（お知らせ） | tenant_id、題名、本文、期間（始め・終わり）、予約の日時、状態（下書き・承認待ち・予約・出した・終わった・取り消し）、承認の実行、作った人・承認した人と日時 |
| `announcement_outputs`（出し先ごと） | tenant_id、お知らせ、出し先（Web・LINE・メール・店頭の画面）、出し先ごとの文、状態（待ち・出した・出せなかった）、結果（WordPress の記事の ID と URL・LINE に送った数・メールの配信・サイネージの素材の ID）、出した日時、理由 |
| `business_closures`（休業日。後の段） | tenant_id、始め、終わり、出どころのお知らせ |
| 会社の設定 `announcements` | 入り切り・Web を公開まで行うか・カテゴリー・流す画面・承認する人 |

### 35.14 段階

| 段 | 行うこと |
|---|---|
| 段 1 | 下書き（出し先ごとの文）・1 回の承認・Web サイト（公開まで・予約・期間の後）・LINE の一斉配信（数と残りの確かめ）・店頭の画面・WordPress が無い会社のコピー |
| 段 2 | メール（まとめてのメール）・休業の期間を覚える（第35.7節） |
| 後で | Google ビジネスプロフィールの投稿（Q-175）、Instagram・X などの SNS、LINE の絞った配信、M2Office が配るお知らせの一覧のページ（Q-180） |

LINE の一斉配信は、問い合わせの記録の段 3（LINE のつなぎ）の後に作る。

### 35.15 行わないこと

| 行わないこと | 理由 |
|---|---|
| 承認なしに出す | 社外への送信は承認が要る（第9.4.0節） |
| 無料の範囲を超える LINE の一斉配信を、知らせずに送る | 会社に思わぬ費用がかかる |
| 出し先ごとに承認を求める | 承認は 1 回にする（ADR-0028） |
| 店頭の画面の 1 枚の字を生成 AI に描かせる | 日本語の字が崩れる。字は M2Office が組む |
| お知らせに個人の情報・お客様の事例を入れる | 社外に出るため |
| 期間の後に Web の記事を消す | 過去のお知らせとして残すほうが、お客様にも検索にもよい。題名に「（終了しました）」を付けるだけにする |
