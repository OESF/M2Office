## 40. 会員とポイント（第 0.275.0 版。第 0.276.0 版で確定し段 1、第 0.278.0 版で段 2、第 0.283.0 版でランクとサイネージを実装）

この章で決めること: 店のお客様を**会員にし、来店と購入のたびにポイントを貯め、特典と交換できる**しくみ（よくあるポイントカード）。
会員証の形、ポイントの貯め方と使い方、店員の操作、お客様の情報の扱い、秘書からの頼み方、ほかの業務とのつなぎ、権限と記録、データモデル、段階。

**この章は確定した**（2026-10-06 に三浦さんが「会員管理、よくあるポイントカードなどのシステムの使用を考えてください。来店や、商品の購入のたびにポイントが貯めるなどの仕組みです」と依頼した。2026-10-06 に三浦さんが案に対して「先に進めてください」と依頼し、第 0.276.0 版で案のとおりに確定した）。「（案）」と書いた値は、確定のときに案のとおりとした値である。方針の判断の記録は [ADR-0073](../docs/adr/0073-members-points.md)。

**2026-10-06 に三浦さんが選んだ形**

- ポイントは**来店と購入の両方**で貯まる。購入は、店員が金額を入れるとポイントに換算する。**金額そのものは M2Office に残さず、ポイントだけを持つ**（お金の機能にしない。お金は税理士と会計パッケージで扱う方針。2026-10-06）。
- 貯まったポイントは**特典と交換**する（「10 ポイントでドリンク 1 杯」など）。**値引きの計算はレジで行い、M2Office はお金を扱わない。**
- 会員証は **LINE とスマホ**。LINE の友だちは LINE の中に会員証（QR）、LINE を使わないお客様には Web の会員証（QR）と、印刷できる紙のカード。店員はスマホで QR を読む。

### 40.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 紙のスタンプカードは、忘れる・なくす・店で数えられない | 会員証を LINE とスマホに持たせ、店員がスマホで QR を読むだけで貯まる |
| ポイントカードの専用のサービスは月額が高く、ほかの道具（問い合わせ・お知らせ）とつながらない | 問い合わせの記録（第33章）とお知らせの作成（第35章）と同じお客様の台帳でつなぐ |
| どのお客様がよく来て、誰が来なくなったかが分からない | 来店の回数と最後に来た日から、秘書が答える（段 2 で離れそうなお客様を知らせる） |

#### 40.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 飲食店・美容室・小売・教室など、来店するお客様が繰り返し来る店。1〜3 店舗 |
| 会員の数 | 数百〜数千人 |
| 操作する人 | 店員（スマホ）と店長（管理者） |

**医療の機関では扱わない**: 保険診療にポイントを付けることは療養担当規則で制限されている。医療の業務は M2Medical で扱い（ADR-0063）、この章では扱わない。

### 40.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「会員とポイント」（ID `members`） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（案。Q-196） |
| 左のメニュー | 「会員」 |
| スマホのページ | 店員がポイントを付ける・特典を使うページ（`/m/members`。在庫のスマホのページと同じ形。第29章） |
| 利用範囲 | 拡張機能の「利用できる人」。既定は会社の全員（店員がポイントを付けるため） |

### 40.3 用語

| 用語 | 意味 |
|---|---|
| 会員 | ポイントを貯めるお客様。呼び名（ニックネームでよい）と会員番号を持つ |
| 会員証 | 会員ごとの QR。LINE の中・スマホの Web のページ・紙のカードのどれでも同じ QR |
| ポイント | 来店と購入で貯まり、特典と交換して減る数。お金ではない |
| 特典 | ポイントと交換できるもの（「ドリンク 1 杯」「10% の値引き券」など）。中身は会社が決める |
| ポイントの記録 | 貯めた・使った・取り消した・失効したの 1 件ずつの記録。消さずに足していく |

### 40.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 入り切り | 管理者ページの「拡張機能」 | 切り |
| 来店のポイント | 1 回の来店で何ポイントか | 1（案） |
| 購入のポイント | 何円で 1 ポイントか | 100 円で 1 ポイント（案。Q-191） |
| 特典 | 管理者が画面で足すか、秘書に「10 ポイントでドリンク 1 杯の特典を作って」と頼む | 無し |
| 有効期限 | 最後にポイントを貯めた日から | 1 年（案。Q-192） |
| LINE | 問い合わせの記録・お知らせの作成でつないだ会社の LINE 公式アカウントを使う。会員証のページを LINE の中で開く設定（Q-193） | つないでいれば使う |

**人に表や規則を作らせない**（ADR-0028）。特典は「名前と必要なポイント」だけで作れ、細かい条件は会話で直す。

### 40.5 会員になる・会員証

| 入口 | 動き |
|---|---|
| LINE | お客様が会社の LINE 公式アカウントの友だちになり、メニューの「会員証」を押す。LINE の中で会員証のページが開き、初めてなら呼び名を入れて会員になる（Q-193）。LINE のお客様の ID で同じ人を見分ける |
| 店頭 | 店員がスマホのページで「会員を作る」を押し、呼び名を入れる（電話は任意）。画面に会員証の QR を出し、お客様が自分のスマホで読むと、本人の Web の会員証が開く（ブックマークして使う）。紙のカードを渡すなら、会員証の QR を印刷する |
| 同じ人 | LINE と店頭で別々に会員になった人は、店員がまとめられる（呼び名と電話で AI が候補を出す） |

| 項目 | 規定 |
|---|---|
| 会員証のページ | 会員番号・呼び名・いまのポイント・使える特典・有効期限を出す。**本人だけが開ける鍵つきの URL**（推測できない長さ）。ほかの会員の情報は出さない |
| メッセージを送らない | 会員証を LINE やメールで自動で送らない（社外への送信になるため。第9.4.0節）。お客様が自分で開く |
| 紙のカード | 会員証の QR と会員番号を名刺の大きさで印刷する（PDF） |

### 40.6 ポイントを貯める・使う

| 項目 | 規定 |
|---|---|
| 来店 | 店員がスマホのページで会員証の QR を読み、「来店」を押す。**同じ会員の来店は 1 日 1 回まで**（案。Q-197） |
| 購入 | 店員が「購入」を押して金額を入れると、会社の率でポイントにする（端数は切り捨て）。**金額は保存しない**（ポイントの記録に「購入」とだけ残す） |
| 特典を使う | 店員が会員証を読み、お客様が選んだ特典の「使う」を押すと、必要なポイントを引く。値引きの計算はレジで行う |
| 取り消し | 付けまちがい・使いまちがいは、その日のうちなら店員が取り消せる（逆の記録を足す）。それより前は管理者が取り消す |
| 足りないとき | ポイントが足りない特典は使えない。マイナスにしない |
| 有効期限 | 最後にポイントを貯めた日から 1 年たつと、残りのポイントは失効する（失効の記録を足す） |
| お客様が自分で付ける | できない。付けるのはログインした従業員だけ（不正を防ぐ） |
| ポイントの販売・現金との交換 | しない（第40.15節） |

### 40.7 秘書と業務から使う

| 依頼の言い方の例 | 動き |
|---|---|
| 「会員は何人？」「今月よく来た会員は？」「しばらく来ていない会員は？」 | 台帳から数えて答える |
| 「田中さん（会員番号 123）のポイントは？」 | その会員のポイントと最後の来店を答える |
| 「10 ポイントでドリンク 1 杯の特典を作って」 | 管理者なら特典を作る |
| 「田中さんに 5 ポイント足して」 | 店員なら足す（理由を残す） |

| 項目 | 規定 |
|---|---|
| ツール | `members.find`（危険度 `read`）、`members.points`（危険度 `write-internal`。足す・取り消す）、`members.rewards`（危険度 `write-internal`。特典を作る・直す） |

### 40.8 ほかの業務とのつなぎ

| 業務 | つなぎ |
|---|---|
| 問い合わせの記録（第33章） | LINE のお客様の ID と電話で、問い合わせの連絡先と同じ人をつなぐ（第33.6.2節と同じ見分け方）。問い合わせの画面に「会員・〇〇ポイント」を出す |
| お知らせの作成（第35章） | 段 2。会員だけに LINE でお知らせを送る（承認の後。第35章の LINE の一斉配信の決まりのまま） |
| 店頭サイネージ（第31章） | 段 2。いまの特典を画面に流す（第 0.283.0 版で実装。第40.19節） |

### 40.9 画面

| 項目 | 規定 |
|---|---|
| 会員の一覧 | 左のメニューの「会員」。呼び名・会員番号・ポイント・来店の回数・最後の来店。検索と並べ替え |
| 会員の 1 件 | ポイントの記録（貯めた・使った・取り消した・失効した）・まとめる・削除（退会） |
| 特典 | 名前・必要なポイント・使える期間・止める。管理者だけが直す |
| スマホのページ（店員） | QR を読む → 会員の呼び名とポイントが出る → 「来店」「購入（金額）」「特典を使う」。会員を作る |
| 説明文 | 常に出さない（原則 u11） |

### 40.10 AI に任せること（ADR-0028）

| AI が決める | 人がすること |
|---|---|
| 同じ人の候補（呼び名と電話）、特典の頼みの読み取り、よく来る・来なくなった会員の見立て（段 2） | 特典を決める（管理者）、ポイントを付ける・使う（店員） |

### 40.11 お客様の情報

| 項目 | 規定 |
|---|---|
| 持つ項目 | 呼び名（必須。ニックネームでよい）・会員番号・LINE のお客様の ID（LINE で会員になったとき）・電話（任意）。**誕生日・住所・性別は段 1 では持たない**（案。Q-195） |
| 利用の目的 | 会員になる画面に、会社の個人情報の扱い（会社がのせるページ）へのつなぎを出す |
| 見える人 | 利用範囲の人 |
| 退会 | お客様の申し出で、管理者が削除する（店員は管理者に頼む。第40.12節）。ポイントの記録は数だけを残し、だれのものかは消す |
| 外部の AI | 秘書の答えに使う範囲で、呼び名とポイントを推論に渡す。電話は渡さない |

### 40.12 権限と記録

| 操作 | 利用範囲の人（店員） | 管理者 |
|---|---|---|
| 会員を作る・ポイントを付ける・特典を使う | できる | できる |
| その日の付けまちがいを取り消す | できる | できる |
| 前の日の記録を取り消す・会員をまとめる・削除する | できない | できる |
| 特典・率・有効期限を決める | できない | できる |

| 項目 | 規定 |
|---|---|
| 監査ログ | 特典と率を作った・直した、前の日の記録を取り消した、会員をまとめた・削除した（`member.*`）。ふだんの来店・購入・特典の使用は数が多いので、ポイントの記録そのものに付けた人と時刻を残す |
| 知らせ | 段 1 は無し。段 2 で、失効の前に会員へ LINE で知らせる（社外への送信なので承認の決まりに従う） |

### 40.13 データモデル（案）

| 表 | 列 |
|---|---|
| `members`（会員） | tenant_id、ID、会員番号（会社の中で連番）、呼び名、電話（任意）、LINE のお客様の ID（任意）、会員証の鍵、問い合わせの連絡先の ID（任意）、最後に貯めた日、作った人と時刻、まとめた先 |
| `member_points`（ポイントの記録） | tenant_id、ID、会員、種類（来店・購入・特典・取り消し・失効・調整）、ポイント（増減）、特典の ID（任意）、取り消した記録の ID（任意）、付けた人、時刻。**追記のみ**（アプリのロールに更新と削除を許さない。在庫の記録と同じ。第29章） |
| `member_rewards`（特典） | tenant_id、ID、名前、必要なポイント、使える期間（任意）、状態 |
| 会社の設定 `members` | 入り切り、来店のポイント、購入の率、有効期限の日数 |

行単位の制限（tenant_id）を付ける（不変則 I-2）。いまのポイントは記録の合計で求める。

### 40.14 段階

| 段 | 行うこと |
|---|---|
| 段 1 | 会員（店頭で作る・LINE の会員証）、会員証のページと紙のカード、来店と購入のポイント、特典と交換、取り消し、有効期限、店員のスマホのページ、秘書からの頼み、問い合わせの連絡先とのつなぎ、権限と記録 |
| 段 2 | 会員だけへのお知らせ（第35章）、失効の前の知らせ、よく来る・来なくなった会員の見立てと提案、サイネージに特典を流す、ランク（よく来る会員の特典） |
| 段 3 | レジ（POS）とのつなぎ（購入の金額を手で入れずに済む） |

### 40.15 行わないこと

| 行わないこと | 理由 |
|---|---|
| 売上・購入の金額の記録、値引きの計算、会計 | お金は扱わない（2026-10-06 の三浦さんの方針。税理士と会計パッケージで行う） |
| ポイントの販売・チャージ・現金や電子マネーとの交換 | お金に当たり、資金決済法などの決まりがかかる。ポイントは来店と購入のおまけとして付けるだけ |
| 会員証や知らせを自動で LINE・メールに送る（段 1） | 社外への送信は承認の後（第9.4.0節） |
| 医療の機関のポイント | 療養担当規則の制限。医療は M2Medical（ADR-0063） |
| ほかの会社とのポイントの共通化 | 会社ごとに閉じる（不変則 I-2） |

### 40.17 段 1 の実装の決まり（第 0.276.0 版）

2026-10-06 に三浦さんが第40章の案に対して「先に進めてください」と依頼した。案のとおりに確定し、段 1（第40.14節）を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張「会員とポイント」（`members`。既定は切り・無償）。左のメニューに「会員」。店員のスマホのページ `/m/members`。付属の業務は「会員とポイント」1 つ（秘書から。学ばない業務の印） |
| 会員 | 呼び名（30 字まで。必須）・電話（任意。9 桁以上）・会員番号（会社の中の連番）・会員証の鍵（24 バイトの乱数）。LINE で会員になった人は LINE のお客様の ID を持つ（画面には出さない） |
| 会員証 | 会員証のページ `/v1/member-card/<鍵>`（ログインなし。会社はアドレスで決まる。会員番号・呼び名・ポイント・使える特典・有効期限・QR。外部を読まず、埋め込みを許さない）。QR にはこの URL を入れる。店員のスマホのページは QR の URL から鍵を取り出して会員を引く。紙のカードは名刺の大きさの PDF |
| LINE の会員証 | 管理者が LIFF ID と LINE ログインのチャネル ID を設定すると、LIFF のエンドポイント `/v1/member-card/line` が開く。LIFF の SDK で ID トークンを受け取り、LINE の確認の口（`/oauth2/v2.1/verify`）でチャネル ID と照らして確かめ、その LINE のお客様の会員証へ移る。初めてのお客様には呼び名を聞いて会員にする（LINE の名前を案にする）。何も送らない。見本の会社では見本の ID トークン（`mock:<ID>:<名前>`）で動かし、外には問い合わせない |
| ポイント | 来店は会社のポイント（既定 1）で、同じ会員は日本時間の 1 日 1 回まで（取り消した来店は数えない）。購入は金額を会社の率（既定 100 円で 1 ポイント）で切り捨てて換算し、**金額は保存しない**。特典はポイントが足りて、止めておらず、使える期間の中のものだけ。調整は理由が要る。ポイントはマイナスにしない |
| 記録 | ポイントの記録は追記のみ（アプリのロールに更新と削除を許さない）。取り消しは逆の記録を足す（1 つの記録は 1 度だけ）。その日の記録は利用範囲の人が、前の日の記録は管理者が取り消す。いまのポイント・来店の回数・最後の来店・最後に貯めた日は記録から求める |
| 有効期限 | ワーカーが 1 日に 1 回、最後に貯めた日（無ければ会員になった日）から有効期限の日数（既定 365 日）がたった会員の残りを失効の記録で 0 にする |
| まとめる・削除 | まとめる（管理者）: まとめる元のポイントを調整の記録で移し、LINE のつながりと電話を移し、元の会員証はまとめた先を開く。候補は同じ電話（9 桁以上）か同じ呼び名。削除（管理者）: 会員の行を消し、記録は残る（だれのものかは分からなくなる） |
