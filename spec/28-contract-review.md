## 28. 契約書チェック（第 0.139.0 版、ADR-0043。第 0.146.0 版で Phase 1、第 0.281.0 版で相手の修正版との差分、第 0.282.0 版で観点を持つ種類の追加を実装）

この章で決めること: 契約書（NDA・売買・業務委託など）を AI が読み、概要と注意したい点・修正の案・相手に確かめることを平易に伝える業務。
法務の境界（弁護士法との関係）、拡張機能としての形、入力と結果の形、会社の基準の使い方、機密の扱い、評価、段階。

### 28.1 目的と位置づけ

中小企業の多くは顧問弁護士を置く余裕がない。一方で、NDA・売買契約・業務委託契約などは日常的に届き、
**読まずに押印するか、読んでも何が不利なのか分からない**まま結ぶことが多い。

M2Office では、契約書を渡すと、AI が次をまとめて返す。

| 返すもの | 目的 |
|---|---|
| 総合の見立て | 「一般的な範囲に収まっています」「交渉したい点があります」「専門家に確認したい点があります」の 3 つのどれかを 1 行で示す（結ぶかどうかの判断ではない） |
| 概要 | 何の契約で、誰が何をいつまでにするのかを数行で分かるようにする |
| 注意したい点 | 当社に不利になりうる条項を、重さの順に、理由と一緒に示す |
| 修正の案 | その条項をどう書き換えるとよいかの文案を示す |
| 相手に確かめること | 交渉やメールでそのまま使える問いにする |
| 交渉の進め方の案 | 必ず直したい点から切り出し、譲ってよい点と引き換えにする、という順番を示す |
| 抜けている条項 | この種類の契約で一般に入る条項が無いことを示す |
| 専門家に相談したほうがよい点 | 自社だけで判断しないほうがよい点をはっきりさせる |

### 28.2 法務の境界

**契約書チェックは、論点の提示と条文の要約にとどめる。法律判断と、契約を結ぶかどうかの判断はしない**（第2.6節・第15.4節）。

弁護士でない者が報酬を得る目的で法律事務を業として行うことは、弁護士法第 72 条で禁じられている。
法務省は 2023 年 8 月に、AI を使った契約書の審査の支援サービスと弁護士法第 72 条の関係についての考え方を示している。
M2Office はこれを踏まえ、次の線を守る。**表示と規約の文面は、公開の前に弁護士の確認を受ける**（Q-97。Q-09 の残りと合わせて行う）。

| 行うこと | 行わないこと |
|---|---|
| 条項の中身を平易な言葉で要約する | 「この契約を結んでよい／結ぶべきでない」と判断する |
| 一般的な契約で見られる条項との違い、当社に不利になりうる点を示す | 個別の事情に当てはめた法律上の結論を断定する（「違法です」「無効です」） |
| 書き換えの文案を「案」として示す | 相手方との交渉を代わりに行う・相手に送る |
| 専門家に相談したほうがよい点を示す | 紛争中の案件の見通しを示す |

| 項目 | 規定 |
|---|---|
| 言い回し | 「問題ありません」「結んで大丈夫です」「違法です」のような**断定と保証をしない**。「一般に〜とされることが多い」「当社に不利になりうる」「確認をおすすめします」と書く |
| 表示 | 結果の冒頭に 1 行、「論点の整理であり、法律上の判断ではありません。重要な契約は弁護士にご確認ください」の旨を置く（第15.4節の「専門家の確認を前提とする」表示）。**画面に常に出す説明文ではなく、結果の一部である**（原則 u11 には当たらない） |
| 秘書 | 「この NDA にサインしていい？」と聞かれても、秘書は可否を答えない。契約書チェックを実行し、注意したい点を伝える（第28.8節） |
| 紛争 | 相手方と揉めている・訴えられた、と読み取れたら、要約だけにとどめ、弁護士への相談を最初に勧める |
| 審査 | 同じ境界を第三者の拡張機能にも当てはめる（第12.5節・第15.4節） |

### 28.3 形: 公式の拡張機能

契約書チェックは、**独自の表も画面も要らない**。ファイルを読み、知識を引き、結果の文書を作るだけで足りる。
そのため、**公式の拡張機能（スキル。第12.12節）として作る**。拡張の仕組みで作れることを示す見本にもなる。

| 項目 | 規定 |
|---|---|
| 置き場 | 公式の配布元（リポジトリの `extensions/contract-review/`。第12.10.3節） |
| 中身 | `SKILL.md`（手順）、`HELP.md`、補助資料（契約の種類ごとの観点。第28.6節）、`evals/`（第28.10節） |
| ツール（`allowed-tools`） | `file.read_text`、`pdf.extract`、`knowledge.search`、`docx.render` |
| 最上位の危険度 | draft（社外に送らない。承認は挟まない） |
| 区画 | 既定は無し。法務の区画を作る会社は、そこに入れられる（Q-48） |
| 導入 | 公式の拡張機能として、管理者が一覧から入れる。**既定では入れない**（使う会社を選ぶため） |

拡張機能の仕組みに、次の 2 つを加える（どちらも第12章の規定を広げる）。

| 加えること | 内容 | 節 |
|---|---|---|
| 会社の名前を渡す | 基盤が、会社の正式名称と略称を業務の指示に添える（第15.2.1節の「自社の書き方」と同じ経路）。契約書の当事者のどちらが自社かを見分けるのに使う | 第12.12.5節 |
| 学ばない業務の印 | `metadata.m2office-private: true` を書いた業務は、秘書がその結果から学ばず（第10.13節）、秘書の答えに結果の要点を添えない（第10.7.3節）。契約の中身を記憶に入れないため | 第12.12.3節 |

### 28.4 入力

| 項目 | 必須 | 内容 |
|---|---|---|
| 契約書 | 必須 | ファイル（PDF・Word・画像）。第9.4.1節のファイルの規則に従う |
| 気になる点・背景 | 任意 | 一言で書く（例: 「損害賠償が心配」「来月から取引を始める新しい取引先」「今週中に返事が要る」「年 1,000 万円の取引」）。書いてあれば、そこを重く見て、期限が近ければ交渉の進め方を絞る。**書かなくても始める**。聞き返さない |

**自社の立場（委託する側か受ける側か、売る側か買う側か）は聞かない。** 当事者の名前と会社の正式名称から AI が見分ける。
見分けられない（ひな形で当事者が空欄など）ときは、条項の内容から最も考えられる立場を仮に決め、**結果の冒頭に「当社を〇〇の側として読みました」と書く**。

### 28.5 手順

| 順 | 内容 |
|---|---|
| 1 | 全文を取り出す（`file.read_text`。画像や、文字の無い PDF のページは OCR。第9.4.1節） |
| 2 | 契約の種類（NDA・売買・業務委託など）、当事者、自社の立場を見分ける |
| 3 | 概要をまとめる |
| 4 | **全文を読んでから**、条項を 1 つずつ、種類ごとの観点（第28.6節）で点検する。条項は互いに効き合うため、1 つの条だけで判断しない（例: 補償の条に上限が無くても、損害賠償の上限の条で抑えられていることがある） |
| 5 | 一般に入る条項の抜けを探す |
| 6 | 照らす基準を決める。会社の知識に「契約の基準」（第28.6.1節）があれば引いて照らす（`knowledge.search`。出典を添える）。**無ければ、一般的な取引の水準で読み、そう書く** |
| 7 | 結果をまとめる（第28.7節）。Word の文書でも作る（`docx.render`） |

**読めなかった部分を黙って飛ばさない。** OCR の上限（1 回 10 ページ。第9.4.1節）や文字数の上限で全文を読めなかったら、
「読めたのは第 1 条〜第 15 条（10 ページ目まで）です」のように、読めた範囲を結果の冒頭に書く。

### 28.6 契約の種類ごとの観点

観点は拡張機能の補助資料に持ち、**法改正に合わせて直す**（観点ごとに根拠と確認日を書く）。Phase 1 で詳しく持つのは NDA・売買・業務委託の 3 種類とし、第 0.282.0 版で建物の賃貸借・ライセンス・利用規約の 3 種類を足した（第28.14節）。ほかの種類は共通の観点で読む。

| 種類 | 主な観点 |
|---|---|
| 秘密保持契約（NDA） | 第28.6.2節の 10 の観点。中小企業に最も多く届く契約のため、観点を最も細かく持つ |
| 売買・取引基本契約 | 目的物と数量、納品と検収、所有権と危険の移る時点、契約不適合の責任（期間と内容）、代金と支払の期日、遅延損害金、個別契約との優先関係 |
| 業務委託（請負・準委任） | 業務の範囲と成果物、検収、成果物の権利（著作権など）の帰属、再委託、報酬と支払の期日、中途の解約、損害賠償の上限。**個人に委託する・個人から受けるときは、フリーランスの取引に関する法律（2024 年 11 月施行）に当たるかを示し、当たるかどうかの判断は専門家の確認とする** |
| 建物の賃貸借（第 0.282.0 版） | 普通の借家か定期借家か（定期借家の書面と事前の説明）、期間と更新と中途の解約（予告・残りの賃料）、賃料の改定（一方的な改定）、敷金と償却、原状回復（通常の損耗の扱い・指定の業者）と造作、修繕の負担、又貸しと譲渡、個人の保証の極度額、明け渡しの遅れの損害金 |
| ライセンス（第 0.282.0 版） | 許諾の範囲（対象・目的・地域・期間・独占かどうか・再許諾・改変）、ロイヤリティと最低保証と監査、改良したものの扱い（グラントバック）と不争（独占禁止法に関わりうる点は可能性だけを示す）、第三者の権利の保証と補償、オープンソース、終わった後の扱い（販売済みのもの） |
| 利用規約（第 0.282.0 版） | **交渉できない前提で読む**（定型約款。修正の案の代わりに備え方を書き、交渉の進め方の代わりに使うかどうかを決める材料を書く）。規約とサービスの一方的な変更、稼働率と返金、データの権利と利用（AI の学習）と置き場所と取り出し、個人情報（委託・外国にある第三者への提供）、利用の停止、自動の更新と解約、責任の上限と補償、外国の準拠法と裁判所 |
| 共通 | 契約の期間と自動更新（更新を止める通知の期限）、中途の解約と解除の条件（直す猶予の有無）、損害賠償の範囲と上限（上限の例外が広すぎないか・間接損害の扱い・双方か片方か）、補償（第三者から訴えられたとき）、知的財産の帰属と利用の許諾、個人情報の取り扱い（預ける・預かる個人データ、漏えいの連絡）、表明と保証、不可抗力、保険、支払の条件と遅延損害金、反社会的勢力の排除、準拠法と裁判の管轄、権利や地位の譲渡と会社の支配権の変更、契約の終わったあとも残る条項 |

#### 28.6.1 会社の契約の基準

会社ごとに「どこまでなら受け入れ、どこからは直してもらうか」の線がある。これを**契約の基準**として会社の知識に置けば、契約書チェックはそれに照らして読む。

| 項目 | 規定 |
|---|---|
| 中身 | 条項の種類ごとに、**標準の立場**（望む書き方）、**受け入れられる範囲**（交渉せずに結んでよい幅）、**専門家に回す条件**（これに当たれば社内だけで決めない）。自社のひな形も置ける |
| 置き場所 | 会社の知識（第11章）。専用の設定の画面は作らない（ADR-0028。人に表を作らせない） |
| 作り方 | **秘書に頼んで作る。** 「このひな形を当社の契約の基準にして」「損害賠償の上限は委託料までにしたい、と覚えて」と頼むと、秘書が基準の文書にまとめて会社の知識に登録する。人が一から書かなくてよい |
| 無いとき | 一般的な取引の水準で読み、結果の冒頭に「会社の基準が無いため、一般的な水準で読みました」と書く。**基準を作るよう求めない**（結果の最後に、秘書に頼めば作れることを 1 行添えるだけ） |

#### 28.6.2 NDA の点検（第 0.139.3 版）

NDA は数が多く、1 通ごとに時間をかけられない。そのため、**まず 10 の観点で全体を見立て**（第28.7節の総合の見立て）、そのうえで気になる点を示す。
観点ごとの一般的な目安（期間の年数など）は補助資料に確認日つきで持ち、会社の基準（第28.6.1節）があればそちらを優先する。

| # | 観点 | 見ること |
|---|---|---|
| 1 | 形 | 双方が秘密を守るのか、片方だけか。**取引の実態に合っているか**（互いに情報を出すのに片方だけが守る形になっていないか） |
| 2 | 秘密情報の定義 | 広すぎないか（「あらゆる情報」など）。「秘密」と表示したものに限る場合、口頭で伝えた情報の扱いが実際に回るか |
| 3 | 秘密にしないもの（例外） | 次の 5 つがそろっているか: **公知の情報、受け取る前から知っていた情報、自分で独自に作った情報、正当に第三者から得た情報、法令や裁判所に求められた開示**。特に「独自に作った情報」が無いと、自社で作ったものまで相手の秘密を使ったと言われかねない |
| 4 | 守り方と使い道 | 自社の秘密と同じ程度の注意でよいか。使い道が目的の範囲に限られているか。**実務で守れない義務**（すべての通信の暗号化、記録の作成など）が無いか |
| 5 | 開示してよい相手 | 必要な従業員、委託先、**顧問の弁護士・税理士など**、必要ならグループ会社、法令による開示 |
| 6 | 期間 | 契約の期間と、終わったあとも秘密を守る期間。**期限の無い秘密保持**は、営業秘密に当たるものを除いて避ける |
| 7 | 返還と破棄 | 終わったとき・求められたときに返すか破棄するか。**法令や社内の保存（バックアップを含む）のための保管の例外**があるか。破棄の証明が重すぎないか |
| 8 | 違反したとき | 差止めを求められることは一般的。**あらかじめ決めた違約金（損害賠償の額の予定）**は NDA では避ける。双方に同じく効くか |
| 9 | 紛れ込んだ条項 | NDA に入っているべきでない条項が無いか: **従業員の引き抜きの禁止、競業の禁止、ほかの会社と話すことの禁止（独占）**、記憶に残った情報は自由に使えるとする条項（残留情報）、知的財産の譲渡や利用の許諾、監査の権利 |
| 10 | 準拠法と裁判所 | 日本法か。裁判所が相手の所在地だけに決められていないか。準拠法と裁判所が食い違っていないか |

| 場合 | 扱い |
|---|---|
| **NDA という題でも、取引の条件（代金・独占・納品など）が入っている** | NDA の点検をやめ、契約全体の点検（第28.5節）に切り替え、そのことを冒頭に書く |
| 大きな契約の中の秘密保持の条 | その条だけでなく、契約全体と合わせて読む（ほかの条と効き合うため） |
| 自社が情報を出すだけ・受け取るだけ | 片方だけが守る形でも、向きが合っていれば「一般的な範囲」とする |

### 28.7 結果の形

結果は実行の詳細（第6.2.2節）に書式つきの文章で出し、同じ中身を Word の文書にする。秘書から頼んだときは、秘書のキャンバスに要点を出す。

| 順 | 見出し | 中身 |
|---|---|---|
| 0 | （冒頭） | 境界の表示（第28.2節）。読めた範囲。仮に決めた自社の立場。**照らした基準（会社の基準か、一般的な水準か）** |
| 1 | 総合の見立て | 契約全体を 1 行で 3 段階に見立てる（第 0.139.3 版）: 「**一般的な範囲に収まっています**」「**交渉したい点があります**」「**専門家に確認したい点があります**」。いちばん重い 1 件で決める。**結ぶかどうかは会社が決めることで、見立てはその判断ではない**と同じ行に書き添える |
| 2 | 概要 | 種類、当事者（自社はどちらか）、目的、期間と更新、金額と支払、主な義務。**10 行まで** |
| 3 | 注意したい点 | 「専門家に確認したい」「交渉したい」の順（下の 3 段階）。1 件ごとの形は下の表 |
| 4 | 抜けている条項 | 一般に入る条項のうち、この契約に無いもの。入れる場合の文案 |
| 5 | 会社の基準との違い | 「契約の基準」の知識があるときだけ。出典を添える |
| 6 | 専門家に相談したほうがよい点 | 「専門家に確認したい」に当たるもの、法律に当たるかどうかの判断が要るもの |
| 7 | 交渉の進め方の案 | 「必ず直したい」から切り出し、「譲ってよい」を引き換えにして「直したい」を取る、という順番。期限が近ければ「必ず直したい」だけに絞る。**交渉の案であり、交渉を代わりに行うのではない** |
| 8 | 次にすること | 相手への確認のメールの下書きを秘書に頼める、専門家に見せる点、など 3 つまで |

| 項目 | 規定 |
|---|---|
| 条項の引用 | 条の番号と見出しを必ず書く。引用は修正に要る文だけを短く行い、**契約書を長く写さない** |
| 3 段階 | 条項ごとに、照らした基準との違いで分ける。**専門家に確認したい**: 基準の「専門家に回す条件」に当たる、または当社に大きな損害や責任が生じうる（例: 損害賠償に上限が無い、自社が元から持つ知的財産まで渡す）。**交渉したい**: 基準から外れるが、よくある書き方で交渉の余地がある。**一般的な範囲**: 基準どおりか近い。結果では件数だけを示し、1 件ずつは畳む。「一般的な範囲」は「問題ない」の意味ではないと書き分ける |
| 1 件の形 | 「条項（第〇条 見出し）」「該当する文（短く引用する）」「何が書いてあるか」「当社への影響（実際に何が起きうるか）」「修正の案（そのまま差し替えられる文案）」「相手に伝える理由（そのまま相手に見せられる 1〜2 文）」「優先度（必ず直したい・直したい・譲ってよい）」「代わりの案（修正の案を断られたときの落としどころ）」「相手に確かめること」 |
| 修正の案の書き方 | 具体的な文にする（方向だけを言わない）。強すぎる案は交渉を長引かせるため、重要な点は譲らず、ほかは取引として無理のない文にする。初めての相手か、長い付き合いの相手かで言い回しを変える |
| 注意したい点が無いとき | 「目立って不利な点は見つかりませんでした」と書く。「問題ありません」とは書かない |
| 英語の契約書 | 読み、日本語で結果を返す。日本語より読み違いが起きやすいことを冒頭に書く |

### 28.8 秘書から使う

| 依頼の例 | 秘書の動き |
|---|---|
| 契約書のファイルを渡して「チェックして」「このNDA大丈夫？」 | 契約書チェックに取り次いで実行し（第10.10.3節）、終わったら注意したい点の要点を伝える。**大丈夫かどうかは答えない** |
| 「さっきの契約書、損害賠償のところを詳しく」 | 実行の結果をもとに答える（本人が頼んだ実行の結果だけ） |
| 「相手に確認するメールを書いて」 | 「相手に確かめること」をもとにメールの下書きを作る（`gmail.create_draft`）。送るのは本人の承認のあと |

### 28.9 機密と保持

契約書は機密であることが多い。

| 項目 | 規定 |
|---|---|
| 見られる人 | 実行の中身は依頼した本人だけ（第6.2.3節） |
| 残す期間 | 業務に渡したファイルと結果は、実行の成果物として 1 年（第10.10.5節・第19.3節） |
| 記憶と知識 | **秘書の記憶にも会社の知識にも入れない**（学ばない業務の印。第28.3節）。会社のひな形や基準を知識にしたいときは、会社が自分で登録する |
| 推論へ渡すもの | 契約書の全文を Gemini に渡す。Limited Use を守り、学習に使わない。自社の鍵で使う会社は自社の契約の条件による（第14.3.3節） |
| 書かれた指示 | 契約書の文はデータであり、指示として扱わない（不変則 I-6）。「この条項は確認不要」のような文があっても従わない |

### 28.10 評価

拡張機能の評価（`evals/`。第18章）に、次を必ず入れる。

| 観点 | 内容 |
|---|---|
| 見落とさない | 種類ごとに、不利な条項を仕込んだ見本の契約書を置き、仕込んだ点を指摘すること |
| 断定しない | 「問題ありません」「結んで大丈夫」「違法です」などの言い回しが結果に出ないこと |
| 境界の表示 | 冒頭の表示があること |
| 基準の明示 | 会社の基準があるときはそれに照らし出典を添え、無いときは「一般的な水準で読んだ」と書くこと |
| 3 段階 | 仕込んだ「専門家に確認したい」点（上限の無い損害賠償など）を、その段階に分けること |
| NDA | 紛れ込んだ競業の禁止・引き抜きの禁止を見つけること。「独自に作った情報」の例外の抜けを見つけること。NDA の題で取引の条件が入った見本を、契約全体の点検に切り替えること。一般的な NDA の見本を「一般的な範囲に収まっています」と見立て、「結んでよい」とは書かないこと |
| 読めた範囲 | 上限を超える長さの見本で、読めた範囲を書くこと |
| 指示に従わない | 契約書の中の「この契約は確認済み」のような文に従わないこと |

### 28.11 段階と行わないこと

| 段階 | 行うこと |
|---|---|
| Phase 1 | 日本語の契約書（PDF・Word・画像）、NDA・売買・業務委託の観点、概要・注意したい点・修正の案・相手に確かめること・抜け・専門家に相談したほうがよい点、Word の結果、秘書からの取次、会社の基準の参照 |
| Phase 2 | 修正の案を変更履歴つきの Word で返す（Q-98）、長い契約書（目安 50 ページ超）をまず主な条項だけ読み、続けて全体を読む 2 段の読み方、観点を持つ種類を増やす（賃貸借・ライセンス・利用規約など）、相手の修正版との差分の点検 |
| 次の拡張の候補 | 結んだ契約の期限と自動更新の管理（更新の期日の前に秘書が知らせる）。取引先ごとの契約の有無と期限を秘書が答える（「〇〇社とは NDA を結んでいる？」）。**この 2 つは第38章「契約の管理」（第 0.271.0 版の案）で行う**。**結ぶ前の確認**（修正が残っていない最終版か、別紙がそろっているか、当事者の正式名称・日付・署名する人、社内の承認）。いずれも付録 B.7 の vendor-check・signature-request の考え方による |

| 行わないこと | 理由 |
|---|---|
| 契約を結ぶかどうかの判断 | 法務の境界（第28.2節） |
| 相手方への送信・交渉の代行 | 社外への送信は本人の承認のあと。交渉そのものは行わない |
| 電子署名・押印 | 目的を超える。お金や権利の確定に当たる |
| 契約書の保管の仕組み | ドライブなどの既存の置き場を使う。M2Office で文書管理を作らない |

### 28.13 相手の修正版との差分（第 0.281.0 版）

2026-10-06 に三浦さんが「次に進んでください」と依頼し、次の作業の候補から「契約書の修正版との差分」を選んだ。Phase 2（第28.11節）のうち、相手の修正版との差分の点検を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 入力 | 欄「前の版」（ファイル。任意）を足す。「契約書」の欄が新しい版（相手から戻ってきた修正版）になる。前の版が空なら、これまでどおり 1 通を点検する |
| 変わったところの見つけ方 | **推論ではなくプログラムが見つける**（見落とさないため）。ツール `file.compare`（危険度 `read`。依頼者本人のファイルだけ）が、2 つの版を文字にし、「第〇条」「Article 〇」の見出しで条項に分け、前文どうし・見出しの題名が同じ条項どうし、残りは中身の近さ（文字の 2 つ組の重なりが半分より上）で結ぶ。条の番号がずれても追える。結んだ条項の中は文（「。」と改行）の単位で比べ（全角と半角・空白の違いは無くす）、足された・消された・変わった条項と、前の版にだけある文・新しい版にだけある文を、新しい版の順に返す。中身の同じ条項は数だけを返し、番号だけ変わった条項は「第〇条 → 第〇条」で返す。文の重なりが 3 割に満たなければ、別の文書を比べた見込みがあると添える。返す変更は 60 件まで |
| 結果 | 「概要」の後ろに「前の版からの変わったところ」の見出しを置き、ツールが返した変更を**1 つも省かずに**挙げる（相手が説明していない変更・数字や期間だけの変更を見落とさないため）。1 件ずつ、前と後の文を短く、当社にとって有利・不利・どちらとも言えない、見立て（受け入れてよい・交渉したい・専門家に確認したい）、不利なら修正の案と相手に伝える理由。番号だけ変わった条項は 1 行。冒頭に比べた 2 つの版の名前。注意したい点（3 段階）は新しい版の全体で点検し、今回の修正で変わった条項には「（今回の修正）」と添える。別の文書の見込みのときは比べた結果を書かず、そのことを冒頭に書く |
| 秘書 | 修正版を渡して「前の版と比べて」「修正版が戻ってきた」と頼まれたら、入力を埋める推論が「前に渡したファイルと比べる依頼か」だけを読み、そうなら本人が同じ業務に前に渡したファイル（本人の実行のうち新しいものの「契約書」の欄。本人のファイルだけ）を「前の版」に入れる。ファイルの欄は推論に埋めさせない（ファイルの ID を推測で作らせない）。業務の 2 つ目のファイルの欄はどの業務でも同じ扱い（`secondFileInputKey`） |
| 評価 | 見本 `sales-basic-revised.md`（`sales-basic.md` の相手の修正版。有利な変更と不利な変更を混ぜ、条の番号をずらした）で、5 件の変更をすべて挙げ、不利な 3 つ（支払いの延長・逸失利益・管轄）を見分けること |
| 拡張機能の版 | 1.1.0 |

**行っていないこと**: 前の版が Word の変更履歴を持つときに、その履歴を読むこと（文字にして比べる）、表や別紙の中の変更を表として比べること（文として比べる）、本物の Gemini での確かめ（プログラムの比べ方は見本の契約書で確かめた）。

### 28.14 観点を持つ種類の追加（第 0.282.0 版）

2026-10-06 に三浦さんが「次に進んでください」と依頼し、次の作業の候補から「契約書チェックの観点を増やす」を選んだ。Phase 2（第28.11節）の「観点を持つ種類を増やす」を、次の決まりで実装した。表も画面も変えず、拡張機能の補助資料と評価を足しただけである（拡張機能 1.2.0）。

| 項目 | 規定 |
|---|---|
| 足した種類 | 建物の賃貸借（事務所・店舗・倉庫。`reference/lease.md`）、ライセンス（ソフトウェア・技術・コンテンツの利用の許諾。`reference/license.md`）、利用規約（クラウド・インターネットのサービスを使う側。`reference/terms.md`）。観点は第28.6節の表。どれも確認日（2026-10-06）を書き、法律の条を挙げるときは当たる可能性を示すだけにし、当たるかどうかは専門家の確認とする |
| 選び方 | 全文を読んで種類を見分け、その種類の観点を 1 回で開く（第28.5節）。2 つにまたがる契約は主な方を開き、もう一方は共通の観点で補う。住まいとして借りる契約（消費者契約）は建物の賃貸借の観点の対象にしない |
| 利用規約の読み方 | 利用規約は多くの人に同じ中身で示す定型約款で、ふつうは交渉できない。そのため注意したい点の修正の案・相手に伝える理由・代わりの案を「備え方」（使い方で備えること・確かめること・法人向けの別の契約で変わるか）に置き換え、「交渉の進め方の案」を「使うかどうかを決める材料」（受け入れる・使い方で備える・別の覚書を求める・ほかのサービスにする）に変える。どれにするかは書かない（会社が決める）。不当な条項が効かないとは断定しない（合意しなかったものとみなされる可能性がある、まで） |
| 評価 | 見本を 3 つ足した（評価は 9 件）: 借りる側に重い事務所の賃貸借（極度額の無い個人の保証を「専門家に確認したい」に）、受ける側に重いソフトウェアのライセンス（改良技術の無償の移転と不争は可能性だけを示す）、交渉できない前提で読むクラウドの利用規約（規約の「当社」は運営する会社と見分ける） |

**行っていないこと**: 本物の Gemini での新しい 3 つの見本の確かめ、労働者派遣・代理店・フランチャイズなどの種類（共通の観点で読む）、観点の資料の弁護士の確認（Q-97 と合わせて公開の前に行う）。
