## 36. 競合の分析（同業の動きを知る。第 0.233.0 版。第 0.235.0 版で調べた結果を入れて直した。第 0.236.0 版で確定し、段 1 を実装した）

この章で決めること: 自社と同業の競合の Web サイトを AI が探して覚え、**月に 1 回見回って**、自社との違い・相手の強み・最近の動き・自社の次の一手をまとめるしくみ。

**この章は確定した**（2026-10-03、三浦さん「第36章の案を確定して、段 1 を実装してください」。第 0.236.0 版）。**汎用のしくみとして作る。** 特定の導入先・業種の条件に合わせた作りにしない。
「（案）」と書いた値は、確定のときに案のとおりとした値である。段 1 の実装の決まりは第36.18節。
方針の判断の記録は [ADR-0069](../docs/adr/0069-competitor-analysis.md)。

**2026-10-03 に三浦さんが示した狙い**

- 自社の Web サイトと、競合になりそうな Web サイトを探し出し、自社とどう差別化されているか・相手の強みはどこかを、自動で分析したい。
- 競合は、基本は同業他社。実店舗などは営業圏の中（近くの何 km 以内など）の同業。特定の近くの店を指定したいときは URL を入れられる。それ以外は、できるだけ近くの競合を自動で探す。営業圏の制限が無い業種は、同じような事業の会社を広く探す。
- 見つけた競合の URL を覚えておき、月に 1 回ほど見直して、「いま競合が何をしているか」をまとめたレポートを作りたい。
- 三浦さんが、近くの同業は Gemini の Google マップのグラウンディングで探すこと・競合の数の上限（自動 5 社・手入力を含めて 10 社）・無償で同梱すること・名前を「競合の分析」にすることを、おすすめのとおりに選んだ（2026-10-03）。
- 第 0.235.0 版で、実装の前に確かめること（第36.17節）を調べた。Google マップのグラウンディングは、結果を残すことと、結果から巡回の相手を決めることを利用規約が禁じ、競合の Web サイトの URL も返さないため、**近くの同業は Google Places API で探す**ことにした（第36.5節で選んでいた「使えないときは Places API」に当たる）。商圏の無い業種でも、Google 検索のグラウンディングの結果を巡回の相手にしない。三浦さんが「Places API の方針で確定してください」として確定した（2026-10-03、第 0.235.1 版）。残っていた確かめ（請求の設定・競合の名前の残し方・名乗り方）も、第 0.235.2 版で三浦さんが決めた（第36.17節）。

### 36.1 目的と位置づけ

#### 36.1.0 いちばんの目的（第 0.238.0 版）

2026-10-04 に三浦さんが、この章のいちばんの目的を次のように示した。

**競合の分析は、1 回きりの調査ではない。定期的に（既定は月 1 回）見回って、競合の「変化」をとらえ、経営者がどう手を打つかを決められるようにするしくみである。**

| 考え方 | 内容 |
|---|---|
| 変化をとらえる | 情報を集めること自体は目的ではない。新しいサービスを始めた・営業時間が変わったようだ・夏休みが例年より長い、といった**変化に気づくこと**が目的である |
| 経営者の判断の材料 | 変化に気づいたら、経営者がどう対応するか（迎え撃つ・差をつける・様子を見る）を決める材料にする。決めるのは経営者で、AI は材料と打てる手の案を出す |
| 常に見張る | 開業のときなどの 1 回きりの競合の調査は、ほかの道具でもできる。M2Office が目指すのは、周りで日々何が起きているか、競合とどう戦うかを**常に見張る**ことである |
| 見回りの間隔 | 既定は月 1 回。毎週は多すぎることがある。間隔を会社が選べるようにするかは段 2 で決める |
| レポートの重心 | レポートの中心は「前の回から変わったこと」と「それに対して自社が打てる手」に置く。自社との違いの表と相手の強みは、変化を読むための土台である |
| 段階の位置づけ | 段 1（探す・覚える・その場のレポート）は見張りの土台づくりであり、本命は段 2 の定期の見回りと変化の届け方である |


| 痛み | M2Office で行うこと |
|---|---|
| 競合がどこか、はっきりしていない | 自社の事業と場所から、AI が同業を探して候補を出す。商圏のある業種は近い順、無い業種は事業の近い順（第36.5節） |
| 競合のサイトを見に行く時間が無い | 月に 1 回、AI が競合の主なページを読み、**前の月から変わったところだけ**を拾う（第36.7節） |
| 自社の強みと弱みを言葉にできない | 自社と競合を同じ物差し（サービス・価格帯・対応の範囲・打ち出していること）で並べ、違いと相手の強みをまとめる（第36.8節） |
| 分かっても次に何をすればよいか分からない | レポートに、自社の次の一手（コラムのテーマ・お知らせ・Web の直すべき所）を添え、ほかの拡張につなぐ（第36.9節） |

#### 36.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・店舗・医院・士業など。Web サイトが無い店舗でも、近くの競合は見られる |
| 商圏 | 来てもらう業種（店舗・飲食・美容・医院・士業の事務所など）は商圏あり。通販・ソフトウェア・全国対応のサービスは商圏なし |
| 競合の数 | 自動で探すのは 10 社まで、人が入れるのを含めて 15 社まで（第 0.238.0 版で 5 社・10 社から上げた） |

### 36.2 形: 内蔵の拡張（既定は切り。案）

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張（第12.13節）「競合の分析」（ADR-0069）。Web の分析（第34章）とは**別の拡張**にする（Web サイトの無い店舗でも、近くの競合は見られるため） |
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 無償で同梱する（三浦さんが選んだ）。推論と地図の検索の費用は、会社の Google Cloud（Gemini と Places API）の料金にかかる。目安は 1 社あたり月 1 ドル未満（自動 5 社・10 ページ。第36.17節）。第 0.238.0 版で自動 10 社にし、評価と件数を引くようにしたため、月 2 ドル程度までを見込む（地図の無料の枠に収まれば推論の分だけ） |
| 左のメニュー | 業務の 1 つとして「競合の分析」を出す |
| 業務（付属） | 「競合を探す」「競合の分析」（その場のレポート）「競合の見回り」（月 1 回）。秘書が取り次ぐ（第36.10節） |

### 36.3 用語

| 用語 | 意味 |
|---|---|
| 自社の像 | 自社の Web サイトと会社情報から AI がまとめた、事業・サービス・価格帯・対応の範囲・打ち出していること・場所 |
| 競合 | 自社と同じお客様を取り合う会社や店。URL・名前・場所（あれば）・距離（商圏ありのとき）・見つけ方（自動・手で入れた）を持つ |
| 商圏 | お客様が来る範囲。商圏ありの業種では、自社の住所を中心にした半径で表す |
| 見回り | 競合のサイトの主なページを読み、取り出した事実（サービス・値段・キャンペーン・お知らせなど）を前の回と比べること |
| レポート | 自社との違い・相手の強み・今月の動き・自社の次の一手をまとめた文。社内向け |

### 36.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 入り切り | 管理者ページの「拡張機能」 | 切り |
| 自社の Web サイト | 会社情報に「Web サイト」の欄を足す（第36.6節。Web の分析・コラムの作成でも使う）。空なら、AI が会社の名前と住所で探して使い、画面に出す（違っていれば直す） | 空 |
| 自社の住所 | 会社情報の住所を使う（商圏の中心） | 会社情報のまま |
| 自動で覚える数 | 管理者ページの「拡張機能」の競合の分析の設定（1〜20 社）。都心と山あい、業種で同業の数が違うため（第 0.239.0 版。三浦さんの指定）。全体の上限は、この数に人が入れる 5 社を足した数 | 10 社 |
| 見られる人 | 利用範囲（第16.7節） | 全員 |

**業種の分類・商圏の半径・競合の一覧を会社に作らせない**（ADR-0028）。AI が決めて候補を出し、違っていれば画面か秘書で直す。

### 36.5 競合を探す

| 項目 | 規定 |
|---|---|
| 商圏の有無と半径 | 自社の像から **AI が決める**。商圏ありなら半径も業種から決める（目安: 飲食・美容・小売 1〜2 km、医院・歯科 3〜5 km、士業・塾 市区町村の中。案）。違っていれば、秘書に「半径 2 km で探して」「全国で探して」と言えば直る |
| 商圏あり | **Google Places API（New）の周辺の検索**（Nearby Search）で、自社の場所を中心に、半径の中の同業を探す（業種は AI が Places の種類から選ぶ。日本語で引く）。管理者が拡張機能の設定で**地図の鍵**（Google Cloud コンソールで作った API キー。Places API を許したもの）を預ける。預けていなければ、会社の Gemini の鍵が昔の形（`AIza` で始まる）のときだけそれを使う（第 0.237.0 版。手順はヘルプ）。使えなければ「地図から探せませんでした」と書き、人が入れた競合だけを見る（第 0.235.0 版で、Google マップのグラウンディングから改めた。第 0.235.1 版で確定。第36.17節） |
| 商圏なし | AI が自社の像から、同じお客様を取り合う会社を挙げ、それぞれの Web サイトのトップを読んで実在と中身を確かめてから覚える。**Google 検索のグラウンディングの結果は巡回の相手にしない**（利用規約が、結果のリンクから巡回の相手を決めることを禁じるため）。秘書との会話で検索の結果を見せるのは、第10.11.4節の調べもののとおり |
| 候補の確かめ | 見つけた候補ごとに、AI が自社の像と比べて「同じお客様を取り合うか」を確かめ、理由を一言付ける。自社・自社の別の店・関係会社は外す |
| 数 | 自動で覚えるのは既定で 10 社まで。人が入れるのを含めて 15 社まで（第 0.238.0 版で 5 社・10 社から上げた。近くに同業の多い業種で、主な競合が漏れないように）。第 0.239.0 版で、自動で覚える数を管理者が 1〜20 社に変えられるようにし、全体の上限はその数 + 5 社にした（第36.4節） |
| 人が入れる | 画面の 1 行の欄に URL か店の名前を入れるか、秘書に「〇〇店を競合に入れて」と頼む。名前なら AI が探して URL を確かめる |
| 外す | 画面の「外す」か、秘書に「〇〇は競合じゃない」と言う。外したものは、次に自動で探しても入れない |
| 探し直す | 3 か月ごと（案）と、自社の像が変わったとき（会社情報の住所・Web サイトを変えたとき）に、自動の競合を探し直す。人が入れたものは残す |

### 36.6 自社を知る

| 項目 | 規定 |
|---|---|
| 材料 | 自社の Web サイトの主なページ（第36.7節と同じ読み方）と、会社情報（名前・住所）。会社の非公開の知識は使わない（外部の AI に渡さないため。第36.13節） |
| まとめるもの | 事業・主なサービスと価格帯・対応の範囲（地域・時間・対象のお客様）・打ち出していること（強みとして書いていること）・場所 |
| 見直し | 月の見回りで自社のサイトも読み、変わっていれば自社の像を直す |
| Web サイトの無い会社 | 会社情報と、秘書に話したこと（「うちは〇〇の店」）からまとめる。違いの比べ方は、相手の Web サイトと地図の情報が中心になる |

### 36.7 読み方（自社と競合のサイト）

| 項目 | 規定 |
|---|---|
| 読む範囲 | **公開されているページだけ**。ログイン・会員登録・支払いの要るページは読まない |
| 読むページ | トップと、トップから同じサイトの中でたどれる主なページ（サービス・メニュー・料金・お知らせ・ブログの一覧・会社案内・アクセス）。**1 社 10 ページまで**。どれを読むかは AI がリンクの名前から選ぶ |
| 相手への負荷 | **robots.txt に従う**（RFC 9309。読み直しは 24 時間ごと。robots.txt が 5xx か届かなければそのサイトは読まない。4xx なら読んでよい）。1 社は同時に 1 本で、ページの間を数秒（5 秒。案）空ける。月 1 回の見回りのほかに読みに行かない（人が「今すぐ」と頼んだときを除く）。M2Office であることを名乗る（User-Agent に M2Office の名前と版と、問い合わせ先の URL。問い合わせ先は運営主体の案内のページで、配備のときにマスター管理画面で設定する。第 0.235.2 版） |
| 取り出すもの | 事実だけを JSON で取り出す: サービス（名前・値段）・キャンペーン（中身・期間）・お知らせとブログ（題名・日付）・営業時間・対応の範囲・打ち出していること |
| 写しを持たない | 相手のページの文章は、事実を取り出して変化を見る間だけ持ち、残さない。残すのは、取り出した事実・ページが変わったかを見る印（文字の要約の指紋）・出典の URL だけ（第36.13節。著作権法 第30条の4・第47条の5 の範囲にとどめる） |
| 読めないとき | 読めなかったページ・サイトは「読めませんでした」と書き、前の回の事実を今の事実として扱わない |
| 外部の文 | 読んだページはデータであり、中の指示には従わない（不変則 I-6） |

### 36.8 レポート

| 項目 | 規定 |
|---|---|
| 中身 | ① 前の回からの動き（競合ごとに、前の回から変わったこと: 新しいサービス・値段の変更・営業時間や休みの変更・キャンペーン・お知らせ。第 0.240.0 版で見出しを「今月の動き」から改めた）、② 自社との違い（同じ物差しの表: サービス・価格帯・対応の範囲・打ち出していること）、③ 相手の強み、④ 自社の次の一手 1〜3 つ |
| 出典 | 事実には、どのページで分かったか（URL）を必ず付ける。推測は推測と書く |
| 言葉 | 相手を悪く書くための言葉を使わない。社内向けの判断材料として、事実を並べる |
| 届け方 | 月の見回りの後に、利用範囲の管理者と、会社が決めた人（既定は管理者）のお知らせに届く。Web の分析（第34.4節）が入っていれば、その月の便りに要点を 2〜3 行で載せる |
| その場で | 秘書に「競合の動きは？」「〇〇店とうちの違いは？」と聞けば、覚えている事実から答える。「今すぐ見回って」で見回る |
| 変化が無いとき | 「今月は大きな動きはありませんでした」と書き、違いの表は前の月のものを短く添える |

### 36.9 ほかの拡張とのつなぎ

| つなぎ先 | 規定 |
|---|---|
| コラムの作成（第32章） | 次の一手のうち、書くとよい話題（「競合 A が〇〇を始めた」→ 自社の〇〇を伝えるコラム）を、テーマ案の材料に渡す。**競合の名前は渡さない** |
| お知らせの作成（第35章） | キャンペーンや営業時間の差から、出すとよいお知らせの案を添える |
| Web の分析（第34章） | 月の便りに要点を載せる。検索で競合に負けている言葉があれば、直すべき所に足す（段 3） |
| 問い合わせの記録（第33章） | 「どこで知ったか」に競合の名前が出ていれば（「〇〇店と比べて」など）、レポートに件数だけを添える（段 3） |
| 社外に出すとき | レポートをもとに広告やコラムで他社と比べるときは、コラムの作成の表現の決まり（景品表示法の比較広告・医療広告ガイドラインの比較の禁止など）で赤入れする |

### 36.10 秘書と業務から使う

| 頼み方 | 動き |
|---|---|
| 「競合を探して」 | 自社の像をまとめ、競合を探して覚える（第36.5節） |
| 「〇〇店を競合に入れて」「〇〇は競合じゃない」 | 足す・外す |
| 「半径 2 km で探し直して」「全国で探して」 | 商圏を変えて探し直す |
| 「競合の動きは？」「今月の競合のレポートを見せて」 | 最新のレポートを答える |
| 「〇〇店とうちの違いは？」 | 覚えている事実から、違いと相手の強みを答える |
| 「今すぐ見回って」 | 見回ってレポートを作る |

### 36.11 画面

| 項目 | 規定 |
|---|---|
| 一覧 | 上に自社の像（短く）と商圏（「半径 2 km」「全国」）。その下に競合を、距離か近さの順に並べる（名前・URL・距離・見つけ方・最後に見回った日・今月の動きの数） |
| 追加 | 一覧の上の 1 行の欄に URL か店の名前を入れて「追加」 |
| 削除 | 競合ごとに「削除」（第 0.239.1 版で「足す」「外す」から言葉を改めた） |
| 1 社 | 取り出した事実（サービスと値段・キャンペーン・お知らせ）と、月ごとの変化を時系列に並べる。各事実に出典の URL |
| レポート | 月ごとのレポートを新しい順に並べる。「今すぐチェック」（見回る）と「レポートの作成」（読み直さずに作る）。表の中にはリンクを付けない（第 0.239.1 版でリンクマークにし、第 0.239.3 版で、どれも同じ先で意味が無いため外した） |
| 自社のデータ | 自社の像の欄の「自社のデータ」で、自社のサイトから取り出した事実を出す |
| 一覧の列 | 競合・距離・Google の評価・取得方法・取得日・データ数（第 0.239.3 版で「見つけ方」「読んだ日」「事実」から改めた） |
| 取得方法 | 「Google Maps」「AI」「手で入れた」。地図で見つけたものは「Google Maps」の 1 つにし、出典の表記を兼ねる（訳さない。第 0.239.2 版で「地図」と「Google Maps」の 2 段から 1 つにまとめた） |
| 説明文 | 常に出さない（原則 u11） |

### 36.12 AI に任せること（ADR-0028）

| AI に任せる | 人が行う |
|---|---|
| 自社の像・商圏の有無と半径・競合の候補と確かめ・読むページの選び方・事実の取り出し・変化の見つけ方・レポート・次の一手 | 入り切り、URL を足す・外す（任意）、間違いを直す |

### 36.13 境界

| 項目 | 規定 |
|---|---|
| 公開の情報だけ | 読むのは公開されているページと、地図の公開の情報だけ。ログイン・会員・有料のページ、相手の社内の情報には触れない |
| 相手への負荷 | robots.txt に従い、月 1 回・1 社 10 ページまで・間を空けて読む（第36.7節） |
| 写しを持たない | 相手の文章・画像を残さない・転載しない。残すのは取り出した事実と変化の印だけ。レポートでも長い引用をしない（著作権。社内での情報の解析にとどめる） |
| 人の情報 | 口コミの投稿者名・従業員の名前など、個人の情報を集めない。口コミは評価と件数だけ（第 0.238.0 版で段 1 に前倒し）。口コミの文は読まない・残さない |
| 地図の情報 | Places API から得た情報で残すのは **place ID だけ**（期限なく残してよい）。名前・住所・評価・Web サイトの URL は残さず、見回りや表示のたびに引き直す。緯度と経度は 30 日まで。距離は表示のときに計算する。Places の位置で商圏の多角形の内外を決めない。表示するときは「Google Maps」の表記（訳さない）と、Places が返す出典の表示を付ける（Google Maps Platform の利用規約。第36.17節） |
| 外部の AI | 読むのは公開の情報なので、**外部の AI を使ってよい業務**（第16.3.7.1節）とする。会社の非公開の知識・問い合わせ・お客様の情報は渡さない。「ローカルだけ」の会社では使えない（地図と Web の検索が外部のため） |
| 社内向け | レポートは社内向け。社外に出す文で他社と比べるときは、表現の決まりで赤入れする（第36.9節） |
| 社外への送信 | 競合に連絡したり、問い合わせのフォームに書き込んだりしない |
| 記録 | 競合を足した・外した・探し直した・見回った（読んだページの数・読めなかった数）を監査ログに残す |

### 36.19 段 2 の実装の決まり（第 0.240.0 版）

2026-10-04 に三浦さんが「次に進んでください」と依頼した。この章のいちばんの目的（第36.1.0節: 定期の見回りで競合の変化をとらえる）を担う段 2 を、次の決まりで実装した。

| 項目 | 規定 |
|---|---|
| 見回りの間隔 | 会社の設定 `competitors.watch`。**毎月（既定）・毎週・しない** から管理者が拡張機能の設定で選ぶ（第36.1.0節で段 2 に回していた決め）。毎月は 1 日、毎週は月曜の、日本時間 3 時すぎに始め、朝には届いているようにする。最後に終わった見回り（探すを含む）がその回の始まりより後なら、その回は行わない（手で「今すぐチェック」した回は数える）。一度も探していない会社では行わない |
| 探し直し | 前に探してから 90 日を過ぎたら、見回りの代わりに探し直す（探すは続けて見回る）。会社情報の住所か Web サイトが、自社の像を作ったときと変わったら、すぐに探し直す |
| 変わったかの見分け | 読んだページごとに印（文字の指紋）を残す（`competitor_pages`）。**印が前の回と同じページは、前の回の事実をそのまま使い、推論に読み直させない**（AI の言い回しの揺れを変化と取り違えないため。推論の費用も減る）。印が変わったページ・新しいページだけ事実を取り出し直す。前の回に無かった事実のうち、変わったページのものを「動き」として数える |
| 回 | 事実・ページの印・レポートの回は、見回った日（YYYY-MM-DD）にする（毎週の見回りで比べられるように。それまでの年月の回もそのまま読む）。競合ごとに新しい 13 回分を残し、古い回は消す |
| レポート | 見出しの 1 つめを「前の回からの動き」にし、変化を先に書く。推論には、変わったページの前の回の事実と今の事実を渡し、言い換えだけのものは動きにしないよう指示する |
