## 32. Web のコラム（情報発信。第 0.218.0 版。案）

この章で決めること: 会社の Web サイトで、お客様に役立つコラム（記事）を**続けて出していく**ためのしくみ。
分野やテーマを決めると AI がテーマ案と下書きを作り、表現と事実を確かめ（赤入れ）、責任者が直して承認したものを Web サイトに出す。
後の段で、アクセスの解析（Google アナリティクス・Search Console）とつなぎ、読まれ方を次のテーマと書き方に返す。

**この章は案である。** **汎用の情報発信のしくみとして作る。** 特定の導入先・業種の条件に合わせた作りにしない。
会社ごとの違いは、**導入のときに会社が設定する項目**（第32.4節）で吸収する。まだ確かめる事項（第32.19節）の答えで直してから実装する。
**「（案）」と書いた値は、会社（三浦さん）の判断を待つ値である。**

**2026-10-02 に三浦さんが示した狙い**

- 中小企業の Web サイトによくある「数ページと社長のあいさつがあるだけで止まっている」状態から、新しい情報を**続けて出す運用**に変える。
- アクセスの解析で「どのような人が見たか」「そこからどこへつながったか」を振り返り、**次のコラムに反映していく**。

### 32.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 何を書けばよいか思いつかない | 登録した分野から、季節・ニュース・検索で増えている話題・お客様からよく来る質問をもとに、**AI がテーマ案を出す**（第32.6節） |
| 書く時間が無い | 調べものと下書きを AI が行う。人は経験や一言を足し、直すだけにする（第32.7節） |
| 書いてよい表現か分からない（医療・化粧品・健康食品など） | **業種ごとの表現の決まり**を M2Office が持ち、引っかかる所に理由と直し案を付ける（第32.8節）。人に決まりの一覧を作らせない（ADR-0028） |
| 続かない | 本数と曜日を決めれば、予定に沿って下書きを先回りで用意し、責任者に知らせる（第32.11節） |
| 出したあと読まれているか分からない | 後の段で、記事ごとの読まれ方・検索の言葉・その後どのページへ進んだかを集めて振り返り、次のテーマに返す（第32.12節） |

#### 32.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・店舗・医院・士業など、自社の Web サイトを持つ会社 |
| Web サイト | WordPress が多い。制作会社に任せていて、自社では触らない会社も多い（第32.10節） |
| 本数 | 月に 2〜8 本（案） |
| 書く人 | 専任はいない。総務・店長・院長などの兼務。責任者（承認する人）は 1〜2 人 |

### 32.2 形: 内蔵の拡張（既定は切り。案）

名刺管理・在庫管理と同じく、**内蔵の拡張**（第12.13節）とする案を第一とする（Q-161）。

| 理由 | 中身 |
|---|---|
| 画面が要る | 記事の一覧と状態・予定表・赤入れの表示・直しの画面は、業務（スキル）1 つの結果の文だけでは足りない |
| 会社の設定が要る | 分野・読み手・業種・責任者・公開先・本数と曜日 |
| 続けて動く | 予定に沿った先回り・効果の集計は、ワーカーの見回りで行う |

| 項目 | 規定 |
|---|---|
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 名刺管理・在庫管理と同じく無償で同梱する案（案。Q-166） |
| 業務（付属） | 「テーマ案を出す」「コラムの下書き」「コラムの赤入れ」。秘書が取り次ぐ（第32.13節） |

### 32.3 用語

| 用語 | 意味 |
|---|---|
| コラム | Web サイトに出す 1 本の記事。題名・本文・出典・説明文（検索の結果に出る文）・画像を持つ |
| 分野 | 会社が書きたい話題のくくり（例: 「花粉症」「肌の手入れ」「相続の手続き」） |
| テーマ | 1 本のコラムで扱う具体的な問い（例: 「花粉症の薬はいつから飲み始めるか」） |
| 取材メモ | 書く人が足す、自社ならではの経験・考え・事例（個人を特定しない）。記事の独自性になる |
| 赤入れ | 表現の決まりと事実を AI が確かめ、箇所・理由・直し案を付けたもの（第32.8節） |
| 責任者 | コラムを承認して公開する人。会社が決める |
| 監修者 | 記事に名前を出す専門家（医師・薬剤師・税理士など）。任意 |
| 公開先 | コラムを出す場所。WordPress のサイトか、M2Office が配る貼るだけのページ（第32.10節） |

### 32.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 分野 | 書きたい話題のくくり（複数）。一言で書けばよい | なし（入れるまでテーマ案は出さない） |
| 読み手 | 地域・年代・お客様の立場など（例: 「市内の子育て世帯」） | なし |
| 業種 | 表現の決まりを選ぶため（医療・歯科・薬局・化粧品・健康食品・飲食・士業・一般など）。会社情報の業種があれば使う | 一般 |
| 責任者 | 承認する人（承認者のロールの人から選ぶ） | 管理者 |
| 監修者 | 記事に出す名前と肩書（任意） | なし |
| 公開先 | WordPress（会社の接続で登録）か、貼るだけのページ | なし（決めるまで公開しない） |
| 本数と曜日 | 例: 月 4 本・水曜日 | なし（予定を作らない） |
| AI が書いたことの表示 | 記事の末尾に入れるか（Q-164） | 入れる（案） |
| 書き方 | **自社の書き方**（第15.2.1節）をそのまま使う。コラムだけの書き方は持たない | — |

人に一覧や規則を作らせない（ADR-0028）。表現の決まりは業種を選ぶだけで M2Office が持つ。言葉の言い換えの表なども作らせない。

### 32.5 流れ

**テーマ → 下書き → 赤入れ → 直し → 承認 → 公開 → 効果を見て次へ**

| 段 | AI がすること | 人がすること | 状態 |
|---|---|---|---|
| ① テーマ | 分野から、テーマ案を週に 1 回まとめて出す（第32.6節） | 選ぶ。一言で頼んでもよい | テーマ |
| ② 下書き | Web で調べて出典を付け、会社の知識と自社の書き方で書く。題名の候補・説明文・SNS の告知文も作る（第32.7節） | 取材メモを足す（任意） | 下書き |
| ③ 赤入れ | 表現の決まり・出典・古さ・似すぎ・個人の情報を確かめ、直し案を付ける（第32.8節） | 指摘を見る | 下書き |
| ④ 直し | 頼まれれば書き直す（「短く」「専門用語を減らして」） | 最終の文を決める | 下書き |
| ⑤ 承認 | — | **責任者が承認する**（社外に出るもの。第9.4.0節） | 承認待ち → 承認済み |
| ⑥ 公開 | 承認した版を公開先に入れる。予約の日時を守る（第32.10節） | — | 公開済み |
| ⑦ 効果 | 読まれ方を集め、次のテーマ案と見直しの提案に返す（第32.12節。段 3） | — | — |

**人の判断は承認の 1 回だけにする**（ADR-0028）。テーマ選びや下書きの途中では確認を求めない。

### 32.6 テーマ案

| 項目 | 規定 |
|---|---|
| 材料 | 会社の分野と読み手、**季節と行事**（その月に増える悩み）、**ニュースと制度の変更**（Web の調べもの）、**検索で増えている話題**（段 3 では Search Console の検索の言葉）、**お客様からよく来る質問**（会社の知識・秘書への問い合わせ・メールのうち、個人を特定しない話題だけ。第32.16節） |
| 出し方 | 週に 1 回、5 つ前後を責任者と書く人に知らせる（案）。1 つずつ「なぜ今か」を一言添える |
| 重ならない | 出したコラムと同じテーマ・ほぼ同じ問いは出さない。古くなった記事は「書き直し」として出す |
| 頼み方 | 秘書に「花粉症の時期の注意点で 1 本」「来月の分を 4 本用意して」と頼めば、テーマ案を飛ばして下書きへ進む |

### 32.7 下書き

| 項目 | 規定 |
|---|---|
| 調べもの | Web の調べもの（第9.4.2節）で調べ、**出典（題名と URL）を必ず付ける**。公的な機関・学会・メーカーの一次の情報を先にする |
| 会社の材料 | 会社の知識（サービス・料金・方針。第11章）と、取材メモ。会社に無いサービスや料金を書かない |
| 書き方 | 自社の書き方（第15.2.1節）。読み手に合わせ、専門用語には言い換えを添える |
| 形 | 題名（候補 3 つ）、見出しで分けた本文（1,500〜3,000 字。案）、まとめ、出典の一覧、説明文（検索の結果に出る 120 字前後）、SNS の告知文（2 つの長さ） |
| 画像 | 段 1 は、会社が入れた写真から選び、画像の説明（代わりの文）を AI が書く。画像の生成は行わない（Q-165） |
| 監修者 | 監修者を決めた会社では、記事の末尾に名前と肩書を入れる（監修者が確かめたかは責任者が承認で示す） |

### 32.8 赤入れ（表現と事実の確かめ）

**赤入れは助言であり、公開してよいかを決めるのは責任者である。** 指摘は「箇所・理由・直し案」で示し、本文を勝手に直さない（直し案を押せば置き換わる）。

| 確かめること | 中身 |
|---|---|
| 業種の表現の決まり | 業種ごとに M2Office が持つ決まり（下の表）に照らす。決まりの改正は運営が直す（会社に一覧を作らせない） |
| 出典の無い断定 | 数字・効き目・統計に出典が無ければ指摘する |
| 古い情報 | 出典の日付が古い、制度や料金が変わっている可能性があれば指摘する |
| 似すぎ | ほかのサイトの文とほぼ同じ文が続けば指摘する（段 2。Web の調べもので確かめる） |
| 個人の情報 | お客様・患者を特定しうる事例・写真・名前が入っていれば指摘する（第32.16節） |
| 読みやすさ | 長すぎる文・専門用語の多さを指摘する（直しは任意） |

**業種の表現の決まり**（最初に入れる範囲は Q-163）

| 業種 | 決まり（要点） |
|---|---|
| 医療・歯科 | 医療広告ガイドライン（医療法）: 体験談、治療の前後の写真（条件を満たさないもの）、ほかの医療機関との比較、誇大な表現、費用を強調した表現などを指摘する。広告に当たらない情報提供の記事でも、同じ目で確かめる |
| 薬局・化粧品・健康食品 | 薬機法: 医薬品でないものに病気の治療・予防の効き目を書く表現、効き目の保証、承認の範囲を超える表現。健康増進法・景品表示法の誇大な表示 |
| 全般 | 景品表示法: 「日本一」「必ず」などの根拠の無い最上級・断定、二重価格 |
| 士業 | 各士業の広告の規程: 「必ず勝つ」などの結果の保証、ほかの事務所との比較 |

### 32.9 直し

| 項目 | 規定 |
|---|---|
| 画面 | 記事の画面で、本文をその場で直せる。赤入れの指摘は本文の横に並べ、押すと該当の箇所へ移る |
| 秘書 | 「もっと短く」「中学生でも分かるように」「最後に予約の案内を一言」と頼めば書き直す。書き直しは新しい版として残し、前の版に戻せる |
| 版 | 直すたびに版を残す。**承認は版に対して行い、承認の後に本文が変われば承認し直す** |

### 32.10 承認と公開

| 項目 | 規定 |
|---|---|
| 承認 | **責任者が承認する**（社外に出るもの。第9.4.0節）。承認の画面には、題名・本文・出典・赤入れで残った指摘・公開先と日時・AI が書いたことの表示を出す。残った指摘があっても承認はできる（責任者の判断） |
| 公開先: WordPress | 会社の接続（第12.11節）で WordPress のサイトを登録する（アプリケーションパスワード。会社の鍵として預かる）。**段 1 は WordPress の「下書き」として入れ、最終の公開は WordPress の側で押す**案と、**M2Office から公開まで行う**案がある（Q-162）。カテゴリー・タグ・アイキャッチ画像・説明文も入れる |
| 公開先: 貼るだけのページ | WordPress の無いサイト向けに、記事の一覧と本文を M2Office が配るページ（在庫の公開と同じ形。第29.12.1節）。**埋め込みは検索で評価されにくい**ため、できれば WordPress かデータ（JSON・RSS）でサイトに取り込む形を勧める |
| 予約 | 公開の日時を決めて承認すれば、その日時に入れる |
| 取り下げ | 公開したコラムを M2Office から取り下げられる（WordPress では非公開にする）。取り下げは監査ログに残す |
| 表示 | 監修者の名前と、AI が書いたことの表示（会社の方針。Q-164）を記事の末尾に入れる |

### 32.11 予定表

| 項目 | 規定 |
|---|---|
| 予定 | 本数と曜日から、月の公開の予定を作る |
| 先回り | 公開の日の 7 日前（案）にテーマ案から下書きまでを用意し、責任者と書く人に知らせる。承認されないまま公開の日を過ぎたら、その回は飛ばして知らせる（勝手に公開しない） |
| 見た目 | 月の予定表に、テーマ・状態（下書き・承認待ち・承認済み・公開済み）を並べる |

### 32.12 効果の振り返り（アクセスの解析。段 3）

| 項目 | 規定 |
|---|---|
| つなぎ | Google アナリティクス（GA4 のデータの API）と Search Console を、会社の Google の接続で読む（読むだけ）。**求める権限が増えるため、管理者の再同意が要る**（Q-167） |
| 集めるもの | 記事ごとの閲覧数・読まれた時間・検索の言葉と表示の回数と順位・どこから来たか（検索・SNS・ほかのサイト）・**次に進んだページ**（問い合わせ・予約のページへ進んだ数） |
| どのような人か | 地域・端末・年代・新しい人か再び来た人か。**解析の道具が出す集計だけ**を使い、個人を追いかけない（第32.16節） |
| 振り返り | 月に 1 回、読まれた記事と読まれなかった記事、問い合わせにつながった記事、伸びている検索の言葉をまとめる。朝のブリーフ・週次ブリーフにも短く載せる |
| 次へ返す | テーマ案の材料にする（伸びている言葉・読まれた分野）。書き方の傾向（長さ・見出し）も次の下書きに返す |
| 見直し | 情報が古くなった記事、順位が落ちた記事を「書き直し」としてテーマ案に出す |

### 32.13 秘書と業務から使う

| 頼み方 | 動き |
|---|---|
| 「来月のコラムを 4 本用意して」 | テーマ案を選び、4 本の下書きと赤入れまで進め、承認を待つ |
| 「花粉症の薬の飲み始めで 1 本書いて」 | そのテーマで下書きと赤入れまで進める |
| 「この記事、もっと短くして」 | 開いている記事を書き直す（新しい版） |
| 「先月どの記事が読まれた？」 | 効果のまとめを答える（段 3） |

### 32.14 AI に任せること（ADR-0028）

| AI に任せる | 人が行う |
|---|---|
| テーマ案・下書き・出典の付与・赤入れ・書き直し・予定に沿った先回り・効果のまとめ | 分野と業種などの導入時の設定、取材メモ（任意）、**公開の承認** |

### 32.15 権限と記録

| 項目 | 規定 |
|---|---|
| 使える人 | 利用範囲（第16.7節）の中の人がテーマを選び、下書きを作り、直せる |
| 承認 | 責任者（会社が決めた人）だけ |
| 公開先の登録 | 管理者だけ（会社の接続） |
| 監査ログ | 承認・公開・予約・取り下げ・公開先の登録と変更 |

### 32.16 人の情報と社外への境界

| 項目 | 規定 |
|---|---|
| 記事に人の情報を入れない | お客様・患者の事例は、個人を特定できない形にする。本人の同意の無い写真・名前・体験談を入れない（赤入れで指摘する） |
| 問い合わせからのテーマ | メール・秘書への質問からは**話題だけ**を取り出し、誰が聞いたかは記事にもテーマ案にも残さない |
| アクセスの解析 | 解析の道具の集計だけを使い、個人の閲覧の履歴を集めない |
| 外部の AI | コラムは会社の外へ出す前提の文章で、個人の情報を扱わない。ローカルを既定の会社でも、**外部の AI を使ってよい業務**（第16.3.7.1節）とする。会社の知識を読む下書きは、会社の知識のうち公開してよいもの（サービス・料金・方針）に限る。「ローカルだけ」の会社では使えない（ローカル AI で書くかは Q-168） |
| 社外への送信 | 公開と WordPress への書き込みは社外への送信であり、承認の後にだけ行う（第9.4.0節） |

### 32.17 データモデル（案）

| 表 | 主な列 |
|---|---|
| `web_column_topics`（分野） | tenant_id、名前、読み手、状態 |
| `web_column_themes`（テーマ案） | tenant_id、分野、問い、なぜ今か、材料（季節・ニュース・検索・質問）、状態（案・選んだ・使った・見送り）、出した日 |
| `web_columns`（コラム） | tenant_id、テーマ、状態（下書き・承認待ち・承認済み・公開済み・取り下げ）、今の版、公開先、予約の日時、公開の URL、公開先の記事の ID、作った人 |
| `web_column_versions`（版） | tenant_id、コラム、版の番号、題名、本文（Markdown）、説明文、出典、取材メモ、赤入れの結果、作った人と日時 |
| `web_column_metrics`（効果。段 3） | tenant_id、コラム、日付、閲覧数、時間、検索の言葉の上位、流入元、次に進んだページの数 |
| 会社の設定 `webColumns` | 入り切り・分野の既定・読み手・業種・責任者・監修者・公開先の接続・本数と曜日・AI の表示 |

### 32.18 段階

| 段 | 行うこと |
|---|---|
| 段 1 | 分野・業種・責任者の設定、テーマを頼んで下書き（出典つき）・赤入れ（業種の決まり・出典・個人の情報）・直し（版）・承認・WordPress への書き込み（Q-162 の範囲）、秘書から頼む |
| 段 2 | 週に 1 回のテーマ案、予定表と先回り、予約の公開、似すぎの確かめ、貼るだけのページ、SNS の告知文 |
| 段 3 | Google アナリティクス・Search Console とのつなぎ、月の振り返り、次のテーマ案への反映、古い記事の見直しの提案 |

#### 32.18.1 段 1 の実装の決まり（第 0.221.0 版）

2026-10-02 に三浦さんが「コラムの作成をインプリメントしてください」と依頼した。段 1 にかかわる未決事項は、案のとおりに置いて実装した（Q-161・Q-162・Q-163・Q-164・Q-165・Q-166。判断の記録は [ADR-0064](../docs/adr/0064-web-columns-stage1.md)）。

| 項目 | 規定 |
|---|---|
| 形 | 内蔵の拡張「Web のコラム」（ID `web-columns`。既定は切り）。左のメニューの業務の 1 つとして「Web のコラム」を出す。会社の設定の区分 `webColumns` |
| 管理者の設定 | 管理者ページの「拡張機能」→「Web のコラム」: 分野（1 行に 1 つ）・読み手・業種（全般・医療と歯科・薬局と化粧品と健康食品・士業）・監修者（名前と肩書）・AI が書いたことの表示・WordPress（サイトの URL・利用者名・アプリケーションパスワード。つながるかを確かめてから預ける） |
| 書く | 「コラムを書く」でテーマ（一言）と取材メモ（任意）を入れると、裏で書き上げる（状態「書いています」）。終わると下書きになり、画面がそのまま開く |
| 書き上げ方 | ① Web の調べもの（Gemini の Google 検索）で出典を集める ② 推論が、題名の候補 3 つ・見出しで分けた本文（Markdown。出典は [1] の番号で示す）・説明文（120 字前後）・SNS の告知文（短い・長い）を JSON で返す ③ 赤入れ。調べものが使えない会社（「ローカルだけ」）では書かない |
| 赤入れ | **決まったプログラムの確かめ**（業種ごとの言葉の一覧: 断定・最上級・効き目の保証・体験談・治療の前後・費用の強調・個人の情報らしい書き方。出典が無い）と、**推論の確かめ**（業種の表現の決まりと出典の無い断定を読み、箇所・理由・直し案を返す）を合わせる。指摘は「直し案に置き換える」で本文に反映できる（新しい版になる） |
| 直し | 本文・題名・説明文をその場で直して保存すると新しい版になる。「書き直しを頼む」で指示（「もっと短く」など）を渡すと、推論が書き直して新しい版にする。前の版に戻せる。直すたびに決まったプログラムの赤入れをやり直す |
| 承認 | 「承認へ進む」で業務「コラムを WordPress に入れる」を起こし、承認トレイに出す（用意 → 承認 → 入れる）。**承認できるのは管理者と承認者のロールの人**（責任者）。承認の画面に題名・字数・残った指摘の数・入れ先を出す。承認した版と違う版になっていたら入れない |
| WordPress | 承認されたら、WordPress に**下書き**として入れる（REST API `wp/v2/posts`、`status: draft`。最終の公開は WordPress の側で押す。Q-162 の案）。本文は HTML にし、末尾に出典の一覧・監修者・AI が書いたことの表示（入のとき）を足す。入れたら、WordPress の編集の画面のリンクを出す |
| WordPress が無い会社 | 承認すると「承認済み」になり、本文（HTML と Markdown）を写して使える |
| 秘書から | 業務「コラムの下書き」（ツール `columns.draft`）。「〇〇でコラムを書いて」で下書きまで進め、画面のリンクを返す |
| 削除 | 下書き（承認へ進めていないもの）だけを削除できる |
| 権限 | 使えるのは在庫管理などと同じく利用範囲の中の人（第16.7節）。コラムは会社で共有する。設定と WordPress の鍵は管理者だけ |
| 監査ログ | コラムを書く・承認へ進める・WordPress に入れる・削除・WordPress の鍵の登録と削除 |

### 32.20 行わないこと

| 行わないこと | 理由 |
|---|---|
| 承認なしに公開する・WordPress に書き込む | 社外への送信は承認が要る（第9.4.0節） |
| ほかのサイトの記事を写す・要約して自社の記事として出す | 著作権と信頼のため。調べた内容は出典を付けて自分の言葉で書く |
| 検索の順位だけを狙った量産・言葉の詰め込み | 読み手の役に立たず、検索でも評価を下げる。本数は会社が決めた予定に限る |
| 個人を追いかけるアクセスの解析 | 集計で足りる。人の情報の扱いを広げない（第32.16節） |
| 本人の同意の無い体験談・事例・写真を入れる | 人の情報と、業種の広告の決まりのため |
| 効き目を保証する言葉を AI が足す | 表現の決まりに反する。書くのは出典のある事実まで |
