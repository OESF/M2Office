## 32. Web のコラム（情報発信。第 0.218.0 版。第 0.221.0 版で段 1、第 0.248.0 版で段 2 を実装した）

この章で決めること: 会社の Web サイトで、お客様に役立つコラム（記事）を**続けて出していく**ためのしくみ。
分野やテーマを決めると AI がテーマ案と下書きを作り、表現と事実を確かめ（赤入れ）、責任者が直して承認したものを Web サイトに出す。
後の段で、アクセスの解析（Google アナリティクス・Search Console）とつなぎ、読まれ方を次のテーマと書き方に返す。

**この章は案である。** **汎用の情報発信のしくみとして作る。** 特定の導入先・業種の条件に合わせた作りにしない。
会社ごとの違いは、**導入のときに会社が設定する項目**（第32.4節）で吸収する。まだ確かめる事項（第32.19節）の答えで直してから実装する。
**「（案）」と書いた値は、会社（三浦さん）の判断を待つ値である。**

**2026-10-02 に三浦さんが示した狙い**

- 中小企業の Web サイトによくある「数ページと社長のあいさつがあるだけで止まっている」状態から、新しい情報を**続けて出す運用**に変える。
- アクセスの解析で「どのような人が見たか」「そこからどこへつながったか」を振り返り、**次のコラムに反映していく**。

### 32.1 目的と位置づけ

| 痛み | M2Office で行うこと |
|---|---|
| 何を書けばよいか思いつかない | 登録した分野から、季節・ニュース・検索で増えている話題・お客様からよく来る質問をもとに、**AI がテーマ案を出す**（第32.6節） |
| 書く時間が無い | 調べものと下書きを AI が行う。人は経験や一言を足し、直すだけにする（第32.7節） |
| 書いてよい表現か分からない（医療・化粧品・健康食品など） | **業種ごとの表現の決まり**を M2Office が持ち、引っかかる所に理由と直し案を付ける（第32.8節）。人に決まりの一覧を作らせない（ADR-0028） |
| 続かない | 本数と曜日を決めれば、予定に沿って下書きを先回りで用意し、責任者に知らせる（第32.11節） |
| 出したあと読まれているか分からない | 後の段で、記事ごとの読まれ方・検索の言葉・その後どのページへ進んだかを集めて振り返り、次のテーマに返す（第32.12節） |

#### 32.1.1 想定する会社

| 項目 | 想定 |
|---|---|
| 会社 | 中小企業・店舗・医院・士業など、自社の Web サイトを持つ会社 |
| Web サイト | WordPress が多い。制作会社に任せていて、自社では触らない会社も多い（第32.10節） |
| 本数 | 月に 2〜8 本（案） |
| 書く人 | 専任はいない。総務・店長・院長などの兼務。責任者（承認する人）は 1〜2 人 |

### 32.2 形: 内蔵の拡張（既定は切り。案）

名刺管理・在庫管理と同じく、**内蔵の拡張**（第12.13節）とする（Q-161 決定）。

| 理由 | 中身 |
|---|---|
| 画面が要る | 記事の一覧と状態・予定表・赤入れの表示・直しの画面は、業務（スキル）1 つの結果の文だけでは足りない |
| 会社の設定が要る | 分野・読み手・業種・責任者・公開先・本数と曜日 |
| 続けて動く | 予定に沿った先回り・効果の集計は、ワーカーの見回りで行う |

| 項目 | 規定 |
|---|---|
| 入り切り | 管理者ページの「拡張機能」。**既定は切り** |
| 料金 | 名刺管理・在庫管理と同じく無償で同梱する（Q-166 決定） |
| 業務（付属） | 「テーマ案を出す」「コラムの下書き」「コラムの赤入れ」。秘書が取り次ぐ（第32.13節） |

### 32.3 用語

| 用語 | 意味 |
|---|---|
| コラム | Web サイトに出す 1 本の記事。題名・本文・出典・説明文（検索の結果に出る文）・画像を持つ |
| 分野 | 会社が書きたい話題のくくり（例: 「花粉症」「肌の手入れ」「相続の手続き」） |
| テーマ | 1 本のコラムで扱う具体的な問い（例: 「花粉症の薬はいつから飲み始めるか」） |
| リクエスト | 書く人が足す、記事への希望と自社ならではの経験・考え・事例（個人を特定しない）。記事の独自性になる。カバー画像の希望（「明るくパステル画のように」など）も書ける。第 0.226.5 版で「取材メモ」から改めた（三浦さんの依頼） |
| 赤入れ | 表現の決まりと事実を AI が確かめ、箇所・理由・直し案を付けたもの（第32.8節） |
| 責任者 | コラムを承認して公開する人。会社が決める |
| 監修者 | 記事に名前を出す専門家（医師・薬剤師・税理士など）。任意 |
| 公開先 | コラムを出す場所。WordPress のサイトか、M2Office が配る貼るだけのページ（第32.10節） |

### 32.4 導入のときに会社が設定すること

| 項目 | 内容 | 既定 |
|---|---|---|
| 分野 | 書きたい話題のくくり（複数）。一言で書けばよい | なし（入れるまでテーマ案は出さない） |
| 読み手 | 地域・年代・お客様の立場など（例: 「市内の子育て世帯」） | なし |
| 業種 | 東証の 33 業種の分類から 1 つ選ぶ（第32.18.3節）。赤入れで照らす**表現の決まりは AI が選ぶ**（業種・分野・読み手・監修者の肩書から） | その他 |
| 責任者 | 承認する人（承認者のロールの人から選ぶ） | 管理者 |
| 監修者 | 記事に出す名前と肩書（任意） | なし |
| 公開先 | WordPress（会社の接続で登録）か、貼るだけのページ | なし（決めるまで公開しない） |
| 本数と曜日 | 例: 月 4 本・水曜日 | なし（予定を作らない） |
| AI が書いたことの表示 | 記事の末尾に入れるか（Q-164 決定） | 入れる |
| AI で挿絵を描く | カバー画像の背景を生成 AI で描くか（第32.7.1節） | 切り（会社の色の模様の型で作る） |
| 書き方 | **自社の書き方**（第15.2.1節）をそのまま使う。コラムだけの書き方は持たない | — |

人に一覧や規則を作らせない（ADR-0028）。表現の決まりは M2Office が持ち、どれを当てるかも AI が選ぶ（違っていれば秘書に言えば直る）。言葉の言い換えの表なども作らせない。

### 32.5 流れ

**テーマ → 下書き → 赤入れ → 直し → 承認 → 公開 → 効果を見て次へ**

| 段 | AI がすること | 人がすること | 状態 |
|---|---|---|---|
| ① テーマ | 分野から、テーマ案を週に 1 回まとめて出す（第32.6節） | 選ぶ。一言で頼んでもよい | テーマ |
| ② 下書き | Web で調べて出典を付け、会社の知識と自社の書き方で書く。題名の候補・説明文・SNS の告知文も作る（第32.7節） | 取材メモを足す（任意） | 下書き |
| ③ 赤入れ | 表現の決まり・出典・古さ・似すぎ・個人の情報を確かめ、直し案を付ける（第32.8節） | 指摘を見る | 下書き |
| ④ 直し | 頼まれれば書き直す（「短く」「専門用語を減らして」） | 最終の文を決める | 下書き |
| ⑤ 承認 | — | **責任者が承認する**（社外に出るもの。第9.4.0節） | 承認待ち → 承認済み |
| ⑥ 公開 | 承認した版を公開先に入れる。予約の日時を守る（第32.10節） | — | 公開済み |
| ⑦ 効果 | 読まれ方を集め、次のテーマ案と見直しの提案に返す（第32.12節。段 3） | — | — |

**人の判断は承認の 1 回だけにする**（ADR-0028）。テーマ選びや下書きの途中では確認を求めない。

### 32.6 テーマ案

| 項目 | 規定 |
|---|---|
| 材料 | 会社の分野と読み手、**季節と行事**（その月に増える悩み）、**ニュースと制度の変更**（Web の調べもの）、**検索で増えている話題**（段 3 では Search Console の検索の言葉）、**お客様からよく来る質問**（会社の知識・秘書への問い合わせ・メールのうち、個人を特定しない話題だけ。第32.16節） |
| 出し方 | 週に 1 回、5 つ前後を責任者と書く人に知らせる（案）。1 つずつ「なぜ今か」を一言添える |
| 重ならない | 出したコラムと同じテーマ・ほぼ同じ問いは出さない。古くなった記事は「書き直し」として出す |
| 頼み方 | 秘書に「花粉症の時期の注意点で 1 本」「来月の分を 4 本用意して」と頼めば、テーマ案を飛ばして下書きへ進む |

### 32.7 下書き

| 項目 | 規定 |
|---|---|
| 調べもの | Web の調べもの（第9.4.2節）で調べ、**出典（題名と URL）を必ず付ける**。公的な機関・学会・メーカーの一次の情報を先にする |
| 会社の材料 | 会社の知識（サービス・料金・方針。第11章）と、リクエスト。会社に無いサービスや料金を書かない |
| 書き方 | 自社の書き方（第15.2.1節）。読み手に合わせ、専門用語には言い換えを添える |
| 形 | 題名（候補 3 つ）、見出しで分けた本文（1,500〜3,000 字。案）、まとめ、出典の一覧、説明文（検索の結果に出る 120 字前後）、SNS の告知文（2 つの長さ） |
| 画像 | 記事の先頭に置く**カバー画像**を、記事ごとに自動で作る（第32.7.1節。Q-165 決定）。本文の中の画像は、会社が入れた写真から選び、画像の説明（代わりの文）を AI が書く |
| 監修者 | 監修者を決めた会社では、記事の末尾に名前と肩書を入れる（監修者が確かめたかは責任者が承認で示す） |

#### 32.7.1 カバー画像（第 0.222.0 版。第 0.223.0 版で決定・実装）

2026-10-02 に三浦さんが「カバー画像の自動生成はできますか」と尋ね、①型から作る形を標準にし、②生成 AI の挿絵を会社ごとに入れられるようにする案で仕様を起こすよう依頼した（Q-165 の見直し）。同日「案のとおりで確定して実装してください」で決定した（Q-165・Q-169。実装の決まりは第32.18.2節）。

**カバー画像は「背景」と「題名」を分けて作る。** 背景は次の 3 つのどれかで、題名の文字は M2Office のプログラムが背景の上に重ねる。**生成 AI に文字を描かせない**（日本語の字が崩れる・誤字を直せないため）。

| 背景 | 中身 | 使える会社 |
|---|---|---|
| ① 型（標準） | 会社の色（会社情報のロゴから AI が選ぶ）を使った模様（第 0.226.2 版でロゴは画像に入れないことにした）。型はいくつかを M2Office が持ち、記事ごとに AI が選ぶ（会社に選ばせない） | すべて。外部の AI を使わない |
| ② AI の挿絵 | 題名と本文の要点から、画像を作るモデル（Gemini。Q-169）で挿絵を描く | 管理者が「AI で挿絵を描く」を入れた会社（既定は切り）。「ローカルだけ」の会社では使えない |
| ③ 会社の写真 | 会社が入れた写真から、記事に合うものを AI が選ぶ | 写真を入れた会社。写真が合わなければ ① にする |

**選び方は AI に任せる**（ADR-0028）。② を入れた会社では ② を先にし、描けなかったときや確かめを通らなかったときは ① にする。③ は記事に合う写真があるときだけ使う。どれも、画面の「カバーを作り直す」と、秘書への「もっと明るい絵に」「写真にして」で変えられる。

**AI の挿絵の決まり**（M2Office が持ち、会社に作らせない）

| 決まり | 理由 |
|---|---|
| **人物を描かない**（顔・体・手も描かない） | 架空の人でも「患者」「お客様」「スタッフ」と受け取られ、体験談や事例のように見える |
| **医療広告ガイドラインか薬機法を当てる会社では、体の部位・治療の前と後の比較・効き目を思わせる変化を描かない** | 医療広告ガイドラインと薬機法（第32.8節）。前と後の写真の決まりを、絵で迂回しない |
| 文字・ロゴ・商品・キャラクター・実在の建物を描かない | 文字の崩れと、ほかの会社の権利。題名は ① と同じくプログラムが重ねる |
| 描く前の指示に、題名と本文の要点と画像の希望だけを渡す | 会社の知識・リクエストの中身・人の情報は渡さない（第32.16節）。リクエストに書いた画像の希望は、推論が**画像の希望だけを短く言い直して**渡す（第 0.226.5 版） |

**描いた後の確かめ**: 描いた挿絵は、推論（画像を読めるもの）が上の決まりに照らして確かめる。人物・文字・体の部位などが見つかれば描き直す（1 回に 3 枚まで。Q-169）。3 回とも通らなければ ① にする。確かめは助言ではなく**通らなければ使わない**（社外に出る画像のため）。

| 項目 | 規定 |
|---|---|
| 大きさ | 横長（1,200×630。SNS で共有したときの見え方と同じ形）。WordPress のアイキャッチにも同じものを使う |
| 代わりの文 | カバー画像の説明（代わりの文）を AI が書く |
| 版 | カバー画像は版に含める。カバーを作り直すと新しい版になり、**承認は画像を含めた版に対して行う** |
| 承認の画面 | **カバー画像を必ず出す**。② の挿絵なら「AI 作成の画像」と添える |
| WordPress | 承認の後、画像を WordPress のメディアに入れ、記事のアイキャッチにする（記事は下書きのまま。Q-162） |
| 写して使う会社 | 画像を書き出せる（PNG） |
| AI が描いたことの表示 | ② の挿絵を使った記事では、末尾の AI の表示（Q-164）に「カバー画像は AI で作成しました」を足す。画像そのものにも、画像を作るモデルが入れる見えない印（SynthID）が残る |
| 費用 | ② は 1 枚ごとに画像を作るモデルの費用がかかる。会社の AI の費用に含めて数え、上限は Q-169 |
| 記録 | 背景の種類・描き直した回数・確かめの結果を版に残す（描く前の指示の全文は残さない） |

### 32.8 赤入れ（表現と事実の確かめ）

**赤入れは助言であり、公開してよいかを決めるのは責任者である。** 指摘は「箇所・理由・直し案」で示し、本文を勝手に直さない（直し案を押せば置き換わる）。

| 確かめること | 中身 |
|---|---|
| 業種の表現の決まり | M2Office が持つ決まり（下の表）のうち、その会社に当てるもの（AI が選ぶ。第32.18.3節）に照らす。全般はどの会社にも当てる。決まりの改正は運営が直す（会社に一覧を作らせない） |
| 出典の無い断定 | 数字・効き目・統計に出典が無ければ指摘する |
| 古い情報 | 出典の日付が古い、制度や料金が変わっている可能性があれば指摘する |
| 似すぎ | ほかのサイトの文とほぼ同じ文が続けば指摘する（段 2。Web の調べもので確かめる） |
| 個人の情報 | お客様・患者を特定しうる事例・写真・名前が入っていれば指摘する（第32.16節） |
| 読みやすさ | 長すぎる文・専門用語の多さを指摘する（直しは任意） |

**業種の表現の決まり**（最初に入れる範囲は全般・医療と歯科・薬局と化粧品と健康食品・士業。Q-163 決定）

| 業種 | 決まり（要点） |
|---|---|
| 医療・歯科 | 医療広告ガイドライン（医療法）: 体験談、治療の前後の写真（条件を満たさないもの）、ほかの医療機関との比較、誇大な表現、費用を強調した表現などを指摘する。広告に当たらない情報提供の記事でも、同じ目で確かめる |
| 薬局・化粧品・健康食品 | 薬機法: 医薬品でないものに病気の治療・予防の効き目を書く表現、効き目の保証、承認の範囲を超える表現。健康増進法・景品表示法の誇大な表示 |
| 全般 | 景品表示法: 「日本一」「必ず」などの根拠の無い最上級・断定、二重価格 |
| 士業 | 各士業の広告の規程: 「必ず勝つ」などの結果の保証、ほかの事務所との比較 |

### 32.9 直し

| 項目 | 規定 |
|---|---|
| 画面 | 記事の画面で、本文をその場で直せる。赤入れの指摘は本文の横に並べ、押すと該当の箇所へ移る |
| 秘書 | 「もっと短く」「中学生でも分かるように」「最後に予約の案内を一言」と頼めば書き直す。書き直しは新しい版として残し、前の版に戻せる |
| 版 | 直すたびに版を残す。**承認は版に対して行い、承認の後に本文が変われば承認し直す** |

### 32.10 承認と公開

| 項目 | 規定 |
|---|---|
| 承認 | **責任者が承認する**（社外に出るもの。第9.4.0節）。承認の画面には、題名・**カバー画像**・本文・出典・赤入れで残った指摘・公開先と日時・AI が書いたことの表示を出す。残った指摘があっても承認はできる（責任者の判断） |
| 公開先: WordPress | 会社の接続（第12.11節）で WordPress のサイトを登録する（アプリケーションパスワード。会社の鍵として預かる）。**WordPress の「下書き」として入れ、最終の公開は WordPress の側で押す**（Q-162 決定。M2Office から公開まで行う形は採らない）。カテゴリー・タグ・アイキャッチ画像・説明文も入れる |
| 公開先: 貼るだけのページ | WordPress の無いサイト向けに、記事の一覧と本文を M2Office が配るページ（在庫の公開と同じ形。第29.12.1節）。**埋め込みは検索で評価されにくい**ため、できれば WordPress かデータ（JSON・RSS）でサイトに取り込む形を勧める |
| 予約 | 公開の日時を決めて承認すれば、その日時に入れる |
| 取り下げ | 公開したコラムを M2Office から取り下げられる（WordPress では非公開にする）。取り下げは監査ログに残す |
| 表示 | 監修者の名前と、AI が書いたことの表示（会社の方針。Q-164）を記事の末尾に入れる |

### 32.11 予定表

| 項目 | 規定 |
|---|---|
| 予定 | 本数と曜日から、月の公開の予定を作る |
| 先回り | 公開の日の 7 日前（案）にテーマ案から下書きまでを用意し、責任者と書く人に知らせる。承認されないまま公開の日を過ぎたら、その回は飛ばして知らせる（勝手に公開しない） |
| 見た目 | 月の予定表に、テーマ・状態（下書き・承認待ち・承認済み・公開済み）を並べる |

| 監査ログ | コラムを書く・承認へ進める・WordPress に入れる・削除・WordPress の鍵の登録と削除 |

#### 32.18.2 カバー画像の実装の決まり（第 0.223.0 版）

2026-10-02 に三浦さんが「案のとおりで確定して実装してください」と依頼した（Q-165・Q-169 決定。判断の記録は [ADR-0065](../docs/adr/0065-web-column-cover.md)）。

| 項目 | 規定 |
|---|---|
| 作るとき | 下書きを書き上げたとき、続けてカバー画像を作る。直す・書き直しでは作り直さない（前の版のカバーを引き継ぐ）。カバーの無い版は、画面の「カバーを作る」で作る |
| 背景の順 | ① 会社が「AI で挿絵を描く」を入れていて、推論が画像を作れ（Gemini）、今月の上限の内なら **AI の挿絵**。② 描けない・確かめを通らないときは、写真の置き場に記事に合う写真があれば **会社の写真**（推論が選ぶ。人の写った写真は選ばない）。③ どれも無ければ **型** |
| 型 | 模様は 3 つ（斜めの帯・水玉・波）。直前のコラムと同じ模様を続けない。色は会社のロゴから推論が選ぶ（読めなければ、テーマから決まる M2Office の色）。**会社の名前の文字とロゴは入れない**（第 0.225.0 版で名前、第 0.226.2 版でロゴを外した。三浦さんの依頼。ロゴは色を選ぶのにだけ使う） |
| 題名を重ねる | 題名は M2Office のプログラムが重ねる（Noto Sans JP の太字、行の長さで字の大きさを変え、3 行まで。収まらなければ末尾を「…」。言葉の切れ目で割り、行の長さをそろえ、句読点と助詞を行の頭に置かない）。字は濃い色。写真と挿絵の上では、題名の大きさに合わせた**白い帯**に置く（画像を暗くしない。第 0.226.5 版）。1,200×630 の PNG |
| 明るさ | **カバーは明るくする**（第 0.226.5 版。三浦さんの指示。暗い画像は Web のページを暗く見せる）。型は会社の色を淡くした地に、会社の色の模様と濃い字。AI の挿絵は明るく淡い色合いで描かせ、描いた画像の明るさをプログラムで測って暗ければ描き直す（確かめの 1 回に数える）。推論が選んだ会社の写真も、暗ければ使わない（人が「ファイルから選択」で選んだ写真はそのまま使う）。雰囲気として暗い感じ（「夜の」「シックな」など）を頼まれたときは、その頼みに従う |
| 雰囲気 | 秘書への頼み（「もっと明るい絵に」）を先に使い、無ければ「リクエスト」に書いた画像の希望を使う（第 0.226.5 版） |
| AI の挿絵 | モデルは `gemini-3.1-flash-image`（16:9）。描く前の指示は題名と説明文と業種と、雰囲気（上の行）だけ。描いた後、推論（画像を読む）が人物・文字・ロゴ・体の部位・前と後の比較を確かめ、通らなければ描き直す（1 回に 3 枚まで）。確かめられなかったものも使わない |
| 上限 | AI の挿絵は**会社で月に 100 枚まで**（確かめを通らなかった分も数える。1 枚およそ 0.067 米ドル、2026-10 の料金表）。上限を超えたら型にする |
| 会社の写真 | コラムの画面の「ファイルから選択」で入れた写真（JPEG・PNG、10 MB まで）は、会社の写真の置き場に入り、次からのコラムでも推論が選べる。入れたときに推論が写真の説明と、人が写っているかを読む。入れた写真はそのコラムのカバーになる |
| 作り直す | 画面の「画像を再作成」（同じ順でもう一度）。秘書に「〇〇のコラムのカバーをもっと明るい絵に」「写真にして」「型にして」と頼むと、業務「コラムのカバー」（ツール `columns.cover`）が作り直す。作り直すと新しい版になる |
| 前の画像に戻す | 作り直した画像が気に入らなければ、画面の「以前の画像」（このコラムの前の版のカバー。同じ画像は 1 つにまとめる）から「この画像に戻す」で戻す。本文はいまのまま、カバーだけを戻した新しい版になる。秘書に「前の画像に戻して」と頼んでも戻る（第 0.226.3 版。三浦さんの依頼） |
| 承認 | 承認の画面にカバー画像を出す（入れ先の業務の入力にカバーのファイルを含め、承認する人がその画像を見られるようにする）。版の指紋にカバーを含める |
| WordPress | 承認の後、カバーを WordPress のメディアに入れ（代わりの文つき）、記事のアイキャッチにする。記事は下書きのまま |
| 写して使う | 画面の「画像を書き出す」で PNG を保存できる |
| AI の表示 | AI の挿絵を使った記事は、末尾の AI の表示に「カバー画像は AI で作成しました」を足す。画面では「AI 作成の画像」と呼ぶ |
| 記録 | 版に、背景の種類・模様・AI の挿絵を描いた枚数・確かめの結果を残す。描く前の指示の全文は残さない |

#### 32.18.3 業種と表現の決まり（第 0.225.0 版）

2026-10-03 に三浦さんが、設定の画面の業種を東証の 33 業種の分類（コードと名称）にするよう依頼した。33 業種ではクリニック・歯科・法律事務所はどれも「サービス業」、化粧品は「化学」、健康食品は「食料品」、薬局は「小売業」に入り、業種だけでは表現の決まりを選べないため、**当てる表現の決まりは AI が選ぶ**と決めた（三浦さんが選んだ。[ADR-0066](../docs/adr/0066-web-column-industry.md)）。

| 項目 | 規定 |
|---|---|
| 業種 | 東証の 33 業種（`0050` 水産・農林業 〜 `9050` サービス業）と `9999` その他。コードで持ち、画面には名称を出す。既定は `9999` その他 |
| 表現の決まり | 全般（景品表示法）はどの会社にも当てる。ほかに当てうるのは **医療広告ガイドライン**・**薬機法と健康増進法**・**士業の広告の規程**（第32.8節の表）。いくつでも当てる |
| 選び方 | 業種・分野・読み手・監修者の肩書・会社の名前から、推論が当てる決まりを選ぶ。あわせて決まった言葉（「歯科」「クリニック」「化粧品」「サプリ」「薬局」「弁護士」「税理士」など）でも選び、**どちらかが選んだものは当てる**（迷えば当てる側に倒す。当てすぎても指摘が増えるだけで、外すと見落とす） |
| 選び直すとき | 業種・分野・読み手・監修者を変えたとき。秘書で直した後は、AI は選び直さない（「表現の決まりを AI に任せて」で戻す） |
| 画面 | 設定の欄に「表現の決まり: 医療広告ガイドライン」のように、当てているものを出す（中身であり、説明文ではない） |
| 秘書で直す | 管理者が秘書に「コラムの表現の決まりに薬機法を足して」「士業の決まりを外して」「表現の決まりを AI に任せて」と頼むと、業務「コラムの表現の決まり」（ツール `columns.rules`）が直す。管理者のほかは直せない |
| 前の設定 | 第 0.224.0 版までの業種（全般・医療と歯科・薬局と化粧品と健康食品・士業）は、移行 064 で、医療と歯科・士業はサービス業、薬局と化粧品と健康食品は医薬品、全般はその他にし、当てていた決まりを引き継ぐ |
| 記録 | 表現の決まりを AI が選んだとき・秘書で直したときは、監査ログに残す |

| テーマ案 | 週に 1 回（月曜の 6 時（日本時間）を過ぎてから）、ワーカーが 5 つまで作り、管理者・承認者と、この 90 日にコラムを書いた人に知らせる（種類「コラムの作成」。個人設定で切れる）。画面の「テーマ案を出す」と、秘書の「テーマ案を出して」でも作る。1 つずつ「なぜ今か」を一言添える |
| テーマ案の材料 | 会社の分野と読み手・季節と行事（推論が知っていること）・**検索の言葉**（Web の振り返りを使っていれば、合う記事が無い言葉と伸びた言葉）・**競合の話題**（競合の分析を使っていれば、いちばん新しいレポートのコラムの話題）・**よく来る質問**（問い合わせの記録を使っていれば、よくある問い合わせの話題。誰からかは渡さない）。材料ごとに印（季節・検索・競合・質問）を付ける。ニュースと制度の変更（Web の調べもの）は、書くときの調べもので扱い、テーマ案では調べない（毎週の費用を抑えるため） |
| 重ならない | 出したコラムのテーマと題名・まだ使っていない案と同じ問いは出さない（推論に一覧を渡し、さらに言葉をそろえて同じものを除く） |
| 書き直しの案 | Web の振り返りの直すべき所のうち、コラムの「読まれなくなった記事」「あと少しで 1 ページ目」を「書き直し」の案として並べる（押すと、案の文を指示にして書き直す） |
| テーマ案から書く | 画面の「書く」で、その案をテーマにして書き始める（案は使ったにする）。「見送り」で外す。秘書の「来月の分を 4 本用意して」は、上から 4 つの案で書き始め、予定表があれば空いている回に入れる |
| 予定表 | 拡張機能の設定で「月の本数」（1 本・2 本・毎週）と「曜日」を選ぶと、月の公開の回を作る（1 本はその月の最初の曜日、2 本は 1 回目と 3 回目、毎週はすべて。公開は 9 時）。画面に今月と来月の回を並べ、回ごとにテーマ・状態を出す |
| 先回り | 公開の回の 7 日前になったら、ワーカーが空いている回に、いちばん上のテーマ案（無ければ作る）でコラムを書き始め、公開の日時を入れて知らせる。**承認されないまま公開の日時を過ぎた回は飛ばし**（公開の日時を外し、下書きのまま残す）、知らせる（勝手に公開しない） |
| 予約 | コラムの画面で公開の日時を入れられる（予定表の回は自動で入る）。承認の画面に公開の日時を出し、日時を版の指紋に含める。**承認の後、日時が先なら「予約」**にして待ち、その日時にワーカーが入れる（WordPress には下書きとして入れる。Q-162 のとおり、最終の公開は WordPress の側。入れたら書いた人に知らせる）。貼るだけのページでは、その日時から出す |
| 取り下げ | 承認済み・入れた・予約のコラムを「取り下げ」できる（管理者と承認者）。貼るだけのページから外し、WordPress では記事を下書きに戻す。予約は取り消す。監査ログに残す |
| 似すぎ | 書き上げたとき・書き直したときに、出典のページ（robots.txt に従い、社内のアドレスは読まない。8 つまで）を読み、本文の文（30 字以上）のうち、出典の文と 10 字のまとまりの 7 割以上が重なるものを赤入れに足す（「出典の文とほぼ同じです。自分の言葉で書き直してください」。3 つまで）。読めなかった出典は確かめず、そのことは指摘にしない |
| 貼るだけのページ | WordPress につないでいない会社のための、コラムの一覧と本文のページ（第32.10節）。管理者が拡張機能の設定で入れると、推測されにくい鍵の URL を作る（ページ・JSON・RSS）。出すのは承認済みで公開の日時を過ぎたもの（日時が無ければ承認したとき）だけ。ページはスクリプトを持たず、どのサイトにも埋め込める（在庫の公開と同じ形。第29.12.1節）。カバー画像も鍵の URL で出す。止めるとすぐ 404。**検索で評価されにくい**ため、設定の欄で WordPress を勧める一言は出さない（ヘルプに書く） |
| SNS の告知文 | 段 1 の短い文と長い文に、画面の「コピー」を足す。公開の URL（WordPress で公開された URL か、貼るだけのページの記事の URL）が分かれば、文の末尾に足してコピーする |

#### 32.18.5 書き方の傾向を次の下書きに返す（第 0.249.0 版）

2026-10-04 に三浦さんが、小さな残りをまとめて片付けることを選んだ。第32.12節の「書き方の傾向（長さ・見出し）も次の下書きに返す」を、次の決まりで実装した。

|---|---|
| 材料 | Web の振り返りを使っていて、WordPress で公開されたコラムのページごとの数字（第34.19節）があるもの。見られた回数が 20 回以上で、読まれた時間の平均が分かるもの |

### 32.20 行わないこと

| 行わないこと | 理由 |
|---|---|
| 承認なしに公開する・WordPress に書き込む | 社外への送信は承認が要る（第9.4.0節） |
| ほかのサイトの記事を写す・要約して自社の記事として出す | 著作権と信頼のため。調べた内容は出典を付けて自分の言葉で書く |
| 検索の順位だけを狙った量産・言葉の詰め込み | 読み手の役に立たず、検索でも評価を下げる。本数は会社が決めた予定に限る |
| 個人を追いかけるアクセスの解析 | 集計で足りる。人の情報の扱いを広げない（第32.16節） |
| 本人の同意の無い体験談・事例・写真を入れる | 人の情報と、業種の広告の決まりのため |
| 効き目を保証する言葉を AI が足す | 表現の決まりに反する。書くのは出典のある事実まで |
| AI の挿絵に人物・文字・体の部位・前と後の比較を描かせる | 事例や効き目のように見え、業種の広告の決まりを絵で迂回することになる（第32.7.1節） |
| 確かめを通らなかった挿絵を使う | 社外に出る画像のため。通らなければ型にする |
