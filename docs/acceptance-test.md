# 実地の確認の手順（受け入れテスト）

自社（OESF）で実際に使いながら確かめるための手順書です。
`npm test`・`npm run smoke` が「壊れていないこと」を見るのに対し、
この手順書は**「使いものになるか」**を人が見ます。

対象は第 0.79.1 版（2026-09-23）の実装です。仕様の正は [specification.md](../specification.md)。

## 0. いま本物で試せること・まだダミーのこと

**ここを取り違えると、ダミーの結果を見て「使える」と判断してしまいます。**

| 区分 | 中身 | 状態 |
|---|---|---|
| ログイン | Google アカウント | **本物**（`oesf.jp` で確認済み） |
| 推論 | Gemini（文章・音声） | **本物**（会社の鍵） |
| 組織知識 | 登録・検索 | **本物**（外部に依存しません） |
| ファイル | PDF・Excel・CSV・Word・画像の読み取り、帳票の PDF | **本物**（読み取りは Gemini） |
| 承認・権限・区画・グループ | すべて | **本物**（推論に依存しません） |
| 監査ログ・費用の記録 | すべて | **本物** |
| **メール・予定・ToDo・ドライブ・Chat** | Gmail、カレンダー、Tasks、Drive、Chat | **ダミー**。接続口の `google` 実装が未完（B-2 の残り） |
| Meet の文字起こし | 会議の記録の取得 | **ダミー**（同上） |
| 通知の Chat への控え | Google Chat への送信 | **ダミー**（会社の Chat アプリの登録待ち） |

### 何が言えて、何が言えないか

| 試すもの | 結果から言えること |
|---|---|
| AG-04 社内ナレッジ Q&A | **そのまま製品の品質。** 本物の規程と本物の推論で動きます |

| AG-02 議事録作成 | **文字起こしのファイルを渡す経路なら本物。** Meet からの取得はダミー |

## 1. 進める順番

**下から積み上げます。** 上の段は下の段のデータを使うため、順を飛ばすと確かめられません。

| 段 | 何を見るか | 所要 | B-2 待ちか |
|---|---|---|---|
| **A. 下ごしらえ** | 会社の情報と人を入れる。ここが揃わないと、以降がすべて空回りします | 40 分 | いいえ |
| **B. 知識で答える** | 本物の規程を入れ、AG-04 が出典つきで答えるか。**Phase 1 の完了条件 4** | 60 分 | いいえ |
| **C. 秘書との対話** | 文字と音声。応答の速さ、口調、事実を作らないか | 60 分 | いいえ |
| **D. 書類を渡す** | PDF・Excel・画像を渡して調べさせる。読み取りの精度 | 60 分 | いいえ |
| **E. 承認と権限** | 承認ゲート、権限区画、グループ。**ここは推論に依存しません** | 60 分 | いいえ |
| **F. 帳票を作る** | 請求書の PDF。体裁・文字化け | 30 分 | いいえ |
| **G. 管理と記録** | ダッシュボード、監査ログ、費用、通知 | 40 分 | いいえ |
| **H. 拡張機能** | 取り込み・同意・コネクタ | 30 分 | いいえ |
| **I. Google の業務** | 受信箱整理、日程調整、週次ブリーフ、Meet の議事録 | — | **はい** |

**A から H までは、いま全部できます。** I だけが接続口の実装待ちです。

### なぜこの順か

| 理由 | 説明 |
|---|---|
| データの依存 | B は A の会社情報が要る。C の秘書は B の知識を引く。D は A の利用者が要る |
| 判断の確かさ | B・C・D は**本物の推論**なので、結果がそのまま製品の品質。ここを先に見ると、続ける価値があるかが早く分かります |
| 落ちても進める | E は推論に依存しないので、B・C・D の結果が悪くても独立に確かめられます |

## 3. 段ごとの手順

各段は「やること」「見るところ」「落ちたら」の 3 つで書きます。
**「見るところ」は、合否を人が判断する点です。**

### A. 下ごしらえ

| # | やること | 見るところ |
|---|---|---|
| A-1 | 3 人でログインする | 全員が入れる。管理者だけに「管理者ページ」が出る |
| A-2 | 管理者ページ → ユーザーで、ロールを割り当てる | 承認者・一般が正しく分かれる |
| A-3 | 会社情報を入れる | 保存され、開き直しても残る |
| A-4 | 自社の書き方（文面の決まり）を入れる | 同上 |
| A-5 | 一般の人で管理者ページを開こうとする | **入れない**。存在も示さない |

**落ちたら**: A-5 が通ってしまう場合、権限の穴です。ここで止めて報告してください。

### B. 知識で答える（Phase 1 完了条件 4）

| # | やること | 見るところ |
|---|---|---|
| B-1 | 就業規則を登録する | 節に分かれる。分かれ方を管理者ページで見る |
| B-2 | 経費規程とそのほかを登録する | 同上 |
| B-3 | 用意した 20 問を、秘書に 1 問ずつ聞く | **出典（文書名 › 見出し）が付く**。正解と合っている |
| B-4 | **登録していないこと**を聞く（例: 「社用車の使い方は」） | **「見つからない」と答える。** 作り話をしない |
| B-5 | 言い換えを登録する（例: 「有休」＝「年次有給休暇」） | 言い換えても引ける |

**見るところの要点**

| 項目 | 合格の線 |
|---|---|
| 正解率 | 20 問中、**出典が正しいものが 18 問以上** |
| 作り話 | **1 件でもあれば不合格。** B-4 で作り話をしたら、そこで止めてください |
| 速さ | 最初の文字が出るまで 3 秒以内 |

**落ちたら**: 正解率が低い場合、原因は「規程の分け方」か「検索」か「推論」のどれかです。管理者ページの「節」の表示で、分け方が妥当かをまず見てください。

### C. 秘書との対話

| # | やること | 見るところ |
|---|---|---|
| C-1 | 「今日の予定は」「承認待ちはある？」と聞く | **速い**（1 秒以内）。予定は**ダミー**であることが画面に出ている |
| C-2 | 雑談・相談をする（文字） | 口調が個人設定に従う。長すぎない |
| C-3 | 個人設定で秘書の名前・呼ばれ方・話し方を変える | 次のやり取りから変わる |
| C-4 | **アバターを押して音声を始める** | 秘書から先に声をかける。名前で呼ぶ |
| C-5 | 音声で 5 往復ほど話す | 途切れない。聞き取りが画面に出る。**割り込んでも音が切れない** |
| C-6 | 声と話し方（「関西弁で」など）を変えて話す | 変わる |
| C-7 | 「この会話は残さないで」と言う | 会話ログに残らない |
| C-8 | 「〜を覚えておいて」と言い、あとで聞く | 覚えている |
| C-9 | 個人設定 → 記憶とデータで、覚えたものを消す | 消える。次から使われない |

**落ちたら**: C-5 で途切れる場合、ネットワークか Gemini 側です。画面の文言をそのまま控えてください。

### D. 書類を渡す

| # | やること | 見るところ |
|---|---|---|
| D-1 | 文字入りの PDF を渡し「合計はいくら」と聞く | **金額が合っている**。処理中の表示が出る |
| D-2 | 渡している間に別のことを話しかける | **会話が止まらない** |
| D-3 | スキャンした PDF を渡す | 読み取った旨の断りが付く。値が合っている |
| D-4 | 領収書の写真を渡す | 同上 |
| D-5 | Excel を渡して集計を頼む | **数値が合っている。暗算で作った数を書かない** |
| D-6 | **読めないもの**（用意した 17）を渡す | **「読み取れません」と言う。作り話をしない** |
| D-7 | 他人が上げたファイルの ID を指定してみる | 読まない。存在も示さない |

**見るところの要点**

| 項目 | 合格の線 |
|---|---|
| 金額・数値 | **1 件でも作り話があれば不合格** |
| D-6 | 正直に言うこと。ここが製品の信頼の分かれ目です |

### E. 承認と権限（推論に依存しません）

| # | やること | 見るところ |
|---|---|---|
| E-1 | 承認のある業務を実行する | 承認待ちで止まる |
| E-2 | **依頼した本人**の承認トレイを見る | 自分が判断できるものだけが出る |
| E-3 | 承認者が承認する | 続きから再開して完了する |
| E-4 | 別の業務を却下する | そこで終わる。理由が残る |
| E-5 | 実行の詳細から**中止**する | 止まる。「送ったものは戻らない」と出る |
| E-6 | 権限区画（HR）を作り、人を入れる | 出入りが管理者に通知される |
| E-7 | 区画の知識を、区画外の人が検索する | **出ない** |
| E-8 | グループを作り、業務の利用範囲を絞る | 範囲外の人のメニューから消える |
| E-9 | 範囲外の人が API で直接呼ぶ | **404**（存在を示さない） |

**落ちたら**: E-7・E-9 が通ってしまう場合は**重大**です。ここで止めて報告してください。

### F. 帳票を作る

| # | やること | 見るところ |
|---|---|---|
| F-1 | 会社情報に、ロゴ・振込先・備考・印の欄を入れる | 保存される |
| F-2 | 請求書の PDF を作る | 体裁が整っている。**日本語が化けない** |
| F-3 | 難しい字を含む名前で作る（旧字体・記号） | 化けた字が `〓` になり、その旨が出る |
| F-4 | 登録番号が印字されるか見る | 出る |

### G. 管理と記録

| # | やること | 見るところ |
|---|---|---|
| G-1 | ダッシュボードを開く | 人の状態が出る。自動で新しくなる |
| G-2 | 別の人が業務を実行する | ダッシュボードに反映される |
| G-3 | 表示の粒度を「部署だけ」に変える | 個人名が出なくなる |
| G-4 | 監査ログを見る | A〜F でやったことがすべて残っている |
| G-5 | 利用状況・費用を見る | 実行ごとの費用が出る |
| G-6 | 通知を見る | 承認依頼・完了・失敗が画面内に出る |
| G-7 | 通知しない時間帯を設定する | その間は Chat へ送らない（いまは見本） |

## 4. 記録のしかた

**1 件ごとに、次を残してください。**

| 項目 | 例 |
|---|---|
| 番号 | B-3-07 |
| 入れたもの | 「有給は何日もらえますか」 |
| 出たもの | 画面の文言をそのまま（**要約しない**） |
| 合否 | 合／否／判断できず |
| 気づき | 「出典は合っているが、条の番号が 1 つずれている」 |

**「だいたい合っていた」と書かないでください。** あとで原因を追えなくなります。
出たものをそのまま残していただければ、こちらで原因を追えます。

### 止めてよい基準

次のどれかが起きたら、**その段で止めて**報告してください。先に進んでも意味がありません。

| # | 事象 |
|---|---|
| 1 | 他人のデータ、他社のデータが見えた |
| 2 | 承認を経ずに、送信や登録が行われた |
| 3 | 取得できていない値を、事実のように答えた（作り話） |
| 4 | 権限の無い人が、管理者ページや範囲外の業務に入れた |

## 5. まず今日やるなら

**A（下ごしらえ）と B（知識で答える）だけで十分です。** 合わせて 2 時間ほど。

B が通れば **Phase 1 の完了条件 4（労務規定への照会が秘書で完結する）**が実地で満たせます。
通らなければ、そこを直すのが最優先になります。

**用意していただきたいのは、就業規則と経費規程、そして「答えの分かっている質問 20 問」です。**
