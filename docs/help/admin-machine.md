会社の中に置いた機械で M2Office を動かしている会社では、管理者ページの左のメニュー、**記録の「機械」**で、機械の様子と控えを確かめられます。業務の中身は出ません。

## 機械の管理者

インターネットや Google が止まって、誰も Google でログインできないときでも、機械の様子を見られるよう、機械の管理だけに使う「機械の管理者」が 1 人います。

- ログイン画面の下の「機械の管理」（`/machine`）から、ID・合言葉・認証アプリの 6 桁の確認コードで入ります。ID と合言葉は、導入のときに技術者から紙で受け取ります
- 入れるのは「機械」だけです。業務の画面には入れません
- 8 時間でログインが切れます。5 回続けて間違えると、15 分は入れません
- 合言葉を忘れた・人に知られたときは、導入した技術者に作り直しを頼んでください
- 機械の管理者が入ったこと・入れなかったこと・「機械」で行ったことは、監査ログに「機械の管理者」として残ります

## 動いている環境

「機械」のいちばん上に、M2Office がどの版のソフトの上で動いているかが出ます。

| 項目 | 内容 |
|---|---|
| M2Office の版 | いま動いている版です。ワーカーだけ違う版のときは印が付きます |
| Node.js（API・ワーカー） | M2Office を動かしているソフトの版と、そのサポートがいつまで続くかです |
| PostgreSQL | データベースの版です |
| OS と CPU・メモリー | 機械の OS と CPU、メモリーの大きさと使える量です |
| 動いている形・推論 | ローカルの形か、デバッグモードか、ローカル AI のモデルと外部の AI です |
| 起動してからの時間 | API とワーカーが動き始めてからの時間です |

- **Node.js のサポートの終わりまで 6 か月を切ると、「Node.js の更新が要ります」と出ます**（ダッシュボードにも出ます）。サポートが終わると、直らない脆弱性が残るようになります。保守の窓口（導入した技術者）に更新を頼んでください
- **「セキュリティの修正があります」と出たら、できるだけ早く、保守の窓口（導入した技術者）か運営に Node.js の更新を頼んでください**（ダッシュボードにも出ます）。Node.js に見つかった穴が、いま動いている版ではまだ直っていないという知らせです。どの部分（API・ワーカー）が古いかと、何の版以上にすればよいかも出ます。M2Office はそのまま動き続けます
- 取れなかった値は「取得できなかった」と出ます。ワーカーの知らせが止まっているときは「知らせが止まっています」と出ます
- 秘密の値（鍵など）や業務の中身は出ません

## 各部の動き

- **データベース・ワーカー**: 動いているかと、答えの速さ・最後の知らせです。「止まっています」が続くときは、機械の電源と、保守の窓口に連絡してください
- **入口と証明書**: 社内のアドレスと、通信を守る証明書の期限です。証明書は自動で取り直します。期限が 14 日を切ると印が付きます
- **ローカル AI**: 社内の機械で動かしている AI が答えるかと、入っているモデルです
- **データのディスク**: 空きと大きさです

## 控え

- 毎晩 2 時ごろ、データベースとファイルの控えを、RAID とは別のディスクに取ります。毎日 14 回・毎週 8 回・毎月 12 回の分を残します
- 毎月 1 回、控えを別の場所に戻せるかを自動で確かめます
- 控えを取れなかったとき・戻せなかったときは、管理者に知らせが届きます
- 「今すぐ控えを取る」を押すと、1 分ほどで取り始めます（機械の入れ替えや大きな作業の前に）
- 会社が選んだ場合は、控えを暗号化して、会社が契約した社外の置き場にも送ります（「社外の控え」）。火事や盗難で機械と控えのディスクを両方なくしても戻せます。開けるための合言葉は、導入のときに渡した紙の「戻すための控え」にだけあります。運営も置き場の事業者も中身を読めません。紙は金庫など社内の安全な場所にしまってください
- 社外の控えは、毎月 1 回、壊れていないかを自動で確かめます。送れなかったとき・確かめに失敗したときは、管理者に知らせが届きます

## 更新

- 新しい版は、毎晩決まった時刻に自動で入ります（導入した技術者が設定します）。入れる前に控えを取り、うまく動かなければ前の版に戻します
- 直近の更新の結果が出ます。入れられなかったときは、管理者に知らせが届きます。導入した技術者に伝えてください
- 大事な仕事が続く時期などは「7 日延ばす」で、自動の更新を止められます。「止めるのをやめる」で元に戻ります

## 遠隔の保守と稼働の知らせ

- 機械の調子が悪いときなど、導入した技術者に頼まれたら、時間を選んで「遠隔の保守を開ける」を押します。技術者がその間だけ、社外から機械に入れます。期限が来ると自動で閉じます。早く終われば「閉じる」を押します
- ふだんは閉じています。技術者や運営の側から勝手に開けることはできません
- 開けた時刻・閉じた時刻・つないだ相手は、監査ログに残ります
- 同じ機械に M2Medical も入れているときは、遠隔の保守は M2Medical の管理者が開けます（技術者は機械全体に入れるため、患者の情報を守る側に合わせています）。「機械」には「M2Medical の管理者が開けます」と出ます
- 保守の契約で、機械の調子（動いているか・控えが取れているかなど）を運営に知らせている場合は「運営への稼働の知らせ」に出ます。人の名前や仕事の中身は送りません。「稼働の知らせを切る」で止められます

## システムログ

機械の動きの記録（システムログ）を、「機械」の下の「システムログ」で見られます。障害の調べや、不審な動きの確かめに使います。業務の中身（メール・文書・会話）は入っていません。

- 期間（直近 1 時間〜28 日）・レベル（エラー・警告）・プロセス・言葉で絞って「表示」を押します。行を押すと、会社・利用者・要求の ID などの項目が開きます
- 「ダウンロード（JSON）」「ダウンロード（CSV）」で、絞った結果を ZIP で保存できます。ZIP には、改ざんされていないかを確かめる値（SHA-256）を書いた `manifest.json` が付きます
- 「改ざんの確かめ」に、日ごとに「合っています」と出ます。「合いません」と出たら、ログが後から書き換えられた疑いがあります。導入した技術者に伝えてください
- 「機械のログのファイル」から、API・ワーカー・データベース・入口のアクセスログなどのファイルを、そのままダウンロードできます
- ログは 4 週分を残し、古いものから自動で消えます（ファイルは週に 1 回入れ替えて 4 世代を残します）
- 見たこと・ダウンロードしたことは、監査ログに残ります

## 証拠保全

攻撃を受けた・その疑いがあるときは、「証拠保全」を押して、理由と期間（直近 28 日・7 日・1 日）を選び「保全する」を押します。

- その時点のシステムログ・監査ログ・不正の兆し・ログイン中の端末・機械のログのファイル（接続元の IP を含む入口のアクセスログも）を、1 つの ZIP にして残します
- できあがると一覧に「保全しました」と出て、管理者全員に知らせが届きます。「ダウンロード」で保存し、警察や調査の会社に渡せます
- ZIP の中の `manifest.json` にファイルごとの値（SHA-256）が、一覧に ZIP 全体の値が出ます。渡した後に変わっていないことを示せます
- 保全したものは、4 週の入れ替えでは消えません。**1 年間は誰も消せません。** 1 年を過ぎたら「削除」で消せます
- 不正の兆しの見張りが、ある人の端末を自動でログアウトさせたときは、自動で保全します（1 日に 1 回まで）
