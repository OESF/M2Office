会社の中に置いたサーバーで M2Office を動かしている会社では、管理者ページの左のメニュー、**記録の「サーバー」**で、サーバーの様子とバックアップを確かめられます。業務の中身は出ません。

## サーバーの管理者

インターネットや Google が止まって、誰も Google でログインできないときでも、サーバーの様子を見られるよう、サーバーの管理だけに使う「サーバーの管理者」が 1 人います。

- ログイン画面の下の「サーバーの管理」（`/machine`）から、ID・合言葉・認証アプリの 6 桁の確認コードで入ります。ID と合言葉は、導入のときに技術者から紙で受け取ります
- 入れるのは「サーバー」だけです。業務の画面には入れません
- 8 時間でログインが切れます。5 回続けて間違えると、15 分は入れません
- 合言葉を忘れた・人に知られたときは、導入した技術者に作り直しを頼んでください
- サーバーの管理者が入ったこと・入れなかったこと・「サーバー」で行ったことは、監査ログに「サーバーの管理者」として残ります

## 全体の状態

「サーバー」を開いたら、まずいちばん上を見ます。

1. **帯**: 全体が「**平常**」「**注意**」「**警戒**」のどれかと、対応が要るものの件数です。緑なら、ほかを見なくても問題ありません
2. **対応が要るもの**: 警戒を先に、1 件ずつ「何が」「詳しい数」「**すること**」が並びます
3. **区分ごとの札**: 各部の動き・サーバーの資源・バックアップ・更新・稼働環境の 5 枚です。押すと、下の詳しい欄に移ります

帯の「更新」を押すと、すぐに読み直します（ふだんは 30 秒ごとに読み直します）。

| 区分 | 状態 | 当てはまるもの | すること |
|---|---|---|---|
| 各部の動き | 警戒 | データベースが応答しない・ワーカーが止まっている | 業務が止まっています。サーバーの電源を確かめ、保守の窓口に連絡する |
| 各部の動き | 警戒 | 入口の証明書の期限が切れた | 画面を開けません。すぐに保守の窓口に連絡する |
| 各部の動き | 注意 | 入口の証明書の期限まで 14 日を切った・入口を確かめられない | 保守の窓口に知らせる |
| 各部の動き | 注意 | ローカル AI が答えない | AI を使う業務が止まります。保守の窓口に連絡する |
| サーバーの資源 | 警戒 | データのディスク 90% 以上・データベースの接続が上限の 90% 以上 | すぐに保守の窓口に連絡する |
| サーバーの資源 | 注意 | データのディスク 80% 以上・バックアップのディスク 80% 以上・メモリー 90% 以上・CPU の負荷が高い状態が続く・データベースの接続が上限の 80% 以上 | 保守の窓口と、ディスクを足す・サーバーの大きさを上げる相談をする |
| バックアップ | 警戒 | 毎晩のバックアップの失敗・止まっている（最後に取れたのが 26 時間より前）・戻せるかの確認の失敗 | 保守の窓口に連絡する。それまでのバックアップは残っています |
| バックアップ | 注意 | 別の置き場へ送れなかった・別の置き場の確認の失敗 | 社内のバックアップは残っています。続くなら保守の窓口に連絡する |
| バックアップ | 注意 | 置き場が設定されていない・まだ一度も取っていない | 保守の窓口に設定してもらう。入れたばかりなら、翌朝も取れていなければ連絡する |
| 更新 | 注意 | 直近の更新を入れられなかった（前の版で稼働中） | 次の夜にもう一度試します。続くなら保守の窓口に連絡する |
| 稼働環境 | 警戒 | Node.js にセキュリティの修正がある・サポートが終わった | できるだけ早く、保守の窓口に Node.js の更新を頼む |
| 稼働環境 | 注意 | Node.js のサポートの終わりまで 6 か月を切った・ワーカーと M2Office の版が違う | 保守の窓口に知らせる |

材料を読めなかった区分は、平常とみなさず「注意」にし、「読めませんでした」と出します。各欄の上にも、その区分の「対応が要るもの」が出ます。

「警戒」になったときは、画面を開いていなくても分かるよう、管理者全員に「お知らせ」が届きます（Google Chat への転送を入れていれば、そちらにも届きます）。警戒が続くあいだは 6 時間ごとに、平常か注意に戻ったときは「回復」として届きます。注意だけのときは届きません。

## 稼働環境

「全体の状態」のすぐ下に、M2Office がどの版のソフトの上で動いているかが出ます。

| 項目 | 内容 |
|---|---|
| M2Office の版 | いま動いている版です。ワーカーだけ違う版のときは印が付きます |
| Node.js（API・ワーカー） | M2Office を動かしているソフトの版と、そのサポートがいつまで続くかです |
| PostgreSQL | データベースの版です |
| OS と CPU・メモリー | サーバーの OS と CPU、メモリーの大きさと使える量です |
| 稼働の形・推論 | ローカルの形か、デバッグモードか、ローカル AI のモデルと外部の AI です |
| 起動してからの時間 | API とワーカーが動き始めてからの時間です |

- **Node.js のサポートの終わりまで 6 か月を切ると、「Node.js の更新が要ります」と出ます**（ダッシュボードにも出ます）。サポートが終わると、直らない脆弱性が残るようになります。保守の窓口（導入した技術者）に更新を頼んでください
- **「セキュリティの修正があります」と出たら、できるだけ早く、保守の窓口（導入した技術者）か運営に Node.js の更新を頼んでください**（ダッシュボードにも出ます）。Node.js に見つかった穴が、いま動いている版ではまだ直っていないという知らせです。どの部分（API・ワーカー）が古いかと、何の版以上にすればよいかも出ます。M2Office はそのまま動き続けます
- 取れなかった値は「取得できなかった」と出ます。ワーカーの知らせが止まっているときは「知らせが止まっています」と出ます
- 秘密の値（鍵など）や業務の中身は出ません

## サーバーの資源

「稼働環境」のすぐ下に、サーバーにどれだけ余裕があるかが、棒と図で出ます。

| 項目 | 内容 |
|---|---|
| CPU の負荷 | 直近 1 分の平均の負荷を、CPU のコアの数で割った割合です。5 分・15 分の平均も数で出ます。100% を超えることがあります |
| メモリー | 使っている量と全体です |
| Swap | メモリーが足りないときに使うディスクの領域の、使っている量と全体です。Swap の無いサーバーは「なし」と出ます |
| ディスク | ファイルの置き場があるディスクの、使っている量と全体です |
| データベースの接続 | データベースへの接続の数と、上限です |

- **80% を超えると黄色、90% を超えると赤**で出ます。割合の数も一緒に出ます
- 下の「推移」で、直近 24 時間の変わり方を折れ線で見られます。「7 日」に切り替えると 7 日分を見られます。図の上で指やマウスを動かすと、その時刻の値が出ます
- 赤が続く・増え続けるときは、保守の窓口（導入した技術者）に伝えてください

## 各部の動き

- **データベース・ワーカー**: 動いているかと、答えの速さ・最終応答です。「止まっています」が続くときは、サーバーの電源と、保守の窓口に連絡してください
- **入口と証明書**: 社内のアドレスと、通信を守る証明書の期限です。証明書は自動で取り直します。期限が 14 日を切ると印が付きます
- **ローカル AI**: 社内のサーバーで動かしている AI が答えるかと、入っているモデルです
- **データのディスク**: 空きと大きさです

## バックアップ

- 毎晩 2 時ごろ、データベースとファイルのバックアップを、RAID とは別のディスクに取ります。毎日 14 回・毎週 8 回・毎月 12 回の分を残します
- 毎月 1 回、バックアップを別の場所に戻せるかを自動で確かめます
- バックアップを取れなかったとき・戻せなかったときは、「警戒」として管理者に知らせが届きます（理由も添えます）
- 「今すぐバックアップを取る」を押すと、1 分ほどで取り始めます（サーバーの入れ替えや大きな作業の前に）
- 会社が選んだ場合は、バックアップを暗号化して、社内の NAS か、会社が契約した社外の置き場にも送ります（「別の置き場のバックアップ」）。サーバーとバックアップのディスクを両方なくしても戻せます。NAS には足すことしかできない形で送るので、サーバーが乗っ取られても NAS のバックアップは消されません。開けるための合言葉は、導入のときに渡した紙の「戻すためのバックアップ」にだけあります。運営も置き場の事業者も中身を読めません。紙は金庫など社内の安全な場所にしまってください
- 別の置き場のバックアップは、毎月 1 回、壊れていないかを自動で確かめます。送れなかったとき・確認に失敗したときは、管理者に知らせが届きます
- NAS に送る場合は、NAS から持ち運べるディスク（USB など）へ定期的にコピーし、別の場所に保管してください。2 台を交互に使い、1 台はいつも別の場所に置きます。中身は暗号化されたままなので、ディスクをなくしても読めません。合言葉の紙は、ディスクと別の場所にしまってください

## 更新

- 新しい版は、毎晩決まった時刻に自動で入ります（導入した技術者が設定します）。入れる前にバックアップを取り、うまく動かなければ前の版に戻します
- 直近の更新の結果が出ます。入れられなかったときは、管理者に知らせが届きます。導入した技術者に伝えてください
- 大事な仕事が続く時期などは「7 日延ばす」で、自動の更新を止められます。「止めるのをやめる」で元に戻ります

## システムログ

サーバーの動きの記録（システムログ）を、「サーバー」の下の「システムログ」で見られます。障害の調べや、不審な動きの確かめに使います。業務の中身（メール・文書・会話）は入っていません。

- 期間（直近 1 時間〜28 日）・レベル（エラー・警告）・プロセス・言葉で絞って「表示」を押します。行を押すと、会社・利用者・要求の ID などの項目が開きます
- 「ダウンロード（JSON）」「ダウンロード（CSV）」で、絞った結果を ZIP で保存できます。ZIP には、改ざんされていないかを確かめる値（SHA-256）を書いた `manifest.json` が付きます
- 「改ざんの確かめ」に、日ごとに「合っています」と出ます。「合いません」と出たら、ログが後から書き換えられた疑いがあります。導入した技術者に伝えてください
- 「サーバーのログのファイル」から、API・ワーカー・データベース・入口のアクセスログなどのファイルを、そのままダウンロードできます
- ログは 4 週分を残し、古いものから自動で消えます（ファイルは週に 1 回入れ替えて 4 世代を残します）
- 見たこと・ダウンロードしたことは、監査ログに残ります

## 証拠保全

攻撃を受けた・その疑いがあるときは、「証拠保全」を押して、理由と期間（直近 28 日・7 日・1 日）を選び「保全する」を押します。

- その時点のシステムログ・監査ログ・不正の兆し・ログイン中の端末・サーバーのログのファイル（接続元の IP を含む入口のアクセスログも）を、1 つの ZIP にして残します
- できあがると一覧に「保全しました」と出て、管理者全員に知らせが届きます。「ダウンロード」で保存し、警察や調査の会社に渡せます
- ZIP の中の `manifest.json` にファイルごとの値（SHA-256）が、一覧に ZIP 全体の値が出ます。渡した後に変わっていないことを示せます
- 保全したものは、4 週の入れ替えでは消えません。**1 年間は誰も消せません。** 1 年を過ぎたら「削除」で消せます
- 不正の兆しの見張りが、ある人の端末を自動でログアウトさせたときは、自動で保全します（1 日に 1 回まで）
