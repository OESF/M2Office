「Google Chat のつなぎ方（管理者・くわしい手順）」のとおりに進めても動かないときの調べ方です。M2Office の画面に出る言葉から探してください。M2Office の言葉の後ろに「Google の答え: …」が付いているときは、Google が返した理由です。

## 段 A 通知が届かない

| 出る言葉・ようす | 原因 | 直し方 |
|---|---|---|
| 個人設定で「会社の Chat アプリの鍵が登録されていません」 | 鍵を預けていない | 「つなぎ方」の A-3・A-4 |
| 鍵の登録で「サービスアカウントの鍵ではありません」「鍵のファイルを読めません」 | JSON 以外のファイル、または OAuth クライアントのファイルを選んでいる | サービスアカウントの「鍵」で作った JSON を選ぶ |
| 「会社の Chat アプリの鍵が Google に認められません」 | 鍵を Google Cloud で削除した、またはサービスアカウントを止めた | 新しい鍵を作って登録し直す |
| 「Chat に届けるには Google の許可を 1 つ足します」が、許可しても何度も出る | 従業員の Google の接続に、個別メッセージを用意する許可が入っていない | 「Google の許可を足す」で許可の画面に出た項目を、すべて入れて許可する。それでも出るときは、個人設定の「Google 連携」で切断して接続し直す |
| 「Google Chat がアプリの呼び出しを断りました（Chat アプリの設定と、鍵のプロジェクトが同じか確かめてください）」 | 鍵のプロジェクトに Chat アプリの構成が無い、または構成を保存していない | 鍵の `project_id` と、構成を入れたプロジェクトが同じかを確かめる。構成を保存し直す |
| 「Google の答え: PERMISSION_DENIED Developer permission settings do not support this action」 | 構成のインタラクティブ機能が切れている（と見ています） | 構成で「インタラクティブ機能を有効にする」を入れ、ほかの欄も入れ直して保存する。数分たってから、個人設定の「Chat（本人への個別メッセージ）」を外して入れ直す |
| 一部の人だけ、個別メッセージを用意できない | 構成の「公開設定」にその人が入っていない | 「公開設定」に、その人かその人のグループを入れる |
| 「Chat の個別メッセージの場所がありません」 | Chat 側で会話を削除した、またはアプリを外した | 本人が個人設定で「Chat（本人への個別メッセージ）」を外して入れ直す |
| 夜や休みの日に届かない | 既定で、夜（21:00〜翌 7:00）と営業日でない日には送らない | 故障ではありません。明けたら 1 通にまとめて届きます。本人が個人設定の「通知」で時間帯を変えられます |
| 一部の種類だけ届かない | 本人が「Chat に送る種類」で外している | 本人の個人設定の「通知」を見る |

## 段 B 秘書が答えない

Chat に書いても秘書が答えないときは、どこで止まっているかを、手前から順に確かめます。

```text
① Chat がアプリに渡す ─▶ ② トピックに書き込む ─▶ ③ M2Office が購読から取る ─▶ ④ 会社の人か確かめる ─▶ ⑤ 秘書が答える
   （HTTP では ② ③ の代わりに、Chat が受け口の URL に送り、M2Office が署名を確かめる）
```

| 止まっている所 | 見分け方 | 直し方 |
|---|---|---|
| ① 発言がアプリに届かない | スペースで、アプリに言及せずに書いている | `@アプリ名` と言及して書く。個別メッセージなら言及は要らない |
| ① 発言がアプリに届かない | 構成の「機能」に「1:1 のメッセージを受け取る」「スペースとグループの会話に参加する」が入っていない | 入れて保存する |
| ② トピックに書き込まれない（Pub/Sub） | 「Pub/Sub › トピック」でトピックを選び、「指標」で公開の数が増えていない | 構成の「サービス アカウントのメール」のアカウント（`service-…@gcp-sa-gsuiteaddons…`）に、トピックの「Pub/Sub パブリッシャー」が付いているか。構成のトピックの名前（`projects/…/topics/…`）が合っているか。**`chat-api-push@system.gserviceaccount.com` に付けても書き込まれません** |
| ③ M2Office が取れない（Pub/Sub） | トピックには増えているのに、購読の「未確認のメッセージ」がたまっていく | M2Office の購読の欄に名前を入れたか。M2Office が動いているか（社内のサーバーが止まっていないか） |
| ③ M2Office が取れない（Pub/Sub） | 「Pub/Sub の購読を読めません（403…）」「（404…）」 | 403 は、会社のサービスアカウントに購読の「Pub/Sub サブスクライバー」が無い。404 は、購読の名前が違う（プロジェクト ID・購読の名前を確かめる） |
| ③ M2Office が取れない（Pub/Sub） | 「Cloud Pub/Sub に届きませんでした」が続く | M2Office の機械がインターネットに出られない。Cloud Pub/Sub API が有効か（「API とサービス」）も確かめる |
| ③ 受け口が断る（HTTP） | Chat に「応答がありません」と出て、M2Office には何も残らない | 構成の URL が、M2Office で作った最新の URL か（作り直すと前の URL は使えません）。認証オーディエンスが「HTTP エンドポイント URL」か。Chat アプリを、M2Office に登録した OAuth クライアントと同じプロジェクトに作ったか（M2Office は、そのプロジェクトの Chat アプリからの発言だけを受けます） |
| ④ 会社の人と分からない | 管理者ページの「監査ログ」に、Chat の発言を断った記録が残る | 書いた人の Google のアカウントが、M2Office の利用者のメールアドレスか、その人の Google の接続のアカウントと同じか。違う人なら、利用者として加えるか、個人設定で Google に接続してもらう |
| ⑤ 秘書が答えられない | M2Office の画面の秘書でも答えない | AI の鍵や利用の上限を確かめる（「Gemini の鍵の取り方（管理者）」の記事） |

### Google の記録を見る

Google は、Chat アプリの呼び出しが失敗した理由を、画面にほとんど出しません。止まっている所が分からないときは、次を見ると手がかりになります。

- **トピックの指標:** 「Pub/Sub › トピック」でトピックを選び、「指標」で公開の数を見ます。書いた後に増えていなければ ② で止まっています
- **購読の指標:** 購読を選び、「指標」で未確認のメッセージの数を見ます。たまり続けていれば ③ で止まっています
- **Chat API の指標:** 「API とサービス › 有効な API とサービス › Google Chat API」の「指標」で、誤りの割合と、誤りの種類（403・404 など）を見ます

## 問い合わせるとき

M2Office の誤りの言葉の後ろの「問い合わせ番号」を控えてください。開発者に調べてもらうときは、デバッグモードの記録（画面の上の赤い「Debug mode」を押すと開きます）と一緒に伝えると、早く原因が分かります。
