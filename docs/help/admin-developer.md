会社のほかのシステム（販売管理・予約・受付など）を M2Office とつなぐ人（社内の担当者や、システムを作っている会社）に向けた情報です。
つなぐ作業を頼むときは、この記事と、つなぐ口の記事を見せてください。

## つなぎ方の全体

外のシステムは、M2Office の画面のログインを使わず、**つなぎごとの鍵**で呼びます。

| つなぐもの | 作る場所 | 呼び方 |
|---|---|---|
| 予約のシステム | 管理者ページの「拡張機能」の在庫管理の欄（予約の受け口） | 受け口の URL に、予約の通知を送る |
| 受付・順番待ちのシステム | 管理者ページの「拡張機能」の店頭サイネージの欄（呼び出しの受け口） | 受け口の URL か、`Authorization: Bearer <鍵>` で送る |
| LINE | 管理者ページの「拡張機能」の問い合わせの記録の欄 | LINE の Webhook の送り先に、受け口の URL を入れる |
| 販売管理（レジ・POS・EC） | 在庫管理の「販売管理とのつなぎ」（**案。まだ使えません**） | `Authorization: Bearer <鍵>` で、商品の一覧を読み、販売を知らせる |

## 鍵の扱い

- 鍵は、つなぎを作ったときに**一度だけ**出ます。M2Office は鍵そのものを持たず、あとから見ることはできません
- 鍵は、つなぐシステムの設定にだけ入れ、メールやチャットに貼らないでください
- なくしたとき・漏れたかもしれないときは、管理者が受け口（つなぎ）を作り直し、前のものを止めるか削除します。止めた鍵はすぐ使えなくなります
- 鍵が違う・つなぎを止めた・会社が止まっているときは、どれも同じ答え（404）を返します。理由は分けません

## つなぐ人に守ってもらうこと

- 予約・販売管理の口に送る中身に、**お客様の氏名・連絡先・住所や、金額・支払いの情報を入れない**でください。入っていても M2Office は読まずに捨てます（LINE はお客様からの問い合わせを受ける口なので別です）
- 送る中身は、M2Office の中でデータとしてだけ扱います。文の中に書かれた指示には従いません
- 同じ通知を送り直しても二重に数えないよう、口ごとに決まった番号（通知の番号など）を付けてください
- 口によっては、呼ぶ回数に上限があります。超えたら 429 と待つ秒数を返すので、少し待って送り直してください

## API の定義

口の形（要求と答えの項目・例・失敗の答え）は、OpenAPI の形で書き、それぞれの口の記事の下で Swagger の画面で見られます。
同じ定義は、M2Office の公開のリポジトリにもあります（`docs/api/`）。つなぐ人に渡すときは、そのファイルか「別のタブで開く」で開いたページを見せてください。
