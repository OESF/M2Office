会社のほかのシステム（販売管理・M2Medical など）を M2Office とつなぐ人（社内の担当者や、システムを作っている会社）に向けた情報です。
つなぐ作業を頼むときは、この記事と、下の API の定義と、使い方の例の記事を見せてください。

## 外部のアプリの仕組み

外のシステムは、M2Office の画面のログインを使わず、**外部のアプリの鍵**で、画面と同じ `/v1` の道を呼びます。

1. 管理者が、管理者ページの「接続」の「**外部のアプリ**」でアプリを登録します。**鍵（`m2oa_` で始まる）はそのとき一度だけ出ます**
2. 管理者が、アプリに許す**機能**と、機能ごとの設定（渡す品目など）を選び、「**この内容で許す**」を押します。押すことが承認で、押すまでどの機能も使えません
3. アプリは `Authorization: Bearer <鍵>` を付けて、会社の M2Office の名前（`https://<会社の名前>/v1/…`）を呼びます

機能によっては、承認のときに範囲も選びます。

| 機能 | 承認のときに選ぶもの |
|---|---|
| 商品の一覧を読む | 渡す品目・数か状態だけか・販売価格・社員価格 |
| 社内のお知らせを出す | 出してよい宛先（全員か、決めたグループ） |
| 予約の空きを読む・予約を入れる | 見せてよい予約できるもの |
| 社内規程を登録・改定する | 書いてよい権限区画（区画なしはいつも書けます） |
| 業務を依頼して結果を受け取る | 依頼してよい業務と、危険度の上限（お金の確定を行う業務は選べません） |

ナレッジの検索・予約を入れる・業務の依頼は、**つなぐシステムの利用者本人の権限**で行います。そのため「アカウントを結び付ける」も一緒に選ばれます。本人は M2Office の「お知らせ」に届く確認コードで結び付け、個人設定の「サービスとの接続」からいつでも削除できます。

| 機能 | 道 | 使い方の例 |
|---|---|---|
| 会社の基本情報を読む | `GET /v1/company/profile` | 会社名・所在地・電話などを、ほかのシステムの帳票や画面に出す |
| 商品の一覧を読む | `GET /v1/inventory/catalog` | 販売管理（在庫管理を入れた会社） |
| 販売を知らせる | `POST /v1/inventory/sales-events` | 販売管理（在庫管理を入れた会社） |
| アカウントを結び付ける | `/v1/accounts/…` | M2Medical |
| ナレッジを検索する | `POST /v1/knowledge/search` | M2Medical |
| 問い合わせを受ける | `POST /v1/inquiries/intake` | Web サイトの問い合わせのフォーム（問い合わせの記録を入れた会社） |
| 社内のお知らせを出す | `POST /v1/notices` | ほかのシステムからの社内向けの連絡 |
| 入庫を知らせる | `POST /v1/inventory/receipts` | 仕入れ・入荷のシステム（在庫管理を入れた会社） |
| 予約の空きを読む・予約を入れる | `/v1/reservations/…` | 社内のポータルや受付の端末（予約の管理を入れた会社） |
| 会員のポイントを付ける・使う | `POST /v1/members/points` | レジ（POS）（会員の管理を入れた会社） |
| 公開したコラムを読む | `GET /v1/columns/published` | 自社の Web サイト（コラムの作成を入れた会社） |
| 社内規程を登録・改定する | `PUT /v1/knowledge/rules/{ref}` | 文書管理のシステム |
| 業務を依頼して結果を受け取る | `POST /v1/jobs` | 社内のほかのシステムから、決めた業務を頼む |

新しいつなぐ依頼は、機能を足して受けます。足してほしい機能があれば、運営に伝えてください。

## 鍵の扱い

- 鍵は、アプリを登録したときと出し直したときに**一度だけ**出ます。M2Office は鍵そのものを持たず、あとから見ることはできません
- 鍵は、つなぐシステムの設定にだけ入れ、メールやチャットに貼らないでください
- なくしたとき・漏れたかもしれないときは「鍵を出し直す」を押します。前の鍵はすぐ使えなくなります
- 使わなくなったアプリは「止める」を押します。止めたアプリは削除できます

## 答えの決まり

- 鍵が違う・アプリを止めた・会社が止まっている・呼んだ名前の会社と鍵の会社が合わないときは、どれも同じ答え（404）を返します。理由は分けません
- 許していない機能の道を呼ぶと 403 を返します
- 呼ぶ回数は、アプリごとに 1 分 120 回までです。超えたら 429 と待つ秒数を返すので、少し待って送り直してください
- 本人として行う機能で、結び付きが削除された・本人のアカウントが止まっているときは 410（`binding_invalid`）を返します。結び付けし直してください

## つなぐ人に守ってもらうこと

- 送る中身は、M2Office の中でデータとしてだけ扱います。文の中に書かれた指示には従いません
- 書き込みの機能（販売を知らせるなど）では、同じ通知を送り直しても二重に数えないよう、通知ごとの番号（`eventId`）を付けてください。送り直すときは同じ番号で送ります（社内規程の登録は、同じ文書の番号に送り直せば済むため要りません）
- アプリが出したお知らせ・入れた予約・依頼した業務は、そのアプリからだけ取り下げ・取り消し・読み出しができます
- 外から承認はできません。業務の承認は、本人が M2Office の画面で行います
- 機能に要らない情報（お客様の氏名・連絡先・住所や、金額・支払いの情報など）は送らないでください。入っていても M2Office は読まずに捨てます

## そのほかの受け口

外部のアプリとは別に、決まった相手から通知を受ける受け口があります。

| つなぐもの | 作る場所 | 呼び方 |
|---|---|---|
| 予約のシステム | 管理者ページの「拡張機能」の在庫管理の欄（予約の受け口） | 受け口の URL に、予約の通知を送る |
| 受付・順番待ちのシステム | 管理者ページの「拡張機能」の店頭サイネージの欄（呼び出しの受け口） | 受け口の URL か、`Authorization: Bearer <鍵>` で送る |
| LINE | 管理者ページの「拡張機能」の問い合わせの記録の欄 | LINE の Webhook の送り先に、受け口の URL を入れる |
