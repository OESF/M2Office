管理者ページの「接続」で、Gemini（AI）と Google Workspace（メール・予定など）、ほかのサービス（コネクタ。MCP サーバ）への接続を設定します。
鍵やシークレットは、登録したあとは画面に表示しません。変えるときは上書きし、要らなくなったら削除します。

## Gemini（業務の推論・秘書・Web の調査・音声）

- **運営一括**（既定）: M2Office の鍵を使います
- **自社の鍵を使う**: Google AI Studio で発行した API キーを登録します。費用は自社の Google Cloud に直接かかります
- 「文章を試す」「音声（Gemini Live）を試す」で、つながるかをその場で確かめられます
- 音声では、鍵をブラウザに渡しません。M2Office のサーバーが Gemini Live へ中継します
- 役割ごとに使うモデルを指定できます（空なら既定のモデル）
- Gemini が混み合っていたり障害が起きていたりして答えられないときは、同じ鍵のまま、指定しているほかのモデルで自動的に答え直します。鍵の誤りでは答え直しません。ローカル AI だけを使う会社では、社外の AI に切り替えることはありません
- 使える鍵が無いと、秘書も業務も動きません

## AI の方針（社内の 1 台に入れた M2Office だけ）

M2Office を社内の機械（Mac mini・Mac Studio など）に入れて使う会社では、「Gemini」の画面に **AI の方針** が出ます。顧客の個人の情報を外部の AI に渡さないための設定です。

- **ローカルを既定**: 秘書と、社内のデータやファイルを読む業務は、社内の機械で動く **ローカル AI** を使います。外部の AI（Gemini）は、社内のデータを読まない業務（SNS の文案・Web の調べものなど）だけに使います
- **ローカルだけ**: 外部の AI を使いません。Web の調べものも使えません
- **クラウド**: これまでどおり Gemini を使います
- ローカルの方針では、音声の秘書は使えません（外部の音声のサービスを使うため）。文字で話しかけてください
- 「ローカル AI を確かめる」で、社内の機械の AI に届くかを確かめられます
- ローカルの方針では、コネクタごとに「この接続（社外）に送るもの」を選びます。はじめは「送らない」です。社外の専門のサービスに、個人を特定する情報を除いて尋ねてよい場合だけ「個人を特定する情報を除いて送る」にしてください

## Google Workspace

会社の Google Cloud で作った OAuth クライアントを登録します。画面の手順どおりに進めてください。

1. Google Cloud でプロジェクトを作り、使う API を有効にします
2. OAuth の同意画面を **「内部」** で作ります（社内だけで使うアプリになるため、Google の審査は要りません）
3. OAuth クライアント（ウェブ アプリケーション）を作り、画面に表示されるリダイレクト URI を登録します
4. クライアント ID とクライアント シークレットを登録します
5. 自分で個人設定の「Google 連携」から接続を試します

**保存するときに、クライアント ID とシークレットが組になっているかを Google で確かめます。** 結果は保存のボタンの横に出ます。

- **正しいとき**: 「保存しました。Google で確かめ…」と出ます
- **誤っているとき**: 保存しません。いまの登録はそのまま残ります。シークレットが違うのか、クライアント ID が見つからないのかを示すので、Google Cloud Console で確かめて貼り直してください。シークレットは作ったときにしか全体が表示されないため、分からなければ「シークレットを追加」で作り直せます
- **確かめられなかったとき**（Google に届かなかったなど）: 保存はしますが、「確かめられていません」と出ます。あとで「**Google で確かめる**」を押してください

登録済みの設定は、「Google で確かめる」を押せば、保存し直さずにいつでも確かめられます。

**Chat に投稿するには、会社の Google Cloud で Chat アプリの設定も要ります。** Google Chat API を有効にしたうえで、その API の構成の画面でアプリの名前・画像・説明を入れて保存してください。設定が無いと、業務がチャットに共有するところで「Chat アプリが設定されていません」と止まります。
確かめられるのは、クライアント ID とシークレットの組までです。リダイレクト URI の登録漏れなどは、手順 5 で自分で接続して確かめてください。

従業員が接続しようとして、会社の設定の誤りで失敗したときは、その人の画面に「管理者に伝えてください」と出ます。

登録したあと、従業員はそれぞれ個人設定の「Google 連携」で、自分の Google アカウントで接続します。
「従業員の接続状況」で、誰が接続したか、足りない許可があるかを確かめられます（トークンは見られません）。

## OAuth クライアントを消す・替えるとき

OAuth クライアントの登録を消す、またはクライアント ID を別のものに替えると、**接続している従業員全員の許可が使えなくなります**。その人たちの Google を使う動いている途中の業務は止まり、業務が読んだメールや文書の中身も消します。従業員は、新しい設定で接続し直す必要があります。消す（替える）前に、影響する人数と業務の件数を示します。

クライアント シークレットだけを替える場合は、従業員の接続に影響しません。

## 取得したデータを残す日数

業務が Google から読んだメールや文書の中身と、そこから作った要約などを、業務が終わってから何日残すかを選びます。上限は 7 日で、それより長くはできません。「業務が終わったらすぐ削除」も選べます。

- 過ぎると中身を消し、使ったツールの名前と件数だけを残します
- 作った成果物（下書き・議事録など）は消しません
- 承認待ちの間は残します。承認されないまま 30 日たった業務は期限切れにして止め、依頼した人に知らせます
- 従業員が Google との連携を解除したときは、その人の業務の中身を日数を待たずに消します

## 接続のときに求める許可と、Google の権限の段階

使える業務（公式の業務と、導入して有効にした拡張機能）が、Google のどの権限を求めるかを「**求める許可**」に一覧で示します。
許可ごとに、**その許可を使う業務**も並びます。Google と接続するときは、使う業務の分だけ許可を求めます。使っていない業務の権限は求めません。

- **制限付き**: Gmail の読み取りなど。M2Office を一般に公開する前に、第三者のセキュリティ評価（CASA）が必要な権限です
- **機密**: カレンダー・ToDo・Chat など。一般に公開する前に Google の審査が必要です
- **機密でない**: M2Office が作ったファイルと、あなたが選んだファイルだけを扱うドライブの権限など

社内で使う間は、どの権限も審査なしで使えます。段階は見込みで、申請の前に Google の一覧で確かめます。

## コネクタ（MCP）

「接続」の下の「**コネクタ（MCP）**」で、外部のサービス（MCP サーバ）への接続を会社として管理します。
登録した接続のツールは、秘書・業務・拡張機能のどれからでも使えます。

- **追加**: 接続先の URL を入れて「追加」を押すと、そのサービスが提供するツールの一覧が並びます
- **危険度**: ツールごとに選びます。サービスが「読むだけ」と示しているツールは「読むだけ」、それ以外は「社外や他の人へ送る」から始まります（承認が入る安全側）。実際に合わせて変えてください
- **ツールの一覧**: 畳んであります。「ツール 21 件（…）」の見出しを押すと開きます。見出しに、危険度ごとの数と止めている数が出ます
- **利用**: ツールごとに止める・戻すができます。止める前に、使えなくなる業務の名前が出ます
- **接続を確認**: その場でつながるかを試せます
- **ツールを取り直す**: サービスのツールが増えたり減ったりしたときに押します。決めた危険度は残ります
- **消す**: 使っている業務があれば、その名前が出てから消えます。消すと、その業務は使えなくなります
- 拡張機能に接続が入っていれば、導入したときにここへ登録されます。拡張機能を削除しても、接続は残ります

### 認証の要るサービス（Slack など）

追加するときに「認証」を選べます。

- **認証なし**: 公開の情報を返すサービス（DeepWiki など）
- **利用者ごとに許可（OAuth）**: 会社がサービスにアプリを作って登録し、**従業員がそれぞれ自分のアカウントで許可**します。業務は、頼んだ本人の許可で動きます。ほかの人の許可では動きません
- **会社の鍵**: 会社で 1 つの鍵を登録し、誰が頼んでも会社として動きます。本人ごとの区別が無いため、ツールの危険度と「利用」で絞ってください

クライアント シークレットと会社の鍵は、登録したあとは画面に表示しません。

**相手のサービスがアプリの自動登録に対応していれば、アプリを作って登録する手間はいりません。** 接続に「自動で登録できます」と出ます。「自分で接続して確かめる」を押して許可すると、M2Office がアプリを登録し（「自動で登録」に変わります）、従業員はそれぞれ自分のアカウントで接続できます。相手に送るのはアプリの名前と戻り先の URL だけです。会社で作ったアプリを使いたいときは「アプリを手で登録する」を開いて登録してください。相手がアプリを無効にしたときは、従業員全員に接続し直しを求め、次の接続で登録し直します。

### Slack とつなぐ

「**Slack を追加**」を押すと、Slack の公式の接続先と、許可の画面の場所が入ります。そのあと次の順に進めます。

1. Slack のワークスペースに**社内向けのアプリ**を作ります（一般公開していない「非掲載」のアプリでは使えません）
2. アプリの「OAuth & Permissions」に、画面に出る**戻り先の URL** を登録します（「コピー」でコピーできます）
3. アプリの「User Token Scopes」に、「Slack の側で行うこと」に出る**権限**を足します
4. アプリの設定の「Agents & AI Apps」で、**Slack の MCP サーバの利用をオン**にします（オフのままだと、ツールを取り直すときに「App is not enabled for Slack MCP server access」と断られます）
5. ワークスペースの管理者がアプリを承認する運用なら、承認を受けます
6. アプリの**クライアント ID とクライアント シークレット**を登録します
7. 「**自分で接続して確かめる**」を押し、自分の Slack アカウントで許可します。戻ってきたら「**ツールを取り直す**」を押すと、Slack のツールが並びます
8. 従業員は、個人設定の「**サービスとの接続**」で、それぞれ接続します。接続していない人がその業務を開くと「Slack との接続が要ります」と出ます

- 検索や読み取りのツールは「読むだけ」、**投稿やチャンネルの作成、キャンバスの更新は「社外や他の人へ送る」**から始まります。社外の人がいるチャンネル（Slack コネクト）もあるため、投稿は承認が入ります
- ツールを止めると、Slack に求める権限も減ります。従業員には「接続し直す」が出ます
- **クライアント ID を替える、または接続を消すと、接続している従業員全員の許可が消えます**（消す前に人数を示します）。シークレットだけを替える場合は影響しません
