販売管理（レジ・POS・EC）が、M2Office の在庫から**販売できる商品の一覧を読み**、**売れたことを知らせる**ための口です。
販売管理を作っている会社にこの記事を見せ、下の API の定義のとおりに作ってもらいます。管理者の操作は、在庫管理のマニュアルの第 12 章にあります。

## 流れ

1. 管理者が、在庫管理の「販売管理とのつなぎ」でつなぎを作り、**販売管理に渡す品目と項目**（使える数か状態だけか・販売価格を渡すか・社員価格を渡すか）を選んで承認します。鍵が一度だけ出ます
2. 販売管理は、鍵を付けて**商品の一覧**を読みます。2 回目からは「前回から変わった品目だけ」を読めます
3. 販売管理は、注文・販売・取り消し・返品のたびに**販売の通知**を送ります。M2Office の在庫がそのとおりに動きます

| 販売の通知 | 在庫で行うこと |
|---|---|
| 注文を受けた | 取り置く（在庫は減らさず、使える数だけを減らす） |
| 販売した・出荷した | 在庫を減らす |
| 取り消した | 取り置きを戻す。販売のあとなら減らした分を戻す |
| 返品された | 在庫に戻す |

## 決まり

- 一覧に出るのは、承認した品目と項目だけです。承認のあとに足した品目は、承認し直すまで出ません
- 販売品の一覧を作るときは、分類の名前で絞って読めます（例: 「販売品」の分類だけ）。分類の名前を変えたら、販売管理の側の指定も直してもらってください
- 品目は、M2Office の品目の番号・自社のコード・バーコードのどれかで照らします。照らせない品目の販売は、在庫管理の「照らせなかった販売」で品目を選べば記録されます
- 同じ通知を送り直しても、二重に数えません（通知ごとの番号 `eventId` で見分けます）
- 注文の取り置きは、「予約との引き当て」を入れていない会社でも使える数から引きます
- 在庫が足りなくても、販売は受け付けます（売れたことは販売管理の側で決まっているため）。マイナスの在庫として知らせます
- 金額・支払い・お客様の情報は受け取りません
- M2Office から販売管理へ知らせる口はありません。数の変化は、販売管理が一覧を読みに来て取ります
