販売管理（レジ・POS・ネットショップ）が、M2Office の在庫から**販売できる商品の一覧を読み**、**売れたことを知らせる**使い方です。外部のアプリの 2 つの機能「商品の一覧を読む」「販売を知らせる」を使います。
道の形と項目は、記事「外部のアプリ（開発者向けの情報）」の API の定義にあります。管理者の操作は、在庫管理のマニュアルの第 12 章にあります。

## つなぐまで

1. 管理者ページの「接続」の「外部のアプリ」で、販売管理をアプリとして登録します（「レジ」「ネットショップ」など、販売の経路ごとに分けられます）。鍵が一度だけ出ます
2. 機能「**商品の一覧を読む**」と「**販売を知らせる**」を選びます
3. 「商品の一覧で渡すもの」で、渡し方（使える数か状態だけか）・販売価格・社員価格と、渡す品目を選び、見本を確かめて「**この内容で許す**」を押します
4. 鍵を、販売管理を作っている会社に渡します

## 販売管理がすること

| すること | 呼ぶ道 |
|---|---|
| 売る品目と数を読む。2 回目からは、前回の答えの `asOf` を `updatedSince` に渡して、変わった品目だけを読む。販売品だけなら `categories=販売品` | `GET /v1/inventory/catalog` |
| 注文を受けた・販売した・取り消した・返品されたたびに知らせる | `POST /v1/inventory/sales-events` |

| 知らせ（`status`） | 在庫で行うこと |
|---|---|
| `ordered` 注文を受けた | 取り置く（在庫は減らさず、使える数だけを減らす） |
| `sold` 販売した・出荷した | 在庫を減らす |
| `cancelled` 取り消した | 取り置きを戻す。販売のあとなら減らした分を戻す |
| `returned` 返品された | 在庫に戻す |

## 決まり

- 一覧に出るのは、承認した品目と項目だけです。承認のあとに足した品目は、承認し直すまで出ません
- 範囲から外した品目・止めた品目・分類を変えて絞った分類から外れた品目は、`updatedSince` の答えに `active: false` として 1 度入ります
- 品目は、M2Office の品目の番号・自社のコード・バーコードのどれかで照らします。照らせない品目の販売は、在庫管理の「照らせなかった販売」で品目を選べば記録されます
- 同じ通知を送り直しても、二重に数えません（通知ごとの番号 `eventId` で見分けます）
- 注文の取り置きは、「予約との引き当て」を入れていない会社でも使える数から引きます
- 在庫が足りなくても、販売は受け付けます（売れたことは販売管理の側で決まっているため）。マイナスの在庫として知らせます
- 入出庫の記録には、記録した人として「外部のアプリ（アプリの名前）」と出ます
- 金額・支払い・お客様の情報は受け取りません
