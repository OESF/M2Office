# ADR-0030 推論（Gemini）が無い環境を想定しない。見本の応答は自動テストの中だけで使う

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-09-26 に三浦さんが合意） |
| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第12.9.4節・第12.12節・第20.2.4節（新設）・第20.4節。ADR-0003（改める） |

## 背景

M2Office は、Google と LLM の準備が整う前も全体を動かせるよう、LLM の鍵が無いときは推論の代わりに**見本の応答（スタブ）**で動く作りにしていた（ADR-0003）。
その結果、次のことが起きていた。

- 鍵の無い会社でも、秘書と業務が見本の応答で**動いたように見える**
- 拡張機能を作る人に、鍵が無い環境のための「見本の答え（`stub`・`answer`）」を書かせていた
- 仕様書・開発者マニュアル・ヘルプの多くの箇所が「鍵が無い環境」を前提に書かれていた

2026-09-26、三浦さんが「そもそもこんな環境は想定する必要がない。M2Office として成立しない」と指摘した。

## 決定

1. **推論が使えない会社では、秘書も業務も動かさない。** 「Gemini の接続が設定されていません。管理者ページの『接続』で設定してください」とだけ伝える。
   見本の応答で動いたように見せない。音声と Web の調べものも同じ。
2. **見本の応答（スタブ）は、自動テストの中だけで使う。** 単体テストと通しの確認（smoke）のために、明示の設定（`LLM_PROVIDER=stub`）のときだけ使う。
   利用者の画面・利用者向けの文書・拡張機能の書き方には出さない。
3. **開発の見本の会社も、本物の推論で動かす**（開発者の Gemini の鍵、または会社の鍵）。
4. 仕様書・開発者マニュアル・ヘルプから「鍵が無い環境」の説明を消す。拡張機能の評価のケースは、品質の確認（入力と期待する結果）のために残す。

## 理由

- 推論の無い M2Office は、何の価値も出さない。動いたように見せると、評価も判断も誤らせる
- 拡張機能を作る人の手間（見本の答えを書く）は、鍵が無い環境のためだけのもので、要らない

## 影響

- `LLM_PROVIDER` の既定を `gemini` にする。`stub` は自動テスト専用
- 運営の鍵も会社の鍵も無い会社では、秘書・業務・音声・調べものが「設定されていません」と答える
- ADR-0003 の「LLM の準備が整う前も全体を動かせるようにする」のうち、LLM の部分を改める（Google の見本の接続口は変えない）
