# ADR-0004 文書形式を扱うライブラリの選定

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-22 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第9.4.1節、第9.4.2節、第20.8節、付録 B.5.3 |

## 背景

仕様書 第9.4.1節で、PDF・Excel・CSV・Word を扱う共通ツールを定めた。
参考にした公開スキルの文書形式の実装は source-available であり取り込めない（第9.4.2節）。
自前で用意するにあたり、形式の解析は自作せず、実績のあるライブラリを使う（第20.8節）。

## 決定

| 用途 | ライブラリ | 版 | ライセンス |
|---|---|---|---|
| Excel の読み書き（`sheet.read`・`sheet.render`） | exceljs | 4.4.0 | MIT |
| PDF の文字の取り出し（`pdf.extract`） | pdfjs-dist（Mozilla の pdf.js） | 6.3.289 | Apache-2.0 |
| Word の出力（`docx.render`） | docx | 9.7.1 | MIT |

CSV の解析と Shift_JIS の判定は自作する。規則が短く（RFC 4180）、
Node.js の `TextDecoder` が Shift_JIS を扱えるため、パッケージを増やすほどではない（第20.8節 第 2 項）。

## 検討した点

| 項目 | 内容 |
|---|---|
| exceljs の依存 | `uuid@8` に既知の注意喚起（中程度）がある。exceljs は該当する使い方をしていないが、`overrides` で `uuid@11.1.1` に差し替え、`npm audit` の指摘を 0 件にした。読み書きの往復はテストで確認している |
| SheetJS（`xlsx`） | npm の公開版が古く、既知の脆弱性がある。最新版は独自の配布先からの取得になり、ロックファイルでの版固定（第20.8節 第 1 項）と相性が悪い |
| pdf.js の実行 | Node.js では `legacy` 版を使う。文書の中の JavaScript は実行しない（pdf.js は評価を行わない）。書体は読み込まない設定にしている |
| PDF の部首の文字 | 書体によっては「金」が部首の「⾦」として取り出される。この範囲の文字だけを通常の漢字に直す（全角の括弧や数字は変えない） |

## 見送ったもの

**`pdf.render`（帳票の PDF 出力）は今回は実装しない。**

日本語の PDF を作るには、日本語の書体をファイルに埋め込む必要がある。
どの書体を使うか（Noto Sans JP・IPAex など。いずれも再配布可能）、リポジトリに同梱するか、
帳票のひな形とどう組み合わせるかは、帳票の体裁（Q-57）とあわせて決める必要がある。
これを Q-59 とした。AG-06（請求書）・AG-07（見積書）は Phase 2 のため、今は止まらない。

## 影響

- ファイルの中身はテナントごとの置き場に保存し、メタデータ（SHA-256 を含む）をデータベースに持つ。
  開発ではリポジトリ直下の `.data/files`、本番はオブジェクトストレージに差し替える
- エージェントが読めるのは、依頼した本人のファイルだけである
