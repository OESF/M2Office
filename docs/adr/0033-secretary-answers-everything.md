# ADR-0033 秘書はあらゆる依頼に応え、専門の業務は頼んで実行して報告する

| 項目 | 内容 |

| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第10.9.6節・第10.9.7節・第10.10.3節・第10.11節。ADR-0028（AI に任せる） |

## 背景

「10 月 1 日の 10 時から 15 時まで大阪の道頓堀の近くで会議がある。東京から日帰りで、新幹線の時刻を含めた行程を教えて」という、よくある依頼に秘書が答えられなかった。
秘書の対話（層 3）は推論 1 回だけで、Web も本人の予定も見ないため、答えないか、時刻をそれらしく作るしかなかった。

また、専門の業務に当たる依頼では「〇〇で対応できます。実行してよろしいですか」と本人に確かめ、画面の入力欄を埋めてもらう作りだった。
三浦さんの方針: 秘書は利用者のあらゆるニーズに応えなければならない。専門的な業務なら、中にあるエージェントにお願いして実行し、その結果をユーザーに報告する。

## 決定

1. **専門の業務は、秘書が入力を埋めて頼んで実行し、結果を報告する。** 本人に実行の可否を聞かない。埋められない必須の入力だけを聞く。
   社外への送信とお金の確定は、頼んだ業務の承認ゲートで止まる（ADR-0028 の境界はそのまま）。
2. **外の最新の情報や本人の予定が要る依頼は、秘書の調べものに回す。** 調べものに Web の調べもの（Google 検索）と、予定・空き・ToDo を読む道具を持たせる。読むだけに限る点は変えない。
3. 頼んだ業務の結果も、調べものと同じ経路（秘書バーの処理中の表示・秘書の答え・持ち越し）で伝え、会話ログに残す。
4. 本人のカレンダーに入れる公式の業務「予定の登録」を置く。秘書に「カレンダーに入れて」と頼めば、それに頼む。

## 理由

- 新しい仕組みを作らずに、既存の「重い依頼を後ろへ回す」経路（第10.11節）とジョブ・実行・承認ゲートに載せられる。監査・費用・中止・テナント境界がそのまま効く。
- 「実行してよろしいですか」は、社外にもお金にも関わらない仕事にまで人の判断を求めていた（ADR-0028 に反する）。
- 時刻表などを推論の記憶で答えさせると作り話になる。調べた結果に出典を添え、目安と明示する。

## 影響

- 秘書の返事は「〇〇に頼みました。終わったらお伝えします」になり、結果はあとから届く。
- 乗換案内の API（駅すぱあと Web サービス・NAVITIME など）は使わず、まず Google 検索で調べる。時刻の正確さが足りなければ、道具を差し替える。
- 切符の購入・予約・支払いはしない。
