# ADR-0117: 体験版を、紹介のページから自分で申し込めるようにする

- 状態: 採用（第 0.488.0 版）
- 日付: 2026-10-29
- 関係: 仕様書 第23.3.1節・第23.3.2節、Q-289、ADR-0115（体験版）、ADR-0028（AI に任せる）

## 背景

体験版（ADR-0115）は、運営者がマスター管理画面でゲストの ID とパスワードを出し、自分のメールで相手に送る形で作った。紹介のページ（`m2office.net`）を公開したので、三浦さんが、**ページを見た人が簡単な入力だけで体験版を使い始められる**形を求めた。

誰でも申し込めるようになると、AI の費用（1 件で推定 1,000 円まで）と体験用の会社を、機械的に何度も作られるおそれがある。M2Office には運営のメールを送る仕組みが無いので、メールアドレスが本物かは確かめられない。

## 決定

1. **申し込みの画面は、紹介のページではなく体験版の入口（`demo.m2office.net/start`）に置く。** 紹介のページは静的なサイトのまま、個人の情報を集めない（第23.3.1節）。紹介のページはボタンを置くだけにする。
2. **入れるのは会社名・お名前・メールアドレスと規約への同意だけ。** 送ると、その場で体験用の会社を作り、ログインした状態で始める。次に入るための ID とパスワードは、その画面に 1 度だけ出す（三浦さんが決めた。メールでは送らない）。
3. **同じ人が使える体験は 1 つだけ**（三浦さんが決めた）。
   - 同じメールアドレス（そろえた形）は一度だけ申し込める。終えた後も、もう一度は申し込めない。
   - 相手の情報を 90 日で消した後も比べられるよう、運営の秘密を混ぜたハッシュだけを残す。
   - メールアドレスは確かめないので、同じ送り元のアドレスからは 24 時間に 1 件までにする。
4. **ロボットよけは、計算を求める方式を M2Office の中に持つ。** ALTCHA と同じ仕組みで、外の部品やサービスは使わない（Turnstile は Cloudflare のアカウントが要るためやめた。第23.3.1節）。
5. **費用の歯止めを 2 つ重ねる。** 自分で申し込む体験は 1 日 20 件まで。体験版全体の AI の利用がその月の上限（既定 20,000 円）に達したら、新しい申し込みを止める。どちらもマスター管理画面の「設定」で変えられる。
6. **体験用の会社を作るのは、データベースの決めた関数だけにする。** アプリのロールに渡すのは「既定の日数と上限で、体験用の会社を 1 つ作る」関数だけで、顧客の会社は作れない。上の歯止めはすべて、この関数の中で見る。
7. 運営者が出す体験（ADR-0115）は残す。営業の場で相手に合わせて日数や上限を変えたいときに使う。

## 理由

- メールで ID やリンクを送るには、運営のメールを送る仕組み（中継のサービス・送信元の認証の設定）が新しく要る。画面に出せば、いまある仕組みだけで作れ、相手も待たずに始められる。
- メールアドレスを確かめない分、送り元のアドレス・1 日の数・全体の月の上限で費用の上限を決めておけば、悪用されても損は月の上限で止まる。
- 体験用の会社を作る力をアプリのロールに渡すのは、ADR-0115 で決めた「アプリは決めた関数だけを使う」形の延長で、体験用の会社の印（`d-` と `kind = 'demo'`）と、表の仕掛けによる制限（1 社 1 人・接続の設定なし・500 MB）がそのまま効く。

## 影響

- 紹介のページに「無料で試す」のボタンを置き、プライバシーの方針に、集める情報（会社名・お名前・メールアドレス・送り元のアドレス）と持つ期間を書き足す（`M2Office-site` の側の作業）。
- 申し込んだ人のメールアドレスが本物とは限らない。営業の連絡に使うときは、そのことを前提にする。
- 同じ会社の別の人が試したいときは、運営者が出す体験を使う。
