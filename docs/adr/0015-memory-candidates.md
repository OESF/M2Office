# ADR-0015 対話からの学習は、候補を示して本人が採る

| 項目 | 内容 |
|---|---|
| 状態 | 採用（Q-23 を決定） |
| 決定日 | 2026-09-23 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第11.2節、第11.5節、第11.5.1節、第11.5.2節、第11.9.6節、ADR-0012、ADR-0014 |

## 背景

個人記憶は、本人が「覚えておいて」と頼んだときだけ覚えていた（ADR-0012）。
それだけでは、頼むことを思いつかない事柄が残らない。第11.9.6節の圧縮も、
「4 週を過ぎた逐語を、要約と抽出済みの事実に置き換える」と定めているが、その要約と抽出が無かった。

対話から自動で覚える形にすると、今度は「何を覚えているか分からない」状態に近づく。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | 対話からは**候補を作るだけ**にし、本人が「覚える」を押したものだけを記憶にする（Q-23） | 覚えたものが必ず本人の目を通る。ADR-0012 で置いた「見える化」を崩さずに、蓄積を増やせる |
| 2 | 候補を作る仕組みは**既定で有効**とする | 候補は記憶ではない。採るかどうかは本人が決めるため、既定で作っても不意打ちにならない |
| 3 | **1 日 1 回、前日ぶんをまとめて**作る | 推論の費用がかかる（第11.9.6節 注意点 5）。会話のたびに呼ぶと、対話の応答も遅くなる |
| 4 | あわせて**その日の会話の要約**を作り、長期に持つ | 逐語は 4 週で消える（ADR-0014）。消えた後に「先週こう言ったはず」に答えられるのは要約だけである |
| 5 | 要約は 4 週を待たず、**その日のうちに**作る | 4 週後に作ろうとすると、その時点で推論が使えない・鍵が変わったといった事情で作れず、逐語だけが消える恐れがある |
| 6 | 「不要」を押した候補は残し、**同じ文を再び候補にしない** | 毎晩同じ候補が並ぶと、本人が見なくなる |
| 7 | 推論が使えない環境（鍵が無い・見本の応答）では**候補を作らない** | それらしい誤った事実を記憶の候補にしない（第12.9.4節と同じ考え方） |
| 8 | 監査ログには件数だけを残す | 記憶と会話の中身を監査ログに入れない（ADR-0012・ADR-0014 と同じ） |

## 検討した点

| 案 | 採らなかった理由 |
|---|---|
| 対話から自動で覚える（候補を挟まない） | 「何を覚えているか分からない AI」に近づく。第11.5節の前提が崩れる |
| 既定を切にして、本人が入れる | 候補を作るだけなら害が小さく、既定で切ると多くの人が使わないまま終わる |
| 会話のたびに候補を作る | 応答が遅くなり、費用も増える。1 日 1 回で足りる |
| 要約を 4 週後（圧縮のとき）に作る | 決定 5 の理由。逐語が消えた後に作り直すことはできない |
| 候補を秘書が会話の中で提案する | 対話の流れを止める。一覧でまとめて見て、まとめて採るほうが早い |
