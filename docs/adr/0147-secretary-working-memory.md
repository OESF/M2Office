# ADR-0147 秘書の入口で話の流れを使い、1 週間の記憶をしっかり持つ

| 関連 | 仕様書 第10.7.3節・第10.7.4節・第10.9節・第11.9.6節・第11.13節。Q-363〜Q-367。ADR-0027（秘書は本人のことを覚え続ける）・ADR-0028（AI に任せる） |

## 背景

2026-11-14 に三浦さんが、業務の数が増えて秘書がどの道具を呼べばよいか分からなくなっていると示した。「三浦皮膚科クリニックのメールを探して」に未読の件数を答え、見つけたメールにはリンクが無かった。調べると、秘書は会話・要約・覚えた事実を持ち、自分で答えるときには使っていた。ところが、依頼を振り分ける入口（決め打ちの決まりと、業務を選ぶ推論）と業務への依頼は、その 1 文か今日の数回しか見ていなかった。今日の 9 回より前は 1 日 600 字の要約でしか見えず、日付で振り返る仕組みも無かった。三浦さんは、その都度忘れていては秘書はずっと新入社員のままであり、少なくとも 1 週間分の記憶をしっかり持ち、長くなれば圧縮するよう求めた。

## 決定

1. **記憶を 3 つの層で持つ。** いまの状況（直近の逐語・今日の要約・話に出たもの・開いている画面）、1 週間の記憶（日ごとの記録と業務の記録すべて）、長い記憶（いまのまま）。
2. **すべての段で使う。** 続きの見分けを決め打ちより先に行い、層 2 と業務への依頼にも、いまの状況を渡す。
3. **話に出たものは、決まりで拾う。** ツールの結果と画面の操作から、種類・ID・リンクを持つ。推論の文からは作らない。
4. **日付で振り返る。** 「月曜日」などを日付に直し、その日の記録を先に渡す。
5. **長くなれば畳む。** 予算を置き、古いものから要約に畳む。話に出たもの・数・日付・決まったことは落とさない。
6. **測ってから直す。** 続きの頼みを含む問題集で、直す前と後を本物の推論で測る。

## 理由

- 秘書の価値は、本人の仕事の流れを分かっていることにある（ADR-0027）。入口が流れを見なければ、覚えていても使えない
- 話に出たものを ID とリンクで持てば、「さっきのメール」をたどれる。推論の文から拾うと取り違える
- 1 日 600 字の要約では、忙しい日の細部が落ちる。1 週間は逐語（28 日残している）から作り直せる
- 機能を足すたびに決め打ちの決まりが増え、互いに当たって取り違える。1 か所にまとめ、流れを先に見る

## 影響

- 推論の入力が増え、会社の AI の費用が増える（実測で予算を直す）
- 秘書の入口の作りが変わる。続きの頼みの問題集を、これからの直しの守りにする

## 実装（第 0.584.0 版）

- いまの状況と 1 週間の記憶は `packages/core/src/secretary/working-memory.ts`、決め打ちの決まりの表は `secretary/fixed-rules.ts`
- 話に出たものは会話ログの列 `mentions`（移行 `207_conversation_mentions.sql`）。今日の要約は、いまの会話の要約（第11.9.6節）をそのまま使い、日ごとの記録は推論を使わずに作る
- 開いている画面は、画面が種類と ID を添え、API が本人に見える題名だけを引く
- 問題集は `docs/evals/secretary-follow-up/cases.json`（100 問）、測り方は `npm run eval:secretary-follow-up`。本物の推論での測定はまだ（鍵が無い）
- 2026-11-14 の測定（会社の鍵）: 直す前 63・直した後 81／100。外れた型（開いている資料の中身や無いメールを作る・覚えているリンクを出さない・振り返りで頼み直す）を第 0.584.1 版で直した。直した後の測り直しは 96／100 で、目安（9 割）を満たした
