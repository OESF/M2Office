# ADR-0096: 権限区画に属する業務の承認と閲覧を、区画に入っている人に限る

- 状態: 採用
- 日付: 2026-10-15
- 関係: 仕様書 第9.2.3節・第6.2.3節・第16.3.6節・第16.9節（第 0.366.0 版）、ADR-0028

## 背景

2026-10-12 の点検で、承認者の役割を持つ人が、権限区画の外にいても区画の業務（給与・評価など）の承認を判断でき、
その実行の中身（ステップの入力と出力・成果物）を見られることが分かった。区画は機微なデータを隔てるためのもので、
承認の役割を通して区画の外へ中身が出るのは、区画の目的に反する。実行を進めるときの依頼した人の区画の確かめ直しは、すでに入っていた。

## 決定

- 区画に属する業務の承認は、`approver_role` のロールを持ち、**かつ区画に入っている者だけ**が判断できる。管理者の承認を加える段も同じ。
  依頼した本人の承認（`approver: requester`）は、本人が区画に入っているので変えない。
- 実行の中身を見られる承認者も同じ範囲に限る。区画を出たら、前に判断した実行も見られない。
- 承認は作ったときに業務の区画を持つ（`approvals.compartment`。移行 138）。判断のときは、業務の定義の区画でも確かめ直す。
  移行より前の承認は、ワーカーが起動のあと業務の定義から一度だけ埋める。
- 判定は `canDecide`（`packages/shared`）の 1 か所に置き、区画を渡さない呼び出しでは区画の承認を判断させない（外す側に倒さない）。
- 区画の中に判断できる人がいなければ、承認待ちのまま気づかれずに止まらないよう、依頼した本人に知らせる。

## 理由と、採らなかった案

- 承認の役割だけで判断させ、中身を伏せる案は採らなかった。中身を見ずに承認することになり、承認の意味が無い。
- 区画に入っていない承認者がいたら、自動で管理者に回す案も採らなかった。管理者も区画の外なら同じ問題が起きる。
  区画の割り当ては管理者が決めることなので、依頼した本人に知らせて割り当てを頼んでもらう。

## 影響

- 区画の業務に、区画の外の承認者だけを当てていた会社では、承認が進まなくなる。依頼した人に知らせが届くので、管理者が承認する人を区画に入れる。
- 業務の定義が見つからない（削除した）業務の古い承認は、区画を埋めずに残す。
