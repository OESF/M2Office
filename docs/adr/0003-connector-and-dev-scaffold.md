# ADR-0003 外部接続の手前に接続口を設け、未接続の間はダミーで骨格を作る

## 背景

Google Cloud の OAuth クライアント（B-2）と Gemini の鍵（B-3）は、社内の申請を経て用意する。
用意できるまでの間も、メール・予定・タスクを使うエージェント（AG-01・AG-03・AG-05）、
定時実行、ログインの仕組みを先に作っておきたい。

一方で、仕様書 第24.2節 第 6 項は「ツール層を Google 非依存のインターフェースにする」ことを
Phase 1 で守るべき制約としている。

## 決定

**1. ツールと Google の API の間に接続口（`WorkspaceConnector`）を置く。**

ツールは接続口だけを呼び、Google の API を直接呼ばない。
接続口には 2 つの実装を用意する。

| 実装 | 内容 | 選び方 |
|---|---|---|
| `mock` | 実行した日を基準にしたダミーデータを返す。書き込みはプロセスの記憶に残すだけで外へ出ない | `CONNECTOR_MODE=mock`（開発の既定） |
| `google` | Google Workspace に接続する。B-2 の完了後に実装する | `CONNECTOR_MODE=google` |

**2. ダミーの値は、本物と取り違えられないように扱う。**

| 場所 | 扱い |
|---|---|
| ツールの戻り値 | すべてに `source: 'mock'` を含める |
| 秘書の即答 | 根拠の 1 行目に「ダミーデータ（Google 未接続）」と出す |
| 画面 | 上部に「ダミーデータで動作中」と常に表示する |
| 管理者ページ | 接続の状態に「ダミーデータで動作中」と出す |
| 起動 | `google` を指定して未実装なら、黙ってダミーに切り替えず起動を止める |

**3. ログインは「本人の確認」と「ログイン状態の発行」の 2 段に分ける。**

ログイン状態（HttpOnly の Cookie とデータベース上の記録）は手段によらず共通とし、
本人の確認の手段だけを差し替える。Google ログインが使えるまでは、
利用者を選ぶだけの**開発用ログイン**で骨格を動かす。

| 設定 | 内容 |
|---|---|
| `AUTH_DEV_LOGIN` | 開発用ログインを許す |
| `AUTH_DEV_HEADERS` | `X-Tenant`・`X-User` ヘッダーでの指定を許す（動作確認のスクリプト用） |

**どちらも `NODE_ENV=production` で有効にすると起動を拒否する。**
誤って公開されると、誰でも誰にでもなれるためである。

## 理由

| 観点 | 内容 |
|---|---|
| 待たずに進められる | エージェント・定時実行・通知・ログイン・管理者ページの骨格を、申請の完了前に作れる |
| 仕様の制約と一致する | 接続口は第24.2節 第 6 項がもともと求めているもの。ダミーのために作る部品ではない |
| 差し替えが局所で済む | B-2 の完了後に `google` 実装を足すだけで、ツール・エージェント・画面は変わらない |
| 動作確認が安定する | ダミーは決まった値を返すため、通しの確認（`npm run smoke`）が外部の状態に左右されない |

## 却下した案

| 案 | 却下した理由 |
|---|---|
| B-2 の完了を待つ | 数週間止まる。接続口はいずれ必要になる |
| ツールの中で `if (mock)` と分岐する | ツールごとに分岐が散らばり、Google 以外への対応（第14.5節）の妨げになる |
| ダミーの値に印を付けない | 画面で本物と区別できず、「取得に失敗した値を推測で埋めない」（開発規約）の趣旨に反する |

## 影響

- API とワーカーは別のプロセスであり、ダミーの書き込みは互いに見えない。
  AG-02 で起票したタスクが、秘書の「今日のタスク」に出ないのはこのためで、不具合ではない
- `google` 実装の追加時は、同じ通しの確認（`npm run smoke`）がそのまま通ることを完了の条件とする
