# ADR-0092 Google Workspace のログインの記録を、不正の兆しの見張りに取り込む

## 背景

- M2Office へのログインは Google のアカウントで行う。Google のアカウントが乗っ取られれば、M2Office にも入られる。
- 段 1・段 2 の見張り（ADR-0091）は M2Office の中の記録（監査ログ・ログイン中の端末）しか見ない。Google の側で起きた異変（不審なログイン、乗っ取りの疑いによるアカウントの停止、社外へのメールの自動転送）は見えない。
- Google Workspace は、ログインの記録を Admin SDK の Reports API（`applicationName=login`）で読ませる。権限は `admin.reports.audit.readonly`、反映は数分の遅れ、保存は 6 か月。記録には接続元の IP が入っている（2026 年 10 月時点の Google の文書で確かめた）。
- 第16.8.1節と第6.7.10節は、IP と場所を持たないこと・1 人ずつのログインの時刻を集めないことを決めている。

## 検討した案

| 論点 | 案（提案） | 採らなかった案 |
|---|---|---|
| 材料 | **Reports API のログインの記録** | 管理コンソールのアラート（アラートセンター API）を読む（使えるエディションの条件を確かめておらず、M2Office の中の兆しとの重なりを判断する細かさが無い） |
| 取り込む範囲 | **Google が異変と判断したものと、乗っ取りの後によく行われる操作だけ**（Q-222） | ログインの成功を全部取り込む（1 人ずつのログインの時刻を集めることになり、第6.7.10節に反する） |
| IP | **読んだらすぐ捨てる**（Q-223） | IP を残し、場所を推定する（第16.8.1節に反する。どこからかは Google の管理コンソールで見られる） |
| 誰の許可か | **担当の管理者の、本人の接続とは別の Google の許可**（Q-224。第34章と同じ形） | 会社の全員の接続に権限を足す（Google の管理者しか許可できない権限のため成り立たない）。ドメイン全体の委任（サービスアカウントの鍵を預かることになり、漏れたときの害が大きい） |
| 読み方 | **5 分ごとの見回りで、続きから読む** | Google から押して知らせる形（`activities.watch`。受け口の公開が要り、ローカルの形では受けられない） |
| 乗っ取りの判断が出たとき | **Google がアカウントを止めたら、すぐに M2Office の端末もログアウトさせる**（Q-225） | 重なりを待つ（Google がすでに乗っ取りと判断しており、待つ理由が無い） |
| 対象の人 | **M2Office の利用者だけ**（Q-226） | ドメインの全員（M2Office を使っていない人は M2Office のデータに届かない。Google から管理者への知らせと二重になる） |

## 決定

1. Google Workspace のログインの記録を、担当の管理者の別の Google の許可で、5 分ごとに読む。
2. 取り込むのは第16.8.6.2節の表のできごとだけ。ふだんのログインの成功・ログアウトは取り込まない。
3. IP は読んだらすぐ捨て、Google の記録そのものは写さない。兆しには、できごとの種類・対象の人・時刻・記録の番号だけを残す。
4. Google が乗っ取りやパスワードの漏洩でアカウントを止めたら、その人の M2Office の端末をすぐにすべてログアウトさせる。ほかの Google の異変は、自動のログアウトのまとまりに「Google」として足す。
5. 対象は M2Office の利用者だけ。

## 結果

- 良い点: Google のアカウントの乗っ取りの兆しを、M2Office の中の持ち出し・権限の変化と重ねて判断できる。IP と 1 人ずつのログインの時刻を持たない境界は変えない。
- 悪い点: Google の管理者である担当が接続しないと動かない。読み取りの権限の段階によっては、一般公開のときに Google の審査が要る（TBD）。数分の遅れがある。
