# ADR-0098: システムログをデータベースにも書き、形ごとに見せ、証拠を保全する

- 状態: 採用（第 0.371.0 版で実装）
- 日付: 2026-10-16
- 関係: 仕様書 第16.10節・第8.6.7節・第23.8節・第11.9.6節（第 0.370.0 版）、開発規約 第7章、ADR-0078・ADR-0091

## 背景

三浦さんが、ローカルの形では会社の管理者が、クラウドの形では運営が、システムログを画面で見てダウンロードできること、
ログの入れ替えができていない問題を直すこと、サイバー攻撃などにあったときに証拠を保全できることを求めた（2026-10-16）。

それまでのシステムログは標準出力へ書くだけだった。ローカルの形では launchd がファイルに書き足すだけで入れ替えず（4 週の決まりに反していた）、
クラウドの形では置き場が決まっていなかった。どちらの形でも、画面から見る手段が無かった。

## 決定

1. **アプリがシステムログをデータベースにも書く**（日ごとに区切った表 `system_logs`。2 秒ごとにまとめて書く）。標準出力への書き出しは続ける。
2. 入れ替えは、データベースは 28 日を過ぎた区切りを捨てる。ローカルの形の標準出力のファイルは、週に 1 回の launchd の仕事で写して空にして 4 世代を残す
   （launchd が追記で開いたままのため、名前を変えると書き込みが古いファイルに続く。macOS の newsyslog には写して空にする指定が無い）。入口のアクセスログは Caddy で 28 日。
3. 日ごとに SHA-256 を作って前の日の値とつなげ（鎖）、追記だけの表に残す。書き換え・削除が分かるようにする。
4. ローカルの形は会社の管理者が管理者ページの「機械」で、クラウドの形は運営がマスター管理画面で、見てダウンロードする。見たことは記録に残す。
5. 証拠保全は、範囲のシステムログ・監査ログ・不正の兆し・端末の一覧・改ざんの確かめの値（ローカルの形は機械のログのファイルも）を 1 つの ZIP にし、
   ファイルごとと全体の SHA-256 を残す。1 年は誰も消せない。不正の兆しの見張りが自動でログアウトさせたときは自動で保全する。

## 採らなかった案

- **機械のファイルだけで持つ**: クラウドの形は台数が増えうるため、運営が全体を見られない。
- **外のログの仕組み（クラウドの事業者のもの）に任せる**: 事業者がまだ決まっておらず（Q-10）、ローカルの形で使えない。決まったら、標準出力から送るのは別に足せる。
- **保全のときにログを消さないように止める（入れ替えを止める）**: 止めている間に容量が増え続ける。写して ZIP にするほうが、後から変わっていないことも示せる。

## 影響

- データベースに書く量が増える（1 日に要求の数ほどの行）。28 日で捨てるので、上限はおよそ 28 日分。
- 移行で、表・区切り・関数・ロールの権限を足す。ローカルの形のセットアップと更新で、入れ替えの launchd の仕事を入れる。
