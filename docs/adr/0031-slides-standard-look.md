# ADR-0031 Google スライドは、テンプレートのファイルを使わずに標準の見た目で組み立てる

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-09-26 に三浦さんの依頼で実装） |
| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第9.4.2節「標準の見た目」・第9.3.2節・第14.3.4節・Q-88。ADR-0006（組み立て方を補う） |

## 背景

`slides.create` は、構成の検証と成果物の記録までできていたが、Google スライドを作る部分は「準備中」のままだった。
AI Radio の作り方（ADR-0006）は、見本のスライドを並べたテンプレートのファイルを**複製**して差し込む。
しかし M2Office が求める Google の権限は `drive.file` だけで、M2Office が作っていないファイル（会社が登録したテンプレート、
運営が用意した見本のファイル）は開けない。複製の元が読めないため、AI Radio の作り方はそのままでは使えない。

## 決定

1. **テンプレートのファイルを使わない。** Slides API で空のプレゼンテーションを作り、レイアウトごとに決めた位置へ図形と文字を置く。
   M2Office が作ったファイルしか触らないため、権限は `drive.file` のままでよい（求める権限を増やさない＝再同意が要らない）。
2. 置き方（位置・色・文字の大きさ）はコードに持つ。LLM は内容と構成だけを決める（ADR-0006 の考え方は変えない）。
3. `drive.file` ではスプレッドシートのグラフをスライドに貼れないため、`CHART` は**表**で示す。画像の生成も後の段階とし、`IMAGE` は説明だけを出す。
4. 会社が登録したテンプレートは、読む権限を決めるまで使わない（Q-88）。登録があっても標準の見た目で作り、結果と成果物にそのことを書く。
5. 組み立てに失敗したら、作りかけのファイルをごみ箱に移す（消しはしない）。空のスライドを本人のドライブに残さない。

## 理由

- 権限を増やすと、すでに接続した全員に再同意を求めることになる。まず今の権限で作れる範囲を本物にする。
- 見た目がコードに固定される代わりに、作るたびに見た目がばらつかない（ADR-0006 の狙いと同じ）。
- 会社のテンプレートは、`presentations.readonly` を足すか、Google の選択画面（Picker）で本人に選ばせるかで道が分かれる。どちらも手間と権限の兼ね合いがあり、別に決める。

## 影響

- Google と接続した会社では、「スライド作成」で本人のドライブに Google スライドができ、PowerPoint 形式のリンクも返る。
- 管理者ページで登録したテンプレートは、Q-88 が決まるまで見た目に効かない（ヘルプ「スライドのテンプレート」に書いた）。
- 会社の Google Cloud で Slides API を有効にしておく必要がある（`docs/google-setup.md` の手順 2 に含まれる）。
