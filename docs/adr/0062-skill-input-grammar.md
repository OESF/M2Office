# ADR-0062 スキルの入力の欄の書き方を、型と属性の文法として先に固める

| 項目 | 内容 |
|---|---|
| 状態 | 採用。文法と `text`・`textarea`・`date`・`file`・任意の印・`@placeholder` を仕様書 第 0.214.0 版で実装。`select`・`radio`・`checkbox`・`@label`・`@default` は文法だけ決め、未実装（2026-10-01。三浦さん「定義だけはアーキテクチャ的に綺麗である必要がある。将来的にはラベルや select / option、チェックボックス、ラジオボタン等も定義できる綺麗な構造にしておきたい。そうしないと、あとから欲しくなったときに作ってきたスキルを全部変更しなければならなくなる」） |
| 決定日 | 2026-10-01 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第12.12.3節・第12.12.3.1節・第12.12.5節・第6.10.4.1節。ADR-0029（スキルの形式で書く）・ADR-0028（AI に任せる） |

## 背景

- スキル（SKILL.md）の入力の欄は、`metadata.m2office-inputs` に 1 行ずつ書く。第 0.211.0 版で `欄の名前: 型`（`text`・`textarea`・`date`・`file`）と任意の印 `?`、型の後ろの `"…"`（欄の例）にした。
- この書き方は、いま使う型だけを足し合わせてできている。選ぶ欄（`select` と `option`・ラジオボタン）やチェックボックス、見出し（ラベル）を後から足すとき、どこにどう書くかが決まっていない。
- 足すたびに書き方を変えると、それまでに作ったスキルを書き直すことになる。

## 検討した案

| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| A. 入れ子の YAML（欄ごとに `type:`・`options:`・`label:`） | 項目を YAML の構造で書く | 読みやすい。JSON Schema に近い | **`metadata` の値は文字だけ**という Agent Skills の決まりに反し、ほかの道具（Claude Code など）でスキルとして読めなくなる |
| B. JSON Schema を文字のまま書く | `m2office-inputs` に JSON を入れる | 何でも書ける | 書く人に重い。1 欄に数行かかり、間違いやすい |
| C. いまの 1 行の形に、思いついた記号を足していく | `"…"` の後ろにさらに記号を足す | 変更が少ない | 足すたびに意味の衝突が起き、文法として説明できない |
| **D. 1 行の文法を決める: `欄の名前[?]: 型[(選択肢…)] @属性(値…)…`** | 型の注釈（TypeScript）と属性（Prisma のスキーマの `@default(…)`）に倣う。型と属性は呼び出しの形で、値は `"…"` | 1 行で書ける。型と属性を足しても文法が変わらない。エンジニアが見慣れた形 | 文法を読む部品を持つ（小さい） |

## 決定

1. **案 D をとる。** 文法は EBNF で仕様書に書く（第12.12.3.1節）。型は HTML の部品の名前（`text`・`textarea`・`date`・`file`・`select`・`radio`・`checkbox`）、属性は `@label`・`@placeholder`・`@default`。
2. **型と属性ごとに、中の定義（JSON Schema）と本文の `$欄の名前` に入る値を決めておく。** 選択肢は `enum`、チェックボックスの組は文字の配列、チェックボックス 1 つは真か偽（本文には「はい」「いいえ」）。
3. **実装は型ごとに進める。** 文法にあってまだ実装していない型と属性は、取り込まずに「この版ではまだ使えません」と知らせる（作った人が、動かない欄に気づけるように）。実装しても書き方は変わらない。
4. **知らない属性は無視して知らせる。** 新しい版のスキルを古い M2Office に入れても、欄は出る。知らない型は取り込まない（どう出すかを決められないため）。
5. 第 0.211.0 版の型の後ろの `"…"` は `@placeholder("…")` と同じとして読み続ける。日本語の型と「（任意）」も読み続ける。文書には新しい形だけを書く。
6. 欄ごとの説明の属性は持たない（原則 u11）。要るときは `@placeholder` の例で示す。

## 理由

- `metadata` を文字のまま保てば、SKILL.md はほかの道具でもスキルとして読める（ADR-0029 の「スキルの形式で書く」を崩さない）。
- 型と属性を呼び出しの形にそろえると、`select("内科", "外科")` も `@default("内科")` も同じ読み方で読め、足すものが増えても文法は変わらない。
- まだ使えない型を「知らない型」と同じに扱うと、実装したときに古い M2Office との差が分からない。文法に場所を決めて「まだ使えない」と言い分けることで、書く人も読む部品も迷わない。
- 選ぶ欄を秘書が埋めるときは、選択肢のどれかを推論が選ぶ。人に選び直させる手間を増やさない（ADR-0028）。

## 影響

- 仕様書 第12.12.3節の `m2office-inputs` の行を、第12.12.3.1節（文法・型・属性・決まり）への参照にした。
- 読み取り（`packages/core/src/extensions/skill.ts`）を文法どおりに読む形に書き直した。`#` の行は注釈。同じ名前の欄は読めないと知らせる。
- 開発者マニュアル（第3章・第6章）を、新しい書き方と実装の状況に合わせた。
- 画面のフォームは、いまは 1 行・複数行・日付・ファイルだけを出す。`select` などを実装するときは、フォームの部品と、秘書が値を選ぶ決まり、実行の前に選択肢に無い値を断る確かめを足す。
