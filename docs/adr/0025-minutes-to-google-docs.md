# ADR-0025 議事録を Google ドキュメントにも保存し、承認②のあとに会社の全員が閲覧できるようにする

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-25 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第9.5.2節、第9.4.4節、第14.3.4節「ドライブ」、ADR-0010、ADR-0023 |

## 背景

議事録作成（AG-02）は、議事録を M2Office の成果物と組織知識に残し、Chat に本文を投稿していた。
会議の参加者が普段使う Google ドキュメントには残らず、あとから開いたり書き足したりできなかった。
ドライブとドキュメントを本物の Google につないだ（第 0.109.0 版）ので、議事録をそこにも保存できるようになった。

ただし、作った文書は共有しないのが既定である。Chat に文書のリンクを載せても、スペースの人は開けない。

## 決定

**1. 承認①で確かめた議事録を、そのまま Google ドキュメントに保存する。**

`docs.create` に成果物の ID（`artifactId`）を渡し、本文は成果物から取る。推論に書き直させない。
組織知識への登録（ADR-0010）と同じく、最初の承認で止めた時点にあった成果物だけを保存できる。

**2. 保存は承認②の画面を作るとき、共有は承認②のあと。**

保存（`draft`）は承認の前の組み立て（ADR-0023）で行い、承認②の画面に文書とリンクを出す。
承認①の前には作らないので、却下された内容の文書は残らない。
会社の全員への閲覧の共有（`drive.share_company`、`write-internal`）は記録だけして、承認②のあとに行う。

**3. 共有の範囲は「会社の全員が閲覧できる」。**

会社のドメインの人だけが、リンクから閲覧できる。検索には出さない。社外は見られない。
承認②は、もともと議事録を組織知識に登録すること、すなわち社内全体への共有を認める承認であり、範囲が同じである。

**4. 保存に失敗しても業務は止めない。**

議事録は M2Office の成果物と組織知識に残る。承認②の画面に理由を出し、投稿にはリンクを添えない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 共有しない（本人のドライブに残すだけ） | Chat のリンクが開けず、参加者に届かない |
| スペースのメンバーだけに共有する | メンバーの一覧を読む許可が増える。社外のメンバーがいれば社外にも共有される。作りが重い |
| 「リンクを知っている全員」への公開 | 社外にも出る。第9.4.4節で作らないと決めている |

## 結果

- 議事録作成が `drive.file` を求めるようになる。まだ許可していない人は、一度だけ接続し直しが要る
- 個人向けの Google アカウント（`gmail.com` など）では会社の全員への共有を行わない（ドメインが会社でないため）
