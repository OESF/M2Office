# ADR-0114: 紹介のページは CMS を置かない静的なサイト（Astro）にし、AI が直す

- 状態: 提案（第 0.475.0 版）
- 日付: 2026-10-27
- 関係: 仕様書 第23.3.1節・第20.4.6節、Q-258・Q-279・Q-280、ADR-0107（紹介のページの置き方を置き換える）・ADR-0113・ADR-0028

## 背景

ADR-0107（第 0.428.0 版）では、紹介のページ（`www.m2office.net`）を Node.js の CMS の EmDash で作り、Cloudflare の上に置く案にした。ADR-0113（第 0.472.0 版）で Cloudflare を使わない形にしたため、EmDash を VPS の上で動かすか、静的なページにするかが残っていた。

2026-10-27 に三浦さんが、次のことを示した。

- WordPress はもう使いたくない。
- **AI でほぼ完全に操作できる**作り方にしたい。
- EmDash を考えていたが、まだ安定していないので採らないほうがよい、という判断を受けている。

## 決定（案）

1. **紹介のページは、Astro で組み立てた静的なサイトにする。** VPS の上では何も動かさず、Caddy がファイルとして出す。管理画面・ログイン・データベース・プラグインを持たない。
2. **中身は Markdown と部品のファイルで持ち、AI（Claude Code など）が直す。** 運営の人は会話で頼み、手元で表示を確かめてから出す。画面で編集する道具は持たない。
3. **別の非公開のリポジトリ（例 `M2Office-site`）に置く。** 運営主体の表示と料金を含むため、公開の M2Office のリポジトリに置かない。
4. **手元で組み立て、WireGuard の網を通して VPS に送る。** 前の版を 1 つ残し、すぐ戻せるようにする。
5. **紹介のページでは個人の情報を集めない。** 問い合わせは、申し込みの口ができるまではメールのリンク、できたら申し込みの口のフォームで受ける。
6. アクセスの解析・広告・外のフォントは入れない。

## 理由

- AI は、管理画面を操作するより、ファイルを読んで直すほうがずっと確実である。文章の追加・デザインの変更・ページの新設まで、会話で頼めば済む（ADR-0028 の「人に画面や規則を作らせない」に合う）。
- VPS に実行するものを置かないので、顧客のデータがある機械に新しい攻撃の面を持ち込まない。守るものが増えず、更新の手間も無い。
- 変更が git に残り、いつ何を変えたかが分かり、戻せる。
- 契約が増えない（Xserver にまとめる ADR-0113 に合う）。費用もかからない。
- Caddy の設定は、すでに親のドメインと `www` で `/var/lib/m2office/site` を出す形になっており、VPS の側の作業がほぼ無い。

## 採らなかった案

- **EmDash を VPS の上で動かす**: 公開から間もない早期のベータで変化が大きい。管理画面とプラグインという攻撃の面が、顧客のデータがある機械に入る。
- **Ghost・Payload など、ほかの Node.js の CMS**: データベースと管理画面が VPS に増える。AI は API を通しての操作になり、ファイルを直すより回りくどい。
- **画面で編集する外部の CMS（microCMS など）**: 契約が 1 つ増える。

## 影響

- 人が画面で直すことはできない。必要になったら、同じファイルを編集する道具（Keystatic など）を足す。
- EmDash も Astro の上に作られているため、落ち着いて人が画面で編集したくなったら、中身を持って移れるかを確かめる。
- 送る命令と組み立ての設定は `M2Office-site` に置く。M2Office の側（`deploy/vps/setup.sh`）は、置き場と仮のページを作るところまでで変わらない。
