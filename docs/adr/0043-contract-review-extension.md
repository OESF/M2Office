# ADR-0043 契約書チェックを公式の拡張機能（スキル）として作り、論点の提示にとどめる

| 項目 | 内容 |
|---|---|
| 状態 | 提案（2026-09-27。三浦さんの依頼「顧問弁護士のいない中小企業のために、契約書を AI がチェックして概要を伝えたい」に対する案） |
| 決定日 | 2026-09-27 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第28章・第2.6節・第15.4節・第12.12節・第12.5節。Q-09・Q-48・Q-97・Q-98。R-16 |

## 背景

中小企業の多くは顧問弁護士を置けない。NDA・売買・業務委託などの契約書は日常的に届くが、読んでも何が不利なのか分からないまま結ぶことが多い。
三浦さんの方針: 契約書を AI がチェックし、概要を利用者に伝え、提案（サジェスチョン）を返せるようにする。

一方で、弁護士でない者が報酬を得る目的で法律事務を業として行うことは、弁護士法第 72 条で禁じられている。
仕様書は既に、法務では「契約書の論点抽出・条文の要約」まで行い、「法律判断・契約の可否判断」は行わないと定めている（第15.4節）。

## 決定

1. 契約書チェックは**公式の拡張機能（SKILL.md）**として作り、公式の配布元（`extensions/contract-review/`）に置く。表も画面も要らないため、内蔵にしない（ADR-0042 の 2）。
2. 返すものは、概要・注意したい点（重さの順・理由・修正の案・相手に確かめること）・抜けている条項・会社の基準との違い・専門家に相談したほうがよい点。
3. **契約を結ぶかどうかは判断しない。** 断定と保証の言い回し（「問題ありません」「違法です」）を使わない。結果の冒頭に、論点の整理であって法律上の判断ではない旨を 1 行置く。
4. 自社の立場は聞かず、会社の正式名称と当事者の名前から AI が見分ける。そのため、基盤が会社の名前を業務の指示に添える（第12.12.5節）。
5. 契約の中身を秘書の記憶に入れない。そのため、学ばない業務の印 `metadata.m2office-private` を加える（第12.12.3節）。
6. 契約の種類ごとの観点は補助資料に持ち、法改正に合わせて直す（根拠と確認日を書く）。Phase 1 は NDA・売買・業務委託。
7. 評価に、見落とさないこと・断定しないこと・境界の表示・読めた範囲の明示・契約書の中の指示に従わないことを入れる。
8. 表示・ヘルプ・規約の文面は、公開の前に弁護士の確認を受ける（Q-97）。

## 理由

- 拡張機能の仕組みだけで作れるなら、拡張機能で作る。公式の見本にもなり、第三者が同じ形で業務を作る手本になる。
- 論点の提示にとどめれば、顧問弁護士のいない会社でも「どこを確かめればよいか」が分かる。判断まで踏み込むと、弁護士法との関係で事業そのものの危険になる（R-16）。
- 自社の立場を聞かないのは、人に選ばせない方針（ADR-0028）に合わせるため。見分けられなければ仮に決めて明示する。

## 影響

- 拡張の仕組みに 2 つ加える（会社の名前を指示に添える、学ばない業務の印）。
- 契約書の全文を推論に渡す。Limited Use を守る。機密の高い会社は自社の鍵で使える。
- 未決: 表示と規約の文面（Q-97）、変更履歴つきの Word（Q-98）、法務の区画（Q-48）。
