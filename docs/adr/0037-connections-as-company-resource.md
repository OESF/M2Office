# ADR-0037 コネクタ（MCP）を拡張機能から切り離し、会社の接続として一元管理する

## 背景

コネクタ（MCP サーバへの接続）は拡張機能の中にしか置けず、Claude Code でいえば「プラグインに同梱した MCP」しか無い状態だった。
そのため、同じ MCP を複数の拡張機能が使うと別々に宣言することになり、秘書や公式の業務からは使えず、
認証の要るコネクタ（freee など）を「会社が登録し、各人が認証でつなぐ」形にしにくかった。

三浦さんの問い: MCP はいろいろなところから使えるので、別に管理すべきではないか。Claude Code や Claude のアプリはどうしているか。
調べた結果、どちらも MCP はスキルとは別の層で管理し（Claude のアプリは組織のコネクタ、Claude Code は範囲ごとの設定）、
スキルは道具の名前を書くだけで、まとめて配るときだけプラグインに同梱していた。

## 決定

1. コネクタは**会社の接続**として管理する（管理者ページ「接続 › コネクタ（MCP）」）。URL を入れると道具の一覧を問い合わせて並べ、管理者が道具ごとに危険度と入り切りを決める。
2. 秘書・公式の業務・拡張機能のどれからでも `<接続の ID>.<道具>` で使う。
3. 拡張機能は接続の宣言を**同梱して提案できる**。導入のときに、会社にその接続が無ければ登録し、あれば使い回す。拡張機能を外しても接続は消さない。
4. その会社に接続が無い道具を使う業務は、使えないものとして扱い「接続が要ります」と示す。
5. 危険度の初期値は、同梱の宣言の推奨か、MCP の読むだけの目印。どちらも無ければ `external-send`（承認が入る安全側）。
   SKILL.md を組み立てるときは会社の接続の危険度が分からないため `external-send` として組み立て、実行のときは会社が決めた危険度で判断する。
6. 秘書の調べものは、会社の接続の読むだけの道具を使える。

## 理由

- 「道具は会社の資源、業務はそれを使う手順」という分担がはっきりし、秘書が外部の業務システムを直接使える（業務システムは MCP で連動する、という基本方針）。
- 同じ接続を複数の業務で使い回せ、認証の要るコネクタも会社の単位で登録できる。
- Claude のアプリ・Claude Code と同じ分け方で、スキルの書き手に新しい考え方を覚えさせない。

## 影響

- 拡張機能の詳細にあった道具の入り切りと接続の確認は、接続の画面へ移る。
- 同意の記録（拡張機能の導入）は、同梱した接続の登録を含む。
- データベースに会社の接続の表を足す（移行 `032_tenant_connections.sql`）。
