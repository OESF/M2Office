# ADR-0091 不正の兆しの見張り

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-10-11。三浦さんが、不正アクセスと情報の漏洩が社会で問題になっていることを受け、不正侵入の兆しを常に見張り管理者に知らせる仕組みを求めた。仕様書 第 0.332.0 版で案として書き、同じ版で Q-218〜Q-221 を案のとおりに決めた） |
| 決定日 | 2026-10-11 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第16.8節・第16.1.2節・第16.6節・第6.5.8節・第6.7.10節・第23.8.6節。ADR-0028（AI に任せる）・ADR-0063（医療は M2Medical に分ける）・ADR-0092（Google Workspace のログインの記録の取り込み。段 3） |

## 背景

- M2Medical で、5 つの兆し（大量の持ち出し・ふだんと違う時間・ログインの攻撃・権限の変化・ありえない並び）を見張る仕組みを考えている。M2Office でも、会社のデータ（名刺・問い合わせ・人事・在庫・契約）を守るために同じ考え方を入れたい。
- 監査ログには、ログイン・ログインの拒否・書き出し・取り込み・権限の変更が残っている。ただし、止めたアカウントのログインの試みは未登録と同じ理由で残り、名刺や問い合わせを開いたことは残していない。接続元の IP は持っていない。ログインの失敗が続いても締め出す仕組みが無い。
- 第6.7.10節は、ダッシュボードを社員を見張る道具にしないため、場所を推定しないこと・1 人ずつのログイン時刻を集計しないことを決めている。

## 検討した案

| 論点 | 案（提案） | 採らなかった案 |
|---|---|---|
| 判定 | **決まった規則**（件数・時間・重なり） | AI に記録を読ませて判定する（遅く、費用がかかり、AI の誤りで見逃す） |
| ふだんと違う時間 | **単独では知らせず、ほかの兆しと重なったときに重さを上げる** | 深夜・休業日のログインをそのまま知らせる（深夜に働く人を見張ることになる） |
| 場所 | **持たない・推定しない** | IP から地域を推定する（第6.7.10節に反する） |
| 受け取る人 | **管理者全員。兆しの本人が管理者ならほかの管理者にも** | 管理者に一律に送る（乗っ取られた管理者のアカウントで握りつぶせる） |
| 誤りの直し方 | **秘書に「これは大丈夫」と言う** | 管理者に除外の一覧や数字を設定させる（ADR-0028 に反する） |
| 画面 | **作らない**（お知らせ・秘書・監査ログ） | 見張りの画面を作る（見張る道具に見えやすい） |

## 決定

1. 兆しは決まった規則で見つけ、管理者全員に「セキュリティ」のお知らせで知らせる。新しい端末でのログインは本人に知らせる。
2. 同じ人に 1 時間のうちに重さ高が 2 つ重なったときだけ、その人の端末を自動ですべてログアウトする。アカウントは止めない（Q-218）。
3. 同じアドレスのログインの拒否が 10 分に 5 回に達したら、そのアドレスのログインを 30 分受けない（Q-219）。
4. 開いた数は、人と 1 時間ごとの件数だけを 7 日数える。段 2 で作る（Q-220）。
5. 知らせる条件の数字は会社ごとに変えない。誤りは秘書に「これは大丈夫」と言う（Q-221）。

## 結果

- 良い点: 乗っ取り・持ち出し・攻撃を早く見つけられる。社員を見張る道具にしない境界を守ったまま、記録の足しは最小で済む。
- 悪い点: IP を持たないため、どこから入られたかは分からない。開いた数を数えるまでは、大量に開くことは見つけられない（段 2）。
