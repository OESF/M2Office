# ADR-0021 キーボードの割り当ては、自前の薄い層で持つ

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-24 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第6.11節、原則 u10、FR-303b |

## 背景

「キーボードから手を離さずに操作できるようにしたい。ショートカットの JavaScript の
ライブラリがあったはずなので、調べて使ってほしい」という指示を受けた。
Mac・Windows・iPhone・iPad・Android の切り分けができること、が期待されている。

## 調べたこと

| 候補 | 版 | 依存 | 大きさ | 備考 |
|---|---|---|---|---|
| `@tanstack/react-hotkeys` | 0.11.0 | `@tanstack/hotkeys`・`@tanstack/react-store` | 約 245 KB（展開後、本体のみ） | `Mod` の別名、入力欄の扱い、並び（Vim 風）、記録 UI、開発用の道具 |
| Zag の Hotkeys | — | Zag 一式 | — | 枠組みに依らない。まとまりとして大きい |
| Mousetrap | — | 無し | 小さい | 古い。React 向けの後片付けは自分で書く |
| 自前 | — | 無し | 約 120 行 | 必要なものだけ |

`@tanstack/react-hotkeys` は作りがよく、`Mod`（Mac は Command、その他は Control）の
解決も、文字を打っている最中に効かせない扱いも入っている。**機能としては申し分ない。**

## 決定

**自前の薄い層（`packages/web/src/keys.ts`）で持つ。ライブラリを入れない。**

| # | 決定 | 理由 |
|---|---|---|
| 1 | 依存を増やさない | 画面の依存はいま **React だけ**である。ここに 0.x の版のものを 3 つ（本体＋依存 2 つ）足すと、釣り合わない |
| 2 | 版が 1.0 に達していない | 0.11.0 は、これから API が変わりうる。**割り当ては 8 つしかない**。追随の手間が割に合わない |
| 3 | 要るものが少ない | `Mod` の解決、文字を打っている最中の扱い、後片付け、表示用の文字列。これで足りる |
| 4 | 表示まで自分で持てる | 画面に `⌘J` と `Ctrl+J` を出し分け、一覧を作る。**割り当ての表を 1 つにしたい**（第6.11.3節）。ライブラリを入れても、この表は自分で持つことになる |
| 5 | 触る端末で出さない判定が要る | 外付けのキーボードが無い端末では表示しない（第6.9節）。これはライブラリの担当ではない |

**乗り換える条件を決めておく。** 次のどれかが起きたら `@tanstack/react-hotkeys` を入れ直す。

- 割り当てが 20 を超える
- 並び（`g` のあとに `i` のような連続打鍵）が要る
- 利用者が割り当てを変えられるようにする
- 衝突の検出が要る

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| `@tanstack/react-hotkeys` を入れる | 上記。**機能が足りないからではない。** 釣り合いの問題である |
| Mousetrap | React の後片付け（外すとき）を自分で書くことになる。それなら自前と変わらない |
| ブラウザの `accesskey` 属性 | 押し方が browser ごとに違い（Alt+・Ctrl+Alt+）、利用者に説明できない |
| 割り当てを利用者に決めさせる | 覚える対象が増える。既定を良くするほうが効く（第6.11.4節） |

## 影響

- `packages/web/src/keys.ts` に割り当ての表と仕組みを置く。**画面と一覧はここから作る**
- `Mod+1`〜`9` はブラウザのタブの切り替えと衝突するため使わない。業務は `Mod+Shift+1`〜`9`
- 触る端末（外付けのキーボードが無い）では、ショートカットを画面に出さない
