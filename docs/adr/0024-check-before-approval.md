# ADR-0024 承認の前に、記録する操作が行えるかを確かめる

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-25 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第9.3.3節、第14.3.4節「Chat」、ADR-0023 |

## 背景

ADR-0023 で、承認の直後の段を承認の前に組み立て、書く・送る操作を記録して承認の画面に出すようにした。
ところが、記録した操作が**承認のあとで行えない**と分かることがあった。

Chat の投稿は、投稿先をスペースの名前（「技術部」など）で受け、本人が入っているスペースから探す。
探すのは投稿の直前（承認のあと）だったため、名前が違う・同じ名前が 2 つある・許可が足りないと、
承認したのに止まる。承認の画面には「チャットのスペース『技術部』に投稿します」と出ており、承認した人は行えると思っていた。
仕様書 第14.3.4節は、これを「既知の制約」として残していた。

## 決定

**1. ツールに「承認の前の確かめ」（`prepare`）を持てるようにする。**

組み立て（`plan`）で書く・送る操作を記録する前に、ツールが `prepare` を持っていれば呼ぶ。
`prepare` は**読む操作だけ**を行い、次の 3 つのどれかを返す。

| 結果 | 記録 | 承認の画面 |
|---|---|---|
| 行える（`ready`） | `prepare` が返した引数で記録する（確かめた値。例: `spaces/…`）。画面に出す名前も添える | 確かめた名前で出す |
| 行えない（`problem`） | 記録しない。推論には「行えない」と理由を返す | 「次のことは行えません（承認しても行いません）」に、何が・なぜを出す |
| 確かめられなかった（`unchecked`） | 元の引数で記録する | 「承認の前に確かめられませんでした」と添える |

**2. 承認のあとは、確かめた値のまま行う。**

記録は確かめた値（スペースの ID）で持つので、承認のあとは探し直さない。
承認と投稿の間にスペースの名前が変わっても、承認の画面に出たスペースへ投稿する。

**3. 行えない操作を、承認の画面から黙って消さない。**

推論に「行えない」を返すだけでは、推論が投稿を書かなかった結果として、承認の画面から投稿が消える。
承認する人は、投稿が行われないことに気づかずに承認する。行えないことは、理由とともに承認する人に見せる。

## 理由

- 承認は「読んで判断する」ためのもので、承認のあとで止まる操作を並べると判断の前提が崩れる
- 確かめに使うのは読む操作だけで、危険度の強制（`external-send` は承認のあとだけ）を変えない
- 仕組みをツールの側に置くので、Chat 以外（共有先の人が社内にいるか、など）にも同じ形で広げられる

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 行えないときは、承認を求めずに実行を失敗にする | 議事録のような判断するものが残らない。行える分（ToDo の登録など）だけ進めたいこともある。承認する人に決めさせる |
| 承認の画面で、投稿先を直せるようにする | 承認は「読んで決める」画面であり、中身を書き換える場所にすると、承認したものと依頼したものが食い違う。直すなら依頼し直す |
| 承認のあとも名前で探し直す | 承認した画面に出たスペースと、投稿するスペースが食い違いうる |

## 結果

- 仕様書 第9.3.3節に「承認の前に、行えるかを確かめる」を加え、第14.3.4節の「既知の制約」を解消した
- `Tool.prepare`（`packages/core/src/tools/registry.ts`）を追加し、`chat.post` が使う。接続口に `chat.findSpace` を追加した
