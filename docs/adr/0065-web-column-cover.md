# ADR-0065 Web のコラムのカバー画像は、背景と題名を分けて作り、AI の挿絵は会社ごとに入れる

## 背景

- 第 0.221.1 版で「画像は AI で作らない」（Q-165）と決めたが、記事の先頭と SNS の共有に出るカバー画像が無いと、記事が読まれにくい。
- 生成 AI の画像は、日本語の字が崩れる、人物が「患者」「お客様」に見える、医療・健康の業種では前と後の比較のように見えるおそれがある。

## 決定

1. **カバー画像は背景と題名を分け、題名は M2Office のプログラムが重ねる。** 生成 AI に文字を描かせない。
2. 背景は ① 会社の色の**型**（標準。外部の AI を使わない。第 0.225.0 版で会社の名前、第 0.226.2 版でロゴを画像から外し、ロゴは色を選ぶのにだけ使う）、② 生成 AI の**挿絵**（会社ごとに管理者が入れる。既定は切り）、③ **会社の写真**（推論が選ぶ）。選ぶのは AI で、会社に型や規則を作らせない。
3. 挿絵の決まり（人物・文字・ロゴ・体の部位・前と後の比較を描かない）は M2Office が持つ。描いた後に推論が確かめ、**通らなければ使わない**（1 回に 3 枚まで。確かめられなかったものも使わない）。通らなければ型にする。第 0.226.5 版で、カバーを明るくする決まりを足した（型は淡い地と濃い字、画像の上は黒い影でなく白い帯、挿絵は明るく描かせて暗ければ描き直す。三浦さんの指示）。
4. 挿絵のモデルは `gemini-3.1-flash-image`、会社で月に 100 枚まで（Q-169）。2026-10-07 追記: `gemini-3.1-flash-image` が 2026-10-29 に終了するため、後継の `gemini-nano-banana-2.1`（Nano Banana 2.1）に改めた（仕様書 第 0.293.2 版）。`MODEL_IMAGE` で変えられる。
5. カバーは版に含め、承認の画面に必ず出す。承認の後、WordPress のアイキャッチにする（記事は下書きのまま）。
6. 画像の組み立て（SVG から PNG）に `@resvg/resvg-js`（MPL-2.0）を使う。字体は帳票と同じ Noto Sans JP を使う。

## 理由

- 題名をプログラムで重ねれば、字が崩れず、題名を直したときも描き直さずに済む。
- 型を標準にすれば、費用も外部の AI も要らず、「ローカルだけ」の会社でも同じ品質のカバーができる。
- 挿絵は会社の判断で入れ、決まりと確かめを M2Office が持つことで、業種の広告の決まりを絵で迂回しない。

## 影響

- 移行 `063_web_column_covers.sql`（版のカバー・会社の写真の置き場）。
- 推論の口に「画像を作る」を足した（Gemini だけ）。画面の書式（Markdown）で、M2Office のファイルの画像を出せるようにした（承認の画面のため）。
- ツール `columns.cover` と業務「コラムのカバー」（秘書から作り直す）。
