# ADR-0141 サイトの更新で、一人ひとりが自分の WordPress の利用者でつなげるようにする

| 関連 | 仕様書 第45.16節・第45.10節・第6.5.9節・第6.6.2.1節。Q-335〜Q-338。ADR-0140（サイトの更新）・ADR-0044（認証の要る接続） |

## 背景

サイトの更新（第45章）は、会社の接続（「接続 › WordPress」）の 1 人の WordPress の利用者で直す。2026-11-12 に三浦さんが、これでは M2Office の利用者 A は WordPress の管理者 AA、利用者 B は編集者 BB、のように分けられないと指摘した。

1 人にまとめていると、次のことが起きる。

- WordPress の版の記録と投稿者が、誰が頼んでも会社の 1 人になる
- WordPress の役割で、人ごとに直せる範囲を絞れない
- 管理者の役割が要る直し（段 2 のヘッダー・フッター）のために会社の利用者を管理者にすると、誰が頼んでも管理者の力で動く

三浦さんは、本人がつないでいれば本人の利用者で直し、つないでいなければ会社の利用者で直す案を選んだ。

## 決定

1. **サイトは会社で 1 つのまま。** 会社の接続が直すサイトを決める。
2. **一人ひとりが、個人設定の「サービスとの接続」で自分の WordPress の利用者をつなげる。** 利用者名とアプリケーションパスワードだけを入れる。つなぐときに会社のサイトで確かめ、表示名と役割を出す。
3. **本人がつないでいれば本人の利用者で、いなければ会社の利用者で直す。** 本人がつないでいるときは、権限が足りなくても会社の利用者に切り替えない。
4. **直し案を作ったときの接続で入れる。** 管理者の承認が加わっても、入れるのは頼んだ本人の接続。間で外したら入れない。
5. **管理者は、誰がつないでいるか（WordPress の利用者名と役割）を見られる。** パスワードは見えない。
6. **この版ではサイトの更新だけ。** コラムとお知らせは会社の利用者のまま。

## 理由

- **本人の利用者:** WordPress に本人の名前で記録が残り、WordPress の役割がそのまま効く。最小の権限で動かせる
- **会社の利用者に戻す:** 小さな会社では WordPress の利用者が 1 人だけのことが多い。全員に登録を求めると手間が増える（ADR-0028）
- **切り替えない:** 本人の役割で断られたものを会社の利用者で通すと、WordPress の役割を回り道で破ることになる
- **接続をそろえる:** 承認した人が見たものと違う利用者で入れると、記録が食い違う

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 本人の接続だけで直す（会社の利用者では直さない） | 全員が登録する手間が増える。会社の設定で選べるようにするのは、求める会社が出てから |
| いまのまま、M2Office の利用範囲と承認で絞る | WordPress の記録と役割の問題が残る |
| 会社が、M2Office の利用者ごとに WordPress の利用者を割り当てる | 他人のパスワードを管理者が預かることになる。アプリケーションパスワードは本人が作って本人が入れるもの |

## 影響

- 個人設定の「サービスとの接続」に WordPress の欄が増える
- 表 `user_wordpress_connections` が増え、`site_edits` に使った接続を持つ
- ヘルプ（サイトの更新・接続・個人設定）を直す
