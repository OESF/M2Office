# ADR-0069 競合の分析は、AI が競合を探して覚え、公開のページだけを月 1 回読み、事実だけを残す

## 背景

- 2026-10-03 に三浦さんが、自社の Web サイトと競合の Web サイトを探し、差別化と相手の強みを自動で分析し、競合の URL を覚えて月 1 回ほど見直し、「いま競合が何をしているか」のレポートを作りたいとした。
- 競合は基本は同業。実店舗は営業圏の中の同業、特定の店は URL を入れられる、営業圏の無い業種は広く探す、という選び方が示された。
- 提案した方針を、三浦さんがおすすめのとおりに選んだ。

## 決定

1. **内蔵の拡張「競合の分析」**（既定は切り・無償で同梱）。Web の振り返りとは別の拡張にする。
2. **商圏の有無と半径は AI が決める。** 会社に業種の分類や半径の表を作らせない。違えば会話で直す。
3. **近くの同業は Google Places API で探す**（第 0.235.0 版で改めた。はじめは Gemini の Google マップのグラウンディングとし、使えなければ Places API としていた）。商圏の無い業種は、AI が挙げた会社を相手のサイトで確かめて覚える（Google 検索のグラウンディングの結果は巡回の相手にしない）。
4. **競合は自動 5 社・手入力を含めて 10 社まで。1 社 10 ページまで。** 人が外したものは自動で入れ直さない。
5. **公開のページだけを、robots.txt に従い、月 1 回、間を空けて読む。** 名乗って読む。
6. **相手の文章を残さない。** 取り出した事実（サービス・値段・キャンペーン・お知らせなど）と変化の印だけを残し、事実には出典の URL を付ける。
7. **レポートは社内向け。** 社外に出す文で比べるときは、コラムの作成の表現の決まりで赤入れする。
8. 読むのは公開の情報なので、外部の AI を使ってよい業務にする。会社の非公開の知識・お客様の情報は渡さない。

## 理由

- 中小企業は競合を見に行く時間が無く、見ても違いを言葉にしにくい。AI が同じ物差しで並べ、変化だけを拾えば、月に一度の判断材料になる。
- 相手のサイトに負荷をかけたり、文章を写して持ったりすると、相手との関係と著作権の両方で問題になる。公開のページを控えめに読み、事実だけを残せば、社内の情報の解析にとどまる。
- 数と読む量に上限を置けば、推論の費用が会社ごとに読める。

## 影響

- 仕様書に第36章を足した（第 0.233.0 版）。会社情報に「Web サイト」の欄を足す（Web の振り返り・コラムの作成でも使う）。
- 実装の前に、Google マップのグラウンディングの提供の状態・料金・利用規約（残してよい範囲）を確かめる（第36.17節）。

## 追記（2026-10-03、第 0.235.0 版）

調べた結果、Google マップのグラウンディングは、利用規約が結果を残すことと抜き出しを禁じ、結果は質問した本人に見せる用途に限られ、競合の Web サイトの URL も返さないことが分かった。Google 検索のグラウンディングも、結果のリンクから巡回の相手を決めることを禁じている。このため決定の 3 を改め、近くの同業は Places API の周辺の検索で探し、残すのは place ID だけにした。費用は 1 社あたり月 1 ドル未満の見込み。三浦さんが「Places API の方針で確定してください」として確定した（第 0.235.1 版）。続けて、別の請求の設定は要らないこと・地図で見つけた競合の名前をレポートに残してよいこと・名乗り方は案のとおりとすることを決めた（第 0.235.2 版）。
