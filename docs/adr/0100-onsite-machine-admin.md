# ADR-0100: ローカルの形のログインは Google のまま、機械の管理だけの「機械の管理者」を 1 人置く

- 状態: 採用（第 0.374.0 版で実装）
- 日付: 2026-10-16
- 関係: 仕様書 第8.6.3節・第8.6.7節・第16.1節（第 0.374.0 版）、Q-154、ADR-0077、ADR-0098

## 背景

ローカルの形（社内の 1 台で 1 社だけを動かす。第8.6節）のログインをどうするかは、第 0.209.0 版から未決だった（Q-154）。
第 0.296.0 版の案は、会社の利用者は Google のログインのまま、M2Office の中の ID とパスワードの利用者は作らず、機械の管理だけに使う管理者を 1 人持つ、というもの。
2026-10-16 に三浦さんが案のとおりに決めた。

決めることは、機械の管理者の入り方（2 段階の確かめ）・ログイン状態の持ち方・作り方だった。
機械の管理者が要るのは、インターネットか Google が止まって、会社の利用者が誰もログインできないとき（機械が止まった原因を見たいとき）である。

## 決定

1. **会社の利用者は Google のログインだけ。** 会社の OAuth クライアントを「内部」にし、戻り先は社内の名前（第8.6.2節）。ID とパスワードの利用者は作らない（Google のアカウントを持たないスタッフは M2Medical を使う。ADR-0063）。
2. **機械の管理者は、ID・合言葉・認証アプリの 6 桁の確認コード（TOTP）で入る。** TOTP は機械と認証アプリの時計だけで動き、インターネットが無くても使える。
   パスキーは端末と名前に結び付き、機械の担当が替わったときの引き継ぎと、名前が引けないときの入り方が難しいため採らない。
3. **入れるのは「機械」だけ**（管理者ページの「機械」と同じ口。第8.6.7節）。業務の画面と API には入れない。会社の利用者とは別の Cookie で、`/v1/machine-admin` の下にしか送らない。
4. **ログイン状態はデータベースに置かず、署名した値を Cookie に持つ**（8 時間）。データベースが止まったときこそ機械の様子を見たいため。
   署名の鍵は、サーバーの秘密の鍵と合言葉の控え・確認コードの種から作るので、作り直すと前のログイン状態はすべて使えなくなる。
   ログアウトは Cookie を消すだけで、盗まれた値は期限まで使えてしまうが、Cookie は httpOnly・SameSite=Strict で、社内の名前でしか開けない入口の下に限るため、短い期限で受け入れる。
5. **合言葉は導入のときに機械の上で作り、画面に 1 度出すだけ。** どこにも残さない（`m2office.env` には scrypt の控えだけ）。運営は知らない。忘れた・漏れたときは技術者が `setup.sh` で作り直す。
   画面で合言葉を変える機能は作らない（機械の管理者は導入と障害のときにしか使わず、変える口を増やすほど狙われる所が増えるため）。
6. 続けて 5 回間違えると 15 分受け付けない（送り元ごと。送り元を変えても全体で 20 回）。どれが違ったかは答えない。ログイン・失敗・ログアウトは監査ログとシステムログに残す。

## 考えた別の案

- **M2Office の中に ID とパスワードの利用者を作る**: Google を使わない会社にも入れるが、パスワードの保管・リセット・2 段階の確かめを自前で持つことになり、第16.1節の「独自のパスワードを持たない」に反する。要るようになったら別に決める。
- **機械の管理者のログイン状態をデータベースに置く**（会社の利用者と同じ）: 取り消しはできるが、データベースが止まると機械の様子も見られなくなり、機械の管理者を置く理由がなくなる。
- **機械の管理者を置かず、技術者が機械にログインして見る**: 会社の担当の人がブラウザで見られず、遠隔の保守（第8.6.4節）を開けるのも会社の管理者のログインが要るため、Google が止まると何もできない。

## 結果

- `deploy/onsite/machine-admin.mjs`（作る道具）、`packages/core/src/machine/machine-admin.ts`（確かめ）、`packages/api/src/routes/machine-admin.ts`（入口）、`packages/web/src/MachineAdmin.tsx`（`/machine` の画面）を足し、「機械」の口と画面を管理者ページと分け合えるようにした（`routes/machine.ts`・`Machine.tsx`）。
- すでに入れた機械は、次に `setup.sh` を走らせ直したときに機械の管理者が作られる（`update.sh` では作らない）。
