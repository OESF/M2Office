# ADR-0007 接続の設定（会社の OAuth クライアント、秘密の値の暗号化、Gemini Live の中継）

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-22 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第14.3.3節、第6.5.2節、第6.6.2節、第10.5節、第21.3節、ADR-0003 |

## 背景

Gemini と Google Workspace への接続を、会社の管理者が自分で設定できるようにする。
同じ作者の AI Radio（MIT）の「システム接続設定」は、次の作りで実際に便利に使えている（`server/routes/oauth-routes.js`、
`client/src/admin/components/system/CredentialsTab.tsx`、`server/routes/secretary-live-routes.js`）。

| AI Radio の作り | 内容 |
|---|---|
| Gemini | API キーをサーバーに保存し、入力欄は伏せ字。Gemini Live はブラウザからサーバーへつなぎ、サーバーが鍵を使って中継する |
| Google | 自分の Google Cloud で作った OAuth クライアントの ID とシークレットを画面で登録し、「Google でサインイン」で `refresh_token` を取る |
| 許可の確認 | 保存の有無ではなく、トークンを取り直して `tokeninfo` に問い合わせ、実際に許可された範囲を一覧する |
| スコープの表 | 求めるスコープと画面の名前を 1 つの表にまとめ、認可の要求と表示の両方がそれを使う |

ただし AI Radio は 1 人で使うアプリであり、M2Office は多くの会社が使う。そのまま移すと合わない点がある。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **Google は、会社の Google Cloud で作った OAuth クライアント（同意画面「内部」）を登録する形**にする | AI Radio と同じ手順で、会社が自分で設定できる。1 つの組織の中だけの社内専用のアプリになるため、一般公開の審査と CASA が要らない（仕様書 第14.3.1節） |
| 2 | 接続は**利用者ごと**。トークンは利用者ごとに持つ | AI Radio は 1 人分の `refresh_token` だが、M2Office では各自が本人のメール・予定だけを扱う（不変則 I-9） |
| 3 | 求める権限は、**会社で使える業務のツールが求める権限から作る**（AI Radio の固定の表ではなく） | 使わない権限を求めない（第14.3.2節 規定 2）。ツールが権限を宣言している（第9.4.4節） |
| 4 | 認可の要求に使い捨ての `state` と PKCE を付ける。戻り先はテナントのサブドメインではなく、設定した 1 つの URI にする | Google は `http` のリダイレクトを `localhost` にしか認めない。戻ってきた要求は `state` からテナントと利用者を引き、照合できなければ何もしない |
| 5 | 秘密の値（Gemini の鍵、クライアント シークレット、リフレッシュ トークン）は **AES-256-GCM で暗号化**して保存する。暗号の鍵はサーバーの設定 `M2OFFICE_SECRET_KEY` に置く | AI Radio は 1 台の手元の JSON に平文で置いていたが、M2Office は会社のデータを預かる。データベースが漏れても値を読めないようにする |
| 6 | API は秘密の値を返さない（登録済みかどうかと日時だけ）。画面の入力欄は伏せ字にする（AI Radio と同じ） | 仕様書 第6.6.2節「登録後は表示しない」 |
| 7 | Gemini Live は AI Radio と同じく**サーバーが中継する**。鍵をブラウザに渡さない | 鍵の漏えいを防ぐ。会社の鍵を使う場合も同じ |
| 8 | 会社が鍵を登録すれば、その会社の推論・秘書・Web の調査がその鍵を使う（会社ごとに LLM の提供者を選ぶ） | BYOK（第21.3節）を実際に効かせるため |

## 検討した点

| 案 | 採らなかった理由 |
|---|---|
| 運営が 1 つの OAuth クライアント（公開アプリ）を持ち、全社がそれで接続する | 一般公開の審査と CASA が必要になる。会社が Google Cloud を扱えない場合の選択肢として残す（Q-79） |
| AI Radio のように `refresh_token` を画面で直接入力させる | 利用者ごとの接続になるため不要。トークンは画面に出さない（第6.5.2節「鍵という言葉を使わない」） |
| 暗号化せずに保存し、データベースの権限だけで守る | 会社の Gmail を読める値である。漏えいの影響が大きい |

## 影響

- 本番では `M2OFFICE_SECRET_KEY` が無ければ起動しない。開発では固定の鍵を使い、警告を出す
- Google の API を実際に呼ぶ接続口（`google`）は、この設定で得たトークンを使って別に実装する（ADR-0003 の見本の接続口と差し替える）
- `state` はいま API のプロセスの記憶に置く。API を複数台にするときはデータベースに移す
