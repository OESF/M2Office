# ADR-0094 コラムのナレーション付きスライドを、サーバーの ffmpeg で MP4 にまとめる

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-10-13。仕様書 第 0.352.0 版で案として書き、同じ日に三浦さんが案のとおりに決め、第 0.353.0 版で実装した） |
| 決定日 | 2026-10-13 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第32.18.6節（段 3）・第31.6節。ADR-0051（サイネージ）・ADR-0064（Web のコラム） |

## 背景

- コラムのサイネージ用の動画は Veo で作り、8 秒か 15 秒しか選べない（第 0.349.0 版）。テレビの CM が 15 秒であり、8 秒で伝えるのは難しい（三浦さん）。
- 数枚のスライド画像をつなぎ、BGM と読み上げのナレーションを付ければ、15〜30 秒で要点を伝えられる。画像と読み上げは、いまの Gemini の鍵で作れる。
- 画像と音を MP4（H.264・AAC）にまとめるには、動画の符号化が要る。M2Office にはいま、その仕組みが無い。

## 検討した案

| 論点 | 案（提案） | 採らなかった案 |
|---|---|---|
| まとめる場所 | **サーバー（ワーカー）で ffmpeg を別のプロセスとして呼ぶ**。画面を閉じても、秘書からでも作れる（三浦さんが選んだ） | 画面を開いたパソコンのブラウザー（WebCodecs）でまとめる（サーバーに足すものは無いが、秘書からは作れず、Safari で動かないことがある）。ffmpeg の WebAssembly 版（遅く、大きい） |
| ffmpeg の入れ方 | **M2Office に同梱しない**。クラウドは組み立ての中で入れ、ローカルの形はセットアップで入れる。無い機械ではボタンを押せない | 同梱する（H.264 の符号化器のライセンスが Apache-2.0 の配布と合わない） |
| BGM | **会社の曲（使う権利のあるもの）と、M2Office がプログラムで合成する曲**（三浦さんが選んだ） | 会社の曲だけ（入れていない会社は BGM が無い）。AI の音楽の生成（使える条件を確かめてから後の段で） |
| 読み上げ | **Gemini の TTS**（日本語に対応。30 秒で約 1 円） | ローカルの読み上げ（日本語の質が足りない） |

## 決定

1. コラムのサイネージ用に「ナレーション付きスライド」を足す。いまの画像と動画は残す。
2. 場面の画像・読み上げ文・読み上げの音・BGM を、ワーカーが ffmpeg で MP4 にまとめる。ffmpeg は同梱せず、機械に入れる。
3. 承認の後にサイネージの素材に登録する（ほかの組と同じ）。

## 結果

- 良い点: 15〜30 秒で要点を伝えられる。費用は 1 本 50 円ほど（画像 5 枚と読み上げ）で、Veo の 15 秒（約 230 円）より安い。
- 悪い点: 配備に ffmpeg が要る。ffmpeg に渡す入力を限り、時間の上限で止める必要がある。
