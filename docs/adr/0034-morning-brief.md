# ADR-0034 秘書が先回りする最初の一歩として、朝のブリーフを本人ごとに自動で用意する

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-09-26 に三浦さんが決定） |
| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第6.5.1節・第6.5.3節・第9.5.5.1節・第10.11.7節。ADR-0028・ADR-0033 |

## 背景

秘書は頼まれてから答える作りだった。三浦さんの方針は「秘書は仕事のあらゆる場面でユーザーを支える」（ADR-0033）。
提案した先回りのうち、毎日使い、秘書が役に立つと感じてもらいやすい朝のブリーフから始める。
三浦さんから「一般的なニュースや居住地の天気があるとすごく嬉しい」との要望があった。
天気の地域と行程の出発地のために、本人の自宅といつもの勤務地も要る。

## 決定

1. プロフィールに**自宅**（地域か最寄り駅）と**いつもの勤務地**だけを足す。ほかの好みは会話から覚える（人に表を書かせない）。
   自宅は本人の秘書と本人の依頼で動く業務だけが使い、管理者・ほかの人には見せない。業務が読むときは道具 `profile.read` を宣言させる。
2. 公式の業務「朝のブリーフ」を置く。予定と出発の目安・ToDo・返事の要るメール・承認待ち・自宅の地域の天気・一般のニュースを伝える。読むだけで、承認は無い。
3. **平日 7:30 の定時実行を、秘書が本人ごとに自動で用意する**（設定しなくても届く。原則 p4）。止めたい人は定時実行の画面で止める。
   秘書の積極性を「控えめ」にした人には用意しない。一度用意したら、止めたり消したりしても作り直さない。
4. 結果は秘書の答えとして、その日のうちに一度だけ届ける（画面を開いたとき・音声をつないだとき）。

## 理由

- 定時実行・秘書バー・持ち越しの仕組みがすでにあり、新しい配信の仕組みを作らずに済む。
- 「届けたいものがある人が設定する」形では、ほとんどの人が設定しない。先回りの価値は、設定なしで届くことにある。
- 前の日のブリーフを翌日に言い出すと、古い予定や天気を伝えることになる。

## 影響

- 本人ごとに毎朝 1 回の実行（Web の調べもの 2 回程度を含む）がかかる。費用はダッシュボードで見える。
- Google と接続していない人は、定時実行が飛ばされ、その旨が知らされる（第6.5.2.1節）。
