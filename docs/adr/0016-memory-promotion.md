# ADR-0016 昇華の実装（二重の承認、承認者の範囲、登録の形）

| 項目 | 内容 |
|---|---|
| 状態 | 採用（Q-24 を決定） |
| 決定日 | 2026-09-23 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第11.3節、第11.3.1節、第11.4節、第9.2.3節、第6.5.4節、ADR-0010、ADR-0015 |

## 背景

昇華（個人の記憶を組織知識へ引き上げること）は第11.3節に規定があるが、実装されていなかった。
個人記憶（ADR-0012）と、対話からの学習（ADR-0015）ができたことで、引き上げる材料が生まれた。

承認できるのが管理者だけか、部門責任者も含むか（Q-24）が決まっていなかった。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | 承認できるのは**管理者、または承認者の役割を持つ人**（Q-24）。本人以外が判断する | 業務の承認（第9.2.3節）と同じ考え方にそろえる。部門責任者という役割を新しく設けると、グループの仕組み（第16.7節）と二重になる |
| 2 | 候補は**本人の提案**と**秘書の夜間の候補**の 2 つから作る | 本人が「これは共有したい」と思った瞬間に出せることと、思いつかないものを拾うことの両方が要る |
| 3 | 秘書が作った候補は、**まず本人が出すかどうかを決める**（第11.3節の二重の承認） | 個人記憶には本人の業務の機微が含まれうる。本人の目を通さずに承認者へ回さない |
| 4 | 承認すると、記憶の一文を**そのまま**組織知識に登録する | 承認した人が読んだ文と、登録される文を同じにする（ADR-0010 決定 2 と同じ考え方） |
| 5 | 却下しても**記憶は消さない** | 記憶は本人のものである。全社に出さないことと、本人が覚えておくことは別である |
| 6 | 監査ログには操作だけを残し、記憶の中身は入れない | ADR-0012・ADR-0014 と同じ。登録された知識は、組織知識として別に見える |
| 7 | 区画は付けない（全社の知識とする） | 区画のデータは昇華の対象にしない（不変則 I-12）。区画つきで出したい要求が出たら、そのときに改めて決める |

## 検討した点

| 案 | 採らなかった理由 |
|---|---|
| 管理者だけが承認する | 小さい会社では管理者に集まりすぎる。承認者の役割はすでにあり、業務の承認で同じ判断をしている |
| 部門責任者の役割を新設する | グループ（第16.7節）と役割が二重になる。必要なら、その人に承認者の役割を与えれば足りる |
| 本人の承認を省き、承認者へ直接回す | 個人記憶に本人の機微が混じったまま、ほかの人の目に触れる |
| 承認のときに文を編集できるようにする | 承認した文と登録される文がずれる。直したいときは、本人が記憶を直してから出し直す |
| 昇華した記憶を個人記憶から消す | 本人が使えなくなる。組織知識は写しであって、移動ではない |
