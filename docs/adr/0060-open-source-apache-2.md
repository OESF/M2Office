## 背景

- 導入予定のクリニックとの契約で、M2Office として作ったソフトは公開してよいことになる見込みである。
  お客様の環境に合わせる特殊な部分を除き、オープンソースにすることも、運営のサーバーで提供することもかまわない。**ただし、データは決して出さない。**
- 三浦さんの方針は、**ソースを共通に保つ**ことである。お客様ごとにフォークを作らず、違いは設定と、公開しないリポジトリの Skill・つなぎで吸収する。
- 開発用のリポジトリの履歴には、出さないと決めた名前（個人の取引先・法人名など）が残っている。いまのファイルからは消してあるが、履歴をそのまま公開すると見えてしまう。
- 開発には Claude（外部の AI）を使っている。お客様の本番のデータを開発の場に持ち込むと、外部の AI にデータが渡る。

## 決定

1. **ライセンスは Apache License 2.0 とし、本体をすべて公開する。** リポジトリ直下に `LICENSE`（原文）と `NOTICE` を置く。
   Apache-2.0 を選ぶのは、特許の許諾と商標の扱いが明記され、企業が採用しやすいためである。
2. **公開は、履歴を引き継がない別のリポジトリで行う。** 開発用のリポジトリは非公開のまま使い続け、公開するときは、いまのコミットの中身だけを書き出す（`npm run publish:export -- <空のフォルダ>`）。
   書き出しは `git archive` で行い、追跡していないファイル・`.env`・作業中の変更は入らない。コミットしていない変更があれば書き出さない。
3. **書き出す前に必ず公開の前の点検を通す**（`npm run publish:check`。書き出しの中でも実行する）。確かめるもの:
   - 秘密の値（API の鍵・秘密鍵・トークンらしい文字列）と、追跡している鍵のファイル
   - メールアドレス。見本に使ってよいのは予約済みの名前（`*.example`・`example.*`・`*.test` など）と、決まった公開の宛先だけ
   - **出してはならない言葉**（客先・個人の取引先・法人の名前など）。**言葉そのものはどこにも書かない。**
     公開しないリポジトリ（`../M2Office-private/publish-denylist.txt`）に「文字数・SHA-256・FNV」だけを置き、点検は当たったファイルの名前だけを出す
   - 本番の依存のライセンス。GPL・AGPL・LGPL・SSPL・BUSL・非商用など、Apache-2.0 で配るのに注意が要るものと、ライセンスが分からないものを止める
4. **お客様に合わせる特殊な部分は公開しない。** お客様のための Skill・接続の宣言・設定・言葉の一覧は、公開しないリポジトリ（`M2Office-private`）に置く。
   クリニックで生まれて他社でも使えるものは、汎用の機能として本体に上げてから公開する。
5. **データは決して出さない。** お客様のデータ（患者・社員・取引先の情報、本番のデータベース、画面の写し、デバッグの記録）は、公開のリポジトリにも開発用のリポジトリにも入れない。
6. **開発でデータを外部の AI に渡さない。** 開発に使う AI（Claude）も外部の AI である（第16.3.7.1節と同じ考え）。
   - 電子カルテ・予約などのつなぎは、お客様が用意する**ダミーデータの入ったトライアルのアカウント**で作り、確かめる。
   - 本番で起きた不具合は、個人の情報を含まない形で再現してもらってから調べる。本番のデータ・画面の写し・記録を開発の場に貼らない。
7. **テストと文書の見本の値は、予約済みの名前を使う。** メールは `*.example` など、会社名は「マルマル商事」のような架空の名前にする。実在の会社・人・お客様を見本にしない。

## 理由

- お客様の賛成があり、同業の医療機関や中小企業にも使ってもらえる。公開することで、運営のサーバーでの提供（SaaS）とパートナーの提供の両方の土台になる。
- 履歴の書き換え（`git filter-repo` など）は、消し漏れが 1 つでもあれば取り返しがつかず、開発用のリポジトリの参照（タグ・コミットの番号）も壊す。新しいリポジトリに中身だけを出すほうが確実で、開発の流れを変えない。
- 出してはならない言葉を平文の一覧にすると、その一覧自体が漏れたときに困る。ハッシュなら、公開しないリポジトリが見られても言葉は分からない。
- ダミーデータのトライアルなら、つなぎの形（項目・認証・エラー）は本番と同じに確かめられ、患者のデータは開発の場に一度も入らない。

## 影響

- 仕様書 第22.5節（ソースの公開）を足し、Q-160（公開のリポジトリの置き場所・貢献の受け入れ方・名前の扱い）を足す。
- `LICENSE`・`NOTICE`・`scripts/check-publish.mjs`・`scripts/export-public.mjs` と、npm のスクリプト `publish:check`・`publish:export` を足す。
- ライセンスの分からない依存（`buffers`。`exceljs` の `unzipper` 0.10 が使っていた）をやめるため、`unzipper` を 0.12.3 に上げる（`overrides`）。
- テストの見本のメールアドレスを予約済みの名前に、開発用のテナントを作る例を見本の値に直した。ADR-0045・ADR-0046 と変更の履歴にあったお客様の詳しい記述を、特定できない書き方に直した。
- 公開のリポジトリの作成と最初の push は、三浦さんが書き出した中身を確かめてから行う。
