# ADR-0006 調査とスライドの作成を AI Radio から移植する

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 決定日 | 2026-09-22 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第9.4.2節、不変則 I-6・I-7、ADR-0003 |

## 背景

「〇〇について調べて、8 ページほどのスライドにまとめて」という依頼に応える道具が要る。
同じ作者のプロジェクト AI Radio（MIT ライセンス）の秘書は、この依頼にすでに応えている（`create_presentation`）。
作り直すより、実績のある作り方と知見を引き継ぐほうが確実である。

参照したファイル（AI Radio `server/lib/`）:

| ファイル | 引き継ぐもの |
|---|---|
| `secretary-tools-presentation.js` | 調べる → 構成 → 組み立ての 3 段、調査の指示文、構成の指示文、`SLIDE_PLAN_SCHEMA`、テンプレートの複製と差し込み |
| `llm-client.js` | Google 検索グラウンディングの結果（検索の言葉・出典）の取り出し方（`extractGrounding`） |
| `presentation-render.js`・`presentation-media.js` | 組み立て・グラフ・画像（Google 連携の後に移植） |

## 決定

| # | 決定 | 理由 |
|---|---|---|
| 1 | **作り方を引き継ぐ**。LLM は内容と構成（JSON）だけを決め、見た目はテンプレートが決める | AI Radio で「作るたびに見た目がばらつく」問題を防げている |
| 2 | **調べる段と構成の段を分ける**（別のツール・別のステップ） | Gemini は Google 検索（tools）と構造化出力（responseSchema）を 1 回の要求で同時に使えない |
| 3 | 調べる道具は内蔵ツール `web.research` とし、Gemini の API を**直接**呼ぶ（`generateContent` に `googleSearch`） | 既定の LLM が Gemini であり、検索サービスを別に契約せずに済む。OpenAI 互換の窓口ではグラウンディングの結果（出典）を受け取れない |
| 4 | 出力は **Google スライド**とし、PowerPoint 形式はドライブの書き出しで提供する | Google への一本化（原則 p8）。AI Radio の組み立て処理をそのまま使える。編集もしやすい |
| 5 | コードは TypeScript に書き直して取り込む。AI Radio の CommonJS をそのまま置かない | 開発規約（型・JSDoc・ファイルヘッダー）に合わせるため。出どころはファイルヘッダーに記す |
| 6 | Google と Gemini が使えるまでは、接続口の見本（ADR-0003）で骨格を通す | 鍵が無くても、構成の検証と成果物の記録までを確かめられる |

これは第三者のコードを M2Office の中で動かすこと（不変則 I-7）にはあたらない。
M2Office の開発者が、ライセンス（MIT、同じ作者）を確かめたうえで、本体のコードとして取り込むものである。

## 検討した点

| 案 | 採らなかった理由 |
|---|---|
| PowerPoint のファイルを直接作る（pptxgenjs など） | Google への一本化に反する。AI Radio の実績ある組み立て処理を使えない。会社のテンプレートの登録も Google スライドのほうが易しい |
| 検索サービス（Brave・Tavily など）をコネクタでつなぐ | 鍵を扱うコネクタ（`api_key`）が未実装。契約と費用が増える。会社が望めば後から拡張機能として足せる |
| AI Radio の新方式（見た目を見て直すヘルパー）から移植する | 仕組みが大きい。まず旧方式（テンプレートへの差し込み）で骨格を作り、段階的に移す |
