# ADR-0140 会社の WordPress のいまあるページを秘書に頼んで直す（REST API で行い、MCP は WordPress.com の口として後に足す）

## 背景

2026-11-12 に三浦さんが、世間で WordPress の MCP との連携が進んでいることを受けて、いまの WordPress とのつなぎ方（REST API とアプリケーションパスワード）が時代遅れではないかと尋ね、MCP を調べたうえで、会社のサイトを簡単に更新できる方法を検討するよう求めた。

調べたこと（2026-11-12）:

- 自前のサーバーの WordPress の公式の MCP（プラグイン「MCP Adapter」v0.7.1、WordPress 6.9 以上）は、最初は読む操作しか持たない。記事・固定ページ・画像を書く操作は、別のプラグインか自前のコードで足す。認証はアプリケーションパスワードで、OAuth は無い。0.x の版で、小さな版上げでも作りを変えている
- WordPress.com の公式の MCP サーバーは、記事・固定ページ（ブロック単位も）・画像など 60 以上の操作を持ち、OAuth 2.1（アプリの自動登録）でつながる。Jetpack でつないだ自前のサイトも使えるが、有料のプランが要る

三浦さんは、導入先の多くは自前のサーバー（レンタルサーバー）であるとして、REST API の上に「秘書に頼んでいまのページを直す」機能を作る案を選んだ。

いまの M2Office は WordPress に新しく入れる（コラムの下書き・お知らせの記事）だけで、いまあるページを直せない。中小企業のサイトの手間で多いのは、営業時間・料金・休業・スタッフの紹介など、いまあるページの文の直しである。

## 決定

1. **内蔵の拡張「サイトの更新」を作る。** 秘書に頼むと、秘書が直すページと場所を探し、直し案を作る。人は直す前と後を並べた画面で承認するだけ。
2. **つなぎ方は REST API とアプリケーションパスワード**（いまの「接続 › WordPress」）。相手のサイトに何も入れない。
3. **推論には文だけを渡し、印（ブロックの印・HTML の札）はプログラムが持つ。** 頼まれた所の外が 1 文字も変わらないことと、スクリプトや埋め込みを足していないことを、プログラムが確かめる。
4. **入れた後に公開のページを読み、直した文が出ているかを確かめる。** 直す前の本文を 90 日持ち、元に戻せる。直し案の後に人が WordPress で直していれば、上書きしない。
5. **ページビルダーで作ったページは直さない。** 制作会社への依頼文の下書きにする。
6. **MCP は、WordPress.com と Jetpack のサイトの裏の口として後に足す。** 直し案・承認・確かめ・元に戻すは M2Office の中に持ち、裏の口を取り替えられる形にする。

## 理由

- **いまの所で一番効くのは「直す口」:** 古さの問題はつなぎ方ではなく、いまあるページを直せないことだった
- **REST API:** WordPress 4.7 からの本体の機能で、レンタルサーバーのどのサイトでも動く。MCP Adapter は書く操作を持たず、認証も同じアプリケーションパスワードなので、自前のサーバーでは手間が増えるだけになる
- **承認の画面に変わる文を見せる:** 社外に出すものは、何が変わるかを読んで判断できなければならない（第9.3.3節）。汎用の MCP のツールを呼ぶ形では、ツールに渡す値しか見せられない
- **文だけを推論に渡す:** 推論にページの HTML を丸ごと書き直させると、頼まれていない所が崩れる。印をプログラムが持てば、崩れないことを確かめられる
- **公開のページで確かめる:** キャッシュとページビルダーのため、本文の欄を書いても表示が変わらないことがある。表示で確かめるのが最も確か

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 自前のサーバーの WordPress に MCP Adapter と、書く操作を足すプラグインを入れてもらい、汎用のコネクタでつなぐ | 会社に入れてもらう物が増える。書く操作はプラグイン次第で決まらない。承認の画面で変わる文を見せられない |
| WordPress.com の MCP だけを使う | 導入先の多くは自前のサーバーで、使えない |
| WordPress の管理画面をまねた、ページの一覧と編集の画面を作る | 人に場所を探させることになる（ADR-0028、原則 u11） |
| 推論にページの本文を丸ごと書き直させる | 頼まれていない所が崩れ、確かめられない |

## 影響

- WordPress の接続の利用者に、編集者の役割が要る（いまのヘルプは「投稿者・編集者など」）
- 拡張の表 `site_edits` が増える（直す前の本文を 90 日持つ）
- Webの分析の「直すべき所」と、お知らせの作成から、直し案を作れるようになる（段 2）
