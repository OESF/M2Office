# ADR-0035 Google Workspace だけでできる基本の業務を、公式に揃える

| 項目 | 内容 |

| 状態 | 採用（2026-09-26 に三浦さんが決定） |
| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 原則 p8・第2.3.2節・第9.5.5.2節・第14.4節。ADR-0033（秘書はあらゆる依頼に応える） |

## 背景

三浦さんの基本方針: 土台は Google Workspace（原則 p8）。そこへのアクセスと、簡単な基本の業務はデフォルトで提供する。
それ以外の業務システムは API・MCP で連動する（第14.4節）。
秘書があらゆる依頼に応えるには（ADR-0033）、頼める先の業務が揃っている必要がある。

## 決定

1. 公式の業務として「会議の準備」「返信待ちの追跡」「文書の作成」「表の作成」「スライド作成」を置く（朝のブリーフは ADR-0034）。
2. **どれも送らない・共有しない。** 作ったものは本人のドライブと Gmail の下書きに置く。送る・共有するのは、承認のある別の業務に任せる。
   危険度は `read` か `draft` で、承認は無い（社外にもお金にも関わらない。ADR-0028）。
3. 見本の拡張機能だった「スライド作成」を公式にする。拡張機能の見本（SKILL.md）は「スライド作成（見本）」として残す。
4. 会議の前に自動で準備することは次の段階にする。まずは秘書に頼むか、朝のブリーフの一言から始める。

## 理由

- 基本の業務が無いと、秘書は「できません」と答えるか、拡張機能を探してもらうしかない。
- 送らない・共有しない業務に限れば、承認を挟まずに秘書がすぐ頼める。
- 交通費・経費の精算は、会計（freee など）と MCP でつないでから作る（第14.4節）。

## 影響

- メニューに業務が増える。使わない業務は、管理者が会社の業務の一覧で止められる。
- スライド作成を導入済みの会社では、公式と見本の 2 つが並ぶ。見本は拡張機能の画面で外せる。
