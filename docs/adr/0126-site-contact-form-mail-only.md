# ADR-0126: 紹介のページで問い合わせのフォームを受け、蓄積せずにメールで送る

- 状態: 採用（第 0.529.0 版）
- 日付: 2026-11-07
- 決定者: 三浦
- 関係: 仕様書 第23.3.1節・第20.4.6節、Q-280、ADR-0114（決定の 5 を改める）・ADR-0113

## 背景

ADR-0114 では、紹介のページ（`m2office.net`・`www`）で個人の情報を集めないことにした。問い合わせは、申し込みの口ができるまではメールのリンクにし、できたら申し込みの口のフォームで受ける形だった。

2026-11-07 に、紹介のサイト（`M2Office-site`）の側が問い合わせのフォームを作り、受け口を VPS の `127.0.0.1:4330` で動かした。三浦さんは次のように判断した。

- 問い合わせのメールの送信まで止めるのは過剰である。
- フォームなどの入力を受けられないと、画面が途中で別のサイトに変わるなどして、サービスとして出せる画面にならない。
- 個人の情報を蓄積しない方針は変えない。

## 決定

1. **紹介のページの問い合わせは、そのページのフォームで受け、SMTP で運営の窓口へメールで送る。**
2. **受けた内容は蓄積しない。** データベースにもファイルにも残さず、送って終わりにする。
3. **受け口は紹介のサイトが作って動かす**（VPS の `127.0.0.1:4330`）。作り・送り先・ロボットよけ・回数の制限は `M2Office-site` が持つ。
4. **Caddy は `/api/contact` だけを受け口に渡す。** WAF を通し、受け取りは 32 KB まで。送り元のアドレスを `X-Client-Ip` で渡す。公開前の確認の BASIC 認証は掛けない。
5. 紹介のページのほかの入力も、蓄積しない形で同じように足してよい。足すときは、Caddy の道を 1 つずつ足す（紹介のページの下の道をまとめて渡さない）。
6. 申し込み・支払い・払い出しは、これまでどおり M2Office の側（`signup.`）で行う。

## 理由

- 問い合わせは見込みの客が最初に触れるところで、メールのリンクだけでは使いにくい。
- 蓄積しなければ、紹介のページの機械に守るべき個人の情報が溜まらない。破られても、それまでの問い合わせは漏れない。
- 道を 1 つだけ渡し、WAF と大きさの上限を掛ければ、VPS の上で増える攻撃の面は小さい。

## 採らなかった案

- **申し込みの口（`signup.`）のフォームで受ける**: 紹介のページから別の名前の画面へ移ることになり、見た目が途中で変わる。M2Office の側の作りも要る。
- **メールのリンクのまま**: 利用者の手元のメールの設定に頼り、使えない人がいる。

## 影響

- 紹介のページは完全には静的でなくなる。VPS の上で紹介のサイトの受け口が動く。
- 受け口が止まっていると、Caddy は 502 を返す（紹介のページの段は更新中の案内を出さない）。
- プライバシーの方針には、問い合わせの内容をメールで受けることを書く（紹介のサイトの側）。
