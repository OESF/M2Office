# ADR-0093 店頭サイネージの呼び出しを、外部のアプリの機能にも定義する

| 項目 | 内容 |
|---|---|
| 状態 | 採用（2026-10-12。三浦さんが、サイネージの呼び出しをシステムの API にも定義することを求めた。仕様書 第 0.341.0 版で案として書き、同じ日に第 0.342.0 版で Q-227〜Q-229 を案のとおりに決めて実装した）。2026-10-13 に決定 3 を改めた（下の「改訂」。第 0.346.0 版） |
| 決定日 | 2026-10-12 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第13.4.1節〜第13.4.3節・第31.7節・第31.8節。ADR-0090（外部のアプリ）・ADR-0051（店頭サイネージ） |

## 背景

- 店頭サイネージには、外の受付・順番待ちのシステムから呼び出しを出す受け口（`/v1/hooks/signage/{鍵}`。第31.8.1節）がある。外部のアプリ（ADR-0090）より前に作った用途ごとの口で、鍵・止める・回数の管理が拡張機能の設定の中に別にある。
- ADR-0090 は、用途ごとに口を作るのをやめ、外部のアプリの機能にまとめることを決めた。販売管理のつなぎは、外で使う人がいないうちに移した。
- サイネージの受け口はすでにリリースしており、使っている会社があるかもしれない。また、決まった形でしか送れないシステムのために、AI が項目の対応を推測して覚える役目を持つ。

## 検討した案

| 論点 | 案（提案） | 採らなかった案 |
|---|---|---|
| 形 | **外部のアプリの機能「サイネージにメッセージを表示する」を足す**（画面と同じ `/v1/signage/interrupts` の道） | 受け口だけのままにする（管理が 2 か所に分かれ、ほかの機能と同じ鍵で使えない） |
| いまの受け口 | **残して使い分ける**（決まった形でしか送れないシステムの入口。Q-229） | すぐに外部のアプリへ移して受け口を消す（使っている会社のつなぎが止まる） |
| 状態を読む | **画面の名前・接続中か・音が出せるか・待っている数だけを返す機能を足す**（Q-227） | 画面の一覧をそのまま返す（いま出している素材の見本など、外のシステムに要らないものまで渡る） |
| 消す | **そのアプリが出した割り込みだけ消せる**（Q-228） | 消せない（呼び出しを取り消すには人がスタッフのページで消すことになる）・何でも消せる（ほかの入口の呼び出しまで消せる） |
| 出せるもの | **文字と、登録した割り込みの素材だけ**（受け口と同じ） | 画像・HTML・URL を送り込ませる（鍵が漏れたとき、勝手な中身を店頭に出される） |

## 決定

1. 外部のアプリに機能「サイネージにメッセージを表示する」（`signage.interrupt`）と「サイネージの画面の状態を読む」（`signage.status`）を足す。承認の対象は、出してよい画面。
2. 出せるのは文字と登録した割り込みの素材だけ。割り込みの決まり（2 分・24 時間・待ちの上限）はほかの入口と同じ。
3. いまの呼び出しの受け口は残し、使い分けをヘルプの「開発者」に書く。

## 結果

- 良い点: 受付・レジのシステムが、ほかの機能と同じ鍵と管理でサイネージを使える。OpenAPI と Swagger で開発者に示せる。
- 悪い点: 外の呼び出しの入口が 2 つ並ぶ（使い分けを示す必要がある）。

## 改訂（2026-10-13・第 0.346.0 版）

三浦さんが、呼び出しを外部のアプリの API に移したので受け口を消すことを求めた。決定 3（いまの呼び出しの受け口は残し、使い分ける）を改め、**受け口を外す**。

| 項目 | 内容 |
|---|---|
| 外したもの | 道 `/v1/hooks/signage/{鍵}`・`/v1/hooks/signage`、管理者ページの受け口の欄と `/v1/admin/extensions/signage/sources`、項目の対応を AI が推測する仕組み |
| 理由 | 外の呼び出しの入口が 2 つ並ぶと、使い分けを説明し続ける必要があり、鍵と止め方の管理も 2 か所に分かれる。外部のアプリに 1 つにそろえる（ADR-0090 の方針） |
| 失うもの | 項目の名前を変えられないシステムからの呼び出し。そうしたシステムからは、スタッフのスマホか手元の自動操作（Q-140）で出す |
| 残すもの | 表 `signage_sources`・関数 `m2o_signage_source`・割り込みの列 `source_id`・`request_id`・出どころ `hook`。前の版に戻しても動くように残し、後のリリースで消す（リリース規定 第7章） |
| 公開 API | 受け口の道を外すのは破壊的な変更に当たる。リリースのときに版の上げ幅を確かめる |
