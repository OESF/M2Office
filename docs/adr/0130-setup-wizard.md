# ADR-0130 最初の管理者に、セットアップウィザードを出す

| 項目 | 内容 |
|---|---|
| 状態 | 採用（第 0.536.0 版。2026-11-09。三浦さんが決めた。同じ版で実装） |
| 決定者 | 三浦 |
| 関連 | 仕様書 第6.10.3節・第23.3.1節・第23.4.5節・第14.3.3節。Q-317。ADR-0028（AI に任せる）・ADR-0123（スターター） |

## 背景

クラウド版は、申し込むとその場でスターターの会社ができ、申し込んだ人が最初の管理者になる（第23.3.1節）。
このとき、次の理由で、申し込んだ人は最初にどうしてよいか分からなかった。

- 初期設定のチェックリスト（第6.10.3節）は、管理者ページの左のメニューの「はじめに行う設定」にしかない。申し込んだ人が最初に着くワークスペースからは見えない。
- クラウド版では、最初に会社の Gemini の鍵が要る。入れるまでは秘書（AI）が動かないので、秘書に案内させることもできない。
- 2 人目を招こうとすると、何も言わずに「ご利用料金」の画面へ移り、入れたメールアドレスも消えていた。

2026-11-09 に三浦さんが、最初はセットアップウィザードを出し、順に設定してもらう形を決めた。

## 決定

1. **管理者がログインしたとき、ウィザードが済んでいなければ、全画面のウィザードを出す。**
   - 「あとで続ける」で閉じられ、次のログイン（新しいタブ）でまた出る。
   - チェックリストからいつでも続きを開ける。
2. **出すのは、この版の後に作られた会社だけ。** それより前からある会社は、移行で「済み」にする。体験版の会社と運営の代理アクセスには出さない。
3. **段は次の順にする。各段で、その場で入力させる。**
   1. 会社の名前（正式な会社名と略称）。この段だけは飛ばせない。
   2. Gemini の鍵（入れてその場で確かめる）。
   3. Google Workspace の接続（会社の OAuth クライアントの登録と、自分の Google の接続）。
   4. 使う業務。
   5. 規程（ファイルを渡すと、文字を取り出して社内規程にする）。
   6. 同僚の招待。スターターは、ここで契約の形と支払いの方法を選ぶ。
   7. 従業員への告知（招待したときだけ）。
4. **済みの判定はチェックリストと同じものを使う。** あわせて、チェックリストの「Google Workspace を接続する」を、会社の OAuth クライアントがあり、見ている管理者が接続したときに済みとするよう改める（前は何もしなくても済みになっていた）。
5. **最後の「使い始める」で、会社として済みにする。** 飛ばした項目は、チェックリストに残る。

## 理由

- **全画面で出す:** 申し込んだ人は、まだ何も設定していない。ワークスペースを先に見せても、鍵が無ければ秘書は動かず、業務も見本のデータで動くだけで、得るものが無い。
- **その場で入力させる:** 段ごとに別の画面へ移すと、戻り方が分からなくなる。管理者ページの画面はたくさんの項目を持つので、最初に要るものだけを抜き出す。
- **段を絞る:** 住所や帳票の体裁などは、使い始めてからで足りる。段を増やすと、途中でやめられやすい。
- **支払いの方法は管理者が選ぶ:** お金に関わるので、人の判断を残す（ADR-0028）。招待と同じ段に置けば、何も言わずに別の画面へ移らずに済む。
- **今ある会社には出さない:** すでに使っている会社の管理者に、急に全画面の案内を出すと、仕事を止める。

## 採らなかった案

- **ログインしたら管理者ページの「はじめに行う設定」を開くだけにする:** 各項目は別の画面へ移すので、戻り方が分からなくなる。三浦さんがウィザードを選んだ。
- **秘書に案内させる:** Gemini の鍵が無いと秘書が動かない。
- **Google の接続を、運営のアプリで済ませる形に同時に変える:** Google の確認と運営の責任が大きく増える。別に考える（Q-317）。
