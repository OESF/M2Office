# ADR-0149 接続の業務を 1 本の会話で進め、見える状態を変える呼び出しの所でだけ止める

| 項目 | 内容 |
|---|---|
| 状態 | 採用（第 0.593.0 版で案、第 0.594.0 版で採用。2026-11-15） |
| 決定者 | 三浦 |
| 関連 | 仕様書 第48章・第47章・第9.2節・第9.3.3節・第20.2節。Q-375〜Q-381。ADR-0023（承認の前に組み立てる）・ADR-0028（AI に任せる）・ADR-0148（会社のサイトを MCP でもつなぐ） |

## 背景

2026-11-15 に、医院のサイトの運営会社の MCP（道具 124 件）を会社の接続にし、コラムとお知らせを入れようとした。Claude Code では AI が道具の説明を読んで最後まで進めたが、M2Office では、役割の取り違え・道具を呼ばずに文で答えて終える・説明と指示の食い違いが 1 つずつ起き、そのたびに直した。三浦さんは、これを場当たり的だと指摘し、新しい MCP をつなぐたびに同じことが起きないよう、きちんとした実行環境を作るよう求めた。

調べると、ずれの根は実行の型にあった。

- 接続の業務を、内蔵の業務と同じ「段」の型（進める → 承認 → 確定）で動かし、段ごとに推論をやり直していた。相手の説明は 1 本の会話を前提にしている
- 承認の前の段では確定の道具を見せず「この段では確定しない」と指示し、相手の説明（「了承を得てから確定を呼べ」）と食い違った
- 1 つの段で道具を呼べる往復が 4 回までで、相手の手順が収まらなかった
- MCP の引数の定義を簡単な形に写すとき、入れ子のオブジェクトの中身が落ちていた
- 道具の呼び出しは推論の文の中の囲みを読む作りで、込み入った引数を作りにくかった
- 業務から業務へ頼んだとき、元の業務が結果を知る仕組みが無かった

## 決定

1. **接続の業務は、段の型ではなく 1 本の会話で動かす。** 手順は相手の道具の説明に任せる。内蔵の業務は段の型のまま。
2. **見える状態を変える呼び出し（役割が確定・戻す）の直前でだけ止める。** 会話を保存して止め、承認したら、その呼び出しをそのとおりに行って会話を続ける。却下の理由は、その呼び出しの答えとして返し、AI に直させる。
3. **M2Office の指示は「約束事」1 つにまとめ、版で管理する。** 「了承が要る道具はそのまま呼べ。M2Office が止めて人に確かめる」を要にする。相手ごと・症状ごとの指示は書かない。
4. **相手の引数の定義（JSON Schema）をそのまま渡し、推論の道具呼び出しの機能を使う。** 推論の抽象化層に口を足し、使えない推論では文の約束に戻す。
5. **道具が多いときは、探して取り寄せる。** 名前の一覧と「取り寄せる」道具を渡す。
6. **業務から業務へ頼むときは、親と子をつなぎ、子の結果を親に返す。** 親は承認を受けたファイル（コラムのカバー画像など）を子に預けられる。推論はデータを持てないので、相手の道具が出した送り先へのデータの送信は M2Office が受け持つ（`files_send`）。送れるのは預けたファイルだけ、送り先はその接続と同じサイトの https だけ（第48.8.1節。2026-11-15 に追記）。
7. **問題集で測ってから直す。** 相手の答えを記録して再生し、本物の推論で、型ごとの問題を測る。

## 理由

- MCP の説明は、AI が 1 本の会話で読み進める前提で書かれている。その前提に合わせれば、相手ごとに直す所が無くなる
- M2Office の値打ちは、境目（承認・会社のこと・記録・ほかの業務とのつながり）にある。手順の中に口を出すほど、相手の説明と食い違う
- 呼び出しの所で止めれば、承認する人は「何を行うか」をそのまま見られ、承認の後に言い直されることが無い
- 却下の理由を会話に返せば、「期限は来週に」のような直しが、作り直しにならずに済む
- 症状ごとの直しは、測らずに足すと別の症状を生む。約束事を版で管理し、問題集で測る
- 追記（2026-11-16。仕様書 第 0.600.0 版）: 約束事を版 2 にし、8「名前で指したものが無ければ探し直し、読むだけなら近いもので進め、送る・作るなら候補を挙げて尋ねる」を足した。頼んだ Slack のチャンネル名がワークスペースに無く、人に名前を探させたため。本物の推論と本物の Slack（読むだけ）で測った。調べものは、Slack が答えた 3 回とも近いチャンネルを探して読んだ（直す前は、読んでいないチャンネルを「まとめました」と書く作り話が 1 回あり、まとめる段の指示から例の名前を外した）。送る頼みは Slack の利用の上限に当たって測れておらず、確かめが残る
- 追記（2026-11-16。仕様書 第 0.600.1 版）: `files_send` を、接続の名前を前に付けた名前でも受け付ける。道具の名前は相手の道具に `<接続>.` が付くため、推論が M2Office の道具にも付けて呼び、「使えない道具」と返って、前の記事の画像をアイキャッチにした。送れなかった預けたファイルは、推論の言い分に任せず M2Office が答えに書く

## 影響

- エンジンに、会話の保存と、呼び出しで止めて続ける仕組みを足す。推論の抽象化層に、道具呼び出しの機能の口を足す
- 接続の業務の継ぎはぎ（3 つの段・承認の前の組み立て・段の初めの道具の選択・「どれか 1 つは呼ぶはず」の促し・頼む文の言い回しの直し）は、段 1 を作ったら外す
- 承認の中身は、組み立てた予定ではなく、止めた呼び出しそのものになる（承認の画面の見せ方は第47.4.2節のまま）
- 止めている間の会話を保存するので、道具の答えの中身を持つ期間を決める（Q-380）
