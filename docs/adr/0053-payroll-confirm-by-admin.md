# ADR-0053 給与の確定は管理者が給与の画面で押すことを承認とし、監修前の表での確定は開発の環境だけに許す

## 背景

給与の確定と振込データの作成は「お金の確定」であり、人が判断する（第9.4.0節）。M2Office の承認トレイは、業務の実行（エージェントの段）の中の承認の段として作られており、
画面の操作から直接つくる承認を持たない。給与の確定のために承認の仕組みを業務の実行の外へ広げると、改修が大きい。

また、法令の表はすべて監修前であり（ADR-0052）、監修前の表で計算した回は確定できない。このままでは、確定・明細・振込データを開発の環境で試せない。

## 決定

1. **会社の管理者で人事区画に入っている人が、点検の結果と合計を見て「確定する」を押す。押すことを承認とする。** 誰がいつ確定したかを回と監査ログに残す。
2. 担当者が管理者でなければ「管理者に確定を頼む」で、人事区画に入っている管理者に知らせる（種類「承認」）。
3. 振込データは確定した回からだけ、管理者が作る（確定を承認とみなし、別の承認は挟まない）。
4. **監修前の表で計算した回は確定できない。デバッグモード（`M2O_DEBUG=true`）のときだけ確定でき**、回に「監修前の表で確定（開発）」と残す。
   デバッグモードは本番の環境では起動を止める（第20.4.1節）ため、本番で監修前の表のまま確定されることはない。
5. 確定した回と明細は、データベースの段でも書き換えと削除を拒む（アプリの利用者の権限のとき）。

## 理由

- 小さな会社では、給与を計算する人と確定する人（社長・管理者）が同じか、すぐ隣にいる。承認トレイを通さなくても、管理者が画面で押せば判断の記録は同じに残る
- 承認の仕組みを業務の実行の外へ広げるのは、給与のためだけには大きすぎる。広げる必要が他でも出たら改めて決める
- 開発の環境で確定から振込データまでを通しで試せないと、監修の前に画面と流れを確かめられない

## 影響

- 承認トレイには給与の確定が載らない。確定を待っている回は、給与の画面と知らせで分かる
- 監修が済んで表を「監修済み」にするまで、本番では確定できない
