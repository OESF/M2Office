# ADR-0115: 体験版のゲストは、使い捨ての体験用の会社と、M2Office が出すパスワードで入る

- 状態: 提案（第 0.484.0 版）
- 日付: 2026-10-29
- 関係: 仕様書 第23.3.2節・第16.1節・第23.3.1節、Q-286・Q-285・Q-284、ADR-0003（Google の設定が無くても動く）・ADR-0028（AI に任せる）

## 背景

2026-10-29 に三浦さんが、導入を考えているお客様が `demo.m2office.net` で M2Office を試せるようにすることを求めた。

- お客様は Google Workspace の契約を持っていないことがある。
- デモの依頼があれば、運営がゲストの ID とパスワードを出し、期間を限って自由に使ってもらう。
- AI の利用は回数などで抑え、作ったデータは残さない。
- 三浦さんが、1 社に 1 人・期限は 2 週間・AI の上限は推定 1,000 円・外部への接続は許す、と決めた。

M2Office は Google アカウントだけでログインし、独自のパスワードを持たない（第16.1節）。1 つの会社は 1 つの Workspace のドメインに結びつき、会社の中の「会社で共有」のデータは、その会社の全員に見える。

## 決定（案）

1. **ゲストごとに、使い捨ての体験用の会社を作る。** 1 つの `demo` の会社に複数のお客様を入れると、会社で共有の名刺・知識・規程が別のお客様に見えてしまう。会社ごとの分離（行の単位の守り）をそのまま使えば、新しい分け方を作らずに済む。
2. **入口は `demo.m2office.net` だけにし、ゲストのログイン状態から体験用の会社を決める。** ゲストごとにサブドメインを作ると、Let's Encrypt の証明書の上限（1 つの親のドメインで週に 50 枚）に当たる。
3. **ゲストだけは、M2Office が出す ID とパスワードで入る。** Google だけでログインする決まりの例外にする。範囲は体験用の会社の中だけ、期限は 2 週間で、パスワードは M2Office が作って 1 度だけ見せ、元に戻せない形で持つ。
4. **Google の部分は見本のデータで動かし、社外への送信はしない。** 見本の接続口（ADR-0003）を使う。外のサイトを読むこと（Web の調べものなど）は、三浦さんの決めたとおり許す。
5. **AI は運営の鍵で、体験の期間を通した上限（推定 1,000 円）を付ける。**
6. **期限が来たら、体験用の会社をデータごと自動で消す。** 相手の会社名・担当者・メールアドレスは運営の表に持ち、終えて 90 日で消す。

## 理由

- 分け方を新しく作らず、いまの会社の分離に乗せるのが、いちばん漏れにくい。
- パスワードを持つ責務は、範囲を体験用の会社に限り、期限と自動の削除を付けることで小さくできる。お客様に Google のアカウントを作らせる手間（とその Google 側の確かめ）をなくせる。
- 証明書の上限を避けるため、名前は `demo` の 1 つにする。

## 結果

- 第16.1節に、体験版のゲストだけの例外を書く。
- 会社に「体験」の印を足し、マスター管理画面に「体験」の画面を足す。会社一覧・毎晩の数・課金には入れない。
- `demo` の名前で来た要求の会社の決め方（ログイン状態から決める）を、API の会社の判定に足す。
- 体験用の会社を丸ごと消す処理を新しく作る（いまは会社のデータを丸ごと消す処理が無い）。
- 見本の会社のデータを、リポジトリのファイルとして用意する。

## 採らなかった案

| 案 | 採らない理由 |
|---|---|
| 1 つの `demo` の会社に全員を入れる | 会社で共有のデータが、別のお客様に見える |
| ゲストごとにサブドメインを作る | Let's Encrypt の証明書の上限に当たる。ワイルドカードの証明書は DNS で確かめる仕組みが要り、Xserver の DNS では自動にできない |
| お客様に Google アカウントを作ってもらう | 試すまでの手間が大きい。会社が管理するアカウントでないと、守りは変わらない |
| 誰でも登録なしで入れる | 社外への送信を止めても、AI の費用と外への接続の悪用を防ぎきれない。運営が相手を知ったうえで出す |
