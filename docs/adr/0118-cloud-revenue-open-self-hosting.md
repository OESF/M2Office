# ADR-0118: 収益はクラウド版だけにし、ローカル・自社運用は自由で無保証とする

- 状態: 採用（第 0.490.0 版）
- 日付: 2026-10-30
- 関係: 仕様書 第2.1.1節・第8.6節・第21章・第22.5節、Q-05・Q-160・Q-291〜Q-293、ADR-0059（クラウドとローカル）、ADR-0060（Apache License 2.0 で公開）、ADR-0077（Mac のパッケージ）

## 背景

M2Office は Apache License 2.0 で本体をすべて公開し（ADR-0060）、運営のクラウド（サブドメインごとのマルチテナント）と、会社の中の 1 台（ローカルの形）の 2 つで動く（ADR-0059）。これまでの仕様書は、ローカルの形も運営やパートナーが導入し、保守の契約を結び、稼働の知らせを運営が受ける前提で書いていた。収益も、利用料のほかに導入支援や拡張機能の販売手数料を並べていた。

2026-10-30 に三浦さんが、開発が進んだ段階でプロダクトの基本方針を明確にした。運営のチームだけですべてを作るのは難しいので、力のある人にはオープンに使ってもらい、コミュニティから知見を得たい。一方で、VPS や常時動かすサーバーの費用は、どこかで賄わなければならない。

## 決定

1. **プロジェクトの収益は、運営のクラウド版の利用料だけにする。**
   - クラウド版は、会社ごとのサブドメインでマルチテナントとして多くの会社に使ってもらう。セキュリティなどを運営が強め、安心して使える環境として出す。
   - 対価は、サーバーと運用の費用などを賄うためにいただく。シートで数える課金にするかは検討中（Q-05）。
2. **クラウド版のほかの使い方（ローカル・自社運用）は、完全に自由とする。**
   - 個人や会社が GitHub からリポジトリを取得し、社内の Mac や自分のサーバーで動かしてよい。
   - 運営は、それらの機械とつながず、公式のサポートもしない。保守とセキュリティは、すべて使う人の責任とする。
   - 常に GitHub の最新の版を自分で取得して使う前提とする。
   - SIer などが、導入やサポートを事業として行うことも拒まない。
3. **自分で入れやすいよう、セットアップのスクリプトを GitHub に置く。**
   - (a) Linux（Ubuntu など）のサーバーや、会社が持つ専用のサーバー向け。
   - (b) Mac のローカル環境向け。外部の LLM にデータを送りたくない利用者が、Mac Studio などでローカル LLM と動かせるようにする。
4. **自分で動かす人には、オープンソースとして自由に使ってもらい、知見を返してもらう。** 自分で動かすのが難しい人には、開発の成果をクラウド版で手軽に使ってもらい、運営の費用を負担してもらう。

## 理由

- サーバーを持ち、運用し続ける費用は、クラウド版で使う会社にだけかかる。その分の対価をいただくのが筋が通る。
- 自社運用に公式のサポートを付けると、少ない運営の手がクラウド版の安全と開発から取られる。サポートしないと決めておけば、自由に使ってもらえる範囲を広げられる。
- 外部の AI にデータを出したくない需要と、ローカル LLM の流れがある。自社運用を自由にしておけば、運営が手を出さずにその需要に応えられ、使った人の知見が本体に戻る。

## 影響

- **ローカルの形の仕組み（第8.6節）は残す。読み方を変える。**
  - 導入・更新・控え・遠隔の保守・稼働の知らせ・管理者ページの「機械」は、使う人と、保守を引き受ける人（SIer など）が自分で使う仕組みとして残す。
  - 「運営が導入する」「運営と保守の契約を結ぶ」「運営の Tailscale」は、公式の提供としては行わない。
  - **運営への稼働の知らせ（第8.6.8節）は、送る側・受ける側ともなくした**（同日に三浦さんが、マスター管理画面の「ローカルの形の機械」も要らないと決めた。移行 175 で表 `ops.machines` を消した。Q-209 は取り下げ）。
- **運営は、クラウド版の導入の支援も提供しない**（2026-10-30 に三浦さんが決めた。Q-292）。Q&A を用意するか、コミュニティを作ってそこで行う。第三者が導入の支援をして収益を上げるのは自由。**拡張機能はばらばらに販売しない**（同日に三浦さんが決めた）。クラウド版の料金は、使うか使わないかに関わらず同じにし、販売手数料・課金の代行・収益分配もしない（第21.7節。Q-14 は取り下げ）。
- **Linux のサーバーで 1 社だけを動かすスクリプトが要る。** いまの `deploy/vps/` はクラウド版（マルチテナント）の配備のため（Q-291）。
- **ほかの人が、ソースを使ってクラウドのサービスを運営するのは自由で、歓迎する**（Apache License 2.0 のとおり。2026-10-30 に三浦さんが決めた。Q-293）。ただし「M2Office」は登録商標にし（出願はこれから）、同じ名前は使わせない（Q-160）。
- README に、自社運用は無保証で公式のサポートが無いこと、知見は GitHub で受けることを書く。
