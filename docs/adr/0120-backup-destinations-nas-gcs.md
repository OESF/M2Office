# ADR-0120: 控えの置き場を、ローカルの形は社内の NAS（足せるが消せない形）と持ち出すディスク、クラウドの形は Google Cloud Storage（東京）にする

- 状態: 採用（ローカルの形は第 0.501.0 版、クラウドの形は第 0.502.0 版で提案し、2026-10-31 に合意して第 0.503.0 版で実装）
- 日付: 2026-10-31
- 関係: 仕様書 第8.6.5節・第20.4.6節、Q-38・Q-156、ADR-0077（Mac のパッケージ）、ADR-0118（収益はクラウド版だけ）

## 背景

控えを守るものは 2 つある。公開を予定しているクラウドの形のサーバー（Xserver の VPS）と、ローカルの形で Mac mini に入れる機械である。

- クラウドの形は、仕様書では国内の S3 互換の置き場へ送る案だった。三浦さんは、契約する会社が増えると管理が大変になるので、できる限りまとめたい（2026-10-31）。
- ローカルの形の最初の機械には、8TB の NAS を用意し、NAS から USB のディスクへさらに控えて、別の場所に保管する予定である。患者の情報を扱う会社もある。
- これまでのローカルの形の「社外の控え」は、S3 互換の置き場だけを送り先にしていた。

## 決定

1. **ローカルの形**
   - 毎晩の控えは、これまでどおり機械に直接つないだディスク（RAID とは別）に取る。NAS をそのまま控えの置き場にしない。ネットワークの共有は、裏で動く専用の利用者から見えなくなることがある。前の控えと同じファイルを共有して場所を取らない仕組みも効かない。何より、機械が乗っ取られると同じ権限で NAS の控えまで消される。
   - 別の置き場として、**社内の NAS で動かす restic の rest-server** を選べるようにする。rest-server は**足せるが消せない形**（`--append-only`）で動かす。機械は古い控えを消さない。間引くのは NAS の管理者が NAS の上で行う。
   - NAS の側で、変更できないスナップショットを毎日取ることを勧める。
   - NAS から持ち運べるディスク（USB など）へ、NAS の機能でコピーし、2 台を交互に別の場所に保管することを勧める。中身は restic で暗号化されたままなので、ディスクをなくしても読めない。鍵の紙は、ディスクと別の場所に保管する。コピーと保管は会社の作業で、M2Office は行わない。
   - 画面と知らせの言葉は、NAS と社外のどちらにも当たるよう「別の置き場の控え」にする。
2. **クラウドの形**
   - 社外の置き場を **Google Cloud Storage の東京（asia-northeast1）の単一のリージョン、Standard のクラス**にする。従量の課金。
   - 控えだけの専用のプロジェクトとバケットを作る。請求先は、Gemini と Google のログインで使っているものと同じでよい。
   - **削除（復元可能）（ソフト削除）を 30 日**にする。VPS には、そのバケットのオブジェクトを読み書きする権限だけを持つ専用のサービスアカウントを渡し、バケットの設定を変える権限は渡さない。
   - pgBackRest（`repo1-type=gcs`）と restic（`gs:`）は、Cloud Storage へ直接送る。どちらも VPS の上で暗号化してから送る。

## 理由

- 控えの最大の敵は、機械と同じ権限で控えまで消されることである（ランサムウェア・乗っ取り）。
  - ローカルの形は、足せるが消せない受け方・変更できないスナップショット・ネットワークから切り離したディスクの 3 つで、どれか 1 つが破られても戻せる。
  - クラウドの形は、ソフト削除の期間をバケットの設定で決め、VPS にはその設定を変えさせない。VPS が乗っ取られて消されても、30 日のうちなら運営が戻せる。
- restic は送る前に暗号化するので、NAS・持ち出すディスク・社外の置き場のどこにあっても、鍵の紙が無ければ読めない。
- Google Cloud は、Gemini と Google のログインですでに使っている。新しい会社と契約せずに済み、契約の管理が増えない。
- pgBackRest と restic がどちらも Cloud Storage に直接送れるので、WebDAV を経由する作りより簡単で、データベースの変更の記録を VPS のディスクを経由せずに送れる。
- 料金は控えの量に比例し、数百 GB までなら固定の料金の置き場より安い（東京の Standard は 1 GB あたり月 0.023 ドル。2026-10-31 に確かめた）。

## 検討した代わりの案

- **Xserver ドライブ**（契約を Xserver に一本化する案）。2026-10-31 に開発の機械で確かめた。
  - restic を rclone の WebDAV 経由で使える（rclone の種類は `other`。`nextcloud` では PATCH が使えず止まる）。225 MB を 46 秒で送り、19 秒で戻せた。全部を読み戻す確かめも通った。
  - 消したファイルはごみ箱から戻せたが、同じ ID とパスワードでごみ箱も空にできる作りのため、乗っ取りの備えには、運営の機械が別のユーザーへ取りに行く仕組みが別に要る。
  - 中身のソフトが古い版（Nextcloud 16.0.4）。規約に自動の控えを禁じる条項は無い。
  - 試しの置き場と rclone の設定は残してある。Cloud Storage が使えなくなったときの代わりにする。
- **国内のリージョンを選べる S3 互換の置き場**（Wasabi の東京など）。契約する会社が 1 つ増える。

## 影響

- `packages/core/src/machine/offsite.ts`: 置き場に `rest:` を受け、rest-server の利用者と合言葉（`M2O_OFFSITE_REST_USER`・`M2O_OFFSITE_REST_PASSWORD`）と証明書（`M2O_OFFSITE_CACERT`）を子の環境変数にだけ渡す。`rest:` の置き場では `forget --prune` を走らせない（第 0.501.0 版）。
- `deploy/onsite/setup.sh`・`m2office.env.template`・`README.md`: NAS か S3 互換かを選べるようにし、NAS の側の用意（rest-server・スナップショット・持ち出すディスク）を書く（第 0.501.0 版）。
- 管理者ページの「機械」とヘルプの言葉を「別の置き場の控え」に改める（第 0.501.0 版）。
- クラウドの形の控え: `deploy/vps/backup/`（毎晩の控えと月に 1 回の確かめ）、`setup.sh` の社外の控えの段、`update.sh` の戻す点、マスター管理画面の「稼働状況」の「社外の控え」、運営のマニュアル 第 13 章 手順 9（第 0.503.0 版）。
- M2Medical は、控えの仕組みを M2Office から写していれば、同じ変更が要るかを M2Medical の側で決める。
