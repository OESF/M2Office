# ADR-0057 名刺を交換した相手のメールの署名から、異動・昇進・電話の変更を連絡先に反映する

## 背景

- 名刺はもらった日の中身のままで、異動・昇進・電話番号の変更に追いつかない。新しい名刺をもらうまで、連絡先は古いままになる。
- 取引先から届くメールの署名には、今の会社・部署・役職・電話が書いてある。多くの会社はすでに M2Office に Gmail を読む許可を出している（受信箱整理・ブリーフ）。
- 人に「名刺の中身が変わっていませんか」と確かめさせる形は、ADR-0028 に反する。

## 決定

1. **名刺を交換した相手からメールが届いたら、差出人本人の署名を名刺と比べ、変わった項目だけを連絡先に反映する。** 人に確かめさせない。
2. **見るのは、差出人のアドレスが連絡先のアドレスと同じで、差出人のドメインの認証（DMARC か、ドメインに合う DKIM）が通ったメールだけ。** 連絡先に無い差出人のメールは本文を取らない。
3. **署名に無い項目は消さない。表記の違いは変化としない。氏名・メールアドレス・範囲は変えない。** 新しい日付の情報だけで上書きする。
4. **前の値は変更の記録に残し、詳細の「戻す」で戻せる。** 戻した値は、署名が同じ値を示している間は再び変えない。
5. **知らせは週次ブリーフに 1 行ずつ載せる。** その場では知らせない。
6. **この機能のために Gmail の権限を新しく求めない。** 許可のある人のメールだけを使う。会社ごとに切り替えを 1 つ置き、既定は入。
7. **件名・本文・署名の全文は残さない。** 残すのは連絡先の値と、変えた項目の前と後だけ。値は連絡先がある間残す（Google のデータの 7 日の決まりの例外。Q-152）。連携の解除では戻さず、本人か会社から削除を求められたら、その人のメールから変えた値を前の値に戻して変更の記録を消す。

## 理由

- 名刺を最新に保つ手間を人に求めず、日々のメールから自然に新しくなる。営業の場面では、昇進や異動を知ること自体に価値がある（お祝いの連絡など）。
- 差出人のアドレスは偽れるため、ドメインの認証を条件にする。名刺を交換した相手のアドレスに限ることで、宣伝のメールや知らない人の署名で連絡先が汚れることを防ぎ、推論の費用も抑える。
- 署名は名刺より項目が少なく、出向先の名前で署名する人もいる。消さない・表記の違いを無視する・戻せるの 3 つで、誤りの影響を小さくする。確認の画面ではなく「戻せる」で守るのは ADR-0056 と同じ考え方である。
- 会社で共有の名刺で「誰のメールから分かったか」を出すと、誰が誰とやり取りしているかが社内に広まる。出どころは「メールの署名」とだけ出す。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 変わっていたら、本人に「反映しますか」と尋ねる | 人に判断させる画面を増やす（ADR-0028）。戻せる形で足りる |
| 名刺の無い人のメールの署名からも連絡先を作る | 会ったことの無い人や宣伝の差出人が会社の連絡先に大量に入る |
| 本文の「異動のお知らせ」から、別のアドレスの人を同じ人とみなす | 差出人が違うと同じ人かを確かめられず、なりすましの余地がある。事例が出たら決める |
| その場で本人に知らせる | 取引先が多い人では知らせが増えすぎる |

## 影響

- ワーカーに、1 時間ごとの見回り（人ごとの前回の位置、連絡先ごとの最後に推論を呼んだ日時）を足す。
- 表 `contact_change`（変更の記録）を足し、詳細の「以前の会社・役職」に並べる。道具 `contacts.changes` を足す。
- 週次ブリーフの伝えることに 1 項目を足す。
- 管理者ページの名刺管理の設定に切り替えを 1 つ足す。
