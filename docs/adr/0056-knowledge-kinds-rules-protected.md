# ADR-0056 組織知識を社内規程・議事録・秘書が学んだことに分け、規程は版を残して消さず、秘書が学んだことは定期的に整理する

## 背景

- 組織知識は 1 つの表と 1 つの一覧で、管理者が登録した社内規程、議事録の業務が登録した議事録、秘書が会話から加えたもの（昇華）が同列に並び、同じ「削除」のボタンで、確認を 1 回押すと取り戻せない形で消えた。規程を編集すると前の本文は残らなかった。
- 三浦さんの指摘（2026-09-30）: 社内規程・旅費規程のような会社のルールは管理の手段であり、人事・給与もそれをもとにデータを取る。消されると会社の根幹が狂う。検索で一緒に探すのは問題ないが、画面と管理は分けるべき。
- 秘書が学んだことは増え続けるだけで、要約・整理・減らす仕組みが無かった（本番の会社で、社内規程 3 件・議事録 4 件に対し、秘書が学んだこと 94 件、個人の記憶 628 件）。秘書が学んだ一文が規程の条文より先に答えの根拠に出る事例も 2026-09-29 に見つかっている。

## 決定

1. **組織知識を、登録の経路で 3 つの種類に分ける。** 社内規程（管理者が登録）・議事録（業務が登録）・秘書が学んだこと（秘書が加える）。人に種類を選ばせない。検索は 3 つをまとめて行う。
2. **根拠は社内規程 → 議事録 → 秘書が学んだことの順に並べる。** 食い違えば規程を採る。
3. **社内規程は版を残す。** 版ごとに施行日を持ち、施行日で切り替える。改定前を尋ねられたら版と施行日を添えて答える（Q-82 を決定）。
4. **社内規程と議事録は消さずに廃止する。** 確認の画面を足さず、廃止から 1 年は戻せる形で守る。古い版と廃止した規程の本文は 7 年残す（人事・給与の記録と同じ）。秘書・業務・会話の訂正は規程を書き換えない。
5. **人事・給与は、登録した社内規程から設定の案を作れる。** 規程を改定したら、今の設定と食い違う項目を担当者に示す（直すかは担当者）。
6. **秘書が学んだこと（会社の知識と各人の記憶）は、週 1 回、秘書が整理する。** 同じ事柄をまとめる・新しい事実で古くなったものと半年使われないものをしまう。しまったものは戻せ、1 年で消す。本人の記憶は本人の処理の中だけで扱う。

## 理由

- 規程は会社の決まりそのもので、給与の計算の根拠にもなる。取り戻せない削除と上書きは許されない。一方、承認や確認の画面を増やすのは ADR-0028 に反するため、確認ではなく「戻せる」「版が残る」で守る。
- 秘書が学んだことは、少々の誤りを会話で直して育てる前提（ADR-0028）だが、量が増えると古い事実や重なりが残り、答えの材料に選ばれる枠を奪う。人に一件ずつ見直させず、秘書が自分で整理する。
- 「しまう」を挟んで 1 年で消すことで、整理の誤りを戻せるようにしつつ、預かる量を減らす（ADR-0027 の「全て記憶する」は、使える形で持ち続けることと読み、使われないものを永久に抱えることとはしない）。

## 影響

- 移行: 既存の知識を種類に分ける（管理者の登録は社内規程、業務の登録は議事録、昇華は秘書が学んだこと）。版の表を足す。個人記憶と知識に、状態・最後に使った日・まとめた先を足す。
- 整理に推論の費用がかかる（週 1 回・上限つき）。推論が使えない環境では整理しない。
- 人事・給与の「規程から設定の案」に、登録した規程を選ぶ道と、改定の見張りが加わる。
- 監査ログに `knowledge.rule.*`・`knowledge.consolidate`・`memory.consolidate` を足す（中身は入れない）。
