## 背景

- 第 0.219.0 版で、会社の Web サイトのコラムを AI が出典つきで書き、表現の決まりに照らして赤入れし、責任者が承認して載せる機能を仕様に起こした（第32章）。
- 段 1 に関わる未決事項（形・公開のしかた・表現の決まりの範囲・AI の表示・画像・料金）が残っていた。

## 決定

1. **形は内蔵の拡張「Web のコラム」**（ID `web-columns`、既定は切り、無償で同梱）。左のメニューの業務の 1 つとして出し、会社の設定の区分 `webColumns` で入り切りする（Q-161・Q-166 の案）。
2. **WordPress には下書きとして入れるまで**にし、公開は WordPress の側で押す（Q-162 の案）。つなぎは REST API とアプリケーションパスワード（Basic 認証）。パスワードは会社の接続の秘密の値として暗号化して預け、つながるかを確かめてから預ける。
3. **WordPress に入れることは社外への送信として扱う**（危険度 `external-send`、いつも人に判断を求めるツールに入れる）。業務「コラムを WordPress に入れる」は、用意 → 承認 → 入れるの 3 段で、**承認できるのは管理者と承認者のロールの人**。承認の前の確かめで版の指紋を記録し、承認の後に版が変わっていれば入れない（まとめてのメールと同じ形）。
4. WordPress につないでいない会社では、承認すると「承認済み」にし、本文（HTML と Markdown）を写して使う。
5. **赤入れは、決まったプログラムの確かめと推論の確かめを合わせる。** 言葉の一覧は業種ごと（全般・医療と歯科・薬局と化粧品と健康食品・士業）に運営が持ち、会社に作らせない（Q-163 の案、ADR-0028）。推論の指摘は、本文にそのまま無い箇所を捨てる。赤入れは助言で、本文を勝手に直さない。
6. **AI が書いたことの表示は既定で入**（Q-164 の案）。画像は作らない（Q-165 の案）。
7. 直すたびに版を足し、前の版を消さない。承認待ちの間は直せない。削除できるのは承認へ進めていないものだけ。
8. 書き上げは裏で進め、止まったもの（15 分）は「書けませんでした」にする。会社の AI の方針が「ローカルだけ」なら、Web で調べられないため書かない（Q-168 は未決のまま）。

## 理由

- WordPress への公開まで M2Office から行うと、取り下げ・予約公開・写真の差し込みなど WordPress の機能を作り直すことになる。下書きまでなら、最後の確かめを慣れた画面で行える。
- 表現の決まり（医療広告ガイドラインなど）に当たる記事を出すと、会社の信用と法の責任に関わる。社外に出すものとして、責任者の承認を必ず挟む。
- 言葉の一覧を会社に作らせると、作られないまま使われる。運営が業種ごとに持てば、入れた日から効く。

## 影響

- 移行 `062_web_columns.sql`（会社の設定の区分・接続の秘密の値の種類 `wordpress`・コラムと版の表）。
- ツール `columns.draft`（write-internal）・`columns.preview`（read）・`columns.place`（external-send）。業務「コラムの下書き」（秘書から）と「コラムを WordPress に入れる」。
- Q-161〜Q-166 は「段 1 は案のとおり実装」とし、三浦さんの確認で確定する。違う決定になれば、この ADR を改める。
