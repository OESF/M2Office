# ADR-0029 業務エージェントは「スキルの形式（SKILL.md）＋α」で書く

## 背景

2026-09-26、三浦さんが拡張機能の作り方を見直し、次のように指摘した。

> JSON での定義があまりにもプログラマチックで難しすぎる。もともとスキルをベースに書けることを前提にしていたのに、
> 独自のプログラミング言語のようになってしまった。基本はプロンプトで書けるようにしたい。
> そうでないと、よいスキルを M2Office の環境（管理・監督のある UI）に移すことができない。それもセールスポイントの 1 つ。
> スキルのフォーマット＋αで書けるのが最高。

いまの業務エージェントは JSON のエージェント定義（第9.2節）で、段（`steps`）・入力のスキーマ・承認の段・上限・ヘルプを
すべて書く必要がある。見本の「あいさつ」ですら、定義だけで 50 行近い。Agent Skills の SKILL.md（名前と説明のフロントマターと、
Markdown の指示）とはまったく形が違い、既存のスキルを持ち込めない。

## 決定

**1. 業務エージェントは SKILL.md で書ける。** SKILL.md は Agent Skills と同じ形（フロントマターの `name`・`description` と、
Markdown の本文）である。**本文がそのまま業務の指示になる。** 既存のスキルは、書き換えずにそのまま取り込める。

**2. Agent Skills の決まりに準拠する。M2Office に固有のこと（＋α）は `metadata` の中に `m2office-` で始まる名前で置き、すべて任意にする。**
決まりでは `metadata` は文字の値だけを持つため、入力の欄のような複数の行は YAML の複数行の文字（`|`）で書く。
画面の名前・使う道具・入力の欄・実行例など。書かなければ既定で動く（読むだけの道具、自由記入の依頼の欄 1 つ）。
**ほかの環境（Claude など）でそのまま動くことは求めない**（プラットフォームが違う。三浦さんの判断）。目標は、公開されているスキルを土台に持ち込めること。
決まりと合わなくなったときは、ファイルの名前を M2Office 独自の名前（例: `JOB.md`）に変えて区別する。

**3. 段と承認の段は、書かせずに組み立てる。** 取り込むときに、SKILL.md から第9.2節のエージェント定義を作る。
送る道具（`external-send` 以上）を使うスキルには、「作業 → 承認 → 送る」の形を自動で組む。承認は、社外にもお金にも
関わらなければ自動で通る（ADR-0028）。書き手は承認の置き方を知らなくてよい。

**4. JSON で書く形は廃止の方向にする。** 中ではエージェント定義（JSON）で動かし、承認の強制・監査・権限の同意・区画は変わらない。
`manifest.json` と `agents/*.json` の拡張機能の取り込みは、しばらく受け付ける（新しく書かない）。

**5. プログラムは実行しない（不変則 I-7 は変えない）。** スキルに付いた `scripts/` などのプログラムは、取り込むときに除き、
除いたことと、本文がそれに頼る部分は動かないことを示す。参考の資料（`references/` などの Markdown・テキスト）は持ち込め、指示に添える。

## 理由

- 業務を知る人が、ふだんの言葉で業務を書ける。第12.2.1節の「作る人は業務知識のみ」を本当にする
- 公開されている数多くのスキルを土台に、管理・監督・承認・監査のある M2Office の環境で業務として展開できる（販売の売り）
- 手順や承認を推論の指示と基盤の強制に任せる方針（ADR-0023・ADR-0028）と合う。段を書かせる必要が薄れた

## 影響

- 用語: 「スキル」を技術文書でも使う（SKILL.md で書いた業務エージェント）。第12.1.1節と Q-70 を改める
- パッケージ: SKILL.md を含むフォルダの ZIP（`.zip`・`.skill`・`.m2ext`）か、SKILL.md 1 つを取り込める
- フロントマターの読み取り: YAML の基本の形（キーと値・`metadata` の 1 段の入れ子・複数行の文字）だけを読む自前の読み取りにし、依存のパッケージは増やさない（第20.8節）
- 第12.7節の「利用者にエージェントを一から設計させない」は、「手順を設計させない」に読み替える（文で書くのはよい）

## 採らなかった案

- **JSON の定義を画面の入力で作らせる**: 段・スキーマ・承認を画面で組ませても、難しさは変わらない
- **独自の Markdown の書き方（段の見出しなど）を決める**: スキルとの互換が崩れ、持ち込み・持ち出しができなくなる
