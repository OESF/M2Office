# ADR-0028 人に判断を求めるのは、社外に出るものとお金の確定だけにする。ほかは秘書と業務が自分で決める

| 項目 | 内容 |

| 状態 | 採用（2026-09-26 に三浦さんが合意） |
| 決定日 | 2026-09-26 |
| 決定者 | 三浦 |
| 関連 | 仕様書 第5章（原則 u11）・第8.3節（不変則 I-3・I-10）・第9.3.3節・第9.4節・第9.5.2節・第11.3節・第11.5節・第11.7.7節。ADR-0016（改める）、ADR-0010（承認の回数を改める）、ADR-0023、ADR-0024、ADR-0027 |

## 背景

2026-09-26、三浦さんから次の指摘を受けた。

> いろんなものが手間がかかりすぎる。AI に任せている意味がない。承認や、学習したことを 1 つずつ公開してよいか・覚えるかを
> 決めなければならない。これをすべて自動にしてほしい。少々間違った学習はやむを得ない。積み重なって大きな知識になる。
> 人の判断に頼るのは、外部にメールを送る、決算の数字など、よほどのものだけ。
> 間違っていたら「違うよ、直しておいて」と言うだけ。秘書も新人教育と同じで、指摘はするが、細かい作業は秘書が自らやる。

いまの M2Office は、利用者に次の判断を 1 件ずつ求めていた。

| 求めていた判断 | 誰が |
|---|---|
| 社内への書き込み（ToDo・予定・ドライブへの保存・本人宛の通知）の「操作の確認」 | 依頼した本人（既定で必要） |
| 議事録の承認①（内容）・承認②（Chat への共有・社内への公開・知識への登録） | 承認者 |
| 個人の記憶を会社の知識にするか（昇華）の二重の承認 | 本人と、管理者または承認者 |
| 覚えたことの確認（新しく覚えたことの一覧） | 本人（ADR-0027） |

## 決定

**1. 人に判断を求めるのは、次の 2 つだけにする。**

| 人が判断するもの | 例 |
|---|---|
| **社外に出るもの** | メールの送信（宛先に関わらず）。社外の人が入れる Chat のスペースへの投稿。社外の人への共有。社外の人を招く予定の登録・変更・取り消し |
| **お金の確定** | 請求の確定、会計への書き込み（`financial`）。社外に出す書類やメールに金額が入るときは、社外に出るものとして判断を求め、承認の画面で金額を目立たせる |

それ以外（社内の人だけの Chat への投稿、ToDo・予定・ドライブへの保存、社内への公開、知識への登録、学習、会社の知識にするかの判断）は、
**秘書と業務が自分で決めて行う。** 行ったことは実行の詳細と監査ログに残し、あとから見て、会話で直せるようにする。

**2. 社外かどうかは、送り先を実際に確かめて決める。** 道具の区分（危険度）は「送り得る先」で決まっていたが、
これからは承認の前の確かめ（ADR-0024）で送り先を調べ、**社外が含まれるときだけ**人の判断に回す。
確かめられないときは社外とみなす（人に回す）。

**3. 承認の段は、承認の後に行うことに社外に出るものもお金の確定も無ければ、自動で通る。**
承認の直後の段は承認の前に組み立てる（ADR-0023）。組み立てた操作がすべて社内のものなら、人を待たずに記録どおり実行する。
業務の定義は変えない（議事録作成は、社内のスペースに共有するなら最後まで自動で進む）。

**4. 会社の知識にするか（昇華）は、秘書が判断して自動で登録する。** 本人の承認も、管理者の承認も求めない。
本人だけに関わること（好み・個人的な事情）、他人の個人情報、権限区画のデータは会社の知識にしない。
管理者は、会社の知識の一覧で、秘書が登録したものを見て消せる。

**5. 間違いは会話で直す。** 本人が「それは違う、〇〇だよ」「覚えたことを直しておいて」と言えば、秘書が自分で記憶を直す。
秘書が会社の知識にしたものも、会話で直せる。管理者が登録した規程は会話では書き換えず、管理者に伝えるよう案内する。
個人設定の「記憶とデータ」は、見たい人が見るための場所とし、確認を求める印は出さない。

**6. 言い換えは、探すたびに秘書が考える。** 人に言い換えの表を作らせない（「育休」が「育児休業」のことだと、人なら想像がつく）。
管理者ページから言い換えの登録を外す。以前に登録した組と標準の言い換えは、そのまま効かせる。

**7. 画面に説明文を常に出さない。** 1 回見れば分かる案内や空の欄の説明は置かず、場所は中身に使う。分からなければ秘書に聞く。
三浦さんは「20 年前の堅苦しい業務システムに見える。AI を使っている雰囲気が無い」と指摘した（2026-09-26）。

## 理由

- 利用者に 1 件ずつ判断を求めると、判断が手続きになり、使われなくなる。細かい判断を代わりに行うことが、秘書を置く意味である
- 間違った学習の損害は、社外への送信やお金の確定に比べて小さく、会話で直せる。直すこと自体が秘書の学習になる
- 取り消せない損害（社外への送信・お金）だけは、人が見て決める。ここは承認ゲートとして基盤が強制し続ける

## 影響

- 不変則 I-3 を「社外への送信とお金の確定は、承認を通過したもののみ」に、I-10 を「個人記憶は、本人の同意または秘書の昇華の判断なしに他者へ開示されない。本人だけに関わることは昇華しない」に改める
- 会社の自動化ポリシーの既定を「社内への書き込み: 承認なし」に改める（厳しくしたい会社は「承認が必要」を選べる）
- 承認トレイに並ぶのは、社外に出るものとお金の確定だけになる
- 昇華の二重の承認（ADR-0016）を廃止する。個人設定の「会社の知識にする提案」は、秘書が会社の知識にしたものの記録に変わる

## 採らなかった案

- **危険度ごとの会社の設定を増やす**: 設定を増やすほど、利用者と管理者の手間が増える。三浦さんの方針に反する
- **昇華に管理者の確認だけ残す**: 三浦さんが「AI が判断して自動で登録」を選んだ（2026-09-26）
