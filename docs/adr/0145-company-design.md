# ADR-0145 会社の見た目を 1 つの決まりにまとめ、DESIGN.md を書き出しと取り込みの口にする

| 決定者 | 三浦 |

## 背景

2026-11-13 に三浦さんが、話題の DESIGN.md（Google Labs が 2026-04 に公開した、AI に見た目の決まりを伝える Markdown の形式。アルファ版）をうまく使えないかと尋ね、各社の見た目を読み解いた DESIGN.md を公開している getdesign.md から取ってきて、自分のサイトに反映できないかと尋ねた。

いまの M2Office は、コラムのカバーと販促物がそれぞれロゴから色を推し量り、スライドは見た目の型を別に持つ。会社の見た目の決まりは 1 つにまとまっていない。三浦さんの 2 つのサイトは、どちらも `theme.json` を持たないクラシックのテーマ（LION MEDIA・Lightning）で、見た目を REST で直には書き換えられない。

## 決定

1. **会社の見た目を 1 つの決まりとして持つ。** 色・文字・形・写真と絵の雰囲気・文の調子。版を重ね、前の版に戻せる。
2. **AI が作る。** ロゴ・会社のサイト・これまでの販促物から作り、直しは会話で頼む。人に色の表を作らせない。
3. **DESIGN.md は口にする。** 中の形は M2Office のものとし、書き出しと取り込みのときに DESIGN.md に変える。仕様が変わっても口を直すだけで済む。
4. **ほかの会社の DESIGN.md は雰囲気を借りる。** 色は会社のロゴに合わせて直すのを既定にし、名前・ロゴ・画像は使わない。
5. **M2Office の成果物をそろえる。** カバー・アイキャッチ・挿絵・販促物・スライド・サイネージ・会社の名前で書く文。
6. **Web サイトは作りに合わせる。** クラシックのテーマは、貼る CSS とテーマの設定の一覧を渡す（M2Office は書き換えない）。ブロックのテーマは、全体のスタイルに承認の後に入れて元に戻せるようにする（第45.12節を見直す）。

## 理由

- **1 つにまとめる:** 成果物ごとに色を推し量ると、そろわない。会社の見た目は会社の情報の一部である
- **AI が作る:** 中小企業に見た目の決まりを作る人はいない（ADR-0028）
- **口にする:** DESIGN.md はアルファ版で、形が変わる見込みである。中の形を外の形に縛らない
- **雰囲気を借りる:** ほかの会社の色をそのまま使うと、その会社に見え、なりすましのおそれがある。getdesign.md の決まりも、なりすましとロゴの写しを禁じている
- **クラシックのテーマは渡す:** 追加 CSS もテーマの設定も REST に出ておらず、書き換えるにはプラグインを入れることになる（ADR-0140 の「相手のサイトに何も入れない」に反する）

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| DESIGN.md をそのまま会社の見た目として持つ | 形が変わる。外のファイルの中の指示を読み込むおそれもある（不変則 I-6） |
| 補助のプラグインを入れて、クラシックのテーマの CSS を M2Office が書き換える | 相手のサイトに何も入れない決まりに反する |
| テーマをブロックのテーマに切り替える | サイトの作り直しになる |
| 見た目は扱わない（いまのまま） | 成果物がそろわず、DESIGN.md を使う AI の道具とも合わない |

## 影響

- 新しい章（第46章）と表（`company_designs`）。コラムのカバー・販促物・スライドの色の決め方が、会社の見た目を先に使うよう変わる
- 第45.12節の「デザインは行わない」を、ブロックのテーマの全体のスタイルに限って見直す（Q-357）
