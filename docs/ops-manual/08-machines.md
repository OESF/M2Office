# 第 8 章 ローカルの形の機械

会社の社内の機械（Mac mini・Mac Studio）に入れた M2Office（**ローカルの形**）は、保守の契約がある場合、1 時間に 1 回、運営に**稼働の知らせ**を送ります。左のメニューの「**ローカルの形の機械**」で、その知らせを見守ります。

知らせの中身は、件数と状態だけです（版・各部が動いているか・控えの結果・ディスクの空き・証明書の残りの日数・更新の結果）。会社の名前・人の名前・業務の中身は送られてきません。

## 1. 機械を登録する（運営管理者）

導入の前に、機械を登録して、受け口と鍵を用意します。

1. 「ローカルの形の機械」を開き、**呼び名**（運営が見分けるための名前）を入れて「登録する」を押します
2. 出た 3 つの値を、導入する技術者に渡します

| 値 | 導入のときに入れるところ |
|---|---|
| 運営の受け口 | `setup.sh` の「運営の受け口（https）」 |
| 鍵 | `setup.sh` の「運営からもらった鍵」 |
| 機械の番号 | `setup.sh` の「機械の番号」 |

- **鍵はいまだけ出ます。** 閉じると二度と見られません。なくしたら、機械を削除して登録し直します
- 鍵は、メール以外の手段で技術者に渡します

## 2. 一覧の見方

| 列 | 内容 |
|---|---|
| 呼び名・番号 | 登録したときの呼び名と機械の番号 |
| 版 | 機械で動いている M2Office の版 |
| 最後の知らせ | 最後に知らせが届いた日時 |
| データベース ／ ワーカー ／ 入口 ／ ローカル AI | 各部が動いているか（○・×・—） |
| 控え ／ 戻せるか ／ 社外 | 毎晩の控え・毎月の戻せるかの確かめ・社外の控えの結果 |
| データの空き | データのディスクの空き（割合） |
| 証明書 | 証明書の残りの日数 |
| 印 | 下の「印」 |

## 3. 印

| 印 | 付く条件 | すること |
|---|---|---|
| まだ届いていない | 登録してから一度も知らせが来ていない | 導入が済んでいるか、受け口と鍵の入れ間違いがないかを技術者に確かめる |
| 3 時間届いていない | 最後の知らせから 3 時間を過ぎた | 機械が止まっている・社内のネットワークが切れている・会社が知らせを切った、のどれかです。会社に連絡する |
| 止まっている部分 | データベース・ワーカー・入口・ローカル AI のどれかが止まっている | 会社に連絡し、遠隔の保守を開けてもらって技術者が調べる |
| 控えの失敗 | 毎晩の控えか、毎月の戻せるかの確かめに失敗した | 控えのディスクの空き・つながりを、会社と技術者が確かめる |
| 社外の控えの失敗 | 社外の控え（会社が選んだときだけ）が送れないか、確かめに失敗した | 置き場の鍵や契約が切れていないかを、会社に確かめる |
| 空きが少ない | データのディスクの空きが 1 割を切った | ディスクを足すか、要らないデータを整理するよう会社に伝える |
| 証明書の期限が近い | 証明書の残りが 14 日を切った | 証明書は自動で取り直すはずなので、取り直しに失敗している。技術者に連絡する |
| 更新の失敗 | 夜の自動の更新に失敗した（前の版に戻した場合を含む） | 技術者に連絡する |

印のある機械の数は、左のメニューの「ローカルの形の機械」の横と、会社一覧の要約に出ます。運営の画面からは、社外にメールなどで知らせません。毎日一度は画面を開いて確かめてください。

## 4. 機械を削除する（運営管理者）

使わなくなった機械は「削除」で外します。その機械からの知らせは、受け取らなくなります。

## 5. 遠隔の保守について

機械に入って調べるときは、**会社の管理者**が、会社の管理者ページの「機械」で時間を限って「遠隔の保守を開ける」を押します。運営の側からは開けられません。開けた時刻とつないだ相手は、会社の監査ログに残ります。
