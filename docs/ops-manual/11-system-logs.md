# 第 11 章 システムログと証拠保全

左のメニューの「**システムログ**」で、すべての会社（サブドメイン）のシステムログを見て、ダウンロードできます。攻撃やその疑いがあったときは、ここから証拠を保全します（仕様書 第16.10節）。

## 1. システムログとは

API・ワーカー・運営の画面の動きの記録です。要求の経路・状態・時間・会社と利用者の ID・失敗の理由などで、**業務の中身（メール・文書・会話・議事録）は入っていません**。
そのため、会社の画面を見る代理アクセス（第 6 章）の手続きは要りません。ただし、見たことは運営の操作の記録（第 8 章）に残り、会社で絞って見たときは、その会社の詳細（第 4 章）の履歴にも残ります。

クラウドの形では、会社の管理者は自分の会社のシステムログを見られません（会社の中で起きたことは、会社の監査ログで見ます）。ローカルの形の機械では、その会社の管理者が管理者ページの「機械」で見ます。

## 2. 見る

| 絞り方 | 内容 |
|---|---|
| 期間 | 直近 1 時間・24 時間・7 日・28 日 |
| レベル | すべて・警告とエラー・エラーだけ |
| プロセス | API・ワーカー・運営 |
| 会社 | すべて・仕組み（どの会社にも属さない処理）・会社ごと |
| 言葉 | 文と項目に入っている言葉 |

行を押すと、利用者・要求の ID・実行の ID と項目が開きます。問い合わせの調べでは、会社から聞いた時刻と要求の ID（画面の応答の `X-Request-Id`）で絞ると早く見つかります。

「改ざんの確かめ」には、日ごとに「合っています」「合いません」が出ます。毎日、前の日のログから値（SHA-256）を作り、その前の日の値とつなげて残しています。「合いません」は、ログが後から書き換えられた疑いです。すぐに運営管理者と配備した技術者に知らせます。

## 3. ダウンロードする

「ダウンロード（JSON）」「ダウンロード（CSV）」で、絞った結果を ZIP で保存します。すべての会社のときは 1 日分まで、会社で絞れば 28 日分まで、1 回 100 万行までです。
ZIP には、ファイルの値（SHA-256）と、範囲の日ごとの改ざんの確かめを書いた `manifest.json` が付きます。

## 4. 証拠保全

攻撃やその疑い（乗っ取り・大量の持ち出し・見覚えのないログインなど）があったら、まず保全します。調べるのは保全の後です。

1. 「証拠保全」を押す
2. 会社（1 社か、全体）・期間（直近 28 日・7 日・1 日）を選び、理由を書く
3. 「保全する」を押す。ワーカーが ZIP を作り、できあがると一覧に「保全しました」と出る。会社を選んだときは、その会社の管理者全員に知らせが届く

| 項目 | 内容 |
|---|---|
| 入るもの | 範囲のシステムログ・監査ログ・不正の兆し・その時点のログイン中の端末・日ごとの改ざんの確かめの値 |
| 入らないもの | 業務の入力・成果物・会話・ファイルの中身 |
| 確かめ方 | ZIP の中の `manifest.json` にファイルごとの SHA-256、一覧に ZIP 全体の SHA-256。渡した後に変わっていないことを示せる |
| 残す期間 | **1 年間は誰も消せない**（運営管理者でも）。1 年を過ぎたら、運営管理者が理由を書いて「削除」で消せる |
| 誰ができるか | 保全を始めるのは運営者なら誰でも（緊急停止と同じく急ぐため）。消すのは運営管理者だけ |

不正の兆しの見張りが、ある人の端末を自動でログアウトさせたときは、その会社の分を自動で保全します（同じ会社で 1 日に 1 回まで）。一覧の「誰が」に「自動（不正の兆しの見張り）」と出ます。

保全したら、必要に応じて緊急停止（第 5 章）を考え、会社の管理者と連絡を取ります。ZIP を社外（警察・調査の会社）に渡すときは、渡した相手と日時を運営の記録に別に残してください。
