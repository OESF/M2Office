# 第 7 章 稼働状況

左のメニューの「**稼働状況**」で、サーバー全体が健全に動いているかを見ます。1 分ごとに読み直します。いちばん上の帯の「**更新**」を押すと、すぐに読み直します。

## 0. 全体の状態

画面を開いたら、まずいちばん上を見ます。画面が数を読んで判断し、3 段で答えます。

1. **帯**: 全体が「**平常**」「**注意**」「**警戒**」のどれかと、対応が要るものの件数。緑なら、ほかを見なくても問題ありません
2. **対応が要るもの**: 警戒を先に、1 件ずつ「何が」「詳しい数」「**すること**」が並びます。「手順を見る」で、この章や第 17 章などの手順が開きます（会社と AI の費用は、会社一覧・設定の画面が開きます）
3. **区分ごとの札**: 業務の実行・サーバーの資源・バックアップ・セキュリティ・外部の接続・稼働環境・会社・AI の費用の 8 枚。押すと、下の詳しい表に移ります

| 状態 | 意味 | すること |
|---|---|---|
| 平常 | どの区分も問題がない | なし |
| 注意 | 見ておくことがある。すぐに止まるわけではない | 「すること」を読み、その日のうちに確かめる。続くなら技術者に知らせる |
| 警戒 | すぐに手当てが要る。業務が止まっている・データを守れないおそれがある | すぐに「すること」をする。多くは配備した技術者への連絡 |

判断の決まりと、そのときにすることは次のとおりです。画面の「すること」と同じ文です。

| 区分 | 状態 | 当てはまるもの | すること |
|---|---|---|---|
| 業務の実行 | 警戒 | ワーカーが応答しない（最終応答が 3 分より前） | 業務が止まっています。技術者に連絡し、ワーカーを起動し直してもらう（`systemctl status m2office-worker`） |
| 業務の実行 | 注意 | 最も古い待ちが 5 分より前 | ワーカーが稼働中かを見る。続くなら技術者に連絡する |
| 業務の実行 | 注意 | 遅れている定時実行がある | ワーカーの止まりか待ちの詰まりを疑う。続くなら技術者に連絡する |
| 業務の実行 | 注意 | 直近 1 時間の失敗の割合が 20% 以上（10 件以上のとき） | 外部の接続で AI や Google の障害を確かめる。1 社に偏っていれば、会社一覧の「失敗」の印で確かめる |
| サーバーの資源 | 警戒 | ディスク 90% 以上 | すぐに技術者に連絡し、容量を足すか、要らないファイルを片付けてもらう（いっぱいになるとデータベースが止まる） |
| サーバーの資源 | 警戒 | データベースの接続が上限の 90% 以上 | すぐに技術者に連絡する（上限に届くと、画面が使えなくなる） |
| サーバーの資源 | 注意 | ディスク 80% 以上 | 技術者と容量を足す相談を始める |
| サーバーの資源 | 注意 | メモリー 90% 以上 | 続き、Swap も増えるなら、技術者とサーバーの大きさを上げる相談をする |
| サーバーの資源 | 注意 | CPU の負荷が 15 分の平均でコアの数を超える | 処理の暴走か攻撃を疑う。続くなら技術者に連絡する |
| サーバーの資源 | 注意 | データベースの接続が上限の 80% 以上 | 技術者に知らせる |
| バックアップ | 警戒 | 毎晩のバックアップの失敗・止まっている（26 時間）・変更の記録を送れていない・データチェックが異常 | 技術者に連絡する（[第 17 章](17-backup-recovery.md)）。変更の記録を送れていないままだと、サーバーのディスクが埋まる |
| バックアップ | 注意 | 未導入・まだ一度も取っていない | 技術者に入れてもらう（[第 13 章](13-vps-m2office-setup.md)）。入れたばかりなら、翌朝も取れていなければ連絡する |
| セキュリティ | 警戒・注意 | 「1.3 セキュリティ」の表 | 同じ表の「すること」 |
| 外部の接続 | 注意 | 接続先ごとに、24 時間の失敗の割合が 20% 以上（10 件以上のとき） | 相手のサービスの障害の情報を確かめる。続くなら技術者に知らせる |
| 稼働環境 | 警戒 | Node.js がセキュリティの修正の下限より古い | できるだけ早く、技術者に Node.js の更新を頼む（M2Office は止まらない） |
| 稼働環境 | 警戒 | Node.js のサポートが終わった | 技術者に、新しい LTS の版への更新を頼む |
| 稼働環境 | 注意 | Node.js のサポートの終わりまで 6 か月を切った | 技術者に、新しい LTS の版への更新を頼む |
| 稼働環境 | 注意 | ワーカーと API の版が違う | 更新が途中で止まったおそれがあります。技術者に知らせる |
| 会社 | 注意 | 失敗が多い会社がある（30 日に 5 件以上で 20% 以上） | 会社一覧の「失敗が多い」の印で確かめ、会社の詳細の「稼働」で、どの業務・どの接続先かを見る |
| 会社 | 注意 | 重い不正の兆しがある会社がある（24 時間） | 会社の詳細で中身を確かめ、必要なら停止を申請する（[第 5 章](05-suspension.md)） |
| AI の費用 | 警戒 | 運営の鍵の全体の上限に届いた | 運営の鍵を使う会社の AI が止まっています。設定で上限を見直すか、来月まで待つ |
| AI の費用 | 注意 | 全体の上限の 8 割を超えた | 会社一覧の「今月の AI」で、どの会社が使っているかを見る。要るなら設定で上限を見直す |
| AI の費用 | 注意 | 今月が前の月の同じ時期の 2 倍以上（1,000 円以上のとき） | 会社一覧の「今月の AI」で、どの会社が増えたかを見る |

区分の材料を読めなかったときは、平常とみなさず「注意」にし、「読めませんでした」と出します。続くなら技術者に知らせます。

各区分の詳しい表の上にも、その区分の「対応が要るもの」が、すること付きで出ます。

## 0.1 警戒のときの知らせ

警戒になったら、画面を開いていなくても分かるよう、運営の API が知らせます。5 分ごとに、画面と同じ判断をします。

- **知らせる先**: `setup.sh` で入れた Google Chat か Slack の受け口（[第 13 章](13-vps-m2office-setup.md)）。Google Chat なら、運営者が入っているスペースの「アプリと統合 › Webhook を管理」で作った URL を入れます
- **知らせるとき**: 平常・注意から警戒になったとき、警戒のあいだに新しい警戒が増えたとき、警戒が続くあいだは 6 時間ごと、平常か注意に戻ったとき（「回復」）。注意だけのときは知らせません
- **中身**: 警戒の件数と、1 件ずつ「何が」と「すること」。会社の名前・IP アドレス・利用者の情報は入れません
- **画面の帯**: 警戒のあいだは、マスター管理画面のどの画面の上にも赤い帯が出ます。「稼働状況を開く」で、この画面に移ります
- 知らせが届かないときは、運営の API の記録（システムログの「ops」）に「警戒の知らせを送れませんでした」と出ます。受け口の URL を確かめ、`setup.sh` を走らせ直して入れ直します

## 1. 稼働環境

いちばん上に、M2Office の版・API とワーカーの Node.js（系・段階・サポートの終わる日）・PostgreSQL・OS と CPU・メモリー・稼働の形・推論・起動してからの時間が出ます。クラウドの形では、これらは運営のサーバーの情報なので、各社の管理者には出しません（運営だけが見ます）。

- Node.js のサポートの終わりまで 6 か月を切ると「Node.js の更新が要ります」と出ます。終わった後は赤く出ます。配備した技術者に、新しい LTS の版への更新を頼みます
- Node.js がセキュリティの修正の下限より古いと「セキュリティの修正があります（v24.22.3 以上に更新してください）」と赤く出て、古い部分（API・ワーカー）も出ます。**できるだけ早く**、配備した技術者に Node.js の更新を頼みます（M2Office は止まりません）
- ワーカーの版が API と違う・ワーカーの知らせが 12 分より古いときは印が付きます
- 画面は外（nodejs.org など）へ最新の版を見に行きません。サポートの終わりの日付は、リリースのたびに公式の予定と見比べて直しています

## 1.0 サーバーの資源

「稼働環境」のすぐ下に、サーバーの資源が棒と図で出ます。棒は **80% 以上で黄色、90% 以上で赤**です。

| 項目 | 内容 | 気にする目安 |
|---|---|---|
| CPU の負荷 | 1 分の平均の負荷 ÷ コアの数（5 分・15 分の値も出る）。100% を超えうる | 100% を超える状態が 15 分の平均でも続くなら、サーバーの大きさが足りない |
| メモリー | 使っている量 ／ 全体（使える量は、すぐに空けられる分を含む） | 90% を超える状態が続き、Swap も増えるなら、メモリーが足りない |
| Swap | 使っている量 ／ 全体。Swap が無いサーバーは「なし」 | 増え続けるなら、メモリーが足りない |
| ディスク | ファイルの置き場があるディスクの使っている量 ／ 全体。うちデータベースとファイルの置き場の量 | 80% を超えたら、技術者と容量を足す相談を始める |
| データベースの接続 | 接続の数 ／ 上限 | 80% を超えたら、技術者に知らせる |

「推移」は、CPU の負荷・メモリー・Swap・ディスクの直近 24 時間の折れ線です（「7 日」に切り替えられます）。API が 5 分ごとに標本を取り、7 日より古いものは消します。止まっていた間は線が切れます。図の上でマウスを動かすと、その時刻の値が出ます。

「ネットワーク」は、サーバーの受信と送信の様子です。現在の速度（直近 5 分の平均）・直近 24 時間の合計（通信量）と、受信速度・送信速度の折れ線が出ます。数えるのは外とつながる口だけで、VPN（WireGuard）とサーバーの中の通信は入りません。回線の上限は契約によって違うので、注意の色は付きません。ふだんの速度を覚えておき、急に何倍にも増えたら、大量の通信の攻撃か、どこかの処理の暴走を疑います（[第 13 章](13-vps-m2office-setup.md) の「大量の通信の攻撃（DDoS）を受けたとき」）。サーバーを起動し直した直後と、記録が途切れた間は線が切れます。

## 1.1 業務の実行

「業務の実行」の見出しの下に、次の数が並びます。バックアップとセキュリティの状態は、いちばん上の区分の札に出ます。

| 項目 | 内容 | 気にする目安 |
|---|---|---|
| 待ち行列 | 始まりを待っている業務の数と、最も古い待ちの日時。実行中の数・承認待ちの数 | 待ちが増え続ける・最も古い待ちが数分より前なら、ワーカーが止まっていないかを見る |
| 実行（1 時間 ／ 今日） | 業務の実行の件数と失敗の割合 | 失敗の割合がふだんより急に上がったら、AI や Google の障害を疑う |
| ワーカー | 業務を動かすワーカーが稼働中か（最終応答）。いま動いているワーカーが 2 台以上のときは台数を出し、下に「ワーカー」の表（名前・最終応答・版）を出す。起動し直して止めた前のワーカーは数えない | 「応答がありません」なら、ワーカーが止まっている。配備した技術者に連絡する |
| 遅れている定時実行 | 予定の時刻を 5 分過ぎても動いていない定時実行の数 | 0 でなければ、ワーカーの止まりか、待ち行列の詰まり |
| AI の費用（今日 ／ 今月） | 全社の AI の費用と、前の月の同じ時期の費用 | 前の月より大きく増えていたら、会社一覧の「今月の AI」で、どの会社が増えたかを見る |
| 外部の接続（24 時間） | AI・Google・会社の接続（MCP）ごとの成功・失敗・失敗の割合・平均の速さ。呼び出しが 1 件も無ければ「まだありません」 | 失敗の割合が高い・速さが急に遅いなら、相手のサービスの障害を疑う |

## 1.2 バックアップ（表）

「業務の実行」の下に「バックアップ」の表が出ます（クラウドの形でバックアップを入れているときだけ）。いざというときに「どこまで戻せるか」「どの名前で戻すか」を、ここで確かめます。題名の横の「？」から [第 17 章](17-backup-recovery.md) を開けます。

| 行 | 内容 |
|---|---|
| 毎晩のバックアップ | 最終取得の日時と、データベース・ファイルのそれぞれが「完了」か「失敗」か |
| 次のバックアップ | 次の予定（日本時間の 2 時。最大 20 分遅れる） |
| データベースを戻せる範囲 | いちばん古い全体のバックアップの終わりから、変更の記録の最終更新の時刻まで。この中のどの時刻にも戻せる |
| データベースのバックアップ | 全体のバックアップの数・最新の日時・大きさ |
| 変更の記録 | 最終更新の日時。いま送れていなければ印が付く |
| ファイルのバックアップ | 回の数・いちばん古い回と新しい回・置き場の中の大きさ |
| データチェック | 月に 1 回、バックアップが壊れていないかを調べた結果（「正常」か「異常」）と日時 |
| 更新の前の戻す点 | 更新のたびに記録した名前と日時（新しい 5 件）。戻せる範囲より前になったものは「戻せる範囲の外」 |
| 置き場 | Google Cloud Storage のバケットの名前とプロジェクトの ID |

画面は VPS の上の結果のファイルを読むだけで、Google Cloud へは見に行きません。合言葉と鍵は出しません。

## 1.3 セキュリティ（表）

「バックアップ」の表の下に「セキュリティ」の表が出ます（クラウドの形だけ）。入口の守りと VPN が働いているかを、VPS に入らずに確かめます。題名の横の「？」から [第 18 章](18-architecture.md)（全体の構成）を開けます。

表の上に、この区分の「対応が要るもの」が出ます。その下に「推移」の図があり、攻撃・WAF に当たった要求・国の遮断で止めた通信の数を、直近 24 時間は 1 時間ごと、「7 日」に切り替えると 1 日ごとの棒で出します。図ごとに目盛りが違います。国の遮断の図の赤い棒は、出ていく通信を止めた数です（あれば警戒）。棒の上でマウスを動かすと、その時刻の数が出ます。

当てはまるものと、することは次のとおりです。

| 状態 | 当てはまるもの | すること |
|---|---|---|
| 警戒 | 集める仕組みが止まった（最終収集が 15 分より前） | いまの様子が分かりません。技術者に知らせる（`journalctl -u m2office-edge-status`） |
| 警戒 | 出ていく通信を国の遮断で止めた（直近 24 時間に 1 件以上） | サーバーの中から止めた国へつなごうとしているものがあります。乗っ取りを疑い、すぐに技術者に連絡する |
| 警戒 | 証明書の期限が切れた | 利用者が画面を開けません。すぐに技術者に連絡する（証明書の自動の更新が止まっている） |
| 注意 | 証明書の期限まで 30 日を切った | ふつうは自動で延びます。数日たっても延びなければ、技術者に知らせる |
| 注意 | 攻撃が急に増えた（直近 24 時間に 20 件以上で、ふだんの 3 倍以上） | 止める役は働いています。この表で種類と国を確かめ、2 日続いたら技術者に知らせる |
| 注意 | WAF に当たる要求が急に増えた（100 件以上で、ふだんの 3 倍以上） | この表で種類を確かめ、技術者に知らせる（WAF が「記録だけ」の間は止めていない） |
| 注意 | CrowdSec が中央とつながっていない（分け合う一覧が 0） | 世界中で分け合う一覧が届いていません。技術者に知らせる |
| 注意 | 一部を読めなかった | 表の「取得できなかった」を確かめ、技術者に知らせる |
| 注意 | 集める仕組みが未導入 | 技術者に `setup.sh` を走らせ直してもらう（[第 13 章](13-vps-m2office-setup.md)） |

「ふだん」は、直近 24 時間より前の 6 日間の 1 日あたりの平均です。入れたばかりで記録が少ない間は、ふだんが小さく出るので、注意になりやすくなります。

推移の図の下に「**直近 24 時間**」の札が 3 枚並びます。

| 札 | 内容 |
|---|---|
| 見つけて止めた攻撃 | CrowdSec が見つけて止めた攻撃の数 |
| 国の遮断で止めた通信 | 止めている国との通信を止めた数。入ってくる・出ていくの内訳が下に出ます |
| WAF に当たった要求 | WAF の規則に当たった要求の数。いまの動き（記録だけ・止める）が下に出ます。記録だけの間は、当たっても止めていません |

その下に「**攻撃の種類**」と「**攻撃の国**」が、多い順に 5 つまで横の棒で出ます。WAF に当たった要求があるときは、その種類も同じ形で出ます。

| 一覧 | 内容 |
|---|---|
| 攻撃の種類 | CrowdSec が見つけた攻撃を、「存在しないページの探り」「管理画面・秘密のファイルの探り」「ログインの総当たり」「既知の弱点を突く要求」などの種類にまとめたもの。種類にまとめられないものは、CrowdSec の見張りの名前のまま出る |
| 攻撃の国 | CrowdSec が見つけた攻撃の、相手の国。分からないものは「不明」 |
| WAF に当たった要求の種類 | WAF の規則に当たった要求の種類（「決まりに反する要求」「SQL インジェクション」など） |

インターネットに出ているサーバーには、いつも世界中から探りが来ます。「存在しないページの探り」や「決まりに反する要求」が毎日いくらかあるのは平常です。ふだんの顔ぶれを覚えておき、見慣れない種類が上に来たら、技術者に知らせます。

いちばん下の「**守りの様子**」の表に、仕組みごとの状態と中身が出ます。

| 行 | 内容 | 気にする目安 |
|---|---|---|
| CrowdSec | 「働いています」と、いま止めている相手の数（このサーバーで見つけたものと、世界中の利用者と分け合う一覧のもの） | 分け合う一覧が 0 なら「中央とつながっていません」と黄色で出る。技術者に知らせる |
| 国の遮断 | 「働いています」と、止めている国の名前・国の一覧を作った日時 | 一覧が 8 日より古いなら、週に 1 回の取り直しが止まっている。出ていく通信を止めた数（上の札）が 1 件でもあれば、サーバーの中から止めた国へつなごうとしているものがある（乗っ取りを疑い、技術者に知らせる） |
| WAF | いまの動き（「記録だけ」か「止める」） | 記録だけの間は、当たった数（上の札）がふだんより多ければ技術者に知らせる（誤って止める道か、攻撃か） |
| 証明書 | 「正常」と、証明書の数・いちばん近い期限と残りの日数。30 日を切ると「期限が近い」と黄色、切れると「期限切れ」と赤 | 黄色のまま数日たっても延びなければ、自動の更新が止まっている。技術者に知らせる |
| VPN | 登録した端末ごとに、網の中のアドレスと「接続中」（3 分以内につながった）か最終接続の時刻 | 自分が使っていない時刻に、見覚えのない接続があれば、端末の鍵が漏れたのを疑う（[第 12 章](12-vps-setup.md) の「人を足す・外す」で外す） |

- 数は VPS の上の小さな仕組み（`m2office-edge-status`）が 5 分ごとに集めて、ファイルに書きます。画面はそれを読むだけです。
- 最終収集の時刻が 15 分より前なら「止まっています」と出ます。技術者に知らせます（`journalctl -u m2office-edge-status`）。
- 仕組みを入れていなければ「未導入」と出ます（[第 13 章](13-vps-m2office-setup.md) の `setup.sh` を走らせ直すと入ります）。
- 読めなかった行は「取得できなかった」と出ます。
- 相手の IP アドレス・VPN の鍵・WAF に当たった要求の中身は出しません。

## 2. 異常に気づいたら

まず、いちばん上の「対応が要るもの」の「すること」に従います。それで分からないときは、次の順に見ます。

1. 1 社だけの問題か、全社の問題かを見分けます。会社一覧の「失敗」「注意」の印で、1 社に偏っていないかを見ます
2. 全社の問題なら、AI・Google のサービスの障害の情報を確かめ、配備した技術者に連絡します
3. 1 社だけなら、その会社の詳細の「稼働」で、どの業務・どの接続先かを見ます
