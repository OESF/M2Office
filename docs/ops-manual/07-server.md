# 第 7 章 稼働状況

左のメニューの「**稼働状況**」で、サーバー全体が健全に動いているかを見ます。1 分ごとに読み直します。

## 1. 動いている環境

いちばん上に、M2Office の版・API とワーカーの Node.js（系・段階・サポートの終わる日）・PostgreSQL・OS と CPU・メモリー・動いている形・推論・起動してからの時間が出ます。クラウドの形では、これらは運営の機械の情報なので、各社の管理者には出しません（運営だけが見ます）。

- Node.js のサポートの終わりまで 6 か月を切ると「Node.js の更新が要ります」と出ます。終わった後は赤く出ます。配備した技術者に、新しい LTS の版への更新を頼みます
- Node.js がセキュリティの修正の下限より古いと「セキュリティの修正があります（v24.22.1 以上に更新してください）」と赤く出て、古い部分（API・ワーカー）も出ます。**できるだけ早く**、配備した技術者に Node.js の更新を頼みます（M2Office は止まりません）
- ワーカーの版が API と違う・ワーカーの知らせが 12 分より古いときは印が付きます
- 画面は外（nodejs.org など）へ最新の版を見に行きません。サポートの終わりの日付は、リリースのたびに公式の予定と見比べて直しています

## 1.1 項目と見方

| 項目 | 内容 | 気にする目安 |
|---|---|---|
| 待ち行列 | 始まりを待っている業務の数と、最も古い待ちの日時。動いている数・承認待ちの数 | 待ちが増え続ける・最も古い待ちが数分より前なら、ワーカーが止まっていないかを見る |
| 実行（1 時間 ／ 今日） | 業務の実行の件数と失敗の割合 | 失敗の割合がふだんより急に上がったら、AI や Google の障害を疑う |
| ワーカー | 業務を動かすワーカーが動いているか（最後の応答）。いま動いているワーカーが 2 台以上のときは台数を出し、下に「ワーカー」の表（名前・最後の応答・版）を出す。起動し直して止めた前のワーカーは数えない | 「応答がありません」なら、ワーカーが止まっている。配備した技術者に連絡する |
| 遅れている定時実行 | 予定の時刻を 5 分過ぎても動いていない定時実行の数 | 0 でなければ、ワーカーの止まりか、待ち行列の詰まり |
| AI の費用（今日 ／ 今月） | 全社の AI の費用と、前の月の同じ時期の費用 | 前の月より大きく増えていたら、会社一覧の「今月の AI」で、どの会社が増えたかを見る |
| データベース | データベースの大きさと接続の数 | 接続の数が急に増えたら、技術者に知らせる |
| ファイルの置き場 | ファイルの使用量 | 置き場の容量に近づいたら、技術者に知らせる |
| 外部の接続（24 時間） | AI・Google・会社の接続（MCP）ごとの成功・失敗・失敗の割合・平均の速さ。呼び出しが 1 件も無ければ「まだありません」 | 失敗の割合が高い・速さが急に遅いなら、相手のサービスの障害を疑う |

## 2. 異常に気づいたら

1. 1 社だけの問題か、全社の問題かを見分けます。会社一覧の「失敗」「注意」の印で、1 社に偏っていないかを見ます
2. 全社の問題なら、AI・Google のサービスの障害の情報を確かめ、配備した技術者に連絡します
3. 1 社だけなら、その会社の詳細の「稼働」で、どの業務・どの接続先かを見ます
