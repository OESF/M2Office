# 第 2 章 運営者の管理（運営管理者）

運営者の追加・ロールの変更・無効化と、パスキーの登録の合言葉は、左のメニューの「**運営者**」で行います。操作できるのは運営管理者だけです。

## 1. 運営者を足す

1. 「運営者」を開きます
2. メールアドレス・名前・ロール（運営管理者・サポート・監視）を入れて「足す」を押します
3. 足した人の行の「**登録の合言葉を出す**」を押します
4. 出た合言葉（`XXXX-XXXX-XXXX`）を、本人に**メール以外の手段**で渡します

- 合言葉は**いまだけ**出ます。閉じると二度と見られません。渡しそびれたら、もう一度「登録の合言葉を出す」を押します（前の合言葉は使えなくなります）
- 合言葉は 24 時間で切れ、1 回だけ使えます
- 足せるのは、配備で許したドメイン（運営主体と提携会社の Google Workspace のドメイン）のアドレスだけです。個人の Gmail などは足せません

> **ロールは小さく始める**: サポートの仕事だけなら「サポート」、見守りだけなら「監視」にします。運営管理者は 2 人以上いるのが望ましいですが、むやみに増やさないでください。

## 1.1 提携会社の人を運営者にする

VPS の運用やサポートを受け持つ提携会社の人は、**提携会社の Google Workspace（か無料の Cloud Identity）のアカウント**で入れます。個人の Gmail は使えません（辞めた人のアカウントを、提携会社の側で止められないため）。

1. **許すドメインに足す**: 配備した技術者に、VPS の上で `setup.sh` を走らせ直してもらい、「マスター管理画面に入れる Google Workspace のドメイン」に、提携会社のドメインをカンマで足します（例 `ops.example.co.jp,partner.example.co.jp`。第 14 章）
2. **Google のログインの画面を「外部」にする**: Google Cloud の「Google Auth Platform › 対象」が「内部」だと、運営主体のドメインの人しか Google の画面を通れません。「外部」にします（お客様の会社の人のログインにも要ります）
3. **WireGuard の網に入れる**: 運営の画面は WireGuard の網からしか開けません。その人の端末ごとに鍵を出して VPS に登録し、端末の hosts で `ops` を網の中の VPS に向けます（第 13 章 手順 8・第 14 章）
4. **運営者として足す**: 上の「1. 運営者を足す」と同じです。ロールは仕事に合わせて小さく選びます（VPS の見守りなら「監視」、問い合わせの調べなら「サポート」）

- 提携会社の人も、ログインのたびのパスキー・2 人の承認・操作の記録の決まりは同じです
- 提携会社との契約が終わったら、その人たちを「無効にする」でログインの状態ごとすぐに止め、許すドメインからも外します（外すと、次のログインから入れません）。WireGuard の鍵も VPS から外します

## 2. ロールを変える・無効にする

- **ロール**: 行のロールの選択を変えると、すぐに保存します
- **無効にする**: 辞めた人・休む人は「無効にする」を押します。その人のログインの状態はすぐに切れ、ログインできなくなります。「有効にする」で戻せます
- 自分自身のロールと状態は、ここでは変えられません
- **運営管理者が 1 人もいなくなる変更はできません**（最後の運営管理者のロールを下げる・無効にする）

## 3. パスキーをやり直させる

運営者がパスキーをすべてなくしたときに使います。

1. その人の行の「**パスキーをやり直させる**」を押します
2. 確かめの問いに「OK」を押すと、その人のパスキーをすべて削除し、ログインの状態も切り、新しい登録の合言葉を出します
3. 合言葉を、本人にメール以外の手段で渡します

- **自分のパスキーは、自分ではやり直せません。** ほかの運営管理者に頼みます
- 本人からの依頼であることを、電話や対面で確かめてから行ってください。乗っ取りの手口として、パスキーのやり直しを頼まれることがあります

## 4. 列の見方

| 列 | 内容 |
|---|---|
| ロール | 運営管理者・サポート・監視 |
| 状態 | 有効・無効 |
| パスキー | 登録しているパスキーの数。0 の人は、まだ登録していません（合言葉を渡します） |
| 最後のログイン | いちばん最近ログインした日時 |
