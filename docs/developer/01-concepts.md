# 1. 用語と全体像

## 1.1 言葉を揃える

同じものが「プラグイン」「アドイン」「スキル」などと呼ばれがちなため、このマニュアルでは次の言葉に揃えます
（仕様書 第12.1.1節）。

| 使う言葉 | 指すもの | こう呼ばれがちなもの |
|---|---|---|
| **拡張機能** | 配布・導入の単位（パッケージ）。業務エージェント・コネクタの宣言・ヘルプなどをまとめたもの | プラグイン、アドイン |
| **業務エージェント** | 1 つの業務の定義。「議事録を作る」「あいさつに返事をする」など | スキル |
| **コネクタ** | 外部の業務システム（freee など）への接続。M2Office の外で動く MCP サーバ | 連携、インテグレーション |
| **ツール** | 業務エージェントが呼べる個々の操作。「文書を作る」「メールの下書きを作る」など。M2Office は Google Workspace を操作するツールを標準で持つ（第4章） | 関数、アクション |

関係を図にすると次のとおりです。

```
拡張機能（パッケージ）
├── 業務エージェント（1 つ以上）… 何を、どの順で、どこで承認して進めるか
│     └── ツールを呼ぶ ─┬─ 内蔵ツール（M2Office が持つ）
│                      └─ コネクタのツール（外部の MCP サーバが持つ）
└── 評価のケース・ヘルプ
```

## 1.2 拡張の 3 階層

| 階層 | 作るもの | 動く場所 | 必要な技術 | このマニュアル |
|---|---|---|---|---|
| **L1** | 業務エージェント（スキル。SKILL.md） | M2Office の中（M2Office が解釈する） | 業務の知識と、指示を文で書く力 | 第2〜6章、第8章 |
| **L2** | コネクタ（MCP サーバ） | **M2Office の外**（提供者か顧客のサーバ） | API の開発 | 第7章 |
| **L3** | 外部アプリ | 完全に外部 | 一般的な Web 開発 | （公開 API の整備後に追加） |

## 1.3 なぜコードを書かないのか

**M2Office は、第三者が書いたコードを自分のプロセスの中で実行しません**（仕様書 第12.2節）。

業務エージェントは、業務の指示（本文）と使うツール（`allowed-tools`）を**書くだけ**です。段と承認の場所は M2Office が組み立てます。
条件分岐や繰り返しも書きません。手順の中の判断は、指示を読んだ推論（LLM）が行います。

| そのおかげで | 説明 |
|---|---|
| 安全に受け入れられる | 定義は M2Office が検証してから動かす。任意の処理を紛れ込ませられない |
| 承認を迂回できない | メールの送信やチャットへの投稿は、定義の書き方にかかわらず必ず承認のあとになる |
| 業務の人が作れる | プログラミングではなく、業務の手順として書ける |

外部のシステムを操作したいときは、その処理を**コネクタ**として M2Office の外に作ります（第7章）。

## 1.4 業務エージェントが動く流れ

```
利用者がメニューで入力して実行
  ↓
M2Office が待ち行列に入れる（すぐに画面へ戻る）
  ↓
ワーカーが定義のステップを順に進める
  ├ agent ステップ: 指示を推論に渡し、推論が選んだツールを呼ぶ
  └ approval ステップ: 人の承認を待って止まる（承認されると続きから）
  ↓
成果物を保存し、実行の詳細に表示する
```

推論には Gemini を使います。会社に Gemini の接続が設定されていないと、業務は動かず「Gemini の接続が設定されていません。管理者ページの「接続」で設定してください」と出ます。
拡張機能の動作は、本物の推論で動かし、評価のケースの期待する結果と見比べて確かめます（第6.4節）。

## 1.5 作れるもの・作れないもの（いまの版）

| 作れる | まだ作れない |
|---|---|
| **Google Workspace を操作する業務**（Gmail・カレンダー・ToDo・Chat・ドライブ・ドキュメント・スプレッドシート・スライド・Meet・フォーム。第4章） | 社内の名簿・Meet・フォームの Google への実際の接続（見本の接続口で動く。ほかのサービスは本物につながる） |
| **スライドを作る業務**（第4.5節） | 条件による分岐・同じステップの繰り返し |
| 内蔵ツールを組み合わせた業務エージェント | 認証の要るコネクタ（`oauth`・`api_key`。第7.6節） |
| 認証の要らない MCP サーバをつなぐコネクタ（第7章）と、会社がすでに登録した接続（MCP）のツールを `allowed-tools` で使う業務 | |
| 承認・操作の確認を含む手順 | 第三者の配布元（リポジトリ）からの取り込み |
| 入力のフォーム（SKILL.md の `m2office-inputs` から自動で作る） | マーケットへの公開・審査の手続き |
| 評価のケース（入力と期待する結果）を添え、推論の結果と見比べる（第5.3節） | GUI からの作成 |
| SKILL.md 1 つか、スキルのフォルダの ZIP（.m2ext も可）で渡し、管理者ページで取り込む（第5章） | |
| 使える人を、会社がグループや人で絞る（第6.2節「利用できる人」） | |
