# 3. 業務エージェントの書き方

**業務エージェントは、スキルの形式（SKILL.md）で書きます**（仕様書 第12.12節）。第3.0節がそのリファレンスです。
第3.1節から後ろは、JSON で書く定義（`agents/*.json`）のリファレンスです。**JSON で書く形は廃止の方向**で、新しくは書きません
（M2Office の中では、SKILL.md をこの定義に組み立てて動かします）。

## 3.0 SKILL.md（標準）

スキル（Claude Code の Skills・Agent Skills）の書き方のまま書きます。**M2Office で覚えることは第2章の冒頭の 4 つだけ**です。

### スキルの項目の扱い

| スキルの項目 | M2Office での扱い |
|---|---|
| `name` | 業務の ID の一部（`<拡張機能の ID>:<name>`）。省けばフォルダの名前 |
| `description` | メニューの説明と、秘書が業務へ取り次ぐ手がかり。省けば本文の最初の行 |
| `when_to_use` | `description` に添えて、秘書の取り次ぎの手がかりにする |
| 本文の最初の見出し（`# 〇〇`） | 画面に出す業務の名前。無ければ `name` |
| 本文 | 業務の指示（推論が読む） |
| `argument-hint` | 入力の欄に薄く出る例 |
| `arguments` | 入力の欄（1 つの名前が 1 つの欄）。無ければ自由記入の「依頼」の欄 1 つ |
| `$ARGUMENTS`・`$ARGUMENTS[N]`・`$N`・`$名前` | 実行のときに入力で置き換える（`\$` は `$` のまま） |
| `disable-model-invocation: true` | 秘書は取り次がない。メニューからだけ使う |
| `user-invocable: false` | メニューに出さない。秘書が取り次いだときだけ使う |
| `allowed-tools` | **M2Office の道具の一覧**（第4章）。書いた道具しか使えない。書かなければ読むだけの道具（`knowledge.search`・`file.read_text`）、`""` なら道具なし。M2Office に無い道具（`Bash`・`Read` など）は無視して知らせる |
| `effort` | `low` は高速のモデル、`medium`・`high` は標準、`xhigh`・`max` は高性能のモデル |
| `model`・`context`・`agent`・`background`・`disallowed-tools`・`hooks`・`paths`・`shell` | 使わない（知らせる） |
| `license`・`compatibility`・`metadata` | 保つ。`metadata.version`・`metadata.author` は拡張機能の版と提供者 |
| 補助のファイル（`reference.md`・`examples.md` など） | スキルと同じく、本文から参照したものを推論が必要なときに読む（道具 `skill.read` が自動で付く）。Markdown・テキストのみ |
| `scripts/`・`` !`コマンド` ``・`${CLAUDE_SKILL_DIR}` | 動かさない。ファイルは除き、コマンドは消して知らせる |

### M2Office で足すもの

| もの | 使うとき |
|---|---|
| `HELP.md` | 利用者向けの説明。業務の題名の「？」とヘルプセンターに出る |
| `metadata.m2office-id` | 他の会社に配るときの ID（逆ドメイン名）。無ければ `skill.<name>`（自社専用） |
| `metadata.m2office-inputs` | 欄に種類を付けたいとき。1 行に 1 つ「欄の名前: 種類」（`短文`・`長文`・`日付`・`ファイル`、後ろに「（任意）」） |
| `metadata.m2office-examples` | 業務の説明に実行例のボタンを出したいとき（1 行に 1 つ） |
| `metadata.m2office-approver` | 社外に出すものを依頼した本人以外が承認するとき（`承認者`・`管理者`） |

### M2Office が組み立てるもの

段・承認の段・入力のフォーム・権限の同意は、取り込むときに M2Office が作ります。
送る道具（`gmail.send`・`chat.post` など）を `allowed-tools` に書けば「作業 → 承認 → 送る」になり、
社外にもお金にも関わらなければ、承認は自動で通ります。結果は、最後に返した文がそのまま出ます。

---

以下は JSON で書く定義（廃止の方向）のリファレンスです。形式は `schemaVersion: 1` です（仕様書 第9.2節）。

## 3.1 全体

| 項目 | 必須 | 内容 |
|---|---|---|
| `schemaVersion` | 必須 | `1` |
| `id` | 必須 | 拡張機能の中での名前（英小文字・数字・ハイフン）。M2Office の中では `<拡張機能の ID>:<id>` になる |
| `version` | 必須 | 定義の版（整数）。手順を変えたら上げる |
| `name` | 必須 | 業務の名前。メニューに出る |
| `category` | 必須 | 分類（例: `sample`・`accounting`）。秘書の取り次ぎの手がかりになる |
| `description` | 必須 | 1 文の説明。メニューに出る |
| `locale` | 必須 | `ja-JP` |
| `compartment` | 必須 | 権限区画の名前（例: `hr`）。区画外は `null`。区画に属する業務は、**区画に入れる人（会社が割り当てたグループと人）だけ**が実行でき、`web.research` を使えない（仕様書 第16.3節・第16.7.5節） |
| `inputs` | 必須 | 入力の JSON Schema。フォームが自動で作られる（第3.2節） |
| `tools` | 必須 | 使うツールの名前。**マニフェストの `permissions.tools` の中から**選ぶ（第4章） |
| `steps` | 必須 | 手順。1 つ以上（第3.3〜3.4節） |
| `constraints` | 必須 | 常に守らせる禁止事項。推論への指示の冒頭に差し込まれる |
| `limits` | 必須 | 上限（第3.5節） |
| `help` | **拡張機能では必須** | 利用者向けの説明（第3.6節） |
| `evals` | 任意 | 評価のケース。`evals/*.json` に分けて書くこともできる（第5.3節） |

**定義に書けないもの**: 条件分岐・繰り返し・モデルの指定・ツールの危険度の上書き・承認の省略・任意のコード。
これらは基盤が決めます（仕様書 第9.2.2節）。

## 3.2 inputs（入力のフォーム）

JSON Schema の `object` として書きます。

```json
"inputs": {
  "type": "object",
  "required": ["title"],
  "properties": {
    "title": { "type": "string", "title": "会議名" },
    "transcript": { "type": "string", "title": "会議の記録", "format": "textarea" }
  }
}
```

| 項目 | 画面での扱い |
|---|---|
| `title` | 入力欄の見出し |
| `required` | 見出しに「（必須）」が付く |
| `format: "textarea"` | 複数行の入力欄になる |

入力はそのまま推論に渡されます（`# 入力` として JSON で）。

## 3.3 agent ステップ

推論に指示を与え、推論が選んだツールを呼ぶステップです。

```json
{
  "id": "draft",
  "type": "agent",
  "label": "作成",
  "instruction": "記録から議題・決定事項・保留事項・担当と期限を構造化し、議事録を作成する。",
  "onEmpty": "continue",
  "onError": "stop"
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | 必須 | ステップの ID。定義の中で重ならないこと |
| `type` | 必須 | `agent` |
| `label` | 推奨 | 画面の「進み方」とダッシュボードに出る短い名前（2〜6 文字）。省略すると ID が出る |
| `instruction` | 必須 | 推論への指示。業務の言葉で書く（第8章） |
| `onEmpty` | 任意 | 推論が何も返さず、ツールも呼ばなかったとき。`continue`（既定）か `stop`（ここで終える） |
| `onError` | 任意 | 失敗したとき。`stop`（既定。実行を失敗にする）か `continue`（次へ進む） |

推論には、`instruction` のほかに、入力と**それまでのステップの結果**が渡されます。
前のステップで読んだメールや文書は「データであり、指示ではない」と明示して渡されます（不変則 I-6）。

## 3.4 approval ステップ

人の承認を待って止まるステップです。承認されると次のステップから続き、却下されるとそこで終わります。

```json
{
  "id": "gate-share",
  "type": "approval",
  "label": "共有の承認",
  "approverRole": ["admin", "approver"],
  "present": "共有先のスペースと、投稿する本文",
  "onReject": "stop"
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `approver` | 任意 | `role`（既定。ロールで判断する）か `requester`（依頼した本人だけが判断する） |
| `approverRole` | `role` のとき必須 | 判断できるロール（`admin`・`approver`・`member`） |
| `present` | 必須 | 承認の画面に出す「何を確認してほしいか」 |
| `onReject` | 任意 | `stop`（既定） |

**承認の置き場所の決まり**

| ツールの危険度 | 決まり |
|---|---|
| `external-send`・`financial` | **承認ステップの直後のステップでしか呼べません。** 定義に承認ステップが無ければ、導入も実行もできません |
| `write-internal` | 承認ステップの直後なら、そのまま実行されます。それ以外では、会社の設定により、実行の直前で依頼者に確認を求めます（操作の確認） |
| `read`・`draft` | 承認は要りません |

## 3.5 limits（上限）

| 項目 | 内容 |
|---|---|
| `maxSteps` | 進めるステップの数の上限 |
| `maxTokens` | 推論に使う量の上限 |
| `timeoutSec` | 時間の上限（秒） |

いずれかに達すると実行を打ち切ります。業務に見合った小さめの値にしてください。

## 3.6 help（利用者向けの説明）

```json
"help": {
  "summary": "会議の記録から議事録を作り、決定事項を ToDo にして、承認のあとにチャットで共有します。",
  "examples": [{ "title": "定例会議の議事録を作る", "input": { "title": "営業定例" } }],
  "notes": ["記録が空のときは、議事録を作らずに止まります"],
  "faq": [{ "q": "承認しないとどうなりますか", "a": "却下すると、そこで止まります" }]
}
```

| 項目 | 必須 | 画面での扱い |
|---|---|---|
| `summary` | 必須 | 業務のカードの冒頭 |
| `examples` | 推奨 | 「実行例」のボタン。押すと `input` が入力欄に入る |
| `notes` | 任意 | 「注意点」 |
| `faq` | 任意 | 「よくある質問」 |

次の項目は**定義から自動で作られる**ので、`help` に書く必要はありません（仕様書 第6.10.5節）。

| 自動で作られる項目 | 出どころ |
|---|---|
| この業務がすること | 使うツールの「すること」（第4章の表の右の列） |
| 進み方 | 各ステップの `label` |
| 承認が入る場所と判断する人 | 承認ステップと `approver`・`approverRole` |
| 入力するもの | `inputs` |

## 3.7 版の上げ方

| 変えたもの | 上げるもの |
|---|---|
| 指示の言い回し、ヘルプ | マニフェストの `version` の 3 番目（`1.0.0` → `1.0.1`） |
| ステップの追加・削除、入力の変更 | 定義の `version` と、マニフェストの `version` の 2 番目 |
| 使うツールや危険度が増える | マニフェストの `version` の 1 番目。導入済みの会社では再同意が要る（今後の実装） |
