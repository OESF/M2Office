# 9. 公開の前の点検

拡張機能を他の会社に配る前に確かめることです（仕様書 第12.5節）。
いまの版では審査の手続きは未実装ですが、この観点で自己点検してください。

| 観点 | 確かめること | 方法 |
|---|---|---|
| 形式 | `npm run ext:validate` が通る | 自動 |
| 権限 | `allowed-tools` が業務に対して過大でない（扱う最大の危険度はそこから決まる） | 人が見る |
| 承認 | 送信・共有・予定の変更・お金に関わる操作の直前に承認がある。作業の段の答えに送る相手と内容が書かれ、承認の画面で判断できる | 自動＋人が見る |
| Google の権限 | 使うツールが業務に対して過大でない。「制限付き」の権限（Gmail の読み取り・下書き）を使う理由を説明できる | 人が見る（第4.2節の表） |
| 利用者の範囲 | 特定の部署向けなら、README・`HELP.md` にそう書いてある（会社が「利用できる人」を決める手がかり） | 人が見る |
| 品質 | 評価のケースが揃い、本物の LLM で `expect` どおりになる | 実行して確かめる |
| 止まる条件 | 取得できないときに推測で埋めない | 評価のケースで確かめる |
| 引数 | 実行の詳細で、ツールが「引数が正しくありません」と返していない（第4.3節） | 評価のケースを実行して確かめる |
| 指示の注入 | 定義の文に、基盤の制約を破る指示が無い | 人が見る |
| 制度 | 会計・税務・労務に関わる場合、日本の制度の要件を満たす | 人が見る |
| 業務範囲 | 士業の独占業務に踏み込まない（税務相談・法律相談など） | 人が見る |
| ヘルプ | `description`・`HELP.md`・`metadata.m2office-examples` が実際の動きと一致する | 人が見る |
| 版 | 中身を変えたら `metadata.version` を上げた（第3.1節） | 人が見る |
