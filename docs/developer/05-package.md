# 5. 拡張機能パッケージ

## 5.0 スキルの形式（標準）

**ふつうは SKILL.md で書きます**（第2章・第3.0節。仕様書 第12.12節）。

```
<フォルダ名>/
  SKILL.md             必須。業務の指示（Agent Skills の形）
  references/*.md      任意。本文から参照する資料（Markdown・テキスト。合計 5 万字まで）
  evals/*.json         任意。鍵が無いときの見本の答え（answer）
  README.md            任意。管理者ページの「詳細」に表示される説明
  icon.png             任意。管理者ページのアイコン
```

取り込むときは、`SKILL.md` をそのまま選ぶか、フォルダを ZIP にします（`.zip`・`.skill`・`.m2ext` のどれでも）。
**`scripts/` などのプログラムや画像が入っていても取り込めますが、それらは除かれ、実行されません。**
マニフェストは SKILL.md から作られるので、書く必要はありません。

以下の第5.1節から後ろは、JSON で書く形（廃止の方向）の説明です。

## 5.1 構成（JSON の形）

```
<ディレクトリ名>/
  manifest.json        必須。拡張機能の名札と権限
  agents/*.json        業務エージェントの定義
  connectors/*.json    コネクタの宣言（第7章）
  evals/*.json         推奨。評価のケースと見本の応答
  help/*.md            任意。ヘルプの記事（表示は今後の版）
  README.md            推奨。管理者ページの「詳細」に表示される説明
  icon.png             推奨。管理者ページのアイコン（PNG、256 KB まで、64×64 程度）
```

`agents/` と `connectors/` の少なくとも一方が必要です。

**入れてよいファイルは上の 7 種類だけです**（仕様書 第12.10.2節）。
それ以外のファイル、**とくにプログラム（`.js`・`.py`・実行ファイルなど）が入っていると、検証を通りません。**
M2Office は第三者のコードを自分の中で動かさないためです。処理が必要なら、コネクタ（M2Office の外で動く MCP サーバ）として作ります。

**形式は JSON だけです。** 仕様書の例は読みやすさのため YAML で書いていますが、読み込むのは JSON です。

## 5.2 manifest.json

| 項目 | 必須 | 規則 |
|---|---|---|
| `id` | 必須 | 逆ドメイン名の形。英小文字・数字・ハイフン・ピリオド（例: `jp.example.construction`） |
| `name` | 必須 | 拡張機能の名前。管理者ページに出る |
| `version` | 必須 | `メジャー.マイナー.パッチ`（例: `1.2.0`） |
| `description` | 推奨 | 管理者ページに出る説明 |
| `publisher.name` | 必須 | 提供者の名前。管理者ページと業務の画面に出る |
| `publisher.verified` | 任意 | 認定済みの提供者か（審査の仕組みの整備後に運営が付与） |
| `platform_schema` | 必須 | 対応する定義の形式の版。いまは `">=1 <2"` |
| `permissions.tools` | 必須 | 使うツールの一覧。定義はこの中のツールしか使えない。コネクタのツールは `<コネクタの ID>.<ツールの名前>` |
| `permissions.max_risk_level` | 必須 | 扱う最大の危険度（`read`・`draft`・`write-internal`・`external-send`・`financial`）。コネクタのツールもこれを超えられない |

管理者は導入の前に、`permissions` とコネクタの接続先を平易な言葉に直したもの（業務エージェントがすること、どこにつなぐか、
使う操作と扱う最大の危険度）を見て同意します。

## 5.3 評価のケース（evals/*.json）

```json
{
  "agent": "hello",
  "cases": [
    { "name": "こんにちは", "input": { "message": "こんにちは" }, "expect": "本文が「Hello World」の返事を保存する" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `agent` | 定義の `id`（拡張機能の中での名前） |
| `cases[].name` | ケースの名前 |
| `cases[].input` | 実行の入力 |
| `cases[].expect` | 期待する結果（文章）。本物の LLM での評価と、審査の基準になる |
| `cases[].stub` | 見本の応答（第5.4節）。任意 |

ケースは、**うまくいく場合**だけでなく、**止まるべき場合**（入力が足りない、対象が無いなど）も書いてください。

## 5.4 見本の応答（stub）

LLM の鍵が無い開発環境で、推論の代わりにスタブが返す応答です（仕様書 第12.9.4節）。

```json
"stub": {
  "reply": [
    { "name": "document.create", "args": { "kind": "reply", "title": "返事", "body": "Hello World" } }
  ]
}
```

| 規則 | 内容 |
|---|---|
| 書き方 | ステップ ID ごとに、そのステップで推論が呼ぶはずのツールの配列 |
| 使われる条件 | 実行の入力が `input` と**完全に一致**したとき（キーの順序は問わない） |
| 一致しないとき | 見本を持つ業務エージェントでは、スタブは推測でツールを呼ばず、「見本の応答がありません」と記録する |
| 前のステップの結果 | 引数の文字列に `{{ステップ ID}}` と書くと、そのステップのツールの結果（文字列）に置き換わる。結果が無ければ「（取得できませんでした）」になる |
| 承認のあるとき | 承認ステップは見本を書かない。承認の後のステップに見本を書けば、承認すると続きが再生される |
| 本物の LLM | 見本を使わない |

`{{ステップ ID}}` を使うと、「コネクタで調べて、その結果を資料に残す」のような流れを鍵なしで確かめられます（第7.3節）。
**コネクタのツールは、見本の応答でも本物の外部サービスを呼びます。** 見本が決めるのは「どのツールを、どの引数で呼ぶか」だけです。

**見本は開発と試験のための仕組みです。** 定義の一部ではありません。
定義の `instruction` は、見本が無くても本物の推論で正しく動くように書いてください。

## 5.5 持ち運べるファイル（.m2ext）

拡張機能は、1 つのファイル（`.m2ext`）にして渡せます（仕様書 第12.10節）。中身は ZIP で、直下に `manifest.json` があります。

```bash
npm run ext:pack examples/extensions/weekly-report
# → dist/extensions/jp.example.weekly-report-1.0.0.m2ext
```

| 規則 | 内容 |
|---|---|
| 作り方 | `npm run ext:pack <ディレクトリ> [出力先]`。先に検証し、通らなければ作らない |
| 入るファイル | 第5.1節の 7 種類だけ。ほかのファイルは入れずに、その名前を表示する |
| 大きさ | 5 MB まで |
| 自分で ZIP にする場合 | フォルダごと圧縮してもよい（1 つのフォルダの下にすべてがあれば、そのフォルダを外して読む）。`.zip` の拡張子でも取り込める |

受け取った管理者は、管理者ページの「拡張機能」で「ファイルから追加」を押すか、画面へドラッグして取り込みます（第6.2節）。

## 5.6 読み込まれる時機

| 置き場所 | 読み込み | 見える会社 |
|---|---|---|
| リポジトリの `extensions/`（公式の配布元） | API とワーカーの**起動時** | 全社（導入は会社ごと） |
| 管理者ページから取り込んだ `.m2ext` | **取り込んだ時点**（再起動は要らない） | 取り込んだ会社だけ（自社専用） |

`extensions/` の拡張機能を追加・変更したら、`npm run dev` を起動し直してください。
置き場所は環境変数 `EXTENSIONS_DIR` で変えられます（既定はリポジトリ直下の `extensions`）。

自社専用の拡張機能の置き場所として、サンプルを [examples/extensions/](../../examples/extensions/) に置いています。
ここは起動時に読み込まれないため、`.m2ext` にして取り込む流れを試すのに使えます。
