# 5. 拡張機能パッケージ

## 5.0 構成

**拡張機能は SKILL.md で書きます**（第2章・第3.0節。仕様書 第12.12節）。
JSON で書く形（`manifest.json`＋`agents/*.json`）は第 0.131.0 版で廃止しました。取り込もうとすると「SKILL.md で書いてください」と断ります。

```
<スキルの名前>/
  SKILL.md             必須。スキルの書き方のまま
  HELP.md              任意。利用者向けの説明
  connectors/*.json    任意。外部のサービス（MCP サーバ）をつなぐコネクタの宣言（第7章）
  reference.md など    任意。本文から参照する補助のファイル（Markdown・テキスト。合計 50 万字まで）
  evals/*.json         任意。評価のケース（入力と期待する結果）
  README.md            任意。管理者ページの「詳細」に出る説明
  icon.png             任意。管理者ページのアイコン（PNG、256 KB まで、64×64 程度）
```

取り込むときは、フォルダを ZIP にするか（`.zip`・`.skill`・`.m2ext` のどれでも）、`SKILL.md` をそのまま選びます。
**`scripts/` などのプログラムや画像が入っていても取り込めますが、除かれ、実行されません**（M2Office は第三者のコードを自分の中で動かしません）。
処理が必要なら、コネクタ（M2Office の外で動く MCP サーバ）として作ります。

拡張機能の名札と権限（マニフェスト）は SKILL.md から作られるので、書く必要はありません。

| マニフェストの項目 | SKILL.md のどこから作るか |
|---|---|
| ID | `metadata.m2office-id`（逆ドメイン名。例: `jp.example.construction`）。無ければ `skill.<name>`（自社専用） |
| 名前 | 本文の最初の見出し（`# 〇〇`） |
| 版 | `metadata.version`（`メジャー.マイナー.パッチ`。無ければ `1.0.0`） |
| 提供者 | `metadata.author`（無ければ「自社」） |
| 使う道具 | `allowed-tools`（コネクタの道具は `<コネクタの ID>.<道具>`） |
| 扱う最大の危険度 | 使う道具の危険度から自動で決まる |

管理者は導入の前に、使う道具とコネクタの接続先を平易な言葉に直したもの（業務がすること、どこにつなぐか、
使う操作と扱う最大の危険度）を見て同意します。

## 5.3 評価のケース（evals/*.json）

```json
{
  "agent": "hello",
  "cases": [
    { "name": "こんにちは", "input": { "あいさつ": "こんにちは" }, "expect": "「Hello World」と返す" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `agent` | SKILL.md の `name` |
| `cases[].name` | ケースの名前 |
| `cases[].input` | 実行の入力 |
| `cases[].expect` | 期待する結果（文章）。本物の LLM での評価と、審査の基準になる |
| `cases[].stub` | M2Office の自動テスト用（第5.4節）。拡張機能を作る人は書かない |

ケースは、**うまくいく場合**だけでなく、**止まるべき場合**（入力が足りない、対象が無いなど）も書いてください。

## 5.4 自動テスト用の見本の応答（stub）

**拡張機能を作る人は書きません。** M2Office 自身の自動テスト（単体テストと通しの確認。`LLM_PROVIDER=stub`）のための仕組みです（仕様書 第12.9.4節・第20.2.4節）。
公式の配布元のサンプルの評価のケースに `stub` があるのは、この自動テストのためです。

M2Office は、Gemini の接続が無い環境を想定しません。接続が設定されていない会社では、業務は動かず「Gemini の接続が設定されていません。管理者ページの「接続」で設定してください」と出ます。
拡張機能は本物の推論で動かし、評価のケースの `expect` と結果を見比べて確かめてください（第6.4節）。

## 5.5 持ち運べるファイル（.m2ext）

拡張機能は、1 つのファイル（`.m2ext`）にして渡せます（仕様書 第12.10節）。中身は ZIP で、直下に `SKILL.md` があります。

```bash
npm run ext:pack examples/extensions/weekly-report
# → dist/extensions/jp.example.weekly-report-2.0.0.m2ext
```

| 規則 | 内容 |
|---|---|
| 作り方 | `npm run ext:pack <ディレクトリ> [出力先]`。先に検証し、通らなければ作らない |
| 入るファイル | 第5.0節のものだけ。ほかのファイルは入れずに、その名前を表示する |
| 大きさ | 5 MB まで |
| 自分で ZIP にする場合 | フォルダごと圧縮してもよい（1 つのフォルダの下にすべてがあれば、そのフォルダを外して読む）。`.zip` の拡張子でも取り込める |

受け取った管理者は、管理者ページの「拡張機能」で「ファイルから追加」を押すか、画面へドラッグして取り込みます（第6.2節）。

## 5.6 読み込まれる時機

| 置き場所 | 読み込み | 見える会社 |
|---|---|---|
| リポジトリの `extensions/`（公式の配布元） | API とワーカーの**起動時** | 全社（導入は会社ごと） |
| 管理者ページから取り込んだ `.m2ext` | **取り込んだ時点**（再起動は要らない） | 取り込んだ会社だけ（自社専用） |

`extensions/` の拡張機能を追加・変更したら、`npm run dev` を起動し直してください。
置き場所は環境変数 `EXTENSIONS_DIR` で変えられます（既定はリポジトリ直下の `extensions`）。

自社専用の拡張機能の置き場所として、サンプルを [examples/extensions/](../../examples/extensions/) に置いています。
ここは起動時に読み込まれないため、`.m2ext` にして取り込む流れを試すのに使えます。
