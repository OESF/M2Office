# 7. コネクタの作り方（freee を例に）

> **この章は設計と見通しです。** M2Office 側でコネクタ（MCP サーバ）とつなぐ仕組みは、まだ実装していません
> （仕様書 第12.9.5節）。つなぐ仕組みができたとき、ここに書いた形で作れるよう、いまから設計を揃えておくための章です。

## 7.1 コネクタとは

**コネクタは、外部の業務システムの操作を、M2Office から呼べるツールとして提供するもの**です。
M2Office の外で動く **MCP サーバ**として作ります（仕様書 第12.1節 L2、第14.4節）。

```
業務エージェント ──ツールを呼ぶ──▶ M2Office ──MCP──▶ コネクタ（MCP サーバ）──API──▶ freee
                                 （承認・危険度・記録）   （提供者か顧客のサーバで動く）
```

| なぜ外で動かすのか | 説明 |
|---|---|
| 第三者のコードを中で動かさない | M2Office は第三者のコードを自分のプロセスで実行しない（仕様書 第12.2節） |
| 認証情報を分けられる | freee の鍵はコネクタの側で扱い、推論には渡さない |
| 言語を選ばない | MCP に対応していれば、どの言語で作ってもよい |

## 7.2 役割の分担

| 担うこと | M2Office | コネクタ |
|---|---|---|
| 外部システムの API を呼ぶ | | ✓ |
| 外部システムの認証（OAuth など） | 認証情報を暗号化して保管し、コネクタへ渡す | 受け取って使う |
| ツールの一覧を返す | | ✓（MCP の `tools/list`） |
| **ツールの危険度を決める** | **✓（管理者が割り当てる）** | 推奨の危険度を宣言できるだけ |
| 承認・操作の確認 | ✓ | |
| 呼び出しの記録（監査ログ） | ✓ | |
| 応答をデータとして扱う | ✓（指示として解釈しない） | |

**危険度はコネクタが決めません。** 提供者が「読むだけ」と宣言しても、管理者が割り当てるまでは最も厳しい扱いになります
（仕様書 第14.4節）。コネクタが嘘をついても、承認を迂回できないようにするためです。

## 7.3 freee コネクタの設計例

### 提供するツール（案）

| ツール | freee で行うこと | 推奨の危険度 |
|---|---|---|
| `freee.list_deals` | 取引（収入・支出）の一覧を取る | read |
| `freee.list_partners` | 取引先の一覧を取る | read |
| `freee.get_invoice` | 請求書を 1 件取る | read |
| `freee.create_invoice_draft` | 請求書を**下書き**で作る | draft |
| `freee.issue_invoice` | 請求書を発行する（取引先に届く・会計に載る） | **financial** |

**下書きと確定を別のツールに分けてください。** 確定（発行）は `financial` になり、必ず承認のあとに行われます。
1 つのツールで「作って発行する」にすると、下書きの段階でも承認が要り、使い勝手が悪くなります。

### 拡張機能のマニフェスト（案）

```json
{
  "id": "jp.example.freee-invoice",
  "name": "freee 請求書作成",
  "version": "1.0.0",
  "publisher": { "name": "株式会社サンプル" },
  "platform_schema": ">=1 <2",
  "permissions": {
    "tools": ["freee.list_deals", "freee.list_partners", "freee.create_invoice_draft", "freee.issue_invoice", "knowledge.search"],
    "max_risk_level": "financial",
    "connectors": [{ "id": "freee", "protocol": "mcp", "required": true }]
  }
}
```

`connectors` は、この拡張機能が必要とするコネクタの宣言です（仕様書 第12.3節）。
**いまの版では、`freee.*` のツールは登録されていないため、この拡張機能は検証を通りません。**

### 業務エージェント（案）

```json
{
  "id": "monthly-invoice",
  "name": "月次の請求書作成（freee）",
  "tools": ["freee.list_deals", "freee.list_partners", "freee.create_invoice_draft", "freee.issue_invoice"],
  "steps": [
    { "id": "collect", "type": "agent", "label": "集計",
      "instruction": "対象月の取引を取引先ごとに集計する。取得できなかった取引先は推測せず、取得不可として報告する。" },
    { "id": "draft", "type": "agent", "label": "下書き",
      "instruction": "取引先ごとに請求書の下書きを作る。適格請求書の記載要件を満たすこと。" },
    { "id": "gate", "type": "approval", "label": "発行の承認", "approverRole": ["admin", "approver"],
      "present": "請求書の一覧（取引先・金額・税率ごとの合計）" },
    { "id": "issue", "type": "agent", "label": "発行",
      "instruction": "承認された請求書を発行する。" }
  ]
}
```

`freee.issue_invoice`（financial）は、承認ステップ（`gate`）の直後の `issue` でしか呼べません。
これは定義の書き方ではなく、基盤が強制します。

## 7.4 コネクタ（MCP サーバ）を作るときの決まり

| # | 決まり | 理由 |
|---|---|---|
| 1 | ツールの説明（`description`）を業務の言葉で書く。**すること・しないこと**を必ず含める | 管理者が危険度を割り当てる判断材料になる。業務の説明にも使われる |
| 2 | 読む・下書き・確定を**別のツールに分ける** | 承認を必要な所にだけ置ける |
| 3 | 取得に失敗したら、失敗として返す。空の結果で代用しない | 「取引なし」と「取得できなかった」を取り違えないため |
| 4 | 応答に指示のような文を含めない。含めても M2Office は従わない | 不変則 I-6 |
| 5 | 1 回の応答を大きくしすぎない。一覧は件数の上限と続きの取り方を持つ | 推論に渡す量に上限がある |
| 6 | 認証情報を応答に含めない | ログや推論に漏れないため |
| 7 | 冪等にする（同じ呼び出しを 2 回受けても二重に発行しない） | 再試行で二重請求を起こさないため |
